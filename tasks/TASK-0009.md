## 背景

部署是独立、可回退的操作（ADR-0012、ADR-0017）；先在开发机上的本地预发演练，不动生产主机。

## 交付内容

- Compose：caddy、web、public-api、private-api、worker、fetcher、postgres（+ 一次性 migrate），没有 admin-web。
- Caddy 公开域名与 `PRIVATE_HOST` 两个主机名（公开主机名访问私有路径 404 且剥离 `Set-Cookie`）；按服务挂载只读密钥文件；镜像按 SHA 构建。
- 部署与回滚脚本（回滚也验收）；共享缓存层默认“无缓存直连”。
- `make release-check` 的制品构建、镜像扫描、SBOM、签名阶段。

## 首个本地故障回滚增量

最终部署目标保留 Owner 现有腾讯上海服务器及 `aiminingpolicy.com` / `admin.aiminingpolicy.com`，不另建部署栈，正式服务器不承担构建。本增量只在隔离本地执行器演练现有 Compose；本地通过不代表正式制品、生产或切换就绪。

- 从本新仓固定 SHA 导出隔离目录，生成仅供演练的合成配置；不读取用户或仓库现有 `.env`、生产秘密、旧代码。采集与模型调用关闭，只绑定 loopback 端口，拒绝远程 Docker 目标。
- 部署控制器只接受执行器已准备好的本地不可变 image ID（`sha256:<64 hex>`），记录候选与上一版本的确切 ID。执行 `--no-build` / `--pull never`，不构建、不拉取；本地 image ID 不冒称仓库镜像 manifest digest。
- 正常及故意不健康的测试镜像由独立本地准备步骤提供，沿用本仓 Dockerfile；准备步骤与部署控制器分开。应用角色显式传入同一个 `AMP_RELEASE`，不改变现有 API 路由或模型行为。
- 使用本次独占的项目名、卷、锁与阶段记录。先启动正常版本，通过实际健康、公开读取及公开 / 私有 Host 隔离检查，再投放不健康候选，触发自动回滚到上一确切 image ID。
- 回滚后重新执行同一套真实检查，不能用容器启动成功代替应用验收。候选失败即非零退出，即使回滚成功也只记录“恢复成功”；回滚检查再失败仍非零，保留失败阶段，不输出部署成功。
- 记录固定源码 SHA、镜像 ID、阶段与结果，不记录环境值；清理仅限本次登记的项目和卷，不做全局 prune。保留足以重放故障、确认回滚和核对清理范围的证据。
- 首片路径：`deploy/local-release.ts`、`deploy/fixtures/unhealthy.Dockerfile`、`docker-compose.yml`、`scripts/verify/tests/local-release.test.ts`、`docs/runbooks/local-release.md`、`Makefile` 及本任务卡。目标为一个可运行的本地闭环；有效改动超过 400 行时按行为自然拆分，不删失败回归。
- 本地入口为 `make local-release-check`；正式 `make release-check` 继续拒绝放行，直到制品、扫描、SBOM、签名、就绪、恢复与外部读回等正式阶段具备并验收。
- 必要验证覆盖：正常启动；候选真实健康失败；回滚后同套检查通过；回滚检查失败；禁止构建 / 拉取与远程目标；合成配置和自有资源清理边界。文档计划合入前不改实现文件。
