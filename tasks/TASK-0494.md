Owner把信源由hot_signal改为editorial后，旧skipped未判断材料目前不会自然续接。服务器续接须先在同一事务中辨识全部人工修改和人工处置，不能用不带事务的宽诊断读取替代，也不能让sources直接写content数据。

本卡与TASK0492合在PR331的完整兼容准备包中，只声明两个必要的内部端口，不加processingNeeded或HTTP字段：

- content/materials.SourceEditorialResumeMarker：`(sourceId: string, db: Db) => Promise<number>`，由后续`markSourceEditorialResume`实现。调用方仅在实际news来源hot_signal→editorial更新事务中调用，返回登记数量；意图属于content，不改变来源身份、模式、权限或人工记录，也不直接入队。
- admin/content.ManualProcessingExclusionsReader：`(articleIds: string[], db: Db) => Promise<string[]>`，由后续`manualProcessingExclusions`实现。同事务按既有人工状态语义返回当前有效的人工字段/修订或主动可见性决定的材料ID，不返回正文或审计原文；既有prefilterAuditExclusions语义保持。

运行实现随TASK0493接入原sweep与队列，复核当前修订、判断、人工归属、许可与暂停，清除失效的自动信号归组；暂停不丢意图，不重复付费。原错误与未知费用原因不得被标记覆盖，不从raw材料接受控制标记。本声明没有执行这些动作，既有可执行函数与公开HTTP不变。

两个端口只有类型声明，既有可执行代码不变；整合quick10与严格文档通过。与原帖显示契约共用PR331最终SHA完整验证，前一头的成功不能替代新增端口后的最终回执。运行消费者另随TASK0493接入。
