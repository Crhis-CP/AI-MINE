## 背景（为什么做）

TASK-0025 把规格改回 ADR-0021 的 Owner 决定：预筛“宽进，只拦明显无关；BLOCK 不出现在任何公开页面，PASS 与 UNKNOWN 继续往下走”，原生中文稿不等模型（INV-13、PIT-038、BR-ENR-06），金属范围不变。代码里还是 PR #77 加的严格门槛：

- 一条稿件只有当前修订的预筛结果是 PASS、提示词版本相同，并且有一张按今天的输入重算后逐字节吻合的付费回执，才算通过（`packages/backend/src/publication/publish.ts` 第 217～229 行、`providers/receipt-evidence.ts`）；
- 预筛 UNKNOWN 一律记成“未知”，不公开（`editorial/analyze.ts` 第 467 行）；
- 负责人在人工修正里选“收录”不起作用（`admin/content.ts` 不接受 `relevance`）。

结果是：中文来源的相关稿件在模型不可用时上不了站；拿不准的稿件不上站；来源改名或预筛提示词改版，会让已经上站的稿件被撤下。AIHOT 原版与 Codex 接手前的版本（`ec37bb6`）都是“不是 BLOCK 就往下走”；中文稿不等模型是交接包的要求，此前任何版本都没有做到，这次补上。

方案与原型：`/mnt/project-files/plans/TASK-0025-plan.md` 第 Q1～Q6 节；补丁草稿 `/mnt/project-files/plans/TASK-0027-sketch.patch`（13 个文件，在本计划 PR 的提交 `5751d8d` 上按 `git diff --numstat` 量为 +184/−143）。第一版在 main 的副本上跑过整套后端测试与类型、格式、边界、数据归属检查；按 PR #146 第 1 轮审查补上“模型被关闭时只等待”一处与它的测试后，重跑整套后端测试（71 个文件、339 个测试）、`tsc`（backend、tests）、Biome、边界与数据归属检查，全部通过；去掉这一处，新断言失败（实际是 `retrying`）。

## 交付内容（做什么）

1. **准入改回“不是 BLOCK 就收录”**：看这条稿件任何修订里最新的一次判断；负责人的“恢复收录 / 不收录”优先于模型；不再重算回执、不再比对提示词版本，所以来源改名或提示词改版不会撤下已上站的稿件。BLOCK 带到新修订，直到新修订被重新判断。删除 `providers/receipt-evidence.ts`（只有 `publish.ts` 一处调用）。
2. **预筛 UNKNOWN 写成“收录”**，与 PASS 一样评分、写作、进入事件归组（同 `ec37bb6` 的 `analyze.ts`）。
3. **中文原稿先上站**：模型可用时，预筛结果一提交就以确定性来源摘录公开，不等评分与写作；判为 BLOCK 的不公开。模型被关闭或异常熔断暂停时，现有失败路径上的公开照常成功；这两种情形都只等待、不耗重试次数（BR-OPS-03“熔断等待”；模型被关闭时，`jobs/content.ts` 的 `afterFailure` 按 `providers/llm.ts` 用的同一个开关 `config.modelCallsEnabled` 判断，每小时再看一次），恢复后自动补判，判为 BLOCK 即撤出全部公开出口。
4. **人工修正加“收录”选择**（私有内容页）：按模型 / 恢复收录 / 不收录；接口只接受 `pass`、`block`，清空即回到按模型。
5. **重新发布一个来源的全部稿件时，单条失败不中断**：进度里记 `failed` 与前 20 个 `failedIds`，只在关停时抛出。
6. **`industry/prompts/prefilter.md` 只改第 6、7 行**，回到 AIHOT 的原意（UNKNOWN 在业务上保留待补材料，不直接丢弃；材料缺失不作 BLOCK；不认识的名称不当成范围外）；写金属范围的第 1～5、8～9 行不动；提示词版本随之变为新的哈希，这两行随 T-0323 交 Owner 审阅的提示词包一起看。
7. **测试**：改 6 个测试文件，新增 2 个测试（人工收录两个方向，`unknown` 被拒绝；一条稿件失败不中断来源的重新发布）；覆盖模型关闭（只等待、不耗次数：连续 12 次仍是等待，`processing_attempts` 为 0）、熔断暂停、来源改名、旧提示词版本、新修订几种情形。
8. **产品更新片段** `changes/TASK-0027-wide-admission.md`（照模板写前置信息块）；`changes/TASK-0010-mining-admission.md` 第 1 行与新行为一致。
