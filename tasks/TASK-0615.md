## 交付内容与联动

- ci-db 在项目依赖安装前即可启动，不依赖第三方包。数据库镜像仍来自同一个 docker-compose.yml，并必须固定补丁版本及摘要；优先复用已存在的 Docker Compose 解析能力，不另写通用 YAML 解析器。
- 同时处理间接依赖：ci-db 和 pg-tools 目前从 toolchain 引用 PINNED_IMAGE，而 toolchain 自身引用 yaml。将这个纯常量放入现有无第三方依赖入口，保留必要调用兼容，不新增一套工具层。
- 去掉工作流自己执行的 npm ci，保留固定 npm 安装及 make verify 的 install 阶段。数据库准备、secret scan、回执与制品导出等步骤不删。
- 用一次 biome ci 取得格式、lint 退出状态和完整告警数据；沿用现有 countWarnings/compareWarnings 检查基线。缺失或无效 JSON、非零退出、告警增减仍按现有规则失败，不把 lint 失败吞掉。

## 验收

- 在无 node_modules 的隔离源码副本中验证 ci-db 及它的导入链可以加载；缺 db 镜像、不固定镜像、解析失败仍拒绝。只测试本卡所需的启动入口，不连生产。
- 对格式失败、lint 错误、告警基线变化和无效报告保留有区分力的检查；正常格式检查仅启动一次 Biome。
- PR 最终 SHA 和合并后的 main 都仍有 21 阶段完整回执，make-verify 必过检查名称和 verify_revision 的计算口径不变；源码内容改变导致哈希值改变是正常现象，不伪造旧哈希。
- 用修订前的直接父版本与本卡最终 CI 各一条真实运行记录比较总耗时、install 与 format-lint 耗时、执行器版本；如样本或执行器不同，写清限制，不重跑成功 CI 来挑更好的数字。
