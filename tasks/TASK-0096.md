## 背景

TASK-0093 已让法规材料留在材料库而不进入资讯评分，但当前工程没有法规文书实体与不可变原件。现有新闻正文提取会去除尾部和限制图片，不能据此认定法规正文与必要附件完整。本卡先建立可追溯的私有登记与原始字节保存；后续取得与提取、文书识别、公开契约、基本事实页面沿同一份原件继续。

## 交付内容

1. 仅新增 `policy` schema 的五张表：`instruments`（来源/官方 URL 回退身份；有已核文号时法域、机关、类型与文号身份）、`versions`（来源明确的法定版本键；无依据写未核验）、`expressions`（版本、语言、原文种类与当前取得头）、`document_revisions`（站内修订、前序、原件清单哈希、许可版本、核对时间和缺口）、`original_resources`（修订内有序正文/附件、URL、媒体类型、原始 bytes、SHA-256、取得状态与必要性）。不把站内重取称作法律修订，不以标题作身份，不按语言复制法定文书。
2. 内部端口 `recordPolicyOriginal(input)` 接收取得结果及 `expectedHead`，自行计算身份/字节/有序清单哈希；在一个事务内保存整份原件和附件、推进取得头。当前清单不变时复跑返回同一修订；A→B→A 返回第三个取得修订，历史不可变；迟到结果与不同的当前头冲突时拒绝，不能覆盖新原件。
3. 复用 `dbOf('policy')` 与 `@amp/backend/admin/sources` 的当前许可读取、共享锁和逐用途判定。始终传 `lane: policy`；保存前对正文与每个附件复核 `store_metadata`，有 bytes 时再核 `store_fulltext`；源版本变化或任一用途/范围不满足时整次保存回滚。不从新闻公开许可或 `processing_state` 推导法规资格。
4. `original_resources` 存实际取得的全部字节，不截断；失败资源只存安全原因和原始入口，不存未获准的响应正文。缺必要附件、目录未闭合、容量受阻分别记录。取得全量字节仍只标 `pending_extraction`，本卡不生成可供模型或公开使用的 complete 标记。
5. `readPolicyOriginal(expressionId)` 为后续本地处理读取当前完整快照，读取时再次复核当前 `store_fulltext` 与 `process_locally` 用途、附件范围；用途收紧后停止处理，既有证据不覆写、不自动删除。所有新表不授予 `public_read`；worker 对历史只有 SELECT/INSERT，当前头表可 UPDATE，private_ops 只读。
6. 内部类型与 README 明确后续衔接：取得/HTML/PDF提取另卡；TASK-0097 认定官方构成性原文和身份；TASK-0098 冻结公开契约；TASK-0099 基本事实页面。原文取得、提取完整、中文完整、语义核验、公开与持续运行各自留状态。

## 输入输出与错误状态

- 输入只来自已授权的内部取得流程，本卡没有 HTTP 或调度入口。身份字段全部保留来源事实；未知类型/文号/法定版本不能由标题或模型猜出。
- 输出为 instrument/version/expression/revision 标识、实际保存的原件清单和缺口；没有公开 DTO、中文稿或法律结论。
- 缺 bytes、失败附件、未闭合目录或超限仍可保存已获准的私有证据；没有任何完整解读资格。数据库连接、当前许可或头指针冲突使整次写入失败，不产生半份修订。

## 验证

- 合成 HTML 字节及二进制附件原样往返，哈希由实际 bytes 计算；正文或附件单字/数字/否定词变化均形成修订。
- 同一输入重复/并发幂等；A→B→A 保留三次取得；迟到期望头不覆盖新头；中文标题改变不能生成另一部法；同号不同机关分开、语言表达分开。
- 必要附件缺失、目录未闭合、超限状态不成为 complete；没有原数替代或自动补全。
- 保存/处理禁止、附件超范围、过期或版本变化均拒绝；许可收窄后读取失败，历史原件仍在；应用角色不可改删历史、公开角色无新表权限。
- 使用现有 test-files 的独立 *_test 库和合成数据，不接外网，不调用真实模型。

## 明确不做

不自动取得网页/PDF，不接 PDF 依赖，不做 OCR/视觉、全文中文/解读、文书自动识别、法律状态判断、公开接口/页面、历史回填、整轮目录扫描或队列接线。以上按后续独立卡完成，不将本卡私有原件登记当成法规栏目完成。
