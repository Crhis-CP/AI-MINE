## 背景（为什么做）

Owner 2026-10-06 12:11:35Z 选「照 AIHOT」：后台从 `https://admin.aiminingpolicy.com/admin` 改回 `https://aiminingpolicy.com/admin`（ADR-0026，规格写回在 TASK-0079）。现在网站把“主机名”当成读者站与后台的分界：Host 等于 `PRIVATE_HOST` 时整站都算后台，别的主机名访问私有路径一律 404（`apps/web/host-policy.ts:47-60`），`PRIVATE_HOST` 还不许等于 `SITE_URL` 的主机名（同文件 :43）；入口层把主域名与私有主机名都转给网站（`deploy/Caddyfile:3-6`）。

本卡只改地址：读者站与后台仍是两次构建；`public-api` 与 `private-api` 仍是两个角色；数据库登录、登录方式、会话不变。分界改成“主机名 + 路径”：生产上 `PRIVATE_HOST` 填主域名，主域名的私有路径归后台，其余归读者站。两个主机名的配置继续支持（本机默认与校验脚本都用它），所以部署出问题时只换回两处配置就能退回。

两次构建现在都把文件放在 `/assets/` 下，同一个主机名时会撞名；私有构建改用 `/admin/assets/`，读者站不变。

同一个主机名还带来一件事：后台登录 Cookie 会跟着主域名的每个请求走，包括转给公开接口的请求；本卡在网站转发时把它去掉，保住“公开侧服务不持有管理凭据”（INV-25）。读者页面被注入脚本的风险由 TASK-0084（内容安全策略）补一道防护，排在本卡部署之前合并。

   ```
   {
   	cert_issuer acme {
   		disable_tlsalpn_challenge
   	}
   }
   ```

1. 在服务器上只看两行配置，不读别的值：`grep -E '^(PRIVATE_HOST|TRUST_PROXY)=' .env`。记下 `PRIVATE_HOST` 的现值（预计是旧子域），退回时用。
2. 先换新代码，`.env` 不动：按发布流程换上新镜像（web、private-api 等照发布流程重建）。这时仍是两个主机名的配置，新代码照旧工作：从主机之外读回主域名首页 200、旧子域的 `/admin/login` 200。不对就按发布流程退回上一版，到此为止。先换代码、后改配置的原因：旧代码遇到 `PRIVATE_HOST` 等于主域名会在启动时报错（`apps/web/host-policy.ts:43`），配置先改的话，之后哪个容器用旧镜像重建，读者站也会跟着起不来。
3. 把 `.env` 的 `PRIVATE_HOST` 改为主域名（只写主机名，不带协议与端口），然后只重建读它的两个进程：`docker compose up -d --no-deps --force-recreate web private-api`（两个进程都在启动时读 `PRIVATE_HOST`；`.env` 里的值只在重建容器时换上）。
4. 换 Caddy：先用线上同一个镜像校验新的 Caddyfile：`docker compose --profile https run --rm --no-deps caddy caddy validate --config /etc/caddy/Caddyfile --adapter caddyfile`，要看到 `Valid configuration`（新配置不再用私有主机名变量，不用像 TASK-0081 那样带 `-e PRIVATE_HOSTNAME`）；再 `docker compose --profile https up -d --force-recreate caddy`。换了文件，运行中的容器仍读旧内容（TASK-0037 的教训）；`.env` 里的值也只在重建容器时换上，所以用重建，不用 restart。中断通常几秒，遇到长连接最长十几秒。
5. 从主机之外读回（地址加引号）：

   - `curl -sI "https://aiminingpolicy.com/admin/login"` 返回 200，`cache-control: private, no-store`，有 `x-robots-tag: noindex, nofollow`，没有 `set-cookie`；

   - `curl -sI "https://aiminingpolicy.com/api/admin/me"` 返回 401，`cache-control` 含 `no-store`；
   - `curl -sI "https://aiminingpolicy.com/"` 返回 200，`cache-control` 与部署前相同；TASK-0084 一起上线时，再按它的读回核对内容安全策略；
