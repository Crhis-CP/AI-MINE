TASK-0672/0679 让读者页面可以被 CDN 和代理共享缓存 30 秒，开关是 web 进程的 `PAGE_CACHE_SECONDS`。但当时这个变量不在那两张卡的允许路径里，没有登记到部署配置：生产上要关闭缓存，只能手动改容器环境。另外，合并前已经去掉了“过期后先用旧的再后台更新”（stale-while-revalidate），因为它会让已撤回的内容多留约 60 秒；0679 的运营记录和任务卡里还留着这个旧说法。

## 交付内容

1. `docker-compose.yml` 的 web 服务加 `PAGE_CACHE_SECONDS: ${PAGE_CACHE_SECONDS:-}`。留空等于不设，按 30 秒运行。
2. `.env.example` 加“公开页面缓存”一节，写明取值 0～300、不填按 30 秒、填 0 关闭、写错时的处理，以及哪些页面始终不缓存。
3. `apps/web/runtime-env.ts` 的放行清单加这个变量，测试和启动器才会把它传给 web 进程。
4. `tasks/TASK-0679.md` 改成“到期即重新取，不先用旧的”，与代码一致（`s-maxage=30`，不带 `stale-while-revalidate`）。已合并的运营片段 `changes/TASK-0679-single-load.md` 第二条仍写着“过期后先用旧的再后台更新”，以本卡和代码为准：运营片段带 `reader_unchanged`，合并后再改，发布检查会要求本次改动的读者文件逐一对上，所以不改。

5. 批量翻译（TASK-0711）的文档跟上代码：
   - `docs/02-rules/03-ai-capabilities.md` 里全文翻译的输出格式仍写着旧的 `{"t": [...]}`，改为 `{"text": ...}`（单块）和 `{"texts": [...]}`（多块，单次不超过 4,000 字节）两种，并写明以下两点：
     - 整批回答不合格时，对半拆开再问；
     - 只改提示词时，已公开的译文不会消失。
   - `packages/backend/README.md` 补一句批量请求的说明。

6. 首页“本国最新动态”改用 TASK-0714 新增的轻量读取（`/api/site/pool?…&lean=1`）：只取最新 5 条，不算信源分面，原来是整页列表。国家页要显示完整列表和筛选，所以不改。

## 不做

- 不改缓存规则和默认值。
- 生产 `.env` 不用改：不设就是 30 秒，Owner 2026-11-14 已同意开启。
