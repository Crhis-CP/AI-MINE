上游没有用量周报，也没有月报推送：用量只能在后台看近 7 天（现在后台“用量与模型密钥”里的“模型与近期用量”，`packages/backend/src/admin/models.ts:28-91` 的 `modelsOverview`）。本卡复用那里的查询与计价办法（:32-45、:54-62），消息格式照周一的信源周报（`packages/backend/src/operations/reports.ts`），走同一个提醒开关、发到同一个提醒群。

## 交付内容（做什么）

1. 新文件 `operations/usage-weekly.ts`，导出 `usageWeekly(now = Date.now())`，`dbOf("ai-gateway")`：
   - **周期**：上一个 ISO 周（北京时间周一 00:00 到下周一 00:00），与再前一周比。日期与周号用 `@amp/contracts/time` 的现成函数（`schedules.ts` :12、:40 的写法）；SQL 里只插普通的时间值。
   - **数字**：只数 `origin = 'live'` 的调用（`receipt_attempts` 关联 `receipts`）。按服务（显示名用 `operations/alerts.ts` 的 `providerName`）与按能力（用 `editorial/models.ts` 的 `CAPABILITIES` 把用途归到能力，照 `admin/models.ts` :63-71；归不进去的写“其他”）列出：调用次数（成功、失败、结果未知分开）、输入与输出 token、金额，每项都比前一周（照 `reports.ts` :8 的 `pct` 写法，前一周为 0 时照它原样不给百分比）。
   - **金额**：`cost_basis = 'actual'` 的用实际金额；`cost_basis = 'estimated'` 的用调用时记下的估算；没有金额的按 `service_prices` 估算（先找同服务同模型，再找同服务、`model = ''` 的一行，照 `admin/models.ts` :56；按每百万 token 的输入、输出单价，或按每次单价），写明“估算”；找不到单价的写“未登记单价”和次数，**绝不写 0**。人民币与美元分开写，不换算。
   - **自动暂停**：用 TASK-0063 的 `autoStopsBetween(from, to)` 写“上周自动暂停付费调用 N 次”，并列出各服务的次数；TASK-0063 上线前的运行记录没有这项数据：`coveredFrom` 晚于周一 00:00 超过 1 小时，就在这一项后面注明“（从 X 日起才有记录）”，为 `null` 时写“上周还没有这项记录”，不写成 0 次。
   - **待核对**：现在还有多少笔付费请求结果未知（`receipts.status = 'unknown'`），请到后台“用量与模型密钥”里的“费用与投递核对”核对；没有就写“没有待核对的”。
   - **发送**：标题“用量周报”加上周的起止日期（北京时间），用 `sendAlert` 发；上周没有任何付费调用也发一条，写“上周没有付费调用”。
   - **不重复发**：用 `admin/runs.ts` 的 `latestSuccessfulRunResult("reports.usage-weekly")`（:16-20）读上一次成功运行的结果。返回值固定为 `{ week, sent, lastSentWeek }` 加各项总数：`lastSentWeek` 等于这一周就跳过不发，返回时把它原样带上；只有 `sendAlert` 返回 `"sent"` 时才把 `lastSentWeek` 记为这一周。`recordRun` 把返回值存进 `job_runs.detail`（`jobs/queue.ts:433-444`）。

3. `apps/worker/src/schedules.ts`：:18 的引入加上 `usageWeekly`；:65（`reports.source-health`）后加一行 `{ name: "reports.usage-weekly", cron: "5 9 * * 1", missed: "once", run: () => usageWeekly() }`（北京时间每周一 09:05，worker 停过就补跑一次）。
