### D4 准备阶段已复现的必测缺口

- JSON.stringify/string 或 Buffer 直接 send 会绕过 provider 的响应校验，坏对象则被拒绝。现有 sendJsonWithEtag/sendProblem 恰有这些形态；JSON 响应必须在生成原字节/ETag前同源校验，或经已验证对象序列化，保留 304、ETag 输入、缓存截止与错误头。非 JSON 出口不强改成对象。
- global registry 的私有 component 泄漏有反例；独立 registry 有正例。客户端不能从总 barrel 同时导出 public/private，两入口及公共网页 bundle 要有反例检查。
- openapi-fetch 返回的类型化 data 不证明运行时校验；合成坏响应仍会得到 data。需要接同源 Zod，而非把 `as T` 换一种写法。SSR 的取消、15s/30s 超时、retryAfter、上游 X-Accel-Expires 与 404/503 映射保持。
- 方言门禁覆盖 nullable、union、date/date-time/uri、strict/strip/loose/record additionalProperties、无体响应；TypeScript 的 format 仍是 string，运行时由 Zod 判定。
- 区分 backend 的 Date/数据库数值字符串和 HTTP wire DTO：保留原日期 JSON 编码后按 wire schema 校验，不为契约转换把 bigint/numeric 字符串强转 Number，不用内存 codec 输出替代传输字段。
- 准备阶段已验证 TS5 生成API、TS5/TS7客户端消费、两入口类型隔离、跨进程/时区/cwd 字节一致、mock 往返、8个非法输入、坏响应、204与XML字节。它们只证明合成技术兼容，不是本项目契约全覆盖回执。

## 未知费用确认：客户端已观察版本（独立于九类分类计划）
