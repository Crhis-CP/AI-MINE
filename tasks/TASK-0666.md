## 背景与依据

[Claude 6855396147](https://github.com/Crhis-CP/AI-MINE/issues/348#issuecomment-6855396147)已裁定同一家机构迁域可在用途不扩大的条件下维修，TASK-0665交CLI与迁域清单。来源线、总协调与合并线实读发现：`saveSourcePolicy`只通过`appendSourcePolicy`锁住许可版本；`updateSource`和`archiveSource`可以改变所属机构或归档状态而不增加许可版本。CLI先读来源再保存，不能证明写入时来源仍符合条件。

本卡是该已准行为的必要技术前置，不新增许可或Owner业务决定。依根AGENTS公开接口单独交付规则，先登记本卡，再独立交接口提供方；TASK-0665消费者须等这个接口实际进入main。计划卡登记时不含实现；当前交付状态见末尾记录。

## 交付内容与接口

- 仅给现有`saveSourcePolicy(id, input, actor)`的`input`追加可选`expectedSourceGuard: { ownerEntityId: string | null }`。返回值、actor/reason必填、原许可版本CAS与审计语义保持。未传守卫时行为不变，不要求修改既有调用方。
- 明确提供守卫时，机构值必须显式给出并与当前`owner_entity_id`精确相等；缺失、类型错误或无效守卫不能被当成省略。允许显式null用于比较既有空值，不从网站名称猜机构，也不以这个技术比较替代0665的同机构正向证据。
- 在同一个`sql.begin`里，按既有`23621 + hashtext(sourceId)`同源事务锁顺序取得锁，再锁定来源行，核对来源存在、未归档且机构值匹配；锁保持到原`appendSourcePolicy`、原审计和提交结束。归档当前不取该advisory锁，因此仍须来源行锁，不能只补一次锁外查询。
- 条件不满足使用既有冲突错误路径，许可版本、当前投影和成功审计都不写入。原`expectedVersion`仍须在同一事务有效，不能以来源匹配替代许可版本比较。
- 不要求来源已经启用：Torex当前停用状态不应妨碍获准维修；本函数不启用来源，也不修改其配置、抓取状态或`updated_at`。
- 在backend README记明可选输入、原子保护与旧调用兼容；不新增HTTP路由、任意SQL或通用配置编辑入口，不另造一套许可保存实现。

## 验收

复用现有数据库fixture和真实保存路径，所有数据为合成、模型调用为0：

- 来源存在且机构一致、未归档：按原保存路径仅增加一次许可版本和一次原审计，返回仍是原许可对象；无效守卫、来源不存在、机构不符或已归档均无许可/成功审计副作用。
- 不传守卫的原调用、显式空机构的精确比较及真实许可版本冲突保持原语义；停用但未归档来源可按条件保存，仍停用。
- 用确定性的双连接事务同步覆盖：机构变更先提交、归档先提交时拒绝；守卫先取得来源行锁时，后到机构变更/归档须等待，保存提交后仍按原人工操作生效，不被复活。
- 并发的真实许可版本编辑仍只允许匹配版本的一方成功，失败不留部分版本或成功审计；并发测试不靠固定sleep碰概率，不以mock锁代替实际阻塞与最终状态。
