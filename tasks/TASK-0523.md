## 执行记录（Claude，2026-11-05）

- **做法：**改用“以中文原文为键”的短语词典 `apps/web/app/i18n/phrases.ts`（约 890 条），代码里写 `tr("中文原文")`。
  - 中文界面原样返回键，所以中文输出逐字不变；`npm run check` 的网页测试全部按中文断言通过。
  - 英文界面查表。`tr()` 只接受词典里的键，漏翻会让类型检查失败，这对应验收要求“词典没有缺键”。
  - 首页路径和外壳仍用 TASK-0521、0522 的结构化词典（`zh.ts`、`en.ts`）。
- **辅助函数：**
  - `tr("… {n} …", { n })` 填占位符；
  - `tr.subject("日报")`：中文加行业词，英文直接用词典；
  - `tr.maybe(text)`：用于运行期字符串（模块标签、标签表的值），词典有就翻，没有就原样返回；
  - `useDateFormat()`：英文日期（如 3 h ago、Nov 5 09:25、Monday），按北京时区。
- **覆盖范围：**全部读者页面（59 个文件），包括热点、全部动态、文章、事件、报告、主题、收藏、反馈、关于、Agent 接入、更新日志、金属价格和法规各页。
  - 模块页面经 `@amp/web/i18n` 引用（`apps/web/package.json` 新增这个出口）。
  - 英文浏览器标签标题由公开布局在导航后翻译；英文页面仍是 noindex。
- **英文界面刻意保持中文的部分：**
  - 资讯和法规内容本身；
  - 使用规则、隐私说明的正文：页面注明“本文为中文原文”；
  - 更新日志的条目；
  - 演示 API 返回的站点资料；
  - 中国省区名。
  - 国名用浏览器的 `Intl.DisplayNames`，国际组织用词典。
- **工具：**迁移脚本只在本地使用，不进仓库。脚本处理后人工修正了以下问题：
  - 双重包裹；
  - 被误翻的查表键（`CopyPage` 的元数据键、日期星期替换）；
  - 代码示例里被误认成标签的 `<上一页的 next_page>`；
  - 模块级常量里的 `tr`。
- **验证：**
  - `npm run typecheck`、`npm run check` 通过；
  - 用生产构建加演示 API 截图，检查 `/en/all`、`/en/about`、`/en/more`、`/en/agent`、`/en/starred`、`/en/feedback`、`/en/privacy` 页面上界面区域的中文：只剩语言切换里的“中文”和字标。
