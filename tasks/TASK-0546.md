Owner 2026-11-05：法规解读不设上限，“主要靠你优化，毕竟这个也不是时时刻刻都有法规出现”；非高峰调度也要加上。

## 做法

- **翻译记忆（`domain/translation-memory.ts`）：**
  - 请求只含语言和去重后的原文段落，同一段落在任何文书里都是同一个请求；回答只要中文，不再要事实，减少输出 token。
  - 按“语言 + 配方 + 段落哈希”复用已有译文，每条都要有真实回执证明；中文原件不翻译。
- **只解读变化：**
  - 按条款与上一份已核对的解读比较，修订稿只送新增、修改的条款（附旧文）和删除条款的旧文，再加最少的背景；
  - 证据全在未变条款的要点和影响原样沿用；
  - 首版文书分块解读；条款都没变时为 0 次调用。
- **核对改为程序判断：**
  - 程序核对引文逐字出现、证据编号存在、日期、条号、数字；
  - 只有程序判断不了的（数字写法不同、判为“排除”）才调用一次复核模型；
  - 单条不过就丢掉，不再让模型重写。
- **分组：**原来的 `policy_group` 是解读里的“分组核对与合并”一步，现在按条号由程序完成，不再调用；用途名为旧回执保留，两份分组提示词删除。
- **扫描件：**没有文字层的标为“需人工”，除非显式设置 `POLICY_VISION_ENABLED=true`。
- **非高峰（`providers/peak-hours.ts`，经 `@amp/backend/providers/llm` 导出）：**
  - 翻译、看图、解读任务在 DeepSeek 高峰时段（工作日 UTC 01:00–04:00、06:00–10:00）被取到时，不发调用，排到下一个非高峰时段再做；
  - 存档和发布不受影响。
- **预计调用（全部按非高峰半价）：**

  | 情况 | 调用次数 |
  |---|---|
  | 10 kB 西文法令 | 约 6～7 次（原设计约 17～23 次） |
  | 20 kB 中文法律 | 约 2～3 次 |
  | 修订稿 | 约 2～3 次 |
  | 未变化的重抓 | 0 次 |

## 部署

- 设置 `POLICY_MODEL_STAGES_ENABLED=true`（与 `POLICY_PILOT_ENABLED=true` 一起）。不设 `POLICY_VISION_ENABLED`。
- 完整解读对外公开仍要 Owner 对新配方做一次质量放行；在此之前，法规页显示基础事实和全文。
