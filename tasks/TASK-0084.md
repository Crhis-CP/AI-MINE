## 背景（为什么做）

后台搬回主域名（TASK-0080）以后，后台和读者页面同源：读者页面里一旦有能运行的注入脚本，就能读到后台的防伪令牌，借已登录管理员的身份调用私有接口（ADR-0026 的后果，规格写回在 TASK-0079；ADR 编号以合并时为准）。原来分开的子域挡得住这一条；现在挡它的只有入库时的正文净化（`packages/backend/src/content/sanitize.ts`）。本卡加第二道：浏览器只运行带本次请求随机值（nonce）的脚本，被塞进页面的脚本不运行；顺带不许别的网站把页面嵌进框架。集成人定的顺序：本卡在 TASK-0080 部署之前合并，和搬家同一次部署上线；Owner 同意部署时也可以说先搬、防护随后补。

现状（写卡时在 97cd559 上核对）：

- **谁发响应头**：网站进程用 `@react-router/node` 的 `createRequestListener` 出页面（`apps/web/server.ts:8`、`:48-54`），自己只设缓存头（`pageCache`，:96-139）与私有路径的 `no-store`（`apps/web/host-policy.ts:22-32`）；`apps/web/app/` 下没有自己的 `entry.server`，用的是 React Router 默认的服务端入口。全站页面现在不发 CSP，Caddy 也不发（`deploy/Caddyfile` 只有转发与跳转）。仓库里唯一的 CSP 在图片代理的响应上（`apps/api/src/routes/media.ts:37`，沙箱）。上游 AIHOT 也一样：本仓库原样导入上游的提交 `f4392e1` 里，CSP 只有 `apps/api/src/routes/media.ts:32` 这一条，页面没有。
- **页面里的内联脚本**：
  - React Router 的 `<Scripts>`：路由清单与水合数据（`window.__reactRouterContext`）、用 `import()` 加载入口模块的模块脚本，外加 `<link rel="modulepreload">`；流式渲染时还有传数据的内联脚本。
  - `<ScrollRestoration>` 的内联脚本（`apps/web/app/root.tsx:33`）。
  - 我们自己的主题脚本（`root.tsx:27`，内容是 `app/lib/local-state.ts:195` 的 `THEME_BOOT_SCRIPT`，在画面出来之前设好深浅色）。
  - 详情页等的 JSON-LD（`app/lib/seo.ts:73`，`type="application/ld+json"`）是数据，不执行，不受 CSP 管。
  - React Router 8.4.0 支持 nonce：`<ServerRouter nonce>` 把它传给 `<Links>`、`<Scripts>`（含 modulepreload）、`<ScrollRestoration>` 与流式脚本（`react-router` 包 `dist/development/lib/dom/ssr/server.js:32-65`、`components.js:132-160`、`:474-568`、`single-fetch.js:27-56`、`lib/dom/lib.js:521-568`）；React 的 `renderToPipeableStream` 也收 `nonce`。浏览器端拿不到 nonce（`dom-export.js` 里没有），客户端跳转时补加的 modulepreload 不带 nonce，靠 `'strict-dynamic'` 或 `'self'` 放行（见交付内容第 2 条）。
- **内联样式与图片**：React 的 `style={{…}}` 在服务端渲染成 `style` 属性，读者页面（例如来源头像 `app/components/ui/SourceAvatar.tsx:14`）与后台图表都在用；后台下拉箭头是 `data:` 的 SVG 背景（`app/features/admin/ui.tsx:213`）；反馈页的截图预览用 `blob:`（`app/routes/feedback.tsx:104`）。
- **外部资源**：字体全用系统字体（`app/app.css:13-14`），没有外部样式、字体或统计脚本；备案、LME 等外链只是链接。详情正文里的配图已改成指向来源网站的链接（`packages/backend/src/content/sanitize.ts:270-278` 的 `linkBodyImages`，DR-78）；正文里保留的 `<video>` 直接从来源网站加载（同一函数只去掉封面，:325）。
- **后台**：私有构建用同一个 `root.tsx` 与服务端入口，脚本同样来自 React Router；表单只提交到本站（`/api/auth/password`、`/api/auth/logout`），飞书登录是普通链接（`app/routes/admin-login.tsx:48`、`:71`）。
- **规格**：06-security 2.2 表“安全响应头”一行（:101）写的是 Caddy 发 CSP、“CSP 随新前端栈调整”。nonce 每个请求都要不同，只有生成页面的网站进程能做，Caddy 做不到，所以本卡把 CSP 放在网站进程，规格这一行同步改。AC-SEC-18、INV-34 要求“公开渲染不执行脚本”，T-079 有 XSS 样本：现在靠入库净化，CSP 是第二道。

## 交付内容（做什么）

代码注释照现有写法用英文，不写上游项目的名称。

1. **服务端入口 `apps/web/app/entry.server.tsx`（新）**：
   - 照 React Router 8.4.0 默认的 Node 服务端入口（`@react-router/dev` 的 `dist/config/defaults/entry.server.node.tsx`）写：`isbot` 判断、`streamTimeout`、HEAD 直接返回、`onShellReady` 与 `onAllReady`、出错处理都照它。
   - 每个请求用 `node:crypto` 的 `randomBytes(16)` 生成 nonce（base64），在 HEAD 提前返回之前就把 `Content-Security-Policy` 设进 `responseHeaders`，HEAD 与 GET 都带。
   - `<ServerRouter context={…} url={…} nonce={nonce} />`，外面套 `NonceContext.Provider`；`renderToPipeableStream` 的选项加 `nonce`，React 自己的流式脚本也带上。
   - 只在生产构建发（`import.meta.env.PROD`）：开发服务器要注入不带 nonce 的内联脚本，加了 CSP 会坏。
   - 两个路由组共用这一个入口，读者站与后台的页面都带同一条策略。`.data` 数据请求、静态文件、接口，以及 `server.ts` 自己回的 404 文本不走这里，不带 CSP（它们不是页面）。
2. **`apps/web/app/lib/csp.ts`（新）**：导出 `NonceContext`（React context，默认 `undefined`）与一个按 nonce 拼策略的函数。只引 `react`，不引 `node:` 模块：根布局会把它带进浏览器端的包。策略写成一行：

   ```
   default-src 'self'; script-src 'self' 'nonce-<N>' 'strict-dynamic'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:; media-src 'self' https:; object-src 'none'; base-uri 'none'; form-action 'self'; frame-ancestors 'none'
   ```

   每一项的理由（写进 PR）：
   - `script-src`：只认本次的 nonce。`'strict-dynamic'` 让带 nonce 的入口脚本再加载的模块也能运行，同时在支持它的浏览器上让 `'self'` 失效，被塞进来的 `<script src="/本站某个地址">` 也跑不了；不支持 `'strict-dynamic'` 的旧浏览器退回 `'self'` 加 nonce。不放 `'unsafe-inline'`、`'unsafe-eval'`。
   - `style-src 'unsafe-inline'`：React 的 `style` 属性读者页面与后台都在用，不放开就要改一批组件。样式注入的危害比脚本小得多；正文净化本来就去掉 `style` 属性（`sanitize.ts:116` 起的 `allowedAttributes` 里没有它）；图片只许本站与 `data:`、`blob:`，借样式往外站发请求也发不出去。
   - `img-src data: blob:`：后台下拉箭头与反馈截图预览要用。
   - `media-src https:`：正文里保留的视频直接从来源网站加载，这是现状，本卡不改。
   - `object-src 'none'`、`base-uri 'none'`：页面不用插件，也不用 `<base>`。
   - `form-action 'self'`：表单只提交到本站（登录、退出、搜索、反馈）；飞书登录是普通链接，不受它管。
   - `frame-ancestors 'none'`：别的网站不能把读者页面或后台嵌进框架（防点击劫持），作用同 `X-Frame-Options: DENY`。
   - `connect-src`、`font-src`、`manifest-src` 不单写，按 `default-src 'self'`：页面只连本站，字体全用系统字体。
3. **根布局 `apps/web/app/root.tsx`**：:27 主题脚本加 `nonce={useContext(NonceContext)}` 与 `suppressHydrationWarning`。浏览器端取不到 nonce，浏览器也会把页面上的 `nonce` 属性藏起来，水合时两边不一致，只在这个元素上忽略。`<ScrollRestoration>`、`<Scripts>`、`<Links>`、`<Meta>` 不用改，由 `<ServerRouter nonce>` 带上；JSON-LD 不加 nonce。
4. **测试 `apps/web/tests/cache.test.ts`**（用现有的构建产物与假接口；nonce 是随机的，用例只比较相同与不同，不写死值）：
   - `/`、`/all`、`/about`、`/items/footer-page`、一个不存在的地址（404 页）与带私有主机名的 `/admin/login`：响应都有 `Content-Security-Policy`；从 `script-src` 里取出 nonce，页面里每个 `<script>`（`type="application/ld+json"` 除外）都带同一个 `nonce`。
   - 同一个地址请求两次，nonce 不同；HEAD 请求也带这个头。
   - 策略里 `script-src` 没有 `'unsafe-inline'`、`'unsafe-eval'`；有 `object-src 'none'`、`base-uri 'none'`、`frame-ancestors 'none'`。
   - `.data` 与静态文件不要求带。
5. **e2e `e2e/smoke.spec.ts`**（在当时的 e2e 配置下做：TASK-0080 先合并时是同一个主机名，否则是两个主机名）：
   - 用 `page.addInitScript` 在每个页面上收集 `securitypolicyviolation` 事件。现有的读者流程（`/all`、搜索、点到“全文相关”的客户端跳转）与后台登录页（填表、按 Tab）走完以后，一条违规都没有；`<html>` 有 `data-theme`（主题脚本运行了）；页面里脚本元素的 `nonce` 与响应头里的一致，同一页打开两次，nonce 不同。
   - 注入：用 `page.route` 拦下一次读者页面的 HTML（`route.fetch()` 取原响应，`route.fulfill({ response, body })` 原样带回响应头），在正文末尾加 `<script>window.__injected=1</script>` 与 `<img src="/x" onerror="window.__injected2=1">`：两处都不执行（`window.__injected`、`window.__injected2` 都是 `undefined`），违规记录里各有一条。
   - 现有的外网探针（`fetch("https://blocked.invalid/browser-smoke")`，写卡时 :73-84）在有 CSP 的页面上会先被 CSP 拦下，到不了 Playwright 的拦截，`expect(blocked).toEqual([probe])` 会失败。把它挪到 `about:blank`（没有 CSP 的空白页）上发，`blocked` 的断言不变；有 CSP 的页面上另断言同一个地址被 CSP 拦下（违规记录里有一条 `connect-src`）。写卡时本机没有浏览器，这一条是按 CSP 的机制推的，没有实测。

## 输入输出与错误状态

- 输入：每个页面请求。输出：页面响应多一个 `Content-Security-Policy` 头，页面里的内联脚本带同一个 nonce；别的响应不变。
- nonce 每个请求重新生成，不存、不记日志。页面现在不进共享缓存（EdgeOne 只缓存 `/assets/*`，`07-deployment-and-ops.md` 2.4 默认无缓存直连）；浏览器自己缓存的页面连同响应头一起缓存，nonce 照样对得上。
- 某个脚本没带上 nonce：浏览器不运行它，页面可能不能交互。cache 测试的“每个脚本都带 nonce”与 e2e 的“零违规”就是挡这一条的。
- 数据与事件所有权：不涉及。
