## D1 用途及 SourcePolicy

| 用途 | 本卡必须分别执行的边界 |
|---|---|
| fetch | 发起来源获取；不能由“网页公开”推导允许 |
| store_metadata | 保存标题、日期、链接等元数据 |
| process_locally | 本机清洗、判重等内部处理 |
| store_fulltext | 保存全文/原件；与可抓取、可展示独立 |
| external_model | 向外部模型发送任何来源材料，包括标题、导读和embedding |
| public_excerpt | 对外展示来源短摘录 |
| public_summary | 对外展示项目撰写导读 |
| public_original_fulltext | 站内展示原文全文 |
| public_translation | 站内展示全文译文 |

九项值固定为allow/deny/unknown；不能用一个fulltext布尔替代多个用途。第十项syndicate_fulltext仅保留既有独立禁止默认，不进入DEC33的九项自动允许，也不在本卡启用。

SourcePolicy为不可变权限版本：source_id、permission_version、九项判定、证据及适用主机/路径/文类范围、条件码、attachments_in_scope、确认人/时间、expires_at和读者许可说明。当前指针单独CAS推进；权限变化不增加材料revision。JSON必须严格列出合法字段/九项用途，不接受未知键或隐含缺省allow。

负责人经既有私有来源创建/确认入口加入时，九项按DEC33写入allow、证据kind=owner_declared、依据“Owner 2026-10-01书面答复”、checked_at及真实actor；该证据expires_at=null。没有新的逐源审批清单。加入与启用分开：先确认加入且停用，再按既有预览/启用流程推进；没有正式记录的候选/草稿不借预览获得模型许可。

已有明确收紧保持；不能通过迁移把false一概改成allow，也不能从site_fulltext推断external_model。既有来源如需补初始版本，必须能说明确认依据及旧设置来源；无法证明的缺记录按技术unknown拒绝相应用途，不谎称已经拥有完整权限记录。生产数据不在本卡执行迁移。

## D2 签发、验证与材料绑定

- `SourcePolicyPort.evaluate`输入来源、预期权限版本、lane、用途及资源描述，返回typed allow/deny/unknown、当前版本、范围和期限。来源/用途/资源不匹配不是普通allow。仅当前版本可执行。
- `issueProcessingPermit`仅sources签发。保留内部契约既定载荷：source_id、lane、capability、permission_version、expires_at、issued_at及品牌类型；签名覆盖载荷和绑定输入，不靠TypeScript品牌作为安全校验。
- 绑定输入是版本化签名封装中的显式字段：材料ID、revision、内容hash、实际输入fingerprint、来源/资源范围；抓取尚无材料时绑定目标资源与采集配置指纹。材料身份由可信内容读取端口按存储对象解析，不能相信HTTP传来的source_id/hash，也不能从subject字符串或域名猜归属。
- 首期使用Node内建Ed25519：sources工厂持私钥，网关仅获公钥验证器及只读当前权限版本端口。沿用当前同进程模块组合，不新建签名服务；permit不作为长期队列凭证，任务保存材料引用，领取时重新取得当前许可。进程/DB根关闭或重初始化撤销当前签发/验证实例；旧permit不能跨根复用。db-bootstrap/db.ts写点仅为注册/清理生命周期，不承载权限业务或泄露DB访问对象。
- 网关验证签名、可信签发实例、source/lane/capability、资源绑定、输入hash、当前版本与到期。签名有效不等于当前仍允许；校验查询失败也拒绝，不能退回缓存的allow。
- 型别明确区分拒绝原因：缺记录/未知、用途禁止、到期、版本已变、来源/业务线/用途不符、材料/输入不符、签名无效。沿用现有Problem协议承载私有错误，不回显凭据、私钥、完整材料或签名原文。
- 发送前与返回使用前都核对权限。写回应用在同一事务核对材料revision和权限版本，避免“核对后收窄、结果又晋升”；已发出的请求仍保存响应与已确认用量，结果未知仍保持占用，权限失效只阻止使用/晋升，不把费用抹掉或自动重发。

## D3 缓存、聚合与评测

1. 固定顺序：许可校验 → 缓存 → 原熔断/回执/调用 → 结果与使用校验。已存结果和内存embedding缓存均不能绕过权限；deny时不返回受限缓存内容。
2. source_id、permission_version、lane、评测/生产用途不作为付费缓存的新分区。相同实际输入/配方仍可共用一份结果；每次使用分别校验和追加权限/用途审计，引用原回执，不覆盖其原始身份、不新造付费attempt。真实输入/配方变化才改变相应缓存身份。
3. 事件、报告及fact/story embedding须携完整输入依赖集合：所有被送入模型的材料版本及来源，而非只取首篇或代表稿。逐项校验；任何缺记录、拒绝或绑定不符阻止整次聚合调用。只有业务明确允许剔除且重新构造了实际输入和fingerprint时，才可在剩余集合上另行调用，不能悄悄沿用原聚合摘要。
4. 聚合衍生文本必须能追溯其输入版本；来源集合未知的历史衍生文本不能假借当前成员列表证明权限。首次激活前对既有缓存使用失败关闭或有据补全，不批量重买、不改写原回执。
5. 评测使用第三方/真实来源材料时同样要求逐来源permit。当前eval-selection把任意gold行变成example.invalid并不证明材料自编；禁止靠URL、purpose=eval、dev标志或空来源数组豁免。
6. 真正非来源输入使用独立的`CapabilityInputAuthorization`分支，不伪造source_id或ProcessingPermit。仅限服务端登记的能力及固定模板/SELF_AUTHORED夹具清单：校验具体artifact/hash、输入fingerprint、许可用途、调用者及lane。连接探针只能使用服务端固定文本；任意上传自由文本、未知清单或来源材料不能进入此分支。本卡定义该边界，不新增连接测试页面/路由。
7. 非来源评测仍走同一网关/回执/熔断、相同输出校验和用量用途记录。它不是付费授权开关；本卡只假服务，真实评测沿用已有显式任务和调用预算，未增加审批程序。
