Owner 2026-11-07 看了最新的更新日志：“最新的更新日志应该叫网站加上了更安全防护性更强，也就不要说这些东西……所有网站只走什么什么什么这些东西……你还是有些技术用语嘛”。同日逐项确认了信源、安全组、正文质量、标签、后台和 3.0 公告等事项，写进台账。

## 背景（为什么做）

- 11-08 06:41（北京时间）上线的条目“网站加了一层安全防护”写的是“所有页面只走 HTTPS，不允许被其他网站嵌入；异常超长的网址和发送过慢的连接会被直接拒绝”。读者看不懂，也不关心用了什么技术。
- 读者用语检查 `readerWordingProblem` 只认“域名”“口径”这类内部词，标准里点名的技术词（接口、缓存、模型、部署）和 HTTPS、服务器、连接都没有拦住。
- 查过线上更新日志的全部 36 条：只有这一条用了技术词，其余都是读者的话。

## 交付内容（做什么）

- `industry/changelog-copy-edits.json`：把这一条改写为“网站安全防护更强了 / 加强了网站的安全防护，能更好地挡住恶意攻击和异常访问，正常浏览不受影响。”原始登记记录保留不变（按原文计算的校验值对得上才改写）。
- `packages/backend/src/site/meta.ts`：读者用语检查加入常见技术词：HTTP(S)、CDN、JSON、SQL、HSTS、服务器、数据库、接口、缓存、部署、限流、并发、请求、连接、嵌入、后端、前端、代码、脚本、队列、字段、超时、重试、阈值、哈希、模型。英文词按整词匹配，所以“AI”照常可用；RSS 和公开 API 是给读者用的功能，保留不拦（现有测试的明确约定）。
- `docs/01-product/11-changelog-standard.md`：用词一节补上这些词，并写明安全、速度这类改进写读者能感到的结果。
- `docs/00-decision-ledger.md`：新增 DEC-78补充·信源扩充、后台实时化与更新日志用语（Owner 2026-11-07），记录逐项决定。`AGENTS.md`：“要问 Owner”的信源一项改为只限法规线，资讯线信源由 Claude 自行新增、修复和开启。

- `docs/research/owner-requests-3.0.md`：Owner 提过的全部要求，左栏写成读者体验，右栏写达成情况，作为 3.0 公告的底稿，状态随进度更新。`AGENTS.md` 新增“Owner 的长期偏好”一段。
