## 交付内容（做什么）

交付第 2 到第 7 条写的是整个价格表的设计；那里说的“本卡”指 TASK-0045、TASK-0085、TASK-0086、TASK-0087 四张卡合起来，各条由哪张卡交付，写在条目标题的括号里。

1. **契约**（本卡，只加不改）：
   - `packages/contracts/src/http/public.ts` 新增 `MetalPrices` 并加进 `schemas`，路由 `siteMetalPrices`：`GET /api/site/metal-prices`，响应 200、304、503；`packages/contracts/src/site.ts` 加类型别名。跑 `pnpm contracts:gen` 更新 `reference/contracts/` 与生成的客户端；`scripts/verify/contract-tests.ts` :264 公开文档的路由清单加 `/api/site/metal-prices`（生成的文档按路径排序，它排在 `/api/site/pool` 前面）。
   - 形状（第四版，集成人定）：

     ```text
     generatedAt   时间
     intro         文字
     latest        [{ tag, label: 文字|null, stale: 布尔, extras: [{ metals: [文字], label: 文字, stale: 布尔 }] }]
     sources       [{ key, name, tag, status: "fresh"|"stale"|"empty", latest: { label, release: { label, url, date|null } } | null }]
     metals        [{ key, name, quotes: [{ key, source, title, spec|null, footnote: 正整数|null,
                      value: 正十进制文字|null, unit, currency: "CNY"|"USD", decimals: 0–6|null,
                      period: { start, end, label } | null,
                      change: { percent, previous: { value, period } } | null }] }]
     notes         [{ ref: 正整数|null, text, link: { name, url } | null }]
     officialLinks [{ name, note, url }]
     ```

     `latest` 是表上方的“最新一期”，每种频率一项；`sources` 不画在页面上，是给硬规则 1 与核对用的（每个报价的 `source` 指向它，带出来源名与频率小标签）；报价的 `key` 是品种键，`title` 是报价标题，`footnote` 是脚注号；`notes` 先是脚注（`ref` 是号），再是整页的几条说明（`ref` 为空）；`link` 是说明里 `{link}` 那个位置要放的链接，由页面画。
   - 约束（不合格就不通过，接口回 503）：
     - 文字都不许是空白；网址都是 https；`percent` 是一位小数的文字（`-1.6`、`1.0`、`0.0`，没有 `-0.0`，正数不带 `+`；页面加 `+`、把 `-` 换成减号）；价格与上期价格都是正的十进制文字（库里 `numeric` 原样带出，不经过浮点数）。
     - `sources` 至少一个、键不重复；`status` 是 `empty` 当且仅当 `latest` 为空。

- 错误与边界：读库出错、登记文件读不进、契约不通过、库里的单位或币种与登记的不同 → 接口 503、不缓存（页面这时也回 503，见 TASK-0060）；某个来源一行都没有 → 它“没有数据”，它的报价都“暂缺”，这一频率在“最新一期”里没有期名；某个来源过了陈旧门槛 → 它“陈旧”，数照常带出，不隐藏，“最新一期”里那一组标陈旧；没有紧挨着的上一期 → 较上期为空；换算的品种某一期没有汇率 → 当这一期不存在。
