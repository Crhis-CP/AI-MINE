Owner 2026-11-07：“我希望我的网站做好安全防护，防止黑客攻击，另外尤其是防止漏洞攻击和高并发攻击等等。”同意分三层（代码加固、服务器加固、前置 CDN/防火墙），并要求“C 需要 Codex 去查给你结果，然后你来评估告诉我”。决定见台账 DEC-78补充·网站安全防护。本卡是第一层。

## 背景（为什么做）

- 网站已有：HTTPS、带随机数的内容安全策略与禁止被嵌入（`frame-ancestors 'none'`）、后台登录失败锁定 15 分钟、访客地址不信任请求头伪造、读者请求不触发模型调用与写库、CI 扫描密钥与高危依赖。
- 缺口：除后台登录外，公开页面和接口都不限同一访客的请求频率，高频刷页面或接口会直接压到服务器和数据库；缺 HSTS、Referrer-Policy、Permissions-Policy；没有显式的请求头/请求体超时与网址长度上限。Caddy 只做 HTTPS 与转发，所有请求都经过 web 进程（`apps/web/server.ts`），所以在这里统一处理一次。

## 交付内容（做什么）

- `apps/web/request-guard.ts`（纯函数与一个内存计数器，无依赖）：
  - 按访客地址、分三类计数，固定 1 分钟窗口：页面（HTML 与 `.data`）240、接口读取 600、提交类（任何非 GET/HEAD）30；`RATE_LIMIT_PAGE/_API/_WRITE` 可调，`RATE_LIMIT=off` 关闭。只有构建文件（`/assets/`）不计数，订阅源、站点地图等带扩展名的动态路径照常计数。超限回 429、`Retry-After` 秒数、`no-store`，请求不再往下走（不到达 api）。
  - 访客地址：设了 `CLIENT_IP_HEADER`（CDN 回源时带访客地址的请求头）时，只在来自本机代理（内网地址）的连接上读它，值必须是合法地址；没设时，信任代理取 X-Forwarded-For 最后一项，否则取连接地址。内网与回环地址永不限。
  - 限流默认不开：只有设了 `CLIENT_IP_HEADER` 或 `RATE_LIMIT=on` 才开。Codex 审查 #379 核实生产前面已有腾讯云 EdgeOne，Caddy 未配置可信代理，X-Forwarded-For 最后一项是 EdgeOne 回源节点，许多读者共用；照旧开启会让同一节点后的读者互相挤掉额度。开不开、用哪个头由部署配置决定，并要求源站只接受 CDN 回源。同一个访客地址也转给 api，用于登录失败与反馈次数限制。
  - 记住的访客上限 5 万，满了先清过期窗口，再按先进先出丢最旧的，洪水来自大量地址时内存仍有界。
  - 安全头：`X-Content-Type-Options`、`Referrer-Policy: strict-origin-when-cross-origin`、`Permissions-Policy`（摄像头、麦克风、定位、支付、USB 全禁）、`Cross-Origin-Opener-Policy: same-origin`、`X-Frame-Options: DENY`；`SITE_URL` 为 https 时加 `Strict-Transport-Security: max-age=31536000`（不含子域名、不预加载，避免误伤同域名下其他主机）。
- `apps/web/server.ts`：每个请求先加安全头，网址超过 8192 字符回 414，再按上面计数；api 代理改用同一个取地址函数；`headersTimeout` 30 秒、`requestTimeout` 120 秒。
- `apps/web/runtime-env.ts`：web 允许读取的环境变量加上限流变量与 `CLIENT_IP_HEADER`。`.env.example` 写明两种开启方式与“源站只接受 CDN 回源”的前提。
- 台账 DEC-78补充·网站安全防护；产品更新片段（读者口径）。

## 测试

- `apps/web/tests/request-guard.test.ts`：计数窗口与等待秒数、不同访客与不同类别互不影响、大量地址下内存有界、类别判定、访客地址（伪造前缀无效、内网不限、IPv6）、环境变量；再起一个真实 web 进程（信任代理、限额调小）验证：超限 429 且 api 未被请求、其他访客与内网检查照常、提交类单独更严、安全头出现在正常响应和拒绝响应上、超长网址 414。
- `apps/web/tests/cache.test.ts` 全量回归：现有页面缓存、随机数、过滤等行为不变（该测试从回环地址访问，不触发限流）。

## 没做什么

- 服务器层（端口、防火墙、SSH、系统更新）：Codex 只读核实后另行处理。
- 前置 CDN/WAF/DDoS 防护：Codex 查资料，Claude 评估后报 Owner 决定（花费与 DNS 属 Owner）。接入后须让 Caddy 只信任 CDN 回源地址，否则限流会把所有访客当成同一个 CDN 地址。
- 多实例共享计数：现在只有一个 web 进程，计数放内存；以后多实例时再换共享存储。
- 生产开启限流：需要先确认 EdgeOne 回源带访客地址的请求头名、并让源站只接受 EdgeOne 回源（安全组或 Caddy 可信代理），再在 `.env` 设 `CLIENT_IP_HEADER`；`.env` 与云配置由 Owner 决定。本卡上线后限流仍是关闭状态，安全头、超长网址与超时立即生效。
