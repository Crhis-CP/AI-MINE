Owner 2026-11-14（原话）：“全文页不需要加入搜索引擎收录，只加我们的网站，就是人家搜 AI 矿策就可以了。”

> 计划版（status: delivered）：下面是实现 PR 要满足的要求，不是本计划 PR 的交付结果。

## 交付内容（做什么）

1. 详情页里“原文全文”和“中文全文译文”两段不进入服务端输出的 HTML，由浏览器在读者打开页面后再取；搜索引擎抓到的页面只有本站写的中文标题、AI 导读、来源和原文链接。读者看到的页面不变。
2. 浏览器不运行脚本时，这两段的位置显示一句“全文需在浏览器中打开本页查看”和原文链接。
3. 取全文的接口在 `/api/` 下，robots.txt 早已写明 `Disallow: /api/`，搜索引擎渲染页面时取不到正文。（实现时改正：计划版写的是给接口加 `X-Robots-Tag: noindex`，但被 robots.txt 禁止抓取的地址，搜索引擎根本不会去请求，也就看不到这个响应头，所以不加。）
4. 本站自己的页面（首页、列表、导读页、日报、关于等）照常允许收录，站点地图不变。
5. 读者说明用运营片段登记“读者所见不变”；文档与决定台账各记一条。

## 不做

- 不把整个详情页设为不收录；不改全文的授权范围和展示范围。

## 测试

- 服务端 HTML 不含全文和译文正文，含标题和导读；浏览器里全文照常出现；全文接口带不收录头。

## 交付结果

- `apps/web/app/features/item/deferred-body.ts`：服务端用 `withoutBody` 从页面数据里去掉正文和由正文生成的目录，只留下“有哪些语言”；浏览器端用 `useDeferredBody` 读取本页语言对应的 `/api/site/items/{id}`（原文页读 `/original`），不带报道组参数，以免多一次查询。读取时按 ETag 重新校验，不用浏览器里的旧副本。读到的修订号与页面不一致时，先重读一次页面数据。
- `routes/item.tsx` 和 `routes/item-original.tsx` 两个页面的数据都走 `withoutBody`。正文没到时显示 `BodyPending`：读取中显示“正文加载中…”，失败时给“重试”和原文链接，浏览器不运行脚本时给 noscript 提示。“本站暂无正文”的提示只在确实没有正文时出现。
- 英文界面新增 3 条短语。
- 测试（`item-fulltext-browser.test.ts`）：
  - 服务端 HTML 和 `.data` 都不含正文，但含标题和导读；
  - robots.txt 禁止抓取 `/api/`；
  - 浏览器里正文照常出现；
  - 读取失败后可以重试；
  - 宽 390px 时不出现横向溢出。

## 没做什么

- 资讯页里 X（推特）帖子本身的文字和引用帖子没有改动：它们是条目本身的内容，不属于“原文全文、全文译文”这两段。
- 浏览器多读一次 API，每次打开详情页会多一次 `/api/site/items/{id}` 请求（响应带 ETag，可以按 60 秒缓存）。
