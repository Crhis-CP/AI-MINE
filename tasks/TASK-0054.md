## 交付内容（做什么）

1. **JSON 文件按还原转义后的文字查**（`names.ts`，AC-M0-01）：
   - 仓库检查里路径以 `.json` 结尾的文件，先把 `\uXXXX` 转义还原成字符，再查名称与标识；第 7 类文件的原句计数和“抹掉原句后剩下的命中”也在还原后的文字上做。
   - 反斜杠本身被转义的不还原：`\\u0061` 是一个反斜杠加“u0061”，不是字母 a。
   - 报出的行号仍是文件里的行号：还原出来的换行（`\u000a`、`\u000d`）不能让后面的行号错位。
   - 只管仓库里的 JSON 文件。构建产物与网站输出照旧：网站发出去的 JSON 是解析后再序列化的，名称就是原样，审查第 12b 条已证明 smoke 拦得住。
2. **两份清单绑在一起**（`names.ts`）：`allowedPhrases.files` 里的文件都必须落在同一个例外类里，而且那一类的文件清单必须和 `allowedPhrases.files` 完全相同；不同就报一条问题，写明多出或缺少哪个文件。不给 names.json 加新字段；`$comment_allowedPhrases` 补一句“这两份清单必须相同，names.ts 会核对”。
3. **更新日志校验说清是哪一条**（`meta.ts`，F-RDR-14、PG-13）：`realDate` 先判断 `new Date(...)` 是否有效（`Number.isNaN(d.getTime())`），无效就当作“不是真实日期”，由 `:52` 报出 `releases[i].date "2026-13-01" is not a real YYYY-MM-DD date`。别的校验规则不变。
4. **PG-13“数据来源”补一句**（`03-reader-pages.md:752` 句末）：“现在的数据是 `industry/changelog.json` 里手写的条目（TASK-0038）；改成登记表时这些条目原样带过去：只写日期的不补时分，‘重大更新 2.0’的版本号保留。”
5. `scripts/verify/README.md` 的 names 一行（:51）补第 1、2 条，各一句。
