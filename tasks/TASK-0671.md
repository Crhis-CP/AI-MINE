Owner 2026-11-14（原话）：“邮件简报不要，因为我们有飞书，后面接飞书可以在飞书那个群里面加个机器人，直接天天在飞书群里面推精选就行了……南美的群里面推南美，不同的群推不同的。”邮件简报就此不做。由开发修复按卡实现。

> 计划版（status: specified）：下面是实现 PR 要满足的要求，不是本计划 PR 的交付结果。

## 交付内容（做什么）

1. **推送方式**：用飞书群的自定义机器人（群里添加机器人后得到一个推送地址）。每个群一条配置：推送地址、可选的签名密钥、地区范围（全部，或一组国家代码，如南美各国）、每天几点推（按北京时间，可多个时点）、条数上限。
2. **配置放哪**：推送地址和签名密钥是秘密，只放生产 `.env`（一个 JSON 变量），不进仓库、看板和日志；日志里只记群的别名。
3. **推什么**：上一次推送之后新入选精选、且属于该群地区范围的条目。每条是中文标题、一句导读、来源名、站内链接；末尾一行“AI 辅助整理，请核对原文”。没有新条目就不推，不发空消息。
4. **不重复**：按群记住已推过的条目；失败重试最多三次，仍失败记一条告警，不影响采集和发布。
5. **试发**：一个只读脚本或命令行参数，把将要推送的内容打印出来而不真的发，用来给 Owner 看样子。
6. **文档**：分发文档加“飞书群推送”一节，写明怎么在群里加机器人、把地址交给发布运维；决定台账记“邮件简报不做，改飞书群推送”。

## 上线（发布运维）

- Owner 在各群里添加机器人后，把推送地址通过安全渠道交给发布运维写入生产 `.env`。地址没配置时功能整体不启用。

## 不做

- 不做飞书应用、不读群消息、不做交互卡片按钮；不做邮件。

## 测试

- 地区范围过滤、去重、无新条目不推、签名计算、失败重试与告警；真实网络一律用替身，测试不外发。
