## 背景（为什么做）

ICP 备案（皖ICP备2026024398号-1）登记的网站首页是 `www.aiminingpolicy.com`，但新站只响应不带 www 的主域名，带 www 的地址打不开。公安联网备案 2026-10-05 已提交、正在审核，民警或通管局可能按登记的首页地址抽查。备案线程发现了这个问题，Owner 在那里同意（2026-10-05 20:11:51Z「那你加，我同意」）：加 www 解析，并把 www 跳转到主域名。

解析已经加好：20:17Z 在火山引擎云解析加了 `www` 的 A 记录，指向本机 111.231.76.204，TTL 10 分钟；火山引擎、Google、腾讯的公共解析都已返回这个地址。现在 `http://www` 被 Caddy 转到 `https://www`，但 Caddy 没有 www 的站点和证书，握手失败。只差 Caddy 这一段。

方案已在本机验证。工具是与 `docker-compose.yml` 固定镜像同版本的 caddy 2.11.4，用官方发布包，sha512 与官方校验和一致。结果如下：

- `caddy fmt` 没有改动，`caddy validate` 输出 `Valid configuration`。
- `caddy adapt` 后，www 主机只有一条路由，返回 301，`Location` 为 `https://aiminingpolicy.com{http.request.uri}`；主域名与私有主机名那一条路由不变。
- 本机起服务实测（内部证书、高端口），用 `amp.test` 代替域名：
  - `https://www.amp.test/item/abc?x=1&y=2` 返回 `301`，`location: https://amp.test/item/abc?x=1&y=2`；
  - `http://www.amp.test/all?page=2` 先由 Caddy 转到 https（308），再 301 到主域名；
  - 主域名与私有主机名照常转给网站进程。

## 交付内容（做什么）

- `deploy/Caddyfile` 新增一个站点，主域名与私有主机名那一段一字不改：

  ```
  www.{$SITE_DOMAIN} {
  	redir https://{$SITE_DOMAIN}{uri} permanent
  }
  ```

  这是永久跳转（301），保留路径与查询。解析已指向本机，Caddy 会自动为 www 申请并续期证书。
- `deploy/Caddyfile.test`（离线对照配置）加对应的 http 段：`http://www.{$SITE_DOMAIN}:{$EDGE_PORT}` 跳到 `http://{$SITE_DOMAIN}:{$EDGE_PORT}{uri}`，保持两份配置的站点一致。
- 产品更新片段 `changes/TASK-0037-www-redirect.md`，类型“更新”。

## 输入输出与错误状态

- 只影响 Host 为 `www.<主域名>` 的请求：任何路径与查询都 301 到主域名的同一路径与查询。主域名、私有主机名、发布标识头都不变。
- 证书申请失败时（例如某地解析还没刷新），只有 www 打不开，主域名不受影响；Caddy 会自己重试。解析在 Caddy 加站点之前就已生效，所以第一次申请就能成功，不会去撞 Let's Encrypt 的失败次数限制。
- 配置写错时 Caddy 起不来，整站都会停，所以部署前必须先校验（见下节第 1 步）。

## 部署（生产变更，Owner 当时同意后执行；本卡的合并不等于上线）

1. 服务器更新代码后，先用线上同一个镜像校验：`docker compose --profile https run --rm --no-deps -e PRIVATE_HOSTNAME=<私有主机名> caddy caddy validate --config /etc/caddy/Caddyfile --adapter caddyfile`，要看到 `Valid configuration`。
2. 让 Caddy 读新配置：`docker compose --profile https restart caddy`。Caddyfile 是挂载进去的文件，`up -d` 看不到它的变化，不会重启 Caddy。不要用 `docker compose exec caddy caddy reload`：exec 起的进程没有入口脚本算出的 `PRIVATE_HOSTNAME`，私有主机名那一段会被替换成空。
3. 从主机之外读回：
   - `curl -sI https://www.aiminingpolicy.com/all?page=2` 返回 301，`location: https://aiminingpolicy.com/all?page=2`；
   - `curl -sI http://www.aiminingpolicy.com/` 最终落到 `https://aiminingpolicy.com/`；
   - 主域名与私有主机名照常，发布标识头不变。

## 明确不做

- 不改 DNS：www 记录已加好。旧站 2026-09-19 留下的 `mcp` 子域名解析（CNAME 到主域名，备注“私有只读MCP”）新站不用；删不删要 Owner 同意，另问。
- 不把规范地址改成 www。备案登记的首页能打开、并落到主域名就够了；改登记信息要 Owner 去备案系统办，不在本卡。
- 不加 HSTS 等安全响应头（`docs/04-architecture/06-security-and-access.md` 的头集合另有任务包），不动私有主机名。
