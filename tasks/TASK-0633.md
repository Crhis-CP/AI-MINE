Owner 2026-11-13：“矿业是分国界的……不同国家的人看到的是一开始不同的……但是也是支持看其他国家”；随后：“先开始从中国和阿根廷就可以了”“先跑通这两个流程再说”。Owner 原先设想按 IP 判断，并说“如果你觉得不好或者可以优化的，你都可以优化”。

> 计划版（status: specified）：下面是实现 PR 要满足的要求，不是本计划 PR 的交付结果。

## 设计取舍

- **用设备时区判断国家，不用 IP。** 现在服务器没有按 IP 查国家的能力，加上它要引入地址库并常驻内存，而服务器内存已经偏紧。时区在读者浏览器里就能读到，不经过服务器；在海外挂国内线路的读者，IP 会显示成中国，时区仍是当地的。时区判断不到省，省一级以后让读者自己选。
- **首页不按读者整页换内容。** 服务器返回的页面对所有人相同，本国这一块在加载后由浏览器读公开接口画出。这样搜索引擎和页面缓存不受影响。
- **首批只开中国和阿根廷。** 其他国家等信源够深再加入：加一个国家就是往名单里加一个代码。

## 交付内容（做什么）

- 不带筛选的首页顶部，显示读者所在国家最新的 5 条动态（取自全部矿业动态，不只精选）：标题、来源、时间；标题旁写“近 7 天 N 条”；底部“看 X 全部动态”链接到全部动态里该国近 7 天的列表。
- “换国家 / 地区”：可选中国、阿根廷或“全球（不指定）”。选过之后记在浏览器里，下次打开直接用；按时区猜出来的会注明“按你设备的时区显示，可以更换”。
- 不在首批名单里的国家、时区不属于某一国的设备：只显示一行“首页先看全球”和选择入口，下面照常是全球精选。
- 首批国家近期一条动态也没有时：显示一行“X 近期没有收录动态，下面是全球精选”，不留空框。
- 带国家、分类、标签筛选的首页不显示这一块，也不去读它的数据。
- 英文界面用英文国名和英文文字。
- 隐私页写明：按设备时区判断，在浏览器里完成，不查询也不上传网络地址；选择只存在浏览器里。
- 不需要新接口，不改契约：用现有的国家列表、资讯地图和全部动态三个公开接口。

## 不做

- 省一级（中国各省、阿根廷各省）：第二步，读者自己选省。
- 每个国家单独的“今日”页面（官方公告、企业、法规分栏）：第二步，另开卡。
- 不按 IP 判断，不在服务器保存读者的国家。

## 测试

- 时区到国家：阿根廷各省时区和旧写法都对到阿根廷，上海和乌鲁木齐对到中国；UTC 等不属于某一国的对不到。
- 阿根廷设备：顶部是阿根廷 5 条，在全球精选之上，带“近 7 天 12 条”和时区说明，链接正确。
- 换成中国后刷新仍是中国；选“全球”后刷新仍是全球，不再出现本国块。
- 日本、智利、UTC 设备：一行“首页先看全球”，能选阿根廷。
- 首批国家没有动态时显示说明行。
- 带国家筛选的首页不显示也不读取。
- 英文界面显示英文。
- 服务器返回的 HTML 里没有这一块。

## 上线后（Codex）

- 无迁移，不改 `.env`。上线后在阿根廷和中国各用一台设备（或把电脑时区改成对应时区）打开首页，截图贴回看板：顶部应是本国 5 条真实动态。阿根廷这一块如果显示“近期没有收录动态”，把 `/api/site/news-map?window=7d` 里 AR 的条数一并贴回。
