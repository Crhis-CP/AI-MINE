## 背景

多个 Agent 并行之前，边界必须由机器检查，而不是靠提醒（规则文件第 4 节）。

**计划补充（2026-10-03）**：动手前把拆分、设计决定与漏列的文件写定，按 `04-aihot-adoption.md` 7.4 拆成 6 个可单独合并的执行 PR，另加一个验收记录 PR；每个都过 7.3 的等价性检查（测试名单、路由表、队列与定时任务、数据库结构、机器出口与冒烟，差异逐项说明）。

- **漏列的文件**：`.env.example`（按角色的数据库地址等新配置要写说明）、`biome.jsonc`（新包的导入分组与 `process.env` 告警）、`.claude/launch.json`（本地预览多一个 private-api）、本任务的验收记录与新行为基线（`docs/acceptance/` 下只开本任务自己的文件名）。
- **D1 注入方式**：AIHOT 的数据访问代码在 `packages/backend` 的 55 个文件里直接用模块级的全局 `sql`，有的在加载时就拼好查询片段（如 `publication/items.ts` 的列清单）。M0 不改函数签名（7.1：结构动作不改行为）：`packages/backend/src/db.ts` 改为按目标模块给数据库句柄 `dbOf("<模块>")`（模块名取附录 B 的新位置，一个文件拆往几处的取第一处），句柄在执行查询时才取组合根注入的连接；组合根（`apps/api`、`apps/worker`、脚本、测试）启动时用 `injectDb` 按模块注入 `dbFor(role)` 给的连接；没注入就执行查询直接报错，不退回任何默认连接。全仓不再 import 全局 `sql`（测试与脚本也改为显式取连接）。模块迁出时，这个句柄就是它 `store/` 的注入点。
- **D2 每个进程持有哪些登录**（`platform/config` 按进程角色校验，`dbFor` 拒绝本进程不该持有的角色）：

  | 进程 | 数据库登录 | 模块注入 |
  |---|---|---|
  | public-api | `public_read`、`feedback_write` | feedback 模块用 `feedback_write`，其余一律 `public_read` |
  | private-api | `private_ops`、`auth` | identity（登录、会话、账号）用 `auth`，其余 `private_ops` |
  | worker | `worker`；备份作业另用 `backup` | 全部 `worker`；`backup` 只给 `pg_dump`，不经模块注入 |
  | 迁移与种子脚本 | `migrate` | 全部 `migrate` |
  | 其余运维脚本（采集、重排、评测等，在 worker 容器里跑） | `worker` | 全部 `worker` |
  | web、fetcher | 无 | — |
  | 测试 | 测试库的单一登录 | 全部同一连接；真实登录测试另建一个临时库和一组临时角色 |

- **D3 配置与过渡**：每个角色一个地址 `DATABASE_URL_<角色>`（如 `DATABASE_URL_PUBLIC_READ`）。一个都没配时退回单一 `DATABASE_URL`，所有角色共用一个登录（本地开发、现有测试与本任务里的 compose 都这样），启动日志写明“没有按角色分登录”。在部署里按角色发登录、密钥改为只读挂载的文件、生产环境必须配齐各角色地址，归部署骨架 TASK-0009（T-0008）与 T-0612；本任务提供角色、授权与真实登录测试。
- **D4 数据库角色与授权**（AC-SEC-02 的 M0 范围；PIT-059 的七类登录）：迁移之后由迁移步骤按一张授权表建角色与授权，角色名为“前缀_角色”（缺省前缀 `amp`，测试用随机前缀）；建出的登录没有口令，口令由部署发放。授权表给每张表定好七类角色的权限，**有表没分类即失败**。`public_read` 只能读公开读取层用到的表与列：`sources`、`articles`、`translations` 只给用到的列，`articles`、`translations` 用行级策略只露出有公开投影行的材料（候选材料的正文读不到），`settings` 只露出 `selected_ledger_epoch` 一行；`NOINHERIT`、限连接数、不给 `TEMPORARY`，撤销 `PUBLIC` 的 `CONNECT` 后逐个角色授权。`feedback_write` 只能写反馈、读封禁名单；`auth` 只碰账号三表；`private_ops`、`worker` 读写业务表，不碰账号与会话两张表，审计表只能追加与读取；`backup` 只读（备份的 `pg_dump` 加 `--enable-row-security`，在行级策略下仍导出全部行）；`migrate` 是属主。**余项**：AIHOT 的详情页与全文 RSS 直接从 `articles`、`translations` 读正文、在代码里按状态过滤，所以公开登录仍能读到“有投影行但不公开”（仅摘要、已下架）的条目的正文；公开投影自带公开正文之后（M1，AC-SEC-02 自身的里程碑）才能收掉，写进验收记录并注明接手任务。
- **D5 任务队列**：pg-boss 的 `pgboss` schema 归 worker 登录所有（它照旧自己安装与维护，为此给 worker 建 schema 的权限）；private-api 只发任务（不跑维护与定时），对 `pgboss` 的表只有读写数据的权限；public-api 不碰队列。
- **D6 读路径不写库**：`selected_ledger_epoch` 改在迁移时初始化（`04-aihot-adoption.md` 2.2、附录 B.7.2），新增一个只插这一行的迁移；`ledgerEpoch()` 的补写分支留着，在迁移过的库上不会执行。public-api 不再写心跳；心跳与 worker 看门狗移到 private-api（运维属私有侧），后台“运行”页里原来的 `api:<端口>` 心跳行变成 `private-api:<端口>`（运行页随 TASK-0007 删除）。
- **D7 两个 api 实例**：`API_ROLE=public-api|private-api`（必填）。public-api 注册读者站接口、v1、RSS、MCP、静态出口、分享图与反馈提交；private-api 注册 `/api/admin/*` 与 `/api/auth/*`；`/api/health` 两边都有；组合根按字母序一行一个注册，v1 兜底仍在最后。路由表快照：两份清单的并集与 T-0002 基线的路由清单相同，私有清单里的每条路径都落在网页判定的私有前缀里。web 把 `/api/admin/`、`/api/auth/` 转发到 `PRIVATE_API_BASE_URL`，其余照旧转发到 `API_BASE_URL`；SSR 的后台加载器同理。公开主机名与 `PRIVATE_HOST` 的隔离归 TASK-0007（T-0006 前端路由组）与 TASK-0009（T-0008 部署骨架）。
- **D8 进程凭据检查**（AC-SEC-07、T-014）：web 与 fetcher 的环境里出现数据库或模型凭据（`DATABASE_URL*`、`PG*`、`POSTGRES_*`，以及任何 `*_API_KEY`、`*_SECRET`、`*_TOKEN`、`*_PASSWORD` 与 `AMP_CREDENTIALS_DIR`）即拒绝启动；生产环境任何进程出现出网代理设置（`HTTP_PROXY`、`HTTPS_PROXY`、`ALL_PROXY`、`EGRESS_PROXY_URL`）即拒绝启动。web 不加载平台包（模块地图第 6 节），检查写在 `apps/web` 里，由 `role-config` 阶段核对它与 `platform/config` 的规则一致。compose 的 web 服务不再读 `.env`。
- **D9 fetcher 骨架**：`apps/fetcher` 只在内部端口监听一个端点 `POST /fetch`，按网址返回录制好的响应，没录的返回 404 `not_recorded`；没有数据库登录、没有模型密钥。worker 暂不调用它，采集搬进 fetcher 随 acquisition 迁出（M1）。
- **D10 边界脚本**：现有 6 个包的边保持现状（`@amp/contracts` 依赖 `@amp/industry` 的反向依赖由 TASK-0005 处理；`@amp/web` 直接读行业包的站点文案与品牌素材，模块地图第 3 节没有这条边，记进验收记录的未完成项，交 TASK-0007 与 TASK-0010 定去向）；新包按模块地图第 3 节 L0–L9 与 apps 的边登记；数据库驱动只许出现在模块的 `store/`、`platform/config`、`platform/queue` 与尚未拆分的 `@amp/backend`；模型 SDK 只许出现在 ai-gateway；跨包不得指向 `internal/`、`store/`；`exports` 不得通配。`@amp/backend` 现有 74 个导出入口列成显式清单，只减不增（快照在 `scripts/verify/`，新代码进新模块）。
- **D11 冲突热点表（3.3）里时机写作 T-0003 的两项**：`apps/api/src/routes/admin.ts` 按模块拆成各自的 `privateRoutes` 要先有模块目录，随模块迁出（M1）；它直接写的 SQL（导航计数、审计列表）不搬，记进《待迁出清单》只减不增，导航计数随 TASK-0007 删除。环境变量：`platform/config` 提供按进程角色的 schema 与启动校验；各模块的配置切片随迁出；“`process.env` 只在 `platform/config` 读取”先用 Biome `noProcessEnv` 告警加告警基线做棘轮（21 个文件的存量只减不增），M1 收口。
