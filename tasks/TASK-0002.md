## 背景

旧项目的检查绑在 GitHub Actions 上，额度用完后任何改动都合并不了（ADR-0017）。新仓库把全部检查写进仓库里的 `make verify`，任何独立执行器都能对同一个提交跑出同样的结果和一份回执。

## 交付内容

- pnpm 12 工作区：`packageManager` 固定版本、一份锁文件、`minimumReleaseAge` 一天、空的 `allowBuilds`；Dockerfile 整仓复制 + `pnpm install --prod --frozen-lockfile`，不用 `pnpm deploy`，保留 `NPM_REGISTRY`；基础镜像补丁版 + sha256（含 compose 里的 postgres 与 caddy）。
- Biome：`css.parser.tailwindDirectives: true`、`lineWidth` 160（实测）；首次全仓格式化单独一个提交；已有告警按文件与规则锁定在 `scripts/verify/lint-baseline.json`，只减不增。
- `make verify`（`scripts/verify/run.ts`）：install、toolchain、format-lint、typecheck、boundaries、path-guard、build-web、migrations、smoke、test、secrets、audit、compose-smoke、docs、tasks；上游 `check.yml` 两个作业逐步翻译，删去“信源数必须是 18”，改为“种子信源数与 `industry` 种子文件一致”。
- 回执：绑定完整 SHA 的 JSON，写在 `.verify/`（不进 git）；缺 `secret_scan` 或 `audit` 视为未通过；有阶段跳过即 `scope: focused`。
- 密钥扫描：trufflehog 3.97.9（下载后核对 sha256）+ 本项目规则；依赖审计 `pnpm audit --audit-level=high`。
- `make release-check`、`make nightly` 骨架（明确报“未实现”，不冒充通过）；`pnpm check` 快速子集。
- 故意违规用例：越权路径、越界 import、提交密钥、工具链违规、坏任务卡各被拦一次（`scripts/verify/tests/`）。
