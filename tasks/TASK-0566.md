Owner 2026-11-06：“法规这个也没有做好”；“更新日志这次 UI 的重大更新应该做一个对比图把老版本和新版本对比”“这些应该用图片说，以前 logo 什么样子现在什么样子，另外不要说必和必拓这些举例”；并要求“继续修英文版和事件页，然后修法规页；修复问题的时候，让 Agent 学会举一反三，把同类的问题一起修复掉”。2026-11-07 线上逐页核查（电脑 1440、手机 390，中英文）复现了下列问题。

## 背景（为什么做）

- **主题全空**：选中国后各主题都显示“暂无已公开文书”，实际已有 56 份公开文书。原因：主题只来自完成的完整解读，模型步骤未开时所有文书都是“基本事实”，主题为空；投影写入的主题名与产品主题表也不一致。
- **标题夹带网页符号**：如“云南省全域</br>消防安全监管实施办法”，来源标题原样入库，读取时没有清理。
- **空地区与重复说明**：没有文书的国家和组织也占一张卡片；页面顶部叠了两段计数说明和暂停说明。
- **卡片**：“来源发布”“本站公开”标签重复；未知的性质、阶段显示“尚未确认”“未知”；文号与标题重复；分几部分公布的同一份法令列成几条；只写日期的来源显示 08:00。
- **文书页**：打开约 4.3 秒；标题印两遍；内部用语（“本站取得修订”“原文 es”）；手机上“查看官方原文”被挤出屏幕。
- **英文界面**：法规页的链接和表单会跳回中文页；国名、说明、日期仍是中文；有两段文字连在一起（“First publishedHappened”）。
- **法规周报、月报**：显示修订导航、“本次新增 X / 移除 Y”和“第 N 版”。

## 交付内容（做什么）

- **主题**：地区页按本地区自己的文书计数（每页读 50 份；超过 1000 份时按主题逐一计数）。没有主题的文书归入网页端的“未归入主题”组（`theme=none`，只在网页端使用，不发给接口），并用一句话说明原因。没有文书的主题合成一行。主题名统一用一张表（`POLICY_THEME_LABELS`），投影写入时使用；已存的卡片在读取时改名。
- **标题清理**：读取层（`modules/policy/backend/reader-copy.ts`）统一清理标题、原文标题、文号、发文机关和证据标题：去掉标签，`</br>` 在中文之间直接拼接、其他位置换成空格，并还原实体。列表、文书页、历史、对比、周月报、RSS、v1 接口、MCP 和资讯页的相关法规链接都走这一层。
- **地区页**：只给有文书的地区显示卡片，其余收成一行链接；没有文书的地区打开后显示如实的空状态；顶部只留一行更新说明（由暂停开关决定）；两段计数说明合成一句。
- **卡片**：日期写成“来源发布 2026-10-15 · 本站公开 2026-10-20”；隐藏未知项；只标“完整解读”；文号与标题重复时不再印；分几部分公布的法令合成一条，并给出各部分链接；只写日期的来源只显示日期（RSS 用 `<dc:date>`）。
- **文书页**：
  - 关系图只读与本文书有存档关系的文书，基本事实文书完全不读；
  - 相关报道和关系并行读取；
  - 相关报道按网址缓存 10 分钟，每次展示前都按当前公开状态重新核对；
  - 历史和对比页只取段落数，不再读取每一版的全文；
  - 标题只印一次，未知项和空栏目隐藏；
  - 内部用语改成读者用语；语言写全称；
  - 手机上“查看官方原文”留在屏幕内。
- **英文界面**：法规页全部改用保留 `/en` 的 Link 和 Form（`apps/web/extension.ts` 增加导出 `Form`、`useNavigate`）；国名取自 `phrases.ts`（来源 `industry/jurisdictions` 的 `name_en`）；说明和日期都经 `tr()`。
- **法规周报、月报**：去掉修订导航、增删计数和版本号；只有本期确实移除了文书时，才写一行更正说明（与日报的 `ReportPaper` 一致）。旧的 `?edition=` 链接仍能打开，提示一次这是较早版本，并链接到当前一期。
