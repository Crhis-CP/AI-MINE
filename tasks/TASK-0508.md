DEC-78（Owner 2026-11-04）：项目开源后，ICP备案号、公安联网备案号、互联网新闻信息服务许可证编号属于部署信息，不再写在代码仓库里，由部署者填写；不填就不显示；git 历史不改写，只从当前版本移除。原“生产环境缺号码不得开放”改为部署者开关，中国大陆的部署应当打开。

## 做了什么

- **后端** `packages/backend/src/site/filings.ts`（内部文件，经现有出口 `@amp/backend/site/meta` 导出，后端出口清单不变）：
  - 从 API 运行环境读取 `SITE_ICP_FILING`、`SITE_PUBLIC_SECURITY_FILING`、`SITE_NEWS_LICENSE`，并校验格式；
  - 公安备案的查询 code 直接从号码中取出。
- **站点元数据**：`siteMeta()` 返回 `filings`；`/api/site/meta` 按契约 `SiteMeta` 校验后发送，ETag 与缓存头不变。
- **后台“受保护的展示配置”**：只报告是否已配置，来源记为 `runtime`，不返回号码本身。
- **启动检查** `apps/api/src/runtime.ts`：在连接数据库前执行，错误信息只写变量名，不回显号码。以下情况拒绝启动：
  - 号码格式不对；
  - `SITE_REQUIRE_FILINGS=true` 时缺少 ICP 或公安备案号。
- **契约**（只增不改）：新增 `SiteFilings`、`SiteMeta` 和路由 `siteMeta`，对外 OpenAPI 文档已重新生成。
- **读者端**：
  - 新增组件 `Filings.tsx`，替换侧栏、手机页脚、“更多”页和关于页四处写死的号码；
  - 公开布局的 loader 按契约校验元数据。旧版 API 不带 `filings` 时，保留更新日志标记，不显示号码。
- **清理号码**：删除 `site/site.ts` 中的三个字段；删除 TASK-0028 和两份验收记录里的具体号码。
- **文档同步**：`.env.example`、industry 与 backend 的 README、BR-SITE-03、INV-46。

## 交给 Codex：部署前必须做

上线后读者看到的页面与原来一致，前提是部署前先做完以下三步：

1. 在生产 `.env` 中填写：
   - `SITE_ICP_FILING=<现用 ICP 备案号>`
   - `SITE_PUBLIC_SECURITY_FILING=<现用公安备案号全文>`
   - `SITE_REQUIRE_FILINGS=true`

   号码即原 `site/site.ts` 中的值，可在 git 历史中找到。
2. 用 `docker compose config` 确认 api 服务能拿到这几个变量。
3. 发布后检查：用手机打开首页、详情页、“更多”页，页脚号码和两个链接都正常；后台“网站资料”显示“已配置，来源 runtime”。

如果忘了填号码：开关已打开时，API 拒绝启动，发布流程会按健康检查失败自动回退；开关未打开时，页脚不显示号码。
