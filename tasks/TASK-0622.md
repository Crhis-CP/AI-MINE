Owner 2026-11-12 实测反馈：同一个人换一个浏览器，或者从微信里的链接再打开一次，后台“访问概况”的访客数就会增加，而且不断增加，希望统计尽量真实。

> 计划版（status: locally_verified）：下面是实现 PR 要满足的要求，不是本计划 PR 的交付结果。

## 原因

访客是“网络地址 + 浏览器字符串”做成的匿名哈希，两样都取了原样：

- 浏览器字符串每个浏览器都不同。同一部手机上的 Safari、微信、Chrome 是三个字符串；微信还把当前网络类型（WIFI/4G/5G）和自己的版本号写在里面，换个网络、升个版本又是新的。
- IPv6 地址的后半段，手机和电脑每隔几小时或每次重连会自己换一个（隐私地址），前半段（/64）不变。

所以同一个人被算成了好几位访客。浏览量（打开次数）不受影响，一直是准的。

## 交付内容（做什么）

- 浏览器字符串只取“操作系统 + 设备类型”（如 iOS 手机、安卓手机、Windows 电脑）。版本号也不用：Chrome 在所有安卓手机上都报“Android 10; K”，微信报真实版本和型号，带上版本又会把同一部手机拆开。
- IPv6 地址只取前 64 位；IPv4 保持完整；按 IPv6 写法给出的 IPv4 地址按 IPv4 算。
- 仍然不用 Cookie，不在浏览器里存任何标识，盐照旧每天、每月更换并销毁。隐私页“把网络地址和浏览器信息做成匿名哈希”的说法仍然成立，用到的信息比以前更少，不用改。

## 改不了的（写明，不做）

- 同一个人从 Wi-Fi 换到流量（网络地址变了），仍会算成两位。
- 同一个网络里用同类设备的两个人（一家人都用 iPhone、一间办公室都用 Windows），会算成一位。
- 这两种情况只有在浏览器里存一个标识（Cookie 之类）才能分清，那要改隐私承诺，是 Owner 才能定的事，本卡不做。

## 测试

- 同一地址下，iPhone 的 Safari、微信（WIFI）、微信（4G、另一个版本号）、Chrome 得到同一个访客；安卓的 Chrome 和微信得到同一个访客。
- 不同类设备、不同地址仍是不同访客；不同日期的盐仍然互不相关。
- IPv6 同一 /64 下不同后缀是同一访客，不同 /64 不是；各种写法（缩写、大写、方括号、IPv4 映射）都归一。
- 原有的访问统计数据库测试保持通过。
