## 输入输出与错误状态

- 只改显示名与简称：`safety_incident` 改为“矿山安全”（简称“矿山安全”），`technology_processing` 改为“技术与冶炼”（简称“技术冶炼”）。键、收录范围（guide）、报告分节（section）都不变。
- 分类名不只存在行业包里：分析时类名被放在标签第一位（`packages/backend/src/editorial/analyze.ts:503`），发布时原样写进 `publications.tags`（`publish.ts:235-237`），对外输出时不转换（`items.ts:127`）。所以已收录的稿件，详情页和电脑版卡片仍会显示“#人身与生产安全”，按新名标签也筛不到它们；搜索文本里也是旧名（`publish.ts:305`）。
- 处理：发布时把两个旧全称和两个旧简称（“人身与生产安全”“安全事故”“技术与加工”“技术加工”）都换成新名（“矿山安全”“技术与冶炼”），对照放在 `industry/mining-taxonomy.ts`。只改对外展示的发布数据，不改私有的原始分析，符合 ADR-0022 第 3 条。人工改过的标签不自动改，列出来交人工处理。
- 已发布的条目要重新发布一次才换名。后台没有这个按钮，也不加（加按钮要新增私有接口，碰到停止条件）。在仓库里加一个只做这件事的小脚本 `scripts/rename-category-tags.ts`，和 TASK-0040 的补日期脚本一样默认不写：
  - 默认只读列出标签里带四个旧名的发布记录，打印条数和标题；人工改过标签的单独标出来，交人工处理；
  - 加 `--apply` 才对其余条目调用 `publishArticle`：只读已存的分析结果，不调模型；然后再列一次，打印剩下的条数；
  - 别的参数一律报错退出，什么都不写；再跑一次改 0 条。
- 部署当天在正式服务器上用 worker 镜像起一次性容器（`docker compose run --rm --no-deps worker node scripts/rename-category-tags.ts`）跑：先列，再 `--apply`，再列。这属于 Owner 2026-10-06 00:49:38Z 预先同意的这次部署。
- 分类说明（`MINING_CATEGORY_GUIDE`）里带着名字，所以结构化与内容理解提示词的版本会变：新稿按新版本处理，已处理的稿件不重新付费。评分的确认版本只绑定评分提示词，不受影响。
