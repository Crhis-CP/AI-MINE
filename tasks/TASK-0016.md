## 背景

Owner 2026-10-03 读完新的根目录 README 后，在项目对话里更正（原话）：

> 旧站只读不保留 ，新版测试后没问题就正式切换上线。
> 这里不要弄错了哈

Owner 看到的是 README 路线图里的一行：“M5 全面切换 | 一次性切换入口；旧站只读保留 7 天作回退，之后下线”（`README.md` :210）。这句出自裁决表 DEC-19 与 Q-25 的落实。Owner 2026-10-01 的答复只是“B：全部功能完成后，直接全面切换”（`08-open-questions.md` 表四）；“旧站只读保留 7 天作回退”是交接包原有的默认做法（附录 C 的 D01-product-007、D10-data-020），落实答复时保留了下来。现在 Owner 明确不要它。

本卡里的 DEC 编号照 `08-owner-voice.md` :5 的写法：08-owner-voice 的决策时间线写“08-owner-voice DEC-nn”，决定台账写“裁决表 DEC-nn”。新登记的是 08-owner-voice DEC-26；被更正的是裁决表 DEC-19（08-owner-voice 自己的 DEC-19 是 09-27 的“正文阅读由模型自动承担”，与本卡无关；裁决表 DEC-26 是主题维度，也无关）。

按这句话，切换规则改成下面这样（实施 PR 照此写回）：

1. **切换门槛不变**：全部排期功能验收通过、影子运行通过、恢复演练一次、告警渠道就绪、Owner 在真实公网与手机上逐项看过。这就是“新版测试后没问题”。
2. **切换当天旧站停止服务**：新站从主机之外读回发布标识、记为已上线（`07-deployment-and-ops.md` :106 的“已上线”证据；下文的“切换完成”都指这一刻）之后，旧站停止对外服务与 worker，不再启动；换机切换（形态 2）时旧主机同样停止对外服务，DNS 不再改回。不保留 7 天只读，没有回切窗口，也不切回旧站。
3. **切换后出问题只在新站内处理**：撤回公开入口（只关入口，保留数据与证书状态），或新站自身的代码、内容指针、数据三类回退（`07-deployment-and-ops.md` 3.2 与 4.3）。读回之后的实测（4.2“激活与读对照”的核心阅读、隔离、用量与熔断、持续任务）出问题，也按这一条处理。
4. **切换窗口内、还没上线就出问题**（新栈起不来，或入口验证没过，即 4.3 第 3 点的 ICP 展示、HTTPS、DNS 任一项失败，发布标识还没读回）：停止公网入口，新栈回到私有预览，中止切换，旧站照常服务，切换改期。同机切换（形态 1）是停新栈、原样启动旧栈，前提是旧栈仍可在内存与磁盘预算内启动（`07-deployment-and-ops.md` :206）；换机切换（形态 2）是 DNS 留在或改回旧主机。旧站已按 Q-56 确认停用的，中止切换就只是新栈回到私有预览、切换改期。这时切换还没有发生，不算“保留旧站”。这一条是开发方按“没问题就正式切换上线”补上的理解，写进 08-owner-voice DEC-26；2026-10-03 已在项目对话里告诉 Owner，Owner 可以纠正。
5. **不变的**：
   - 切换前对旧生产库做一次加密存档备份。原写“只作回退与存档”，现在切换后没有回退，改为：存档，兼作切换窗口内中止切换的兜底（旧栈数据卷不可用时据此恢复旧库，属规则文件 14.2 的“数据库恢复”，须 Owner 授权）；不导入新系统；切换完成后不再用于恢复旧站服务。读取旧生产库做这份备份须 Owner 授权（规则文件 14.2，T-0233）。`07-deployment-and-ops.md` :198 做这份备份的理由（同机窗口内出错没有兜底）因此照旧成立。
   - 旧站退役先吊销凭据、再回收旧栈与销毁数据，须 Owner 授权（T-0809）。
   - 新旧两站之间不回写数据；旧站地址在新站一律 404。
