## 背景（为什么做）

- **Node 运行时**：Node 24.22.3（2026-11-11）是安全版，修了 tls、http、http2 的多项高危，包括“空写入触发嵌套解析”和“可远程触发的 TLS 服务端崩溃”。生产镜像固定在 24.22.1（`Dockerfile:3`），而 CI 用浮动的 `node-version: 24`（`.github/workflows/verify.yml:44`），所以测试跑在新版、线上跑在旧版。
- **fast-xml-parser 5.11.2**：公告 GHSA-474x-hrwr-fgx4，stop node 里有大量未闭合的标签时，CPU 消耗按平方增长。这个问题只在开了 `stopNodes` 时才会触发，而 `packages/backend/src/sources/rss.ts:23` 正好对 Atom 的 xhtml 字段开了 `stopNodes`，订阅源内容来自外部网站，一个坏掉或被篡改的源就能占满后台任务进程。
- **fastify 5.12.7**：CVE-2026-120216，`handlerTimeout` 不为 0 且接口返回流时，一个请求就能让进程崩溃。本项目没设 `handlerTimeout`（`apps/api/src/app.ts:37-45`），当前打不到；但 MCP 接口有长连接流（`apps/api/src/routes/mcp.ts:488-490`），以后有人加这个设置就会变成可利用，所以一并升到修复版。

## 交付内容（做什么）

1. `Dockerfile:3` 改为：
   `FROM node:24.22.3-trixie-slim@sha256:af02d57b57719b9657a45199a79264a9437940cd55b3c7b3fc99615654f124a0 AS base`
   这是 2026-11-12 从 Docker Hub 读到的多架构索引摘要。有 docker 时用 `docker buildx imagetools inspect node:24.22.3-trixie-slim` 复核一致，不一致以复核结果为准并在 PR 里写明。
2. fast-xml-parser 5.11.2 → 5.12.0：`packages/backend/package.json:105`、`modules/metals/package.json:18`。
3. fastify 5.12.7 → 5.12.8：`package.json:36`、`apps/api/package.json:16`、`packages/backend/package.json:106`、`modules/policy/package.json:27`、`modules/site-admin/package.json:22`。
4. 用 `npm install --package-lock-only --ignore-scripts --no-audit --no-fund` 更新锁文件。
5. 回归测试，加在 `tests/rss-xhtml.test.ts`：本地服务返回一份**被截断**的 Atom：`<entry>` 里 `<content type="xhtml"><div xmlns="http://www.w3.org/1999/xhtml">` 后面接 10 万个 `"<a "`，然后直接结束，后面不再有任何 `>`。断言 `fetchRss` 在 3 秒内结束，报错或返回空条目都算通过，只断言耗时。旧版本在这份输入上要几十秒以上。
