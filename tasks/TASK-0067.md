## 背景（为什么做）

结论：飞书登录的回调地址现在用公开地址 SITE_URL，配好飞书登录也登不进去；本卡把回调改到私有主机名。

现在的回调地址在导入时按 SITE_URL 算好（`packages/backend/src/admin/auth.ts:14-15`），授权跳转（:67）和换令牌（:100）都用它。可公开主机名上 `/api/auth/*` 一律 404（`apps/web/host-policy.ts:16-20`、`:55-57`），private-api 也只认私有主机名（`apps/api/src/app.ts:61-69`），而且登录时的状态 Cookie 是在私有主机名上设的（`apps/api/src/routes/admin-auth.ts:105-111`），到了公开主机名带不过去。所以飞书授权以后跳回公开地址，只会看到 404。

TASK-0004 记过这件事（`tasks/TASK-0004.md:154`：回调用的是 SITE_URL，配了 PRIVATE_HOST 后会被拒绝，接入飞书登录的任务把回调改为私有主机名；那里引的 `admin/auth.ts:13` 现在是 :15）。

Owner 2026-10-02 要保留飞书登录：「飞书推送与登录还是要保留，我也要后面接飞书的呢」（`docs/00-decision-ledger.md:29` DEC-05）。规格写的是保留、默认关闭、接入时另立任务（`docs/01-product/02-feature-catalog.md:295`、`docs/01-product/04-private-operations.md:309`）。接口契约那边写着身份提供商回调不进私有接口契约、接入时另立任务并开契约卡（`docs/03-data/contracts/interface-behavior.md:242`）；本卡不改路由、请求与响应，所以写 `contracts.change: none`，要不要先开契约卡由集成人定（见停止条件）。

Owner 在飞书里要做的事（在飞书开放平台登记新的回调地址、配允许名单）另有一页操作说明，本卡不重复。

## 交付内容（做什么）

1. **`packages/backend/src/admin/auth.ts`**：
   - :14-15 的 `CALLBACK_URL` 改为每次调用时算的函数（例如 `callbackUrl()`），:67 的授权跳转和 :100 的换令牌都用它，两处必须是同一个值。
   - 规则：设了 `PRIVATE_HOST`（`config.privateHost`，`packages/backend/src/config.ts:40`）时，协议取 SITE_URL 的；主机名取 PRIVATE_HOST；端口：PRIVATE_HOST 自带端口就用它的，否则沿用 SITE_URL 的；路径 `/api/auth/callback`。例：SITE_URL 为 `http://localhost:3000`、PRIVATE_HOST 为 `private.localhost` 时，回调是 `http://private.localhost:3000/api/auth/callback`，和 `.env.example:137` 写的本地私有入口一致。
   - 没设 PRIVATE_HOST：照旧用 SITE_URL 加 `/api/auth/callback`（本机开发；这时 private-api 也不查主机名，`apps/api/src/app.ts:61`。这一支只对直连 private-api 有用：经 web 访问时仍要设 PRIVATE_HOST，`.env.example:138` 默认已设；web 没设时也按 `private.localhost` 认私有主机，`apps/web/host-policy.ts:36`，公开主机上的 `/api/auth/*` 一律 404）。
   - PRIVATE_HOST 设了但不合规（规则同 `apps/api/src/app.ts:21-29`：只能是一个主机名，可带端口，不能带协议、路径、逗号、空白、`@` 等）：抛错，错误信息里只写配置名、不写值，也不退回 SITE_URL；这时 private-api 本来就对所有请求回 404（`tests/api-role-routes.test.ts:153-168`）。不要直接给 `URL` 的 host 赋值：遇到 `https://…` 这样的值它不报错，会悄悄换成别的主机名。
   - 改写 :14 的注释：在飞书开放平台登记的回调地址是私有主机名上的 `/api/auth/callback`。
2. **新测试 `tests/feishu-login.test.ts`**（写法照 `tests/api-role-routes.test.ts:8-27`：先设 `config.privateHost`，再 `buildApp("private-api")`，请求带 `x-forwarded-host`；回调地址现在每次调用时才算，所以 `config.privateHost` 要在整个文件里一直设着，在 `after` 里还原；`config.siteUrl`（设成 https 开头的 `.test` 地址）、`config.devAdmin`（设为 null）、允许名单 `config.adminUnionIds` 与 `config.adminEmails` 同样先存后还原；登录应用的凭据照 `tests/auth-options.test.ts:28-30` 用假值设环境变量；主机名一律用保留的 `.test` 域名，允许名单只用假的 union_id，不写任何邮箱地址）。`globalThis.fetch` 只放行 passport 的换令牌与取用户信息两个接口，记下请求体，其余请求让用例失败。用例：
   - 授权跳转：`GET /api/auth/feishu?return=/admin/sources` 回 302；跳转地址里的 `redirect_uri` 是 `https://` 加私有主机名加 `/api/auth/callback`；设了状态 Cookie。
   - 完整登录：拿上一步的 `state` 与状态 Cookie 请求 `/api/auth/callback`；换令牌请求体里的 `redirect_uri` 与授权跳转时的一字不差；用户信息里的 union_id 在允许名单里：回 302 到 `/admin/sources`，设了会话 Cookie、清掉状态 Cookie；带这个会话请求 `/api/auth/check` 回 204；审计里多了一条 `auth.login`。
   - 不在允许名单的账号：回 403，页面写“这个飞书账号没有后台权限”，不设会话 Cookie。允许名单是空的：同样回 403。
   - 状态对不上（Cookie 与 `state` 不一致）：回 403，不向 passport 发任何请求。
   - 没设 PRIVATE_HOST：`loginRedirect` 给出的 `redirect_uri` 是 SITE_URL 加 `/api/auth/callback`。
   - PRIVATE_HOST 带端口、不带端口各一例；不合规的值（带协议、带路径、空白）抛错，错误信息里没有这个值。
   - 假的 App Secret 只出现在发给换令牌接口的请求体里：跳转地址、Cookie、响应正文与日志里都没有。
3. **`.env.example`**：:78 的注释改为“用飞书账号登录后台（可选，和管理员密码并存）。在飞书开放平台登记的回调地址是私有主机名上的 /api/auth/callback，不是 SITE_URL：”，:79-82 不动。
