## 背景（为什么做）

Owner 要在真实数据上看过新版本再说“上”。现在只能看演示数据的截图，或者直接发布到线上。预览槽让候选版本的页面读正式的数据，但不影响线上、不让别人看到。

## 交付内容（做什么）

1. **独立的 Compose 工程** `deploy/preview/compose.yml`（工程名与正式的不同）：只启动一个 web 容器，用候选镜像，`API_BASE_URL` 指向正式的 api 容器。不启动 worker、api、数据库，不跑迁移。
2. **只读**：预览的 web 进程带一个只读开关，除读取以外的请求（反馈提交、访问统计、任何后台操作）一律拒绝；页面遇到被拒不报错、不白屏。预览不提供 `/admin`。
3. **资源与时限**：容器内存上限 512MB、CPU 上限 1 核；`deploy/preview/preview.sh up <镜像> [小时数]` 启动并排好定时关闭，默认 2 小时；`down` 立即关闭；`status` 显示是否在跑和剩余时间。启动前可用内存不足 1GiB 就拒绝启动。
4. **入口**：只有 Owner 能打开——口令保护（口令在服务器上生成，经安全方式交给 Owner，不进看板和仓库）；响应一律带“不缓存”和“搜索引擎不收录”；CDN 不得缓存预览页面。
5. **入口用哪个地址，先只读核对再定**：先读回现有哪些子域名直接指向源站、哪些经过 CDN，报到看板。能用现有解析就用现有的；需要新增一条解析记录时，把“在哪里、填什么”写成一步一步的说明交给 Owner（域名解析只有 Owner 能改）。
6. **与发布的关系**：`deploy/release-one.sh` 在发布前先关预览（TASK-0731 第 5 项）。

## 不做

- 不让预览写任何正式数据，不在预览里跑采集、模型调用和定时任务。
- 不改正式站点的缓存、限流和安全头。
- 不常驻：没有人在看的时候预览必须是关着的。

## 验收

- 用线上同一个镜像启动预览，首页、全部、热点、日报、条目、法规、金属这几页与线上逐页一致。
- 启动前后各读一次主机内存和三个正式容器的状态：正式容器不重启，可用内存下降不超过 600MB。
- 在预览里提交反馈、触发访问统计：请求被拒，页面不崩，正式库里没有新增记录。
- 不带口令打不开；带口令打开后，响应头里有“不缓存”和“不收录”。
- 到点自动关闭；关闭后内存回到启动前的水平。

## 停止条件

真实失败、会花钱、会删数据、需要改域名解析（交 Owner）。其余按最合理的理解继续。
