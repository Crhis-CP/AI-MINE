## 背景（为什么做）

交接包要的数据归属检查很小：模块代码里引用别的模块的表，要么在拥有方登记的只读白名单里，要么记进一张“现有跨模块访问”的计数表，计数只减不增，新增的跨模块访问一律失败（规则文件第 4 节第 104 行；`04-architecture/04-aihot-adoption.md` 3.1(3)、3.2(1)、7.4(4)；ADR-0003；AC-M0-02）。TASK-0004 当时估的是约 250 行。

Codex 续建期间实际做成了 37 个文件、5,474 行：用 TypeScript 7 检查器加一个手写的 PostgreSQL 词法器逐处解析 SQL，债务键里带闭包的行号、列号，拿不准的位置（UNKNOWN）按整个文件和锁文件子图的哈希冻结。结果是：

- 与数据归属无关的改动也会让检查失败：在 `group.ts` 里加一行注释、在 `compose.ts` 顶上插一行，旧检查报 54 个问题；纯粹 `git mv` 两个文件，报 35 个问题；
- 有 8 个 PR、约 3,000 行，只是在给这些键换编号；
- 这一阶段每次要跑约 30 秒，自测再多 10 秒；
- 验收记录里仍写着“保留的 UNKNOWN 位置未经证明”。

真实的访问权限由 `role-config` 的真实登录矩阵证明，那一部分不动。Owner 的理念是照 AIHOT 做自动化的工程，检查与把关做到交接包要求的程度为止（总原则 DEC-64；08-owner-voice DEC-28、DEC-29）。所以把这一阶段换回规格写的大小。

方案与草稿实现：`/mnt/project-files/plans/TASK-0026-plan.md`、`TASK-0026-sketch.patch`（在 main `2246635` 的副本上做过全部试验）。

## 交付内容（做什么）

1. 重写 `scripts/verify/data-ownership.ts`（约 200 行），规则：
   - 扫 `apps/`、`packages/` 下的运行代码（不含 `.d.ts`、`node_modules`、构建产物），先抹掉注释；
   - 取 `FROM`、`JOIN`、`INTO`、`UPDATE`、`DELETE FROM`、`TRUNCATE`、`REFERENCES`、`CREATE TABLE`、`CREATE INDEX … ON` 等关键字后面的表名；不在授权目录里的名字（CTE、别名、函数）不算；
   - 一个文件属于哪个模块，看它唯一的 `dbOf("…")`；没有或有多个，记为 `?`；
   - 表归谁，读 `database/roles/table-grants.json`（与旧映射的 53 张表一致）；`public.settings` 按键归属（附录 B.7.2 的 8 条规则）；
   - 本模块的表不算；publication 读白名单里的读模型表不算；其余每处给（模块，表）计数加一；
   - 运行时拼出的表名与经变量传入的整段 SQL 只列在阶段日志里，不计数、不冻结；
   - 计数存在 `data-ownership-baseline.json`（`version: 2`），`--write` 生成。以下情况失败：任一计数比 base 的大；存的计数与现状不符；文件不是 version 2；与 base 比，读模型白名单变宽、settings 规则改了、已有表换了归属。base 上没有 version 2 文件时（只有本卡这一个 PR），只跳过与 base 的比较；
   - 保留 `checkCatalogue`：迁移建的表都在授权目录里，目录里的表都有人建；模块迁移只写、只建本模块的表（同时满足 TASK-0020 卡第 135 行要的迁移写权检查）。
2. 映射文件只留 publication 的读模型白名单与 settings 的 8 条键规则；其余（表归属、别名、外部表、退役键、存储文件、拆分文件、授权目录指纹）删去。
3. `run.ts` 接线改 4 处左右，阶段名、位置与 `quick: true` 不变；`package.json` 的 `check:data-ownership` 不变。
4. 测试重写为 5 个：本模块与读模型不计数；新增跨模块读写失败；AC-M0-02 当时记录的那条故意违规（同一文件、同一查询）仍然失败；迁移写别的模块的表被报出；白名单变宽、归属变化、版本缺失、计数过期都失败。
5. 删除 31 个只服务旧检查的文件（10 个模块、11 个测试、10 个夹具，共 4,009 行），删除后没有任何文件再引用它们（自测与 `tsc -p scripts` 证明）。

- 只改检查脚本，不改产品代码、数据库、授权目录、契约、`package.json` 与锁文件；读者看不到变化，不附产品更新片段。
