## 背景（为什么做）

1. **回滚只回代码不回表结构**。`deploy/production-release.sh` 的 `restore()`（第 159-179 行）放回镜像、程序和 `.env`，不恢复数据库。这样做是对的：自动还原数据库会丢掉发布期间的新数据。但它的前提是“迁移只增不破”（规则文件第 3 节第 10 条），而这条规则没有自动检查：`scripts/verify/migration-sql.ts` 只查归属，不查兼容。已合并的迁移里就有 `ALTER COLUMN … TYPE`（`0028_selectbench_mean_score.sql:3`）。新代码一旦带上破坏性迁移又激活失败，就会回到“旧代码配新表结构”。
2. **worker 没确认跑稳就解除了回滚**。第 359-362 行起 worker 后只看一次 `.State.Running == true`，第 369 行就 `trap - EXIT`。worker 启动几秒后崩溃、反复重启，也会被记为 `deployed_origin_verified`；采集和模型任务全停，网站看起来却是好的。

## 交付内容（做什么）

1. **迁移检查**：在 `scripts/verify/migration-sql.ts` 的现有扫描里，对本次新增的迁移文件（`database/migrations/**`、`modules/*/migrations/**`）拒绝下列语句：
   - `DROP TABLE`、`DROP COLUMN`、`DROP SCHEMA`
   - `ALTER COLUMN … TYPE`、`ALTER COLUMN … SET NOT NULL`
   - `RENAME COLUMN`、`ALTER TABLE … RENAME TO`
   
   例外：文件里有一行 `-- contract-phase: ADR-nnnn`，且 `docs/04-architecture/adr/` 下有这份 ADR，就放行（先扩后收的“收”那一步）。报错信息写明文件、行号和语句，以及怎么改成只增的做法（加新列、双写、回填、下一版再删）。
   测试覆盖：每种被拒的语句各一条；带标记且 ADR 存在时放行；带标记但 ADR 不存在时仍拒；`CREATE TABLE … (… NOT NULL …)` 这类新表里的 NOT NULL 不误报。
2. **发布脚本的 worker 就绪检查**：在 `production-release.sh` 第 362 行之后、`phase deployed_origin_verified` 之前，最多等 180 秒，满足以下两条才往下走，否则让脚本失败，由现有的 EXIT trap 回滚：
   - 连续 60 秒内 `docker inspect --format '{{.RestartCount}}' amp-worker-1` 保持为 0，且 `.State.Running` 为 true；
   - 数据库 `settings` 表里 `heartbeat.worker` 这一行的 `value->>'release'` 等于 `$RELEASE_ID`。worker 启动时会立即写一次心跳（`packages/backend/src/operations/heartbeat.ts:7-17`，`apps/worker/src/main.ts:33`）。用脚本里现有的写法查：`docker exec amp-db-1 psql -X -q -A -t -v ON_ERROR_STOP=1 -U amp -d amp -c "…"`。
   每一步写进脚本现有的日志或阶段记录。
3. `docs/runbooks/release-retention.md` 或发布手册里补一句：发布在 worker 连续 60 秒不重启、并写出本版心跳后才算激活成功。

代码量预算：检查约 40 行，测试约 60 行；发布脚本约 25 行。
