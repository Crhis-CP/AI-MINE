Owner 2026-11-05：“法规政策动态这个严重要优化，非常不直观不方便去找到我想要的，不是说去检索，而是应该像卡片或者更好的UI层层去检索。”

## 做法

- **第一层 `/policies`：**国家和组织卡片，分“目标国家”“跨国与国际组织”两组。每张卡片有代码标记、可读文书数，以及该国在列表第一页里最新一份的日期和标题。没有文书的国家排在最后、变淡、不可点。卡片下面是最新 5 份文书和“查看全部 N 份文书 →”。
- **第二层 `?jurisdiction=CL`：**面包屑“法规政策动态 › 智利”，“全部主题”卡片加 7 个经营主题卡片和数量，注明一份文书可能计入多个主题，下面是该国最新 3 份文书。数量来自现有列表接口，服务端并行最多 8 次；某个数量取不到就不显示，数量为 0 的主题变淡、不可点。
- **第三层 `?jurisdiction=CL&theme=mineral_rights`：**完整面包屑，文书性质和制定阶段用横向滑动的切换条，然后是文书卡片和分页。原来的表单收进“高级筛选（日期范围与组合条件）”，有日期或参数无效时自动展开。
- **“全部主题”：**网页端新增 `theme=all`，有自己的地址；请求接口前去掉，不带到法规解读、周报、月报。
- **搜索：**桌面在右上角，手机点放大镜展开；沿用 `q`，在当前国家和主题内搜索。
- `apps/web/extension.ts` 向模块导出 `PillTabs`、`IconSearch`、`IconChevronRight`。演示 API 按国家、主题、性质、阶段、关键词和分页筛选。

## 不做

- 接口、契约和后端不变。
- 周报、月报页仍用原来的下拉筛选。

## 验证

- 类型检查和网页构建通过；`policy-browser`、`cache` 测试通过。新增逐层点选测试，覆盖 1440 和 390：两组标题、空国家不可点、主题数量、取不到的数量隐藏、性质切换缩小结果、返回与面包屑、无横向溢出。
- 演示 API 截图核对三层的桌面、手机和深色。
