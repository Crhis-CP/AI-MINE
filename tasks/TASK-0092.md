## 背景（为什么做）

结论：法规政策动态要从各国官方网站自动取得新发布的法律、法规、政令和正式政策文件。Owner 2026-10-08 13:47Z 给了一份 34 国及欧盟、156 条的官方信源表（GPT 整理），要求“在他基础上优化”，并“看看怎么去接到网站上”。本卡把这份表逐条核对后放进行业包，作为法规线信源的唯一来源；TASK-0094 按它建信源、开始采集（TASK-0093 先把信源分成资讯、法规两条线）。

核对的办法：每条信源都打开官网看过，找到“按时间列出新发布文书”的那一页（或官方 RSS、官方开放数据接口），用项目里真实的采集代码空跑一遍（不入库）确认能取到标题、链接和日期；再从我们的服务器（上海）测一次能不能直连。数据库检索页、整部法规汇编、网站首页换成该机关自己的“最新文件”列表；同一份文书在两个渠道都发的，标出哪个是主渠道（F-046 的“核心 / 补充 / 参考 / 重复渠道”）。项目里另一个线程同一天在境外网络逐条核实过（先读 robots、礼貌访问），还读了每个网站的使用条款；两边对不上的，以那份核实报告为准（例如 RU-003、RS-002、ID-002 的网址是它更正过的），作者再从上海服务器空跑一次。

## 交付内容（做什么）

1. `industry/policy-sources.json`：156 条（按 Biome 的 JSON 格式写，预计两千行以上；数据表不计入“有效改动 ≤400 行”，见 `docs/06-agents/01-parallel-development-rules.md` 第 175 行，PR 里按第 372 行第 11 条说明巨型文件），编号沿用 Owner 表里的 `source_id`（如 `CN-004`），不重编。每条：
   - 身份：`jurisdiction`（法域代码）、`level`（国家 / 地方 / 超国家）、`subdivision`、`authority`（中文与原文）、`name`（中文与原文）、`type`（官方公报 / 法律法规数据库 / 矿业规范栏目 / 相关领域法规栏目 / 地方规范栏目 / 正式政策栏目）、`identity`（Owner 表的官方身份结论与依据链接，原样保留）。
   - 角色：`role` 为 `core`（核心）、`supplement`（补充）、`reference`（参考：整部法规汇编、检索库，只用来查原文，不当新文书来源）、`duplicate`（重复渠道，带 `duplicate_of`）。
   - 入口：`listed_url`（Owner 表原链接）与 `entry`（核对后用的链接；换了的写明原因）。
   - 采集：`collect` 为 `{ kind, config }`（`rss` / `web_list` / `json_list`，键名与新闻信源完全一样，过 `assertSupportedConfig`）；没有可用配置的为 `null`。
   - 状态 `status`：`ready`（直连可采，已空跑验证）、`needs_reader`（要经网页读取服务渲染，才看得到列表）、`needs_overseas`（从上海服务器直连超时或被拒，境外可正常打开，要境外线路）、`blocked`（暂不采：官网有防机器人拦截或需要登录；条款禁止自动采集或 AI 处理；要服务器信任别国的国家根证书；服务器没发中间证书。`notes` 写明是哪一种）、`reference_only`（参考渠道，不采新文书）、`identity_pending`（官方身份待核实，不采）。
   - 条款 `terms`（照核实报告读到的网站使用条款）：`open`（公有领域或开放许可，明确允许翻译转载）、`reuse`（允许转载原文，没写能否翻译）、`exempt`（网站没写，按该国著作权法官方文本不受保护）、`restricted`（限制、不明、只许非商业使用或禁止演绎）、`no_automation`（禁止自动采集或 AI 处理）。哪些显示中文全文由 Owner 定（集成人选择卡片的 D2，不回复按只给 `open`），TASK-0094 据此写全文许可；`no_automation` 的一律 `blocked`（D4，不回复按不接）。
   - 暂缓 `hold`：能采、但现在还不该启用的中文原因，没有为 `null`。例如 robots 写了 Crawl-delay（新加坡法规在线 6 秒、gov.sr 60 秒等），要等同主机限速（集成人的 TASK-0107）上线；条款只许北京时间 03:00–07:00 自动抓取（新加坡法规在线），要等采集能按时段排。原因解除后改这一项即可，不用改代码。
   - 其他：`language`（BCP47）、`detail_format`（文书全文在网页里、在带文字层的 PDF 里、还是只有扫描件）、`themes`（Owner 表的主题标签对到七个经营主题键，能源不单列）、`notes`（中文说明，写给集成人与日后维护的人）。
2. `industry/policy-sources.ts`：纯数据入口（不读文件系统、不连库），导出冻结的 `POLICY_SOURCES` 与类型，供 TASK-0094 的初始化脚本和覆盖说明使用；`industry/package.json` 加 `"./policy-sources"` 一行导出。
3. `tests/policy-sources.test.ts`：
   - 156 条，`id` 唯一，与 Owner 表一一对应（编号集合相等）。
   - 每条的 `jurisdiction` 都在法域字典的法规范围里（`POLICY_JURISDICTIONS`）；唯一例外是 `identity_pending` 的条目（ER-001 厄立特里亚：字典里还没有这个国家，身份也待核实，先不采）。
   - 枚举值合法（`level`、`type`、`role`、`status`、`terms`、`themes` 只能是七个主题键）；`duplicate` 必有存在的 `duplicate_of`；`ready`、`needs_reader`、`needs_overseas` 必有 `collect`，其余不得有；`terms = no_automation` 的必须 `blocked`；`hold` 是非空中文或 `null`。
   - 每个 `collect.config` 都过 `assertSupportedConfig`，且都声明了 `language`；`needs_reader` 的入口经网页读取服务，其余的不经。
   - 按状态计数打印在测试名里，便于审查时一眼看到“现在能采多少”。
