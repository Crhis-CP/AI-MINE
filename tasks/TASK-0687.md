## 交付内容（做什么）

1. **转发**（`server.ts:268-276`）改为：
   ```ts
   import { pipeline } from "node:stream";
   const upstream = httpRequest({ hostname: target.hostname, port: target.port, path: raw, method: req.method, headers, timeout: 60_000 }, (up) => {
     res.writeHead(up.statusCode ?? 502, up.headers);
     pipeline(up, res, () => {});
   });
   upstream.on("timeout", () => upstream.destroy(new Error("api idle timeout")));
   res.on("close", () => { if (!res.writableFinished) upstream.destroy(); });
   upstream.on("error", () => { if (res.headersSent) res.destroy(); else { res.statusCode = 502; res.end("api unavailable"); } });
   pipeline(req, upstream, () => {});
   ```
   `timeout` 是套接字**空闲**超时。MCP 长连接每 15 秒发一次保活（`mcp.ts:488` 的注释），不会被误切。
2. **静态文件**（`server.ts:129`）：`pipeline(createReadStream(file), res, (error) => { if (error) res.destroy(error); });`
3. **构建资源未命中**：`buildAsset(pathname)` 为真时只走静态文件；找不到就直接返回 `404`，`Content-Type: text/plain; charset=utf-8`、`Cache-Control: no-store`、正文 `Not found`，不进入整页渲染。
4. **只信任来自内网对端的 X-Forwarded-For**（`request-guard.ts:184`）：
   `const last = forwarded.at(-1); const address = trustProxy && last && privateAddress(peer) && isIP(last) ? last : peer;`（`isIP` 来自 `node:net`）。

测试，在现有两份测试文件里加：读者在 api 还没响应完时断开 → api 测试桩看到连接关闭（断言 1 秒内）；api 空闲超过超时 → web 返回或断开且不残留连接（测试里把超时调成可注入的小值）；`GET /assets/不存在.js` 返回 404 且不调用渲染；`TRUST_PROXY=true` 时来自公网对端的 X-Forwarded-For 被忽略。
