Owner 2026-11-05：“法规解读的代码也要好好做。”任务书 v2 对法规页的要求是生命周期、日期日历、逐条对照。

## 做法

- **代码：**`modules/policy/web/policy.tsx` 从 456 行减到约 160 行，只管读取和版本核对；页面各部分移到新文件 `features/PolicyDetail.tsx`（工具条、目录、基础事实、一眼看懂、阅读状态、重点解读、法律状态、待核实、证据、关联、页脚），每部分只接收解析后的 `Policy`。
- **日期日历（任务书 §5）：**`policyCalendar()` 取公布、施行、过渡期与截止三项；文件处于拟议或征求意见阶段时，第一项换成征求意见截止。日期只取原文记录，没有的显示“未知”。
- **一眼看懂：**日期日历下面列影响方面（主题）、涉及谁（受影响主体）和日历之外的其他关键日期；都取自下方已有字段，不新增解读。
- **工具条：**收藏、政策脉络、版本记录、复制链接、查看官方原文统一成一排药丸按钮，手机上横向滑动；返回链接不再折行。
- **手机跳转：**侧栏目录只在大屏显示，小屏新增一排跳转按钮，跳到基础事实、重点解读、法律状态、正文和证据（无完整解读时不出现“重点解读”）。
- **日期改表格：**公布与变化记录、施行安排、适用范围、截止要求改为“日期｜事项”两列。
- **主要条款**加序号和条款号标签；**经营影响**的字段在手机上也是两列，先写受影响主体、经营活动、条件，再写区域和法定主体；**原文证据**被锚点跳到时高亮。

## 不做

- **逐条对照（redline）：**新旧版本按条款对齐需要后端在入库时做确定性比对并提供接口，属于法规线重启（DEC-71 暂停仍有效），本卡不做。
- 接口和契约不变。

## 验证

- 网页类型检查和构建通过；`policy-browser`、`cache` 测试 42 项通过（`cache` 中“来源发布日期：”的断言改为匹配标签本身，冒号随新版式去掉）。
- 演示 API 截图核对桌面与手机：完整解读文书和征求意见稿两种情况。
