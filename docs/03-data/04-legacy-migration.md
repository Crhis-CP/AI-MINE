## 2. 旧链接、旧 RSS 与旧接口：全部不做兼容（DEC-21；【Owner 决定】2026-10-01）

> **决定**（Owner 2026-10-01）：“旧文章链接也全都不要，相当于从 0 开始做文章内容。”——新站**不为旧站的任何地址做兼容、重定向或专门的说明页**：没有旧链接对照表，没有 301 映射，没有“本站已改版”专页，没有旧接口适配期。v2.0 的“逐条 301 + 旧机器接口 90 天适配期”随之取消。新站只有自己的路由与接口；本节没有需要在入口层配置的映射，也没有需要在预发环境演练的处置项。

### 2.1 规则（只有这几条）

| 对象 | 处理 |
|---|---|
| 新站不存在的地址：旧站的条目、事件、故事、报告页面与修订，旧栏目路径，旧 RSS，旧 `/api/v1/*`、`/api/v2/*` 机器接口，以及任何其他不存在的路径 | **一律 404**。页面类地址走新站通用的“页面不存在”页（`01-product/03-reader-pages.md` PG-17，带首页与搜索入口，响应不带 Set-Cookie）；接口类地址返回统一错误体 `not_found`（`03-data/02-public-api-contract.md` §2.7、§5.1）。**不重定向**（不带 `Location`），不猜测对应内容，不按形似旧 ID 的字符串去查新对象，不为旧地址返回专门的状态码、说明页或迁移响应头（`Deprecation`、`Sunset`、`Link`） |
| 新公开 API 前缀 | **`/api/v3`**：只为避免旧客户端打到同名路径拿到形状不同的响应，**不承担任何兼容义务**；旧站在全面切换前仍在线的 `/api/v1/*`、`/api/v2/*` 与它不相撞 |
| 订阅地址（RSS） | 新站只有自己的订阅地址（见 `01-product/05-external-interfaces.md`）；旧 RSS 地址在新站不存在，按第一行 404，订阅者须自行订阅新地址；新站条目的 RSS `guid` 用新站自己的公开 ID，不做 `guid` 兼容 |
| 浏览器里的旧本地收藏与旧外观设置 | 新站**忽略，不报错**（不解析旧 ID，不迁移，不弹提示；PG-10） |
| 公开 ID | **一经发出永不复用**（INV-18、T-107）：这是新站自身的规则，与旧站无关；新对象 ID 的格式见 `01-domain-model.md` §1 |

### 2.2 说明

- **没有任何需要为旧站地址写的代码或配置**：不建对照表、不写重定向规则、不做静态说明页、不加旧接口适配层、不设响应头；访问旧地址与访问任何其他不存在的地址完全一样。旧站的数据库、日志与页面不被新站读取（§1.3）。
- **影响如实写明（不是缺陷）**：切换后，旧站文章、事件、报告的外部链接（搜索引擎、第三方引用、读者书签）、旧 RSS 订阅与旧接口调用方都会得到 404。新站的内容从空库重新采集生成（§1.1），本来就没有对应页面；Owner 如需提前知会老读者与集成方，用站外渠道自行通知，新站不为此增加页面或响应。
- **新站上线当天旧站停止服务**（不保留只读，§9）；此后旧站的地址在新站眼里同样只是不存在的地址。
- 旧站公开写过的“V1、V2 接口继续兼容”的承诺，由 Owner 的全重做决定取代（DEC-21）。
- **验收**：对旧站公开地址的样本（条目、事件、故事、报告、栏目路径、旧 RSS、旧机器接口路径，清单见 T-107）逐条请求，全部是通用 404，没有重定向、说明页与适配响应头；公开 ID 不复用；旧本地收藏被忽略且不报错（AC-MIG-02、T-107、AC-OPS-15、AC-M1-12）。

| # | 步骤 | 说明 | 里程碑 |

## 9. 切换步骤与旧站下线（全面切换；旧站当天停止服务，不回写数据）

新站**全部排期功能**完成并通过各自验收后，**一次性全面切换**（Owner 2026-10-01，DEC-19）。“全部排期功能”= 功能全集中除“候选（不排期）”以外的全部功能：资讯线、法规线、事件、精选与热点、报告、主题、搜索、收藏、对外出口（API、RSS、MCP 等）、最小私有页面、告警。切换前旧站照常服务，新旧两站互不依赖、互不写数据（各有自己的数据库与运行环境，新站的模型密钥由 Owner 另行录入）。

1. **切换门槛**（缺一不得切换；T-159、AC-M1-21）：①全部排期功能验收通过——含切换当天条目页的“相关报道”“事件进展”、日报周报月报必须有，以及精选与热点的校准记录（留出集检查，BR-SEL-08）与矿业版评分标准的 Owner 审阅确认记录（BR-SEL-09）；②影子运行通过；③恢复演练一次；④告警渠道就绪；⑤Owner 在真实公网与手机上逐项看过。**没有“旧数据导入对账”这一项。**
2. **法规线计入门槛的方式**：页面与管线的功能完成并通过验收场景即可；覆盖度（36 个法域的研究、取得、中文、解读、持续运行）在台账里如实展示并持续推进，**不以 36 个法域全部供稿为切换门槛**；完整解读仍按“法域 × 文书类型”抽检通过后分组开放（DEC-15）。此前“法规栏目不作切换门槛”的说法作废。
3. **入口预演**：在预发环境演练入口层切换（AC-OPS-09），并核对 §2 的唯一规则：不存在的地址（含旧站地址样本）返回通用 404，没有重定向与说明页（AC-OPS-15、T-107）；没有旧链接映射需要预演。
4. **切换**（M5）：入口层一次性切到新站，并从主机之外读回发布标识头确认；登记一条产品更新（新站这次记为“重大更新 2.0”，Owner 2026-10-05，TASK-0038；普通的更新日志条目）。切换不带任何旧地址处置（§2）。切换时点与步骤见 `04-architecture/07-deployment-and-ops.md` 的切换一节。切换窗口内、发布标识读回之前出问题（新栈起不来、入口验证没过），中止切换：新栈回到私有预览，旧站照常服务（同机切换停新栈、原样启动旧栈，换机切换时 DNS 留在或指回旧主机），切换改期；旧站已按 Q-56 确认停用的（§9.1），只是新栈回到私有预览、切换改期。
5. **旧站当天停止服务**（Owner 2026-10-03 更正裁决表 DEC-19：「旧站只读不保留」）：新站读回成功、记为已上线后，旧站停止对外服务与 worker，不再启动；不保留只读，也不切回旧站。切换后出问题只在新站内处理：撤回公开入口，或代码、内容指针、数据三类回退（`04-architecture/07-deployment-and-ops.md` 3.2、4.3）。新旧两站之间**不回写数据**（T-143 已废弃）；AC-MIG-12 已废弃。
6. **观察**：切换后 24 小时与 7 天观察（`05-quality/04-acceptance-criteria.md`）。
7. **旧站退役**：切换完成后按 `07-deployment-and-ops.md` 第 8 节退役——先撤销旧站的凭据与访问入口（凭据清单，AC-OPS-11），再回收旧栈与销毁数据（各步须 Owner 逐项授权）；旧站的数据库快照是否保留、保留多久由 Owner 决定（不在仓库内，新站从不读取它）；旧站的地址在新站眼里仍只是不存在的地址（§2，404），旧价格表等旧站维护事项随旧站关闭。

### 9.1 旧站过渡期维护事项（写入上线 / 切换检查表；Q-56 不变）

- **旧站模型价格表 2026-10-13 到期**：旧站 `config/live/pipeline.json` 的 `pricing_observed_at` = 2026-09-13、`pricing_valid_until` = 2026-10-13（`:11-12@main`），过期后 `model_prices()` 抛 `model_pricing_review_due`，旧站**新的付费调用全部被拒**（`services/live_pipeline/config.py:285-294@main`）。旧站在全面切换前仍需正常运行，所以 **2026-10-13 前**须按服务商现价更新这两个字段并走旧站正式发布；或确认旧站届时已停用 / 只读。此后每 ≤45 天复核一次，直到旧站退役；由旧站现有维护者执行，是否继续对外服务见 Q-56（详见 `02-rules/05-cost-and-budget.md` §5）。新系统用价格表实体 ENT-81 与到期告警避免同类事故。
- 切换日若旧站已停用，则该项在检查表中标“已确认停用”并关闭。
