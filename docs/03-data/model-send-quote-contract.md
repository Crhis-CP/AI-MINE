# 实际发送的只读报价（TASK-0652）

`providers/llm`的`beforeRequest(context?)`兼容旧无参守卫，用只读旁路信息支持实验自己的费用上限，不改变默认生产准入。

- `prepare`只表示既有许可预检查；`send`在本次实际发送前携带receipt/attempt、service/model、非秘密配置身份和请求指纹。免费复用不触发新的send准入，包装的许可守卫仍先执行。
- `send.quote`给出CNY价ID/版本/冻结时刻、预留微元和输入输出硬界；有效零价有明确quote，缺报价用null，不补0。上下文与嵌套报价只读，不含key、密钥指纹、prompt/正文或响应。
- 预留来自同attempt的authorizeUsageSend冻结结果；峰谷重算先完成，沿用原已接受价格版本。实际body的prefix/extra/think限制及已登记协议余量继续由既有引擎计价，脚本不重建价格算法。
- 价/请求绑定不一致、报价失效或请求选项无法证明单次上界时，quote为空并带固定issue码。旧守卫可忽略此信息，新实验应在发送前拒绝；不增加全站金额门槛。
- 发送守卫拒绝沿现有明确未发送路径记failed并释放预留；原金额保持未记而非伪造供应商零元账单，不计未知扣费。不修改请求字节、逻辑键、缓存或未知恢复语义。
