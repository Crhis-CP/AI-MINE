# 开工前必读：当前最常犯的错（≤60 行）

由定期整理维护（流程：`README.md`）。每条一句话，细节和证据看对应 PIT（`docs/05-quality/02-pitfalls.md`）。
上次整理：2026-11-07（TASK-0581，首次）。

## 提交与 CI
1. 改动文件必须在 **main 上**任务卡的 `allowed_paths` 里；要加路径，先合一个只改任务卡的 PR。（PIT-108）
2. 改契约的，契约单独一个 PR，合并后再开实现 PR。（PIT-113）
3. PR 描述按模板写，必须有“- 任务卡：TASK-nnnn”。（PIT-114）
4. 新增路由或读者端写请求前，先搜写死清单的自检（`scripts/verify/tests/`、`e2e/`），同一 PR 一起改。（PIT-115）
5. 修问题按类修（举一反三），并加防复发测试；同一问题第二次修必须补自动检查。（AGENTS.md 完成的定义；并行规则第 13 条）

## 交接与汇报
6. 交接里的 SQL 先跑 `scripts/check-handoff-sql.ts`；时间段、限额等数字写代码出处。（PIT-109）
7. 验收用到的数字，先在代码里确认它统计的是什么，再定标准。（PIT-110）
8. 估算只写“范围 + 假设 + 未知项”，不承诺上限或“实际更低”。（PIT-111）
9. 不编造 SHA、表名或结果；没核实的写“未核实”。

## 付费与运行
10. 批量付费任务同时估请求次数，对比每小时、每天的共用额度；后台任务给核心步骤留额度。（PIT-112）
11. 会改许可、花钱或删数据的写操作，先预演，再按 Owner 授权执行；Codex 执行前核对授权范围。

## 冲突
12. 和 Owner 决定冲突：拿给 Owner 决定（附证据和建议），决定前维持现状，有风险的先停。技术冲突：按证据裁决，新的核实过的经验取代旧的。（README“冲突怎么判”）
