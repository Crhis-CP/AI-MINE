# 测试标准

> 目标：让多个 Agent 并行修改时，“有没有改坏”由机器快速、确定地回答；让“真的能用”由真实环境证据回答。两者分开，不能互相替代。
> 旧项目的教训：大量测试证明了“离线合成数据上的行为”，却被当成上线与质量的证据；同时关键的真实运行（持续供稿、下架全出口、读者体验）缺少自动验证。新项目把测试分成六层，每层回答不同的问题。
> **v2.0 的五处变化**：①集成测试的数据库写成接口（`DATABASE_URL` 指向一次性库，由执行器提供），不再以 Docker 或 testcontainers 为硬前提（§1）；②测试夹具统一为三类，**不把第三方页面与政府文书原文放进 Git**（§3）；③验证与发布不依赖 GitHub Actions：统一入口 `make verify`，结果以“绑定完整提交的验证回执”为准，生产只接受签名制品（§5，旧ADR-0038、ADR-0017）；④验证入口只用假模型与已缓存回执，真实模型评测是显式任务、只用最小必要样本（§5）；⑤AIHOT 的 35 + 5 个测试文件按处置表引入，其中与不变行为相反的断言必须先改后用（§7），旧站 13 份 E2E 规格里验证过的断言按清单改写为新项目用例（§8；只取断言描述，不从旧仓库复制规格文件）。
> **v2.1 的变化（Owner 2026-10-01 答复）**：①真实模型评测不设金额上限，只用最小必要样本，费用按“评测”用途记入用量账本并受异常熔断保护（§1、§5.4）；②精选与热点按 AIHOT 机制矿业化后随全面切换上线，扫描清单与冒烟集改验“分数展示规则”“热点只给名次”，不再验“暂未启用”（§1.1、§4）；③页脚冒烟含公安联网备案号与新闻许可证编号（§4）；④旧 E2E 规格只作断言清单、不导入旧仓库文件；新站不为旧站的任何地址做兼容，旧站的页面、RSS 与接口地址一律 404（§8）；⑤追加（Owner 补充答复）：分数展示规则写准 AIHOT 的显示（“AI 评分 · NN”、手机只显示数字、85/70 分色、无评分什么都不显示）并加“矿业版评分标准经 Owner 审阅确认才可用于正式站精选”的关卡（§1.1、§4、§7，T-160）；日报、周报、月报的选材与出刊时间都沿用 AIHOT（取自精选候选；日报 08:00、周报周一 10:00、月报 1 日 10:30 出刊，§7、§8，DEC-65）；异常熔断前有 70% 预警（§8 的 OP-13 断言）。

## 1. 六层测试

| 层 | 回答的问题 | 范围与工具 | 运行时机 | 外部依赖 |
|---|---|---|---|---|
| **L1 单元** | 业务规则写对了吗？ | 各模块 `src/domain/` 纯函数；`node:test` | 每个 PR（受影响工作区） | 无 |
| **L2 模块集成** | 模块在真实数据库上行为正确吗？ | 任务处理器、存储、事件发布；**`DATABASE_URL` 指向一次性 `*_test`/`*_ci` 数据库**（沿用 AIHOT `tests/setup.ts` 的守卫：库名不以 `_test` 或 `_ci` 结尾即拒绝运行）；数据库由执行器提供，本机服务、服务容器或 testcontainers 均可；每个测试文件用 `CREATE DATABASE … TEMPLATE` 从已迁移的模板库克隆，去掉 AIHOT 的串行限制；假模型服务；自编夹具与许可内回放（§3） | 每个 PR（受影响工作区） | 一个 PostgreSQL 18（来源不限） |
| **L3 契约与产物扫描** | 接口和事件有没有被悄悄改坏？密钥有没有进产物？ | Zod → OpenAPI 3.1 生成物无漂移（干净克隆逐字节一致）、破坏性变更检测、公开响应敏感字段扫描、事件 fixture 双向校验；**密钥扫描**（PR 差异）与**依赖审计**、前端产物与镜像层扫描（工具与版本见 `04-architecture/02-tech-stack.md` 7.2）；公开产物的私有路由、品牌、分数展示规则、文本门禁与字体缺字扫描（§1.1） | 每个 PR | 无 |
| **L4 端到端** | 读者和私有操作的关键路径能走通吗？ | Playwright：桌面（1440×1000，另测 1024）与手机（390×844，另测 320）视口，深色与浅色，200% 缩放；axe（WCAG 2.2 AA）；键盘旅程；关键页面截图对比——**视觉差异须人工审查，不批量更新基线**（旧 `docs/testing-strategy.md:361-363@main`）；种子数据 + 假模型；只对生产构建运行 | 每个 PR 跑冒烟集（§4）；每晚（`make nightly`）跑全集 | 浏览器依赖 |
| **L5 AI 评测** | AI 能力的质量达标吗？ | 每个能力的黄金集（开发/留出）；指标见 `05-evaluation-sets.md`；真实模型 + 回执缓存复用。**只由显式评测任务触发**（任务卡写明样本范围与调用次数 `budget.model_calls`，只用最小必要样本，不设金额上限；在专用环境执行），不在 PR 验证入口、不在夜间任务里 | 改提示词、门槛、模型的任务；发布前留出集；首轮冒烟每能力 50 例（最小必要样本）；精选的校准与全面切换前的留出集检查见 AC-M2-03（矿业版评分标准是草案，须经 Owner 审阅确认后才能用于正式站精选，T-160） | 真实模型（无金额上限；费用按“评测”用途记入用量账本，受异常熔断保护） |
| **L6 环境验收** | 在真实环境里真的在运转吗？ | 部署后冒烟、持续供稿观察（24 小时、7 天）、资源与成本观测、真实浏览器与手机检查、备份恢复与回滚演练 | 每次部署后；里程碑验收 | 目标环境（预发或生产） |

**规则**：

- L1–L4 不访问外部网络与真实模型；L5 只在声明了样本范围与调用次数（`budget.model_calls`）的显式评测任务中访问真实模型；L6 的结论只来自真实环境，不能用 L1–L5 的结果代替。
- 验证入口（`make verify`）= L1 + L2 + L3 + L4 冒烟集 + 文档与编号检查，**不含 L5、L6**。
- 本机缺 Docker、PostgreSQL、浏览器或固定版本工具时继续失败关闭，不安装或修复全局工具；只能出具 `scope: focused` 的回执，标为补充（supplemental），**不得用于合并，也不得宣称完整通过**（旧 `docs/testing-strategy.md:17@main`；旧分支最近一次本地全门禁正是 `blocked_docker_unavailable`，`docs/policy-upgrade/acceptance/ci-20260926.json:12@policy`）。执行器不可用时换执行器，不跳过检查（ADR-0017）。“不得用于合并”在 M0 期间有一个例外，见 ADR-0017 的 2026-10-03 更新（08-owner-voice DEC-24 ②）。
- 每个场景的层、级与 INV 见 `06-acceptance-scenarios.md`；每条 INV 的主守护层见 `01-invariants.md` §4。

## 3. 测试数据与替身

- **假模型服务**（`packages/testkit`）：按能力返回预置响应；可模拟超时、截断、非法结构、429/5xx、“结果未知”；记录调用次数用于断言“没有调用模型”。验证入口里执行器不持有任何模型密钥。
- **夹具分三类**（取代 v1.0 的“录制的信源响应”（把真实页面录制后放进测试目录）——它与 `05-evaluation-sets.md` 禁止第三方全文、网页快照、原始 HTML 进 Git 的规则自相矛盾，旧仓库只用“固定且可合法保存的 fixture”，`docs/testing-strategy.md:257@main`；抓取成功不等于允许保存，许可逐来源逐用途）：

  | 类别 | 内容 | 放在哪里 | 例子 |
  |---|---|---|---|
  | ① 自编（`SELF_AUTHORED`） | 保留真实页面的结构与陷阱（分页、置顶旧文、验证页、仅日期、PDF 链接、GBK 编码、否定与脚注、同名不同实体、恶意指令），**内容自写**，链接用 `example.invalid` | 仓库测试目录 | 政府网站平台族的最小复现页；带 `<script>` 的恶意正文 |
  | ② 许可允许保存的短事实 | 许可明确允许保存的结构化短事实 | 仓库测试目录 | 许可说明、法域字典片段 |
  | ③ 许可范围内的真实材料引用 | 只存修订 ID、字节哈希、许可依据与回执；**正文放私有制品库，不进 Git** | 私有制品库 + 仓库中的指针 | 联邦公报 PDF 的压力样本（只存 URL 与哈希） |

  适配器最低测试 = ①自编复现页 + ③私有真实回放（只在有许可的来源上做，并保留失败原件的哈希，不只收“好处理”的样例）。允许把脱敏的真实网络结果作为仓库证据，但不含响应正文、新闻标题、解析条目、公网 IP（旧 `docs/testing-strategy.md:245@main`）。“去除个人信息”解决不了版权问题，不作为入库理由。
- **固定时钟**：所有时间相关测试注入时钟，覆盖北京时间日界、周界、月界（报告 08:00 边界、月度用量报告与每 100 元用量提示的月界）、法域当地日历日、来源时区的夏令时。测试不得读取系统时间与随机源（`pit-checks`）。
- **语言识别夹具**（自编，来源未声明语言）：日文稿（含汉字，不得当作中文原稿）、繁体中文稿（按中文处理，标题转简体并并列繁体原标题，DR-36）、波斯语稿与希腊语稿（非拉丁文字，必须识别为有可译文字）、中英混排稿（按主要语言判定）、无法判定的稿件（标“未识别”，阻止进入翻译与公开）。用于 T-022 与 AIHOT `translate.test.ts` 的改造（§7）；评测集样本见 `05-evaluation-sets.md` 的“语言识别”行（02-rules/03-ai-capabilities.md R-03）。
- **种子数据**：E2E 使用的最小业务数据集（若干信源、材料、事件、报告、法规文书、下架记录），由脚本生成，**绝不在生产代码路径中加载**（INV-09）。
- **并发与崩溃**：在预留、发出、回执、入库、提交等精确点杀进程、重复投递、延迟与网络失败（T-071、T-074）。

## 4. 端到端关键场景（L4 冒烟集，每个 PR 运行）

A 包的 10 条冒烟场景保留，并按 v2.0 改写、补齐。#7–#9 对**私有入口**执行（没有“运营台”，D16-quality-001）。

当前 `e2e/smoke.spec.ts` 是这张清单的首个生产浏览器子集：1440×1000 与 390×844，公开空态搜索/全文相关切换、公开及错误 Host 拒绝私有页面、伪造转发头不能访问私有 API、私有登录页可达且不缓存、键盘焦点、无水平溢出、WCAG 2.2 AA 的 critical/serious 违规为零。其余场景仍按表补齐，不把此子集称为完整 L4 验收。

- `pnpm e2e` 先构建公私生产产物再运行；`verify` 的 `e2e-smoke` 在 `build-web` 后复用产物。`pnpm e2e:smoke` 缺构建或浏览器时直接失败，禁止跳过或下载浏览器。
- Playwright 固定 1.63.0、axe 适配器固定 4.13.0；优先已有 Chrome，可用 `E2E_BROWSER_PATH` 指定现有可执行文件。实际版本记录在测试输出，不能以工具清单替代执行证据。
- 两个本机合成 API 只提供契约校验的空态与登录选项；真实 web 子进程无数据库/模型凭据，时钟固定；浏览器仅允许本轮精确的公开、私有及错误 Host loopback origin，其余请求和 WebSocket 均拦截，axe 从本地依赖注入。
- JSON 报告、axe 原始结果（含需人工确认的 `incomplete`）、上游调用及失败追踪在 `.verify/e2e-smoke/`；critical/serious 违规使测试失败并退出非零，结束时清理浏览器、web 与两个合成 API。此片不证明真实登录、数据库业务链、内容质量或线上部署。

## 5. 验证、回执与制品（不依赖 GitHub Actions）

Owner 已批准验证与交付不依赖 GitHub Actions（旧ADR-0038，2026-09-26；ADR-0017，DEC-17）。**执行器可替换，规则不变**：检查由仓库内受跟踪的 `make verify` 实现，在**任一**独立执行器上对指定完整 SHA 的干净检出运行，结果以“提交版本 + 验证回执”为准；本文不规定任何托管 CI 的工作流文件，**测试代码也不得断言某个 CI 工作流文件存在**（旧项目 `REQUIRED_PATHS` 的教训）。**2026-10-03 补注（TASK-0015）**：Actions 可作执行器之一。Owner 2026-10-03 决定使用 GitHub Actions（公开仓库、不计费；08-owner-voice DEC-25 ③），它跑的就是 `make verify`，不另写检查，也不是必过检查（ADR-0017 的 2026-10-03 更新）。仓库里唯一的工作流 `.github/workflows/verify.yml` 由 `toolchain` 阶段核对形状；“不得断言工作流文件存在”照旧：检查只断言“存在就必须是这个形状”。

### 5.1 入口与阶段

| 命令 | 用途 | 层 |
|---|---|---|
| `pnpm check` | 提交前快速子集：类型、Biome、边界脚本、契约漂移、受影响工作区的 `node:test` | L1–L3 子集 |
| `make verify` | **合并前必过**：install（冻结锁文件）→ format-lint → typecheck → boundaries / data-ownership / role-config → contracts → path-guard → migrations → test（L1、L2）→ secrets / audit → e2e-smoke（L4 冒烟集）→ product-update → docs（编号与链接）→ pit-checks → tasks | L1–L4 |
| `make release-check` | **发布前必过**：制品构建、镜像扫描、SBOM、签名、容量与冒烟 | L3、L6 |
| `make nightly` | 夜间（显式启动，不假设云端 cron）：全量 E2E、容量基准、依赖升级检查；**不含 AI 评测** | L4、L6 |

阶段的完整定义见 `06-agents/01-parallel-development-rules.md` §8.2；密钥扫描、依赖审计、镜像扫描、SBOM 的工具与版本见 `04-architecture/02-tech-stack.md` 7.2。**不再规定“PR 总时长 ≤15 分钟”**：全量 `make verify` 超过 10 分钟才触发引入 Turborepo（ADR-0015）。

### 5.2 验证回执

机器可读 JSON，绑定完整 SHA，随 PR 附在评论里，不提交进 git 树（提交进树会改变被验证的 SHA）。字段与示例见 `06-agents/01-parallel-development-rules.md` §8.3；本文固定验收要求：

- 必含：完整提交 SHA、tree、锁文件哈希、各阶段结果、退出状态、失败阶段、操作系统与架构与工具版本、起止时间、`scope`（`full` 或 `focused`）、`secret_scan`（工具、版本、范围、命中数）、`audit`（工具、数据源、日期）、私有日志摘要。
- **缺 `secret_scan` 或 `audit` 项的回执视为未通过**；首尾校验 HEAD、tree、已跟踪与未跟踪文件状态和锁文件，拒绝替换对象、隐藏修改、错误提交、中断与漂移；不含环境变量、凭据、个人路径、主机名；不得把假目标或部分检查记成完整通过；不手工填写成功。
- **无签名回执只是执行记录，不构成生产信任**；`scope: focused` 不得用于合并（M0 期间的例外见 ADR-0017 的 2026-10-03 更新，08-owner-voice DEC-24 ②）。
- 每个 INV 与每个 T 的结果按 `06-acceptance-scenarios.md` §1 的证据字段记录（回执的补充），存入 `docs/acceptance/`。

### 5.3 可信制品（`make release-check`，由 T-085、AC-M0-08、AC-OPS-06 验收）

镜像按 SHA 构建（linux/amd64），附 manifest（镜像 digest 清单）、SBOM 与离线签名；签名绑定仓库、目的、提交与 tree、manifest、通过的验证回执与平台。checksum 不能替代签名，签名也不能替代构建与内容验收。生产主机只接受受信公钥签名的制品并按 digest 拉取；信任根由 Owner 一次性授权设定，**不能先关验签来上线**；候选制品不得自带验证器或信任配置。公开响应带发布标识头，从主机之外读回该头等于目标 SHA 才算“已上线”（验证通过 ≠ 已上线）；回滚也要验收。ARM 本地验证与 Linux AMD64 制品核验分开，不由宿主机测试推断镜像架构正确。

### 5.4 PR、夜间与评测的分工

| 内容 | 在哪里跑 | 说明 |
|---|---|---|
| L1–L4、扫描、文档检查 | PR 的 `make verify` | 只用假模型、录制响应与黄金集固定夹具；执行器不持有模型密钥 |
| 全量 E2E、容量基准 | `make nightly` | 不花钱；不含 AI 评测 |
| AI 评测（L5） | 显式评测任务 | 任务卡声明样本范围与调用次数（`model_calls`）、只用最小必要样本，不设金额上限；专用环境；回执缓存复用并回写评测记录；费用按“评测”用途记入用量账本、受异常熔断保护（“研究与评测合计每月 ≤15 元”的份额已作废，Q-54）；改提示词或模型的 PR 必须附评测对比报告链接（T-141、BR-COST-15） |
| 真实环境验收（L6） | 部署后 | 24 小时与 7 天观察、备份恢复、回滚演练、Owner 手机与桌面验收 |

失败的测试不允许用“跳过”“放宽断言”“增加重试次数”掩盖；确需临时跳过的用例要有任务卡与截止日期。修复类 PR 先写能复现的测试，并说明是否新增了自动检查（PIT-079）。

## 6. 什么不算证据

| 不算 | 为什么 |
|---|---|
| “CI 全绿”或“验证回执通过” | 只证明 L1–L4；不证明真实信源在供稿、真实读者体验良好；无签名回执更不构成生产信任 |
| `scope: focused` 回执、本机跑通 | 不是完整验证；不等于生产环境运行成功 |
| 合成样本上的 AI 测试通过 | 只证明结构与流程；不证明真实新闻质量或法律解读质量 |
| 配置了 N 个信源 | 配置 ≠ 启用 ≠ 成功采集 ≠ 持续供稿 ≠ 中文完成 |
| 一次预览成功、fixture 预览成功 | 预览不等于持续供稿；fixture 永不计作真实预览 |
| worker 心跳正常、容器健康 | 不等于有新内容公开（旧站停更 5 天期间进程心跳全程正常） |
| 某次手工运行成功 | 不等于无人值守持续运行 |
| PR 合并、部署命令成功 | 不等于已上线；已上线以外部读回的发布标识头为准 |
| 截图、路由存在、浏览器无报错 | 不能单独签收产品功能与内容质量 |
| “测试了上百种流程” | 不等于语义质量达标；留出集未建成时内容质量标 `not_evaluated` |
