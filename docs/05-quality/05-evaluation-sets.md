## 0. 原则

1. **一个能力一个评测集**，放在 `evals/<代码名>/`。评测集是 AI矿策 规则的可执行版本。【设计｜ADR-0007】
2. **合成样本只能证明行为，不能证明真实新闻的质量**。质量结论只能来自真实样本评测和业务验收（ADR-0007 第 4 条）。【已验证（缺口）】
   - 旧项目没有任何真实样本金标：中文整理的质量“不确定、无金标”（INT-08）；聚簇的“真实质量无金标”。
   - 旧项目合成回放了 1001 / 10001 / 100001 条，只证明了回放结果可以复现（INT-18）。
   - 旧分支对法规链的测试同样是自编材料与自编提供商响应，不是真实法律金标（`interpretation-runtime.md:40-45@policy`）。
3. **高风险错误单独报告**，设上限或零容忍（ADR-0007 第 3 条）。资讯线：误合并、重大政策误拒、阶段提前、编造日期、同名误配。法规线：法律状态提前、义务主体错置、遗漏关键例外、日期性质混淆、适用范围外推等（`10-policy-service.md` 第 8.2 节）。
4. **评测走生产的同一条代码路径**：提示词组装、schema、后置校验和缓存键都与生产相同，只是用途标记为“评测”。【设计】
5. **金标不为系统让路**。规则本身裁决不了时，标 `POLICY_GAP`；先修规则版本，再建新的金标版本。不得改写答案来让系统通过（annotation-manual §9）。
6. **覆盖范围**。vNext §47 要求筛选、聚类和影响分析都必须有黄金集，至少覆盖以下 13 类情形，并比较 accuracy、precision、recall、false merge、latency、cost。【设计（vNext §47，Owner 批准的目标）】
   - 真阳性、真阴性、hard negative；
   - 多语言；
   - 同一事件、不同事件、同一 Policy Thread、误合并；
   - 单企业高先例、高外资影响、低影响有效法规；
   - 媒体转载、独立多源事件。

   其中“影响分析”在 v2.0 指法规线的定性经营影响（AI-20），不再有 0–100 影响分与高/中/低等级（DEC-11）。
7. **自编样本、模型标签不冒充人工金标**（POL-T48）；程序测试通过不等于语义质量通过。
8. **评测与验收用的是同一本账**：评测调用走网关，按用途 `eval` 记账并计入用量报告；不设月度金额上限，也不设“单列免限”额度；评测用最小必要样本，不浪费（DEC-08，见第 10 节）。

## 1. 样本来源与版权边界【设计｜annotation-manual §1】

| 类别 | 内容 | 能否进 Git | 主要用途 |
|---|---|---|---|
| `SELF_AUTHORED` 自有合成 | 项目自己撰写的短事实或合成材料，链接一律用 `https://example.invalid/` | 可以 | 难例、对抗例、CI 夹具、提示词示例 |
| `EXPLICITLY_ALLOWED_SHORT_FACT` 允许保存的短事实 | 逐项确认允许保存的标题式短事实，以及时间、来源角色、规范链接 | 可以，只存短事实 | 预筛、分类、关系 |
| `LICENSED_MATERIAL_REF` 许可范围内的真实材料 | 只存材料修订 ID、内容哈希和标注；正文留在 materials 模块的许可存储里 | 不可以，清单放私有库 | 得出真实质量结论（留出集、密封集的主体） |

- **测试夹具用同一套三类**（D16-quality-011）：自编复现页保留真实页面的结构与陷阱（分页、置顶、验证页、date-only、PDF 链接），内容自写；真实回放只在有许可的来源上做，并保留失败原件的哈希，不只收“好处理的样例”。
- **禁止入库的内容**：第三方全文、网页快照、原始 HTML、模型原始输出，都不得进入 Git 或评测目录。报告中引用原文，每段 ≤200 字符。能公开访问，不等于允许保存、送模型处理或转载。
- **真实材料的许可条件**：真实材料送模型评测，必须有 `external_model` 许可；法规线真实原件同样须来源契约中“内部处理 / 发送模型”用途有效（BR-POL-17），未授权的来源只能用自编的等价样本。许可一旦撤销或材料被下架，样本自动退役并记录原因，不得用快照代替。
- **真实样本占比**：留出集和密封集中真实样本 ≥70%；合成样本主要放在开发集和难例层。达到之前的过渡口径见 1.1。
- **标注者自写的内容**：翻译参考译文和政策解读金标由标注者自己撰写，版权归项目。
- **Owner 提供的范文与第三方报告**：只作体例依据，不作法律真值，也不作金标；版权确认前不入集（Owner 的 16 份写作样本等见 `10-policy-service.md` 第 8.0 节，DEC-41）。

### 1.1 冷启动路径【设计｜D07-ai-010】

新项目启动时没有任何真实材料（新站从空库开始，旧数据一概不导入，Owner 2026-10-01 “全重做”），旧仓库唯一成形的金标是 24 例自编校准集（不取回、不使用，DEC-42），Hermes 试验也没有现成的人工错例（首批三个真实任务均未形成可审草稿，`docs/reviews/hermes-pilot-recovery-20260921.md:3@main`）；旧ADR-0009:33@main 要求“至少 200 篇文档、50 个真实事件簇、50 组硬负例”的黄金集基线，这个基线从未达成。所以路径分四步：

| 步骤 | 内容 | 时点 |
|---|---|---|
| ① v0 开发集 | **自编样本与对抗例**：项目自己撰写的短事实与合成材料（`SELF_AUTHORED`，链接一律用 `https://example.invalid/`），格式沿用 AIHOT 的 `industry/gold.example.jsonl`（精选）与 `industry/relation-gold.example.jsonl`（事件关系），再转换为第 4 节的 JSONL。旧 Gold v1 的 24 例（含旧评分 rubric 字段）**不取回、不使用**：Owner 2026-10-01 答复不从旧仓库导出任何文件（DEC-42），本包也不再附其路径、字节数与 SHA-256 | M1 |
| ② 真实样本来源 | (a) **新站自己采集的内容**：首批接入期产生的“已审定 `model_allowed` 来源”的材料，以材料修订 ID + 内容哈希引用，不入 Git；(b) **不使用旧站已公开内容**（原 AIQ-18 = Q-51 作废，Owner 2026-10-01：全重做）；(c) 法规线真实原件，见 1.2 | M1 首批来源接入后持续累积 |
| ③ 标注分层 | silver / gold，见第 2 节 | M1 起 |
| ④ 截止 | Owner 本人是唯一评判人，其单人 gold 可进开发集与留出集（注明“单人金标”）；**留出集规模达到第 3 节下限的截止**：精选（AI-03）= 全面切换前完成一次留出集检查并留记录；其他能力的首轮真实标注评测 = 影子运行期（M4）起，最迟切换后 4 周（默认，AIQ-19 = Q-52）；法规线质量资格抽检 = M3 前；逾期回到整改，不隐瞒 | M3 前 / M4 / 切换前 |

### 1.2 法规线的样本来源【设计】

- **自编样本**：自编法规文书（合成法域，链接 `example.invalid`），刻意覆盖文末例外、缺附件、长节点、同号不同法域、同文多语言、同 URL 更正、权限漂移、错误引文（与旧分支自编测试同类，`material-processing.md:53-54@policy`）。它们只证明程序行为，不证明语义质量。
- **真实原件**：须来源契约授权；**只存 URL 与内容哈希，不入 Git 正文**。压力与覆盖样本取自旧分支已实测的路径：联邦公报 2024-06920（硅尘规则，268 页、118 处图件引用、5 张结构化表格）、eCFR Title 30 批量 XML、加拿大 Justice XML、中国国家行政法规库 HTML（见 `10-policy-service.md` 附录 A）。这些路径只证明格式与取得方式可行，不证明许可、现行性或语义质量。
- **真实质量结论**只来自 Owner 本人对真实样本的评判记录（`03-ai-capabilities.md` AI-21 的质量资格）；结构测试不得冒称语义质量。

## 2. 标注规则（通用）【设计｜annotation-manual §9–12｜评估人 DEC-15】

- **标注分层：silver 与 gold**【设计｜B:architecture/06-ai-and-agent-runtime.md】
  - **silver**：模型预标、开发 Agent 的判断、自动建议，以及人工纠错形成的候选标注（candidate label）。只进开发集与难例层，不计入留出集与密封集，不作质量结论的依据。预标结果不算一名独立标注者。
  - **gold**：经 Owner 本人确认、并消除冲突的标注。读者反馈、修订、下架、异常项都是候选来源：候选 → silver → Owner 确认 → gold。**新的反馈不自动修改提示词。**
- **评估人为 Owner 本人**（Owner 2026-10-01 已定，DEC-15）：精选校准样本的标注、法规完整解读的一次性抽检、每月小样本复核都由 Owner 本人完成；日后另指定法律或矿业政策人员或外部标注者，须 Owner 另行决定；标注者使用匿名编号。
- **双人标注 + 第三人裁决**是**扩展期目标**（有第二名评判人之后；Owner 本人是现阶段唯一评判人，AIQ-15 = Q-23 已答复）：两名各自独立标注，互相看不到对方结果；分歧由第三人裁决，裁决时保留两份原始立场。
  - **现状（Owner 为唯一评判人，DEC-15）**：Owner 本人标注的单人 gold 可以进开发集与留出集（精选校准的留出集即如此，结论注明“单人金标”）；密封集在第二名评判人到位前不宣称建成，相应能力在签收表标 `not_evaluated`（8.6），不阻塞开发。
  - **必须裁决的分歧**（扩展期），出现以下任一情况即需裁决：
    - 处置不同，或收录类别不同；
    - 主分类不同；
    - 阶段、日期角色或日期性质不同；
    - 分档不同，且跨越了精选门；
    - 关系（same_event / progress / separate）不同，或成员角色不同；
    - 所选实体不同；
    - 相关性（relevant / excluded / uncertain）或影响条目的主体不同；
    - 生成类样本的 5 分制评分相差 ≥2 分。
- **`POLICY_GAP`**：规则无法裁决的样本，标 `POLICY_GAP`，不计入决定性指标；同时提交规则修订，进入 `08-open-questions.md` 或 BR 修订。
- **一致性检查**
  - 抽 10% 的样本重复投放，检查标注者前后是否一致。
  - 两人标注：分类类和关系类的 Cohen's κ ≥0.70，版本才能冻结；达不到就先修订标注手册。【设计】
  - 单人阶段：用重复投放的前后一致率（≥90%）代替 κ，结论注明“单人金标”。【设计】
- **标注手册**
  - 位置：`evals/<代码名>/GUIDE.md`。
  - 以 legacy `annotation-manual.md` 为起点，按当前 BR 和本包规则改写。
  - 规则一变，就出新版本手册；受影响的样本要么重标，要么用 `supersedes` 标明被取代。
- **法规线金标**：由评判人按原文给出两份清单——关键义务清单（主体、内容、条件、期限、例外、条款）与不得出现的错误清单；日期与状态类金标可由开发 Agent 按原文预标为 silver，评判人按比例抽检确认后升 gold（默认抽检 20%，分歧全查）。【设计，默认】
- **建设期质量资格抽检不是金标标注**：法规完整解读的开放由评判人一次性抽检真实样本（每个语种 / 法系组若干份，建议约 5 份）并留评审记录；完整解读按“法域 × 文书类型”抽检通过后开放，绑定质量资格（QualityRelease）；它决定某组能否公开，不产生可重复运行的评测指标。抽检样本可与评测集重叠，但评审记录单独保存。
- **不设日常审核**：评判工作只在建设期与每月小样本复核（EVQ-05 = Q-53）发生，占用评判人工时（DEC-14）。

## 3. 划分与防泄漏【设计】

**三个划分**

| 划分 | 用途与可见范围 |
|---|---|
| 开发集（dev） | 调提示词时使用，可以查看全部错例。 |
| 留出集（holdout） | 发布前复核用，只看汇总结果和错例摘要，不据此逐条修改提示词。 |
| 密封集（sealed） | 换默认模型、季度审计、重大版本发布时，由质量泳道运行，只报告汇总结果；数据放在权限受限的私有存储中；在评测运行记录（ENT-43）里单独标“密封”划分。 |

**比例**
- 正式规模：开发 35% / 留出 35% / 密封 30%（annotation-manual §12）。
- 首期（单个评测集不足 300 例）：开发 50% / 留出 30% / 密封 20%。
- 只有 silver 的样本全部归开发集；Owner 本人标注的单人 gold 可进开发集与留出集（结论注明“单人金标”，精选校准即如此），密封集待第二名评判人到位。

**分组整体拆分**
- 以下样本彼此相连、构成一组：同一事件、同一发展线、同一政策进展线、同一发布方族、近似重复的模板、同一文书的不同版本与不同语言版本。
- 每一组整体放进同一个划分，不得拆开（annotation-manual §12）。旧审稿台的 `validate_split` 也是这样做的，它按条目、事件、故事三重身份防止泄漏（ED-14）。

**时间切分**：密封集优先收最近一段时间的新样本，用来发现漂移。

**提示词示例**：提示词里的示例只能用合成样本，不能取自留出集或密封集。CI 会校验划分，一旦发现泄漏即判失败。

**稳定性重复**：需要测稳定性的评测，对同一样本多次独立调用，**尝试序号进缓存键**（`03-ai-capabilities.md` 1.3）；否则评测与生产共用缓存键，会复用同一份回执，测不出输出的不稳定性。

**版本管理**
- `gold_version` 使用语义化版本号。
- 新增样本只能追加。
- 更正某个样本，用 `supersedes` 字段指明它取代了哪一条。
- 退役的样本要记录原因。

## 4. 数据格式【设计】

每行一个 JSON 对象（JSONL）。所有能力共用下面这个外层结构：

```json
{"case_id":"ai08-000123","capability":"AI-08","lane":"news","gold_version":"1.0.0","split":"dev",
 "tier":"gold","attempt":1,
 "strata":["cross_language","policy_thread"],
 "groups":{"event":"g-evt-17","story":null,"thread":"g-thr-3","publisher_family":"g-pf-9"},
 "rights_basis":"LICENSED_MATERIAL_REF",
 "input_ref":{"material_revision_id":"mrv_…","content_hash":"…"},"input":null,
 "gold":{},"annotations":[{"annotator":"ann-A","labels":{},"rationale":"…"},
                          {"annotator":"ann-B","labels":{},"rationale":"…"}],
 "adjudication":null,"policy_gap":false,"supersedes":null}
```

- **`input` 与 `input_ref` 二选一**：合成样本和短事实直接写在 `input` 里；真实材料只填 `input_ref`，即引用。法规线的真实原件用 `{"doc_revision_id":"…","content_hash":"…","source_url":"…"}`，不含正文。
- **`lane`**：`news` 或 `policy`；**`tier`**：`gold` 或 `silver`（silver 只能出现在 `dev` 划分）；**`attempt`**：稳定性重复时的尝试序号，默认 1。
- **`gold` 的字段**：各能力不同，见第 6 节。
- **两可样本**：金标取值为 `either`（两可）的样本，不计入决定性指标。

## 5. 指标定义【设计】

**分类类（AI-01、AI-02、AI-18）**
- 报告准确率、宏 F1、混淆矩阵，以及每一类的查准率、查全率、F1 和样本数。

**预筛（AI-01）**
- **误拒率**：金标为“收录”、却被判“拒绝”的数量 ÷ 金标“收录”的总数。
- **误收率**：金标为“拒绝”、却被判“收录”的数量 ÷ 金标“拒绝”的总数。
- 按层分别报告：重大政策层、硬负例层、边界层。

**关系判断（AI-08）**
- 3×3 混淆矩阵（same_event / progress / separate；`uncertain` 并入 separate 另计）；“同一事件”的查准率与查全率。
- **误合并率**：金标应分开（progress、separate）、却被判为 same_event 的对数 ÷ 金标应分开的总对数。
- **关键误合并**单独计数，包括：跨法域、政策不同阶段、同一矿山的不同事故。
- 按置信度阈值扫描；召回阶段看 recall@k（确定性召回基线；AI-16 启用评测时用）。

**精选类（AI-03，AIHOT 校准办法）**
- 准确率、查准率（选出来的有多少是对的）、查全率（该选的有多少选上了）、F1；金标 `either` 不计入决定性指标；按信源分级（T1 / T1_5 / T2）与 `samplingStratum` 分层报告，看错在哪一类。
- 门槛从 40 到 90 每隔 2 分扫描的结果（各门槛下的准确率、查准率、查全率），以及分数贴着门槛的判错条目数（用来判断“该调标准还是调门槛”）。
- 两次评分之间的差值分布与相差 ≤10 分的占比（稳定性）。
- 噪声层（获奖、参会、空预告、泛宣传）误入精选的条数（零容忍项）；“必须正常评价”层中重大政策法规、重大事故被压到门槛以下的“关键漏选”条数（单独报告）。

**生成类（AI-04、AI-09、AI-13、AI-20）**
- **句级依据率**：先由 R-17 自动核对，再人工抽查；事实句 = 含数字、日期、主体动作、阶段、因果的句子，纯结构性句子不计；**无依据的事实句为零容忍项**。
- **硬错误计数**：数字、日期、阶段、主体、口径错误。
- **格式合规**：用确定性规则检查。
- **人工评分**：5 分制，评忠实、完整、可读、口径四项。
- **引用有效率**。
- AI-20 另报：相关性三值准确率、七主题枚举正确率、影响条目的**主体错置率**、direct / indirect 标注正确率。

**翻译类（AI-05、AI-17）**
- 数字与条款号保留率（自动检查）；坏段率（R-21）。
- 漏译句比例（人工逐句对齐）。
- 否定、情态、时态错误数。
- 术语一致率（按术语表自动检查）。
- 人工评的忠实度。
- AI-17 另报：事实覆盖率（每个部分有事实结果或显式分类，程序断言 100%）、表格行列保持、错引文数。

**法规核验类（AI-19、AI-21）**
- 分组覆盖率与归并输入 ID 覆盖率（程序断言 100%）。
- **反证检出**：陷阱样本（文末例外、但书、过渡条款、定义推翻前文结论）中，被推翻的结论被发布的数量。
- 引文对结论的支持性（人工抽查）。

**Agent 类（AI-14、AI-15）**
- 官方身份判断准确率；试抓通过率。
- 候选的查准率和查全率。
- 超限率；平均步数。

**附件理解类（AI-23）**
- 位置集合相等率；表格单元格漏失数；数值类单元格准确率。

**成本与运行**
- 每例平均输入、输出 token。
- 单位成本，分高峰和非高峰（人民币，R0 价格）。
- p50 / p95 延迟。
- 结构合法率、重试率、未知结果数、复用数、预留与结算的差。

**统计口径**【设计｜D07-ai-013：统一 v1.0 自相矛盾的“1 个百分点 / 2 个百分点”，并保证规划样本量下可执行】
1. **所有结果都报告样本数。**
2. **配对比较**：两个版本用同一批样本；主指标配对差异小于 max(2 个百分点, 3 条样本) 视为持平；**退步超过该阈值，或出现新的零容忍项，才拒绝**。
3. **零容忍项**报告“计数 + Wilson 95% 区间”：计数大于 0 即判失败；要下“通过”结论，该层样本数必须达到第 6 节“必含层”写明的下限，否则标“**样本不足**”，不作通过结论（样本 30–40 条时，“0 次”对应的 95% 区间上界约 9–11%，统计上证明不了“为 0”）。
4. **n<30 的层**只报计数与区间，不报比例、不作通过结论。
5. **稳定性**：对需要测稳定性的能力（AI-03、AI-08、AI-20/21），同一样本多次独立调用，带尝试序号进缓存键，报告结论一致率。
6. **公开资格**不靠“每个组合统计达标”：法规完整解读由评判人一次性抽检（每个语种 / 法系组若干份，建议约 5 份），按“法域 × 文书类型”抽检通过后开放（DEC-15，见 `03-ai-capabilities.md` AI-21），分组小样本只作评审依据，不下统计显著性结论。

## 6. 各能力评测集

> 各能力的指标门槛以 `03-ai-capabilities.md` 中对应一节为准，本节不再重复。本节只规定样本、金标字段、标注要点、必须覆盖的层级和规模。**规模是目标值**：冷启动期先用 Gold v1 与自编样本，真实样本随首批来源累积（1.1）；达不到“必含层”下限的层标“样本不足”（第 5 节）。

### 6.1 AI-01 预筛【设计】（资讯线）

- **样本**：真实材料 ≥200 条，覆盖所有已接入的国家和语言；合成难例 ≤100 条。
- **金标字段**：
  - `disposition`（处置）、`inclusion_class`（收录类别）、`reason_code`（理由码）；
  - `is_major`：是否属于重大政策法规、重大事故或约束性文书；
  - `boundary_topic`：油气、下游，以及“获奖 / 参会 / 预告 / 泛宣传”。
- **标注要点**：
  - 依据 BR-ENR-01/02 和 vNext §12–16 标注。
  - “拒绝”只用于明确无关的内容。
  - **纯一般获奖、参会、空预告、泛宣传的金标为“拒绝”；含具体项目进展或经营信息的对照样本金标为“收录”**（DEC-12）；收录须有正向的矿业联系证据。
  - AIQ-02 = Q-30（油气、下游是否算矿业）尚未定案的边界样本，标 `POLICY_GAP` 或 `either`。
- **必含层**：
  - 重大政策法规与重大事故 ≥40；硬负例 ≥30；机关事务与消费监管 ≥30。
  - B/C 类影响路径边界 ≥40；普通噪音 ≥30；材料不足 ≥15。
  - 获奖 / 参会 / 空预告 / 泛宣传 ≥15，另配含具体事实的对照 ≥10。
  - 语言：中文 ≥100，英文 ≥80，西班牙文 ≥30，法文 ≥20，俄文 ≥20，其他 ≥10。
- **规模**：300（M1）→ 600（M2）→ 1,200（M3）。

### 6.2 AI-02 结构化抽取（与 AI-01、AI-04 共用“编辑金标”）【设计】

- **样本**：与 AI-01、AI-04 共用同一批材料，一次标注，产出多种金标，以节省人力（AI-03 的精选金标按 6.3 单独标注 select / reject / either）。
- **金标字段**：主分类、内容类型、国家与主法域、矿种、实体提及（原名 + 角色）、frame、阶段、文号、`doc_refs`（文书身份）、关键日期（角色、值、精度）。
- **标注要点**：
  - 按 annotation-manual §4 的主分类原则和四条常见分界标注。
  - 以下首批分歧类型要单独保存：出口许可新规；收购并扩建；事故后停工抗议；更正是否需要重算；多语言报道算独立来源还是翻译。
  - 新闻稿给出约束性阶段而来源不是构成性原文的样本，金标阶段为“宣布”（R-30）。
- **必含层**：
  - 九类各 ≥20 条；
  - 实际出现的每个阶段各 ≥5 条；
  - 陷阱样本 ≥20 条，如 US$、Indian land、发布方总部、Gold Fields 类公司名、近似子串（印度尼西亚、加勒比海地区、几内亚系列）；
  - 日期歧义与相对时间 ≥15 条。
- **规模**：240（M1，九类各 20 + 跨类 60，annotation-manual §11）→ 600 → 2,400（九类各 ≥120，≥800 个事件簇，annotation-manual §12）。

### 6.3 AI-03 精选评分【设计】（沿用 AIHOT 的校准办法，随全面切换上线）

- **状态**（Owner 2026-10-01，DEC-10）：精选与热点沿用 AIHOT 并矿业化，切换前完成；本评测集用来校准评分标准与门槛，**不再有“待 Owner 初稿”，也不再有“暂未启用”**。**被评测的矿业版评分标准是草案，生效前须交 Owner 审阅确认（硬前置，BR-SEL-09、T-0323、T-160）**：影子运行期与评测环境可以用草案跑；评测记录必须登记所用评分标准的版本（提示词内容哈希）与 Owner 确认状态（草案 / 已确认）；评分标准每出新版本，用于正式站前须重新确认。
- **样本**：100–200 条矿业材料，分开发集与留出集（`samplingContext.benchmarkSplit` = development / holdout；调提示词只看开发集，留出集只在最后检查时跑），**难例为主**——差一点该选、差一点不该选的；一眼能判断的放太多，准确率会虚高。材料来自新站自己采集的内容（1.1），以材料修订 ID + 内容哈希引用，正文不入 Git；按信源分级（T1 / T1_5 / T2）与 `samplingStratum`（如新规、许可、并购、停复产、资源量储量、价格供需、安全事故、营销软文）分层，分别看错在哪一类。
- **标注**：由 Owner 本人逐条标“该选 / 不该选 / 两可”（金标取值 `select` / `reject` / `either`，`either` 不计入准确率；与 Q-23 是同一安排）；标注时只看模型能看到的内容（标题、正文、发布时间），不看来源名、转载数与旧分数。
- **金标格式**（沿用 AIHOT `docs/selection.md`，每行一条；`industry/gold.example.jsonl` 有示例）：`caseId`；`material`（title、originalTitle、publishedAt、sourceName、bodyZh 或 bodyOriginal，有一个就行）；`sourceFacts`（sourceKind、sourceTier、firstParty、language；分级决定用哪个门槛）；可选 `samplingContext`（benchmarkSplit、samplingStratum）；`gold.decision`。存放在 `.data/gold.jsonl`（`.data/` 不进 Git）；与第 4 节外层结构的对应由运行器转换。
- **运行**：用 AIHOT 的 `scripts/eval-selection.ts` 对每条样本跑预筛与两次评分，输出准确率、查准率、查全率、F1，门槛从 40 到 90 每隔 2 分的扫描结果，判错条目与完整报告（`.data/eval/`），并导入后台 SelectBench 逐条看分数与模型理由；`--models` 同批比较几个模型，`--split holdout` 只跑留出集；同样的输入和提示词再跑不会重复调用模型（回执复用），只有改过的部分才产生新调用。
- **校准顺序**：先改评分标准、再动门槛——该选没选上，多半是评分标准里没写清它为什么重要：把这类价值写进“必须正常评价”并给例子；不该选却选上，多半是噪声没压住：写进“必须压住”；整体偏松或偏紧、判错条目的分数都贴着门槛时，才调门槛（门槛只能整体移动，解决不了“哪一类判错了”）。每改一次跑一遍，每版对比。影子运行期可先用 AIHOT 原门槛（T1 60 / T1_5 65 / T2 76）；**全面切换前必须完成一次留出集检查并留记录**（记录：准确率、查准率、查全率、门槛扫描、判错清单、沿用或调整门槛的决定、评分标准版本及其 Owner 确认状态与日期）；留出集检查所用的评分标准版本必须就是 Owner 已确认的那个版本（BR-SEL-09 第 5 点），改了评分标准就是新版本，须重新交 Owner 确认。
- **必含层**（【设计】起步值；样本不足的层标“样本不足”，第 5 节）：“必须正常评价”的各类价值（法规政策变化、矿权与项目里程碑、并购与融资、资源量与储量披露、价格供需与官方统计、重大安全与环境事件）各 ≥8；“必须压住”的各类噪声（获奖参会空预告泛宣传、转载同稿、无实质行情复述、例行人事与会议通稿、同形词、软文与招聘）各 ≥8；单一官方来源的高价值事件 ≥10；三种信源分级（T1 / T1_5 / T2）各 ≥20。
- **离线对照**：旧 55/70/65/75 公式与旧 Gold v1 的评分 rubric 字段**不再使用**（旧数据不取回，公式作废，DEC-10、DEC-42）；对照基线改为“AIHOT 原门槛下的结果”。
- **规模**：100–200（切换前）→ 随新站累积的难例每季度补充；错例与反馈进入候选池（第 12 节）。
- **审阅样例**：提交 Owner 审阅矿业版评分标准草案时（T-0323）附草案在开发集与影子数据上的跑分样例——评分分布、入选清单、与 AIHOT 原规则并排的差异示例（BR-SEL-09 第 3 点）；样例只用开发集，不动留出集。
- **对应规则与记录**：业务规则 BR-SEL-08、BR-SEL-09（矿业版评分标准的 Owner 审阅关卡）；留出集检查记录与评分标准的审阅确认记录都是 ENT-84 精选校准记录的一类（全面切换前必须有，T-158、T-159）。

### 6.4 AI-04 中文标题与导读【设计】

- **样本**：
  - 外文 80 条：英 40、西 15、法 10、俄 10、其他 5。
  - 中文原稿 40 条。
  - 对抗例 40 条：阶段、数字、公司名（含未核实公司名）、指控、相对时间、提示词注入。
  - **超过输入上限的长文 ≥10 条**，文末含例外、生效日期或落款，用于检验“导读依据范围”与施行 / 例外 / 过渡期陈述的引文位置校验（DR-97、D06-content-026）。
  - **公开条件与标注类场景样本**：外文新稿三项就绪才公开（T-101）、AI 标识与“已人工复核”禁用字样（T-132）、未核实译名公开 0 次（T-025）、熔断期间不降级（T-099、T-138）、原生中文权限四分支（DR-19，逐源收紧后才出现后三个分支），样本与断言见 6.20。
- **金标**：
  - 不写整篇标准答案，只标：必须出现的事实点（3–6 个）、禁止出现的内容（阶段写错、臆造主体、未核实译名、“暂译”字样等）、公司名的规范写法（已核实词表或材料自带中文名，否则只写原名）。
  - 另由评判人按 5 分制打分：忠实、完整、可读、口径。
- **规模**：160 → 400。

### 6.5 AI-05 全文翻译【设计】（资讯线）

- **样本**：
  - 40 篇文章，约 250 段，其中政策类新闻 10 篇（法规原文归 AI-17，不在本集）；语种按已接入信源分配。
  - 另加 60 条合成难例段：否定、may/must/shall、例外条款、表格、数字密集段、条款编号；**含节点边界用例**：分段不得切断表格行与条款（PIT-098）。
  - **坏译文与语义保真样本**：DR-35 的六类坏译文判据（T-144）、DR-31 的否定 / 情态 / 时态 / 数字 / 尾段例外五类对照（T-030），各类样本数见 6.20。
- **金标**（二选一）：
  - 人工参考译文（版权归项目）；

## 8. 发布门槛：改提示词、改门槛、换模型【设计｜ADR-0007、BR-COST-10】

### 8.1 提交 PR：用开发集

PR 必须附上开发集上修改前后的对比，内容包括：

- 主指标；
- 全部零容忍项（计数 + 区间，第 5 节）；
- 结构合法率；
- 单位成本与 p95 延迟；
- 新增错例。

**对比默认只用假模型与已缓存回执**（D07-ai-009）：需要真实调用时只跑冒烟子集（第 10 节）；全量开发集对比按里程碑排期（不设评测额度，但不浪费），并在 PR 里声明调用次数与费用。

### 8.2 合并条件

以下三条都满足才能合并：

1. **零容忍项不得变差。** 任何一项从 0 变为大于 0，即拒绝合并。零容忍项包括：
   - 资讯线：重大政策误拒；同形词误收；阶段提前；编造日期或时分；关键误合并；制裁对象同名误配；翻译未全部完成却标“全文翻译”；引用无效；口径违规；未核实译名出现在任何公开字段；无依据的事实句。
   - 法规线：法律状态提前；由非构成性来源确立约束性状态；日期性质混淆；义务主体错置；建议写成强制；现有义务写成新增；罚款上限写成一律罚款；遗漏关键例外；适用范围外推；错引文；数字、条款号丢失；被反证推翻的结论被发布；根级日期被继承为逐条施行日；输出数值影响分或等级。
2. **主指标不得明显退步。** 用配对比较：配对差异小于 max(2 个百分点, 3 条样本) 视为持平，**退步超过该阈值或出现新的零容忍项才拒绝**（统一 v1.0 的“1 个百分点”与“2 个百分点”，第 5 节）。
3. **成本涨幅需说明。** 单位成本上升超过 20% 的，须在 PR 中写明理由，并经 Owner 确认。

### 8.3 上线：用留出集

- 新提示词或新门槛生效前，先在留出集上复跑。门槛与 8.2 相同，同时还要达到 `03-ai-capabilities.md` 中各能力的绝对门槛。
- 留出集尚未建成时（冷启动，见 1.1 与 8.6），按 8.6 口径处理，不宣称“质量已验证”。
- **精选（AI-03）**：评分标准或门槛的任何改动，上线前都要在留出集上复跑一次并留记录（AIHOT 的校准办法，6.3）；全面切换前必须完成一次留出集检查；用于正式站的评分标准版本须是 Owner 已确认的版本，未经确认的草案只在影子与评测环境运行（BR-SEL-09）。
- 达不到绝对门槛的，只能以私有候选或影子模式运行。
- **AI-20、AI-21 的公开资格不由本条自动放行**：按建设期质量资格办理（Owner 本人一次性抽检、按“法域 × 文书类型”开放，BR-POL-11 第 5 项）；评测分数只作参考。

### 8.4 换默认模型：准入状态机与密封集

- 换某环节的默认模型 = 发布新的 RouteRevision，并走准入状态机 `eval → shadow → canary → promoted`（`03-ai-capabilities.md` 1.9）：
  - eval：该环节的留出集与密封集上都有最新评测记录且达标；
  - shadow：小流量影子，对差异做审阅；
  - canary：小比例真实流量；
  - promoted：Owner 二次确认并写明原因（BR-EDT-06）。
- 没有达标记录的切换属于高风险操作，同样需要 Owner 二次确认。
- 响应模型或 fingerprint 漂移 → 路由退回 eval，须新评测后才能恢复。
- 法规线：模型或提示词更换即令已授予的质量资格失效，须重新评估（AI-21）。
- 回退不丢已付费结果与账本，也不抹掉人工下架记录。

### 8.5 定期复核

- 密封集建成后，每季度用密封集复跑一次当前的生产路由。
- 出现以下任一情况即启动调查：指标下降超过 3 个百分点，或任一零容忍项出现非零。

### 8.6 首期过渡【设计｜D16-quality-009、D07-ai-010】

- 金标还没达到首期规模时，允许只凭开发集结果合并，但留出集建成后必须补做留出集复核。这一阶段的评测结论要注明“样本不足”或“单人金标”。
- **M1 验收只要求 AI-01、AI-02、AI-04、AI-05 的开发集结果 + 人工可读性抽检**（AI-06 随词表核实）；留出集门槛从留出集建成起生效，最迟 M2。
- 留出集尚未建成的能力，在验收签收表（AC-M1-17）的“内容”列标 `not_evaluated`；公开页面与更新日志不得宣称“质量已验证”。是否以此阻塞全面切换，由 Owner 决定（AIQ-19 = Q-52）；**默认不阻塞但必须记录：精选（AI-03）必须在切换前完成留出集检查并留记录；其他能力的首轮真实标注评测在影子运行期（M4）完成，切换后 4 周内补齐仍未完成的**，未达门槛的能力回到整改，不隐瞒。

## 10. 评测费用控制【已验证（回执复用思路）｜设计】

- **走网关，按用途 `eval` 记账，不设月度金额上限**（DEC-08，Owner 2026-10-01）
  - 用途记为“评测”（`eval`）；按被评测环节所属的 lane 与记账类别记账，计入用量报告。**不设月度金额上限，也不设评测份额**（Q-54 作废），不设“单列免限”额度；但评测用最小必要样本，不浪费（BR-COST-15、BR-COST-17；EVQ-02 已裁定 DEC-08）。
  - 缓存键与生产一致：输入、提示词、路由都相同时，直接复用已有回执，不重复计费；需要测稳定性的评测带尝试序号（第 5 节）。
  - 同一次运行里输入相同的样本，只发一次请求。
- **先小样，后全量**
  - **PR 对比默认只用假模型与已缓存回执**；需要真实调用时，先跑 50 例冒烟子集（预计每个能力约 0.5 元量级）；法规全文链的冒烟用 3 份自编短文书（每份 ≤10 KB，预计每次约 1 元量级）【设计，起步值；这是最小必要样本的规模，不是金额上限】。
  - 冒烟通过后，才跑完整开发集；全量评测**按里程碑分批执行**，每次声明样本数与调用次数。
  - 留出集只在发布前运行。
- **错峰**：批量评测默认排在非高峰时段（BR-COST-08）。
- **声明与约束**
  - 每次运行都要声明样本数与真实调用次数（`model_calls`），默认只跑冒烟子集；**不设评测金额上限**，但异常熔断（同一输入 1 小时内重复付费 ≥3 次等，`03-ai-capabilities.md` 1.4）与达到阈值 70% 的预警（BR-COST-20 第 7 点）对评测同样有效。
  - 开发 Agent 的任务卡要写明真实调用次数与样本数；默认只使用假模型（`05-cost-and-budget.md` 第 4 节）。

## 13. 实现基础（AIHOT，沿用）

> Owner 2026-10-01（DEC-64）：精选与事件关系的评测直接沿用 AIHOT 的脚本与办法；其余能力的运行器按同一套回执复用与分层报告方式写。

- **`scripts/eval-selection.ts`**（精选，6.3）
  - 评测对象：预筛 + 两次评分，金标取值为 select / reject / either；评测走生产的同一条代码路径（`editorial/analyze.ts` 的 `runAnalysis`，两次评分之和对照信源分级门槛）。
  - 输出：准确率、查准、查全、F1；门槛从 40 到 90 每隔 2 分扫描一次；错例写入 `.data/eval/`，并导入后台 SelectBench。
  - 常用参数：`--gold`、`--models`、`--n 200`、`--seed 7`、`--split development|holdout|all`、`--concurrency 6`、`--label`、`--no-import`。
  - 回执可以复用，所以同样的输入和提示词重跑不产生新调用与费用。
- **`scripts/eval-relations.ts`**（事件关系，6.8）
  - 直接复用生产环境的成对提示词、schema 与提示词版本（提示词一变，评测随之变）；不重新跑候选召回，也不把结果写回事件归组。
  - 输出：4×4 混淆矩阵、每类的 P/R/F1 与 support、overall accuracy 与宏 F1；`SAME_OCCURRENCE` 或 `SAME_STORY` 作正例时，各置信度阈值（默认 0.75、0.8）的二分类 P/R/F1；模型错误、token 用量与平均延迟、每条 case 的 decision / confidence / difference / receipt id（AI矿策 的关系取值为三值，映射见 `03-ai-capabilities.md` AI-08）。
  - 参数：`--gold`、`--models`、`--split`、`--n 200`、`--seed 7`、`--concurrency 6`、`--thresholds`；用途记为 `eval_relation_pair`，与生产统计分开；同一次运行中，输入相同的样本共享同一个请求。
- **`docs/selection.md`**：建议每批标注 100–200 条，多放难例，并把开发集和留出集分开（6.3 已采用）。
- **新项目的做法**：沿用上面两个脚本，并扩展为 `evals/<代码名>/` 加一个统一的运行器，覆盖全部现行 AI 能力（AI-01～AI-23，已废弃的 AI-10～AI-12 除外；AI-16、AI-22 默认不启用，只在启用前评测；AI-03、AI-09 随全面切换启用）。门槛和结论以本文及 `03-ai-capabilities.md` 为准。
