# 工程规范

> 对所有泳道生效。目标：任何 Agent 打开任意模块，都能用同一套习惯读懂和修改代码。
> 具体库与版本见 `02-tech-stack.md` 与 ADR-0015；本文只定“怎么写”。与 AIHOT 现有写法一致的地方直接沿用。所有规则由统一验证入口 `make verify` 检查（ADR-0014、ADR-0017），不依赖任何托管 CI 平台。

---

## 1. 语言与代码风格

1. 全仓 TypeScript，`strict` 全开，ESM。后端由 Node 直接运行 TypeScript（沿用 AIHOT：后端无构建步骤）；前端由框架构建。
2. 格式化与 lint 只用一个工具（Biome，配置随仓库）；本地提交前钩子可选；`make verify` 中格式或 lint 不通过即失败。首次全仓格式化单独成一个提交。
3. 命名：
   - 目录与文件：`kebab-case`；React 组件文件 `PascalCase.tsx`；
   - 类型：`PascalCase`；函数与变量：`camelCase`；常量：`UPPER_SNAKE_CASE`；
   - 数据库：`snake_case`，schema 名与模块名一致（`ai-gateway` → `ai`）；
   - 业务线：代码名 `news` / `policy`（与 `03-data/contracts` 一致）；
   - 领域事件：`<聚合>.<过去式动作>`，聚合名取词汇表代码名，如 `material.enriched`、`policy.changed`；信封必带 `lane`；
   - 任务类型：`<模块的 schema 名>.<动词>`，如 `acquisition.collect-source`（`ai-gateway` 用 `ai`，`platform/ops` 用 `ops`）；
   - 队列（调度与并发单位）：`<lane>.<stage>`，如 `news.fetch`、`policy.interpret`；历史回填用独立的低优先级队列 `<lane>.backfill`；lane=`all` 的平台任务用 `platform.<stage>`（如 `platform.ops`）；不属任一业务线的离线任务用 `offline.<stage>`（`offline.research`、`offline.eval`、`offline.import`）。一个任务类型按载荷中的 lane 投入对应队列；任务目录以 `03-data/03-internal-contracts.md` 第 3 节为准。
4. 业务名词统一使用 `01-product/09-glossary.md` 的“代码名”一列，不另起同义词（例如统一用 `material` 而不是 article/item/document 混用；`item` 专指公开条目）。模块名只用 `03-module-map.md` 的规范名。
5. 注释：解释“为什么”，不复述“做什么”；引用规格编号时写 `// BR-TIME-03`。匹配周围代码的注释密度。
6. 单文件超过 400 行、单函数超过 80 行需在 PR 中说明或拆分。
7. 不写“以后可能用”的抽象；共享代码至少两个真实使用方才进共享包；不建通用 `utils` 目录承载业务。

## 2. 模块代码组织

见 `03-module-map.md` 第 5 节（路径 `packages/domains/<name>/`）。补充规则：

- `src/domain/`：纯函数与类型，不做 IO，不读环境变量、不取当前时间（时间由调用方经 `Clock` 端口注入）。业务规则优先写在这里，便于单元测试和评测复用。
- `src/store/`：SQL 与数据映射；只访问本模块 schema；连接由注入的 `dbFor(role)` 提供；每个查询在注释中写明依赖的索引。
- `src/jobs.ts`：任务声明（见第 8 节）。
- `src/routes.ts`：HTTP 路由，分 `publicRoutes` 与 `privateRoutes` 两组（`public-api` 实例只注册前者，`private-api` 只注册后者）；请求/响应 schema 引用 `@amp/contracts`；私有路由只承载 ADR-0018 所列六组操作。
- `src/index.ts`：只导出别人需要的东西；每个导出写一行说明；不导出 SQL、表模型、密钥或内部类。
- acquisition 的 `src/fetch-runtime.ts` 只含抓取适配器与守卫，禁止 import `store/`（它在无数据库的 fetcher 进程里运行）。

## 3. 边界上的校验

- 所有外部输入（HTTP 请求、任务载荷、领域事件、模型输出、信源响应、fetcher 返回、行业包配置文件、配置与密钥文件）在进入模块时用 schema 校验；校验失败给出可读原因。
- 模型输出必须按能力的输出 schema 校验；不通过视为该次调用失败（计费照常记录），按能力的重试策略处理。
- 未知配置项一律拒绝（沿用 AIHOT：信源配置填了不认识的键，保存被拒绝、抓取直接失败并显示原因，不悄悄退回通用解析）。
- 原始网页、PDF、模型输出一律视为不可信文本，不作为指令执行，不拼进 SQL 或命令行。

## 4. 错误处理

- 区分三类错误：
  1. **可预期的业务结果**（例如“信源权限不允许全文”“相关能力已被异常熔断暂停，等待负责人恢复”）——用返回值表达（结果类型/判别联合），不抛异常；
  2. **可重试的外部失败**（超时、5xx、限流、fetcher 超时）——抛出带分类的错误，由任务框架按“重试、退避与租约参数表”重试；
  3. **程序缺陷**——直接抛出，进入死信并推送告警。
- 面向负责人的信息（私有页面提示、告警文字）使用中文业务语言（例如“该网站连续 3 次返回 403，已按规则推迟重试”），技术细节放在诊断字段。
- 不吞错误：`catch` 后要么处理、要么带上下文重新抛出。
- 单源、单材料、单次调用的失败只影响它自己；批处理中一条失败不能让整批失败（除非是事务性要求）；一条业务线的失败不能拖停另一条线。
- 数据库或身份存储故障返回 503，不当成“未登录”或“被拒绝”，不清除合法会话。

## 5. 时间

- 时间值类型与纯函数放在 `@amp/contracts` 的时间子模块；当前时间通过注入的 `Clock` 端口获取（测试可冻结）。
- 数据库统一存 `timestamptz`（UTC）；另存来源原始 IANA 时区（未知为空）与精度字段（`date`/`minute`）；法律/政策的各类日期分维存储。
- “北京时间”是业务概念（报告的出刊时刻与覆盖窗口、用量月份〔用量报告与每 100 元用量提示按北京时间自然月计〕、“今天”、旧文判据），统一用 `Asia/Shanghai` 计算，函数名显式带 `Beijing`，例如 `beijingDayRange(date)`。
- 只有日期的来源时间，存储为当地日期 + 精度 `date`，显示时不补时分。
- 规则见 `02-rules/04-time-semantics.md` 与 ADR-0010。

## 6. ID

- 实体使用带类型前缀的稳定 ID：`src_`（信源）、`mat_`（材料，公开 URL 中的“条目”即材料）、`evt_`（事件）、`sty_`（发展线）、`thr_`（政策线）、`ent_`（实体）、`rpt_`（报告刊期）等，前缀后为全局唯一、可按时间排序的随机串。完整前缀表见 `03-data/01-domain-model.md` 第 1 节。
- ID 在创建时生成，**不从 URL、标题、分类、阶段等可变属性派生**；一经公开永不改变、永不复用；合并事件时保留被合并方 ID 的重定向。
- 旧项目公开 ID（`itm_`、`evt_`、`sty_`、`rpt_` 等）**不导入、不建别名表、不复用**（Owner 2026-10-01 全重做，DEC-20、DEC-21）：新站从空库生成自己的 ID；**新站不为旧站的任何地址做兼容或重定向**——旧站的条目、事件、报告等链接、旧 RSS 与旧接口地址在新站都是不存在的地址，一律走通用的 404（页面类是带首页与搜索入口的“页面不存在”页，接口类是统一错误体 `not_found`），不查库、不按形似旧 ID 的字符串去找新对象、不跳转（见 `03-data/04-legacy-migration.md`）。公开 ID 不复用是新站自身的规则。

## 7. 数据库访问

- 采用“SQL 优先”：查询以参数化 SQL 书写（沿用 AIHOT 的 postgres.js tagged template 风格），不使用会隐藏查询的重型 ORM。
- 每个 repository 为对外查询声明 Zod 行 schema 并在边界解析；集成测试断言表的列集合与行 schema 字段一致（改列名必须让对应测试失败）。模块外禁止直接拿到 `sql` 对象。
- 连接按进程角色提供：`dbFor(role)`（`public_read`、`feedback_write`、`private_ops`、`auth`、`worker`、`migrate`），由组合根注入；公开 GET 路径只用 `public_read`；不 import 全局连接单例。备份作业另有专用只读 `backup` 登录，不经模块注入；web、fetcher 没有数据库登录。
- 每个模块的 SQL 只能出现本模块 schema 的表名（静态检查）。
- 写操作在事务中完成；需要推进流水线时，在同一事务内写领域事件（outbox）；私有写操作与审计同事务。
- 长任务不持有长事务；外部网络与模型请求一律在短事务之外；分页处理大批量数据。
- 迁移规则见 ADR-0003：按模块目录、UTC 时间戳命名、跨 schema 视图声明依赖、只增不破、expand-contract、已合并迁移不可改。
- 新表必须写：主键、`created_at`、必要的唯一约束（幂等与阶段键依据）、面向查询的索引。**数值**：不设 numeric/int8 的全局 Number 解析；`numeric` 保持字符串或 decimal，`int8` 用 bigint/字符串，仅在分数、计数等明确处局部转换；金额以“币种 + 最小单位整数”（微元）进入领域层，账本加减用整数或 decimal，不用浮点（`02-tech-stack.md` 4.3、`03-data/01-domain-model.md` 原则 10；预算模块验收：累计 10 万笔微小预留与结算后与数据库精确求和逐位一致）。
- 不在数据库存巨型 JSON 快照替代关系模型；JSON 列只用于有 schema 版本的半结构化数据（例如模型原始响应），并限制大小。原始网页、PDF、附件、截图存对象存储（`platform/storage`），数据库只存键、sha256、大小、媒体类型、权限版本与到期时间；先写暂存对象、再在事务里提交引用。

## 8. 任务（队列）

- 任务声明必须包含：名称（`<模块>.<动词>`）、载荷 schema、所属 lane 与 stage（即投入的 `<lane>.<stage>` 队列）、幂等键、并发上限、重试次数与退避（引用“重试、退避与租约参数表”，不自写数值）、超时、是否可能产生费用、记账类别、单次输入长度上限。
- 阶段成功以本模块结果表上的唯一键 `(subject_revision, stage, recipe_version)` 为准；recipe 版本含解析/规则/提示词/输出 schema 版本，不含运行时间；已有合法成功结果与费用不重做。
- 处理器必须幂等：重复执行不会产生重复数据或重复费用；消费领域事件用 inbox `unique(consumer, event_id)` 去重。
- 长任务（全文翻译、法规全文处理与解读）持有租约并定期写检查点；结果写回是对 `(task_id, lease_token, attempt, 来源权限版本, lane 控制修订)` 的比较交换，失配只结算费用、不晋升结果。
- 需要全局串行的步骤用数据库锁或唯一约束，不依赖 `localConcurrency: 1`。
- 付费步骤前后都要可恢复：先写回执再调用，先持久化响应再使用（ai-gateway 负责）；结果未知不自动重发。
- 任务之间传递 ID、版本与 lane，不传大对象或密钥；处理器开始时读取最新状态，并检查“是否仍需处理”（例如材料已被下架、该 lane 已暂停、权限已收窄则跳过）。
- 定时任务使用北京时间表达业务时刻（例如“每天 08:00 出日报、每周一 10:00 出周报、每月 1 日 10:30 出月报”，沿用 AIHOT），在声明中注明时区。
- 超过重试上限进入死信并推送告警；不写人工逐条重试入口。

## 9. 配置、密钥与运行控制

- 配置只在 `platform/config` 中读取并按**进程角色**校验（web、public-api、private-api、worker、fetcher、migrate 各一份 schema），其他地方通过注入的配置对象使用。角色禁止的字段出现即拒绝启动：web 不接受数据库连接串或模型密钥；fetcher 不接受数据库凭据；生产不接受出网代理设置（如 `EGRESS_PROXY_URL`）。
- 服务级密钥（数据库口令、会话/CSRF/限流/游标 HMAC、对象存储凭据，以及模型密钥与告警渠道地址的封装材料）一律为只读挂载的密钥文件，配置里只放文件路径；禁止放环境变量与命令行；启动时自检文件属主、权限、类型与大小，不符拒绝启动。每个进程只挂自己需要的文件（`06-security-and-access.md` 4.2）。密钥永不写入仓库、日志、错误信息、前端包或数据库明文字段；在私有页面录入的模型密钥与告警渠道地址以信封加密存储（只有 worker 能解密），只显示指纹。
- 可由负责人调整的业务参数（信源与采集配置、加入信源时的权限确认与逐源收紧开关、模型接入与环节指派、异常熔断阈值与预警比例、站点资料含备案号与许可证信息）存在数据库，只经 ADR-0018 所列私有页面修改；代码中只保留默认值。
- 工程参数（lane×stage 并发与保留份额、重试与租约参数、告警阈值）是随代码发布的版本化配置，经 PR 修改。
- 行业参数（分类、法域字典、词表、提示词、门槛初值、品牌文案）放在 `industry/`，变更需要 Owner 确认的规格依据；其中矿业版评分标准（`selection-score.md`：读者定义、内容类型与权重表、两张清单、封顶规则）是草案，生效前须先经 Owner 审阅确认，未经确认不得用于正式站的精选（ADR-0021）。
- 运行控制按业务线：`LaneControl`（采集暂停、处理暂停、公开暂停，带原因与到期时间）存数据库，暂停触发告警；另有一个“紧急全停”；异常熔断状态（ENT-82）是独立记录，与 `LaneControl` 暂停互不覆盖。环境级安全阀 `COLLECT_ENABLED`、`MODEL_CALLS_ENABLED`、`PUBLISH_ENABLED`、`NOTIFY_ENABLED`、`INDEXNOW_ENABLED` 只控制“是否对外发出”，不改变代码路径；开发与测试环境默认全部关闭。

## 10. 日志与追踪

- 结构化 JSON 日志；必带字段：时间、级别、模块、`lane`（适用时）、`trace_id`；按需带 `job_id`、`source_id`、`material_id`、`event_id`、`instrument_id`。
- 禁止记录：密钥、完整正文、完整提示词与模型响应（这些进入受控的私有表，并有保留期限）、读者个人信息；正文、token、个人身份不作为高基数指标标签。
- 一条流水线（定时触发 → 采集 → 加工 → 归组/法规处理 → 发布）共享追踪上下文；任务载荷携带 trace 信息；用 OpenTelemetry API 打点，默认不导出（ADR-0020）。
- 面向负责人的运行状态写入业务表（`platform/ops` 按 lane 汇总）并以告警推送；日志只给工程诊断与只读 MCP。

## 11. 前端

- 页面数据只通过 `@amp/api-client` 获取；公开路由组只用公开客户端，私有客户端只在私有路由组中使用。不在前端实现业务规则（例如精选门槛、时间精度判断），只做展示。
- 所有用户可见文案集中管理（读者站与私有页面各一份文案表），便于统一措辞与审查；不在组件里散写长文案。
- 时间显示使用接口返回的精度与标签（例如 `timestamp_label`），前端不自行推断：一律按 `Asia/Shanghai` 显示；来源时区已知且当地日期与北京日期不同才括注来源当地时间与时区；只有日期精度只显示日期；**不使用浏览器时区**。
- 支持浅色/深色/跟随系统；桌面与手机同一路径、同一功能；返回列表时恢复阅读位置。
- 可访问性：语义化标签、键盘可达、对比度达标；图片有替代文本。
- 性能：列表不加载正文；首屏只取必要数据，首屏接口请求数有上限且远低于公开入口突发额度；私有路由按路由拆包，不进入公开页面包；静态资源由构建执行器构建。

## 12. 测试

见 `05-quality/03-testing-standards.md`。最低要求：

- 运行器统一为 Node 内置 `node:test`；不引入第二套单元测试框架。
- `domain/` 的业务规则有单元测试；
- 每个任务处理器至少有一个集成测试（临时 PostgreSQL——`DATABASE_URL` 必须指向 `*_test` 库、每个测试文件从已迁移模板库克隆；假模型服务；录制的信源响应），覆盖：成功、外部失败、重复执行、人工决定不被覆盖、租约过期后旧结果不晋升；
- 公开接口有契约测试（响应符合 OpenAPI）；不存在的地址（含旧站条目、事件、报告、栏目、RSS 与旧接口路径的样本）一律 404、不带 `Location`；
- 两条业务线的隔离测试：“暂停新闻、法规继续”“法规回填、新闻实时流不受阻”，以及双 lane 公平基准；
- 按角色的配置校验测试与数据库登录允许/拒绝矩阵（真实登录）；
- 修复缺陷时先写能复现的测试；
- 用量与异常熔断：用假模型与注入时钟覆盖三个触发条件的边界（同一输入 1 小时内重复付费 ≥3 次；单篇 5 元与单份法规文书 100 元；单日 50 元与 7 日均值 3 倍）、各指标达到阈值 70% 时先预警且不暂停任何处理、每 100 元用量提示的跨档合并，以及熔断只停付费、不停公开；
- 测试不访问外部网络与真实模型：`make verify` 只用假模型与已缓存回执，真实模型评测另行发起、用最小必要样本。

## 13. 提交、PR 与合并

- 分支：`agent/<泳道名>/<task-id>-<slug>`（泳道名是开发泳道，不是业务线 `news`/`policy`）；提交信息用中文或英文均可，但 PR 标题与描述用中文。
- PR 模板见 `06-agents/templates/pull_request_template.md`；审查清单见 `06-agents/01-parallel-development-rules.md` 第 7 节。
- 合并规则（ADR-0017）：PR-only；squash 合并保持线性历史；禁止强推与删除主分支；审查意见须解决；管理员同样受约束。合并前必须附该 PR **最终 SHA** 的 `make verify` 通过回执（在隔离环境、干净检出上执行，不得在生产主机执行）；不手工填写成功、不删除必需检查。
- 合并后不自动部署；部署是独立、可回退的操作。
- 生成文件（OpenAPI、api-client、类型）由命令生成并提交，`make verify` 检查无漂移；不得手改生成文件。
- 用户可见变化附 `changes/*.md` 产品更新片段（模板：`06-agents/templates/product-update-fragment.md`）；产品更新只在发布成功后登记。

## 14. 新增依赖与工具的门槛

- 新增运行时依赖、开发工具或基础设施组件，PR 必须写明：解决的已观察问题、替代接口、失效与回退方式、运维负担；“2026 年应该有”不是理由。
- ADR-0015 的“按触发条件再引入”表中的工具，只在触发条件满足后引入，并在同一 PR 中更新该表。
- 一个包管理器、一份锁文件（pnpm）；禁止 `latest` 进入发布配置；升级经原有契约、安全与内容回归。
