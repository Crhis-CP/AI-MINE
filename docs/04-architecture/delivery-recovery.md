# 精选内容投递恢复

TASK-0408先声明兼容字段，消费者随后实现。每条投递仍使用目标与事实的唯一去重键，sending/unknown不等于未送达。

`DeliveryIssue`可带retry_reason（not_sent/rate_limited或null）、retry_at和abandoned_at；旧响应省略时默认人工处理。人工放弃保留failed历史状态，abandoned_at使其退出自动队列与待办。明确未发和限流拒收才可自动重试；5xx、连接中断或响应丢失按unknown核对，不猜测外部未执行。

消费者只在现有恢复定时任务中领取到期记录，使用已有updated_at版本认领；重新检查目标enabled/enabled_at、当前公开精选、静默、撤回、12小时时效及事实去重身份，重新生成卡片。每条投递最多6次自动发送尝试，达到上限转人工；人工核对后的明确重发单独记录。限流至少等待现有2分钟通知等待间隔，遵守有效Retry-After并随尝试次数退避；停机未发保留原次数。人工明确重发仍须同样资格检查，不能被自动循环代替。

回放覆盖发前停机、限流拒收、HTTP5xx、响应丢失、并发领取、人工放弃、目标关闭/重新启用、内容撤回/变更和时效。旧failed不迁移为可重试，不写历史推测。所有正式目标和环境开关保持原状态。
