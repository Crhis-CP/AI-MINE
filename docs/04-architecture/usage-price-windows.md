# 缓存命中与绝对时段计价

TASK-0413只交付兼容契约、契约测试与OpenAPI。当前消费者尚未使用新费率，不能把本PR称为费用精确结算已上线；运行接入由TASK-0367集成人另立消费者卡。无需新依赖或付费服务，真实模型调用预算0。

## 1 价格含义与兼容

- `cache_hit_input_per_million_micros?: string | null`：基础缓存命中单价，单位沿用原输入/输出字段的“每百万token的人民币微元”；最多两位微元小数，即八位人民币小数。省略/null表示没有单列缓存价，维持原总输入计价；明确`"0"`是有依据的零单价。
- `rate_windows?: UsagePriceWindow[]`：省略或空数组使用基础价。每段必需`starts_at`、`ends_at`、`input_per_million_micros`、`cache_hit_input_per_million_micros`、`output_per_million_micros`。缓存字段可null但不能省略；段内费率是完整替换，不从基础缓存价隐式继承。单次固定价和最坏费用依据仍使用基础报价字段。
- 时刻必须是`YYYY-MM-DDTHH:mm:ssZ`，精度为秒，无偏移别名、无小数秒。区间左闭右开，最多128段，按开始时刻升序且前一结束不得晚于后一开始。不自动排序、拼接、循环或推断中国节假日；未命中任何时段使用基础费率。
- 仍要求真实`observed_on`/`valid_until`日期、有效期大于0且不超过45天，保持结束日包含全天的现行北京时间判断。时段位于`observed_on 00:00:00 +08:00`至`valid_until次日00:00:00 +08:00`之间；UTC只是时段表示，不能改变旧日期业务语义。
- 缓存价非null或有时段时，基础输入/输出单价须完整，保证时段间隙仍有明确基础计价。旧按请求收费可继续省略全部新增字段；不猜测不同模型、端点或版本共用价格。

合法示例：2026-10-23观察、10月24日到期的价格，时段可从`2026-10-22T16:00:00Z`开始，最晚在`2026-10-24T16:00:00Z`结束；结束时刻本身不适用该段。明确相邻两段在边界只命中后一段。非工作日是否特价必须转换成有依据的具体UTC时段，不引入日历服务。

## 2 调用前快照与结算决定

复用`ai.usage_attempts.quote`现有JSON及其`price_id`、`price_version`、完整`price`、`bounds`、`reserved_micros`，无需为该快照新建表。消费者在真实物理请求提交前最后一次可确认的时点冻结：

```ts
// 后续UsageQuote兼容补充；本PR不修改运行类型。
quoted_at?: string; // 实际报价UTC时刻，旧quote缺省保持历史语义
rate_window?: UsagePriceWindow | null; // 实际采用段的完整副本；null明确采用基础价
```

带新报价的请求必须同时有这两个字段；不靠结束时再查询价格，也不按数组下标回查一份已修改价格。等待发生于提交前且跨越时段边界时，在未发出请求的前提下重新冻结并更新本次预留；提交后不可改价。每次真实重试有自己的attempt和调用前快照；免费复用已有结果不产生新的费用。供应商按完成时间或其他未知时点计价时，不能冒用本方案的请求开始时点，须另有价格依据或实际账单。

实际结算优先级：

1. 供应商提供可核的实际CNY收费与actual依据时沿现有actual路径，独立保留用量缺项。
2. 未提供实际收费，且当前采用的缓存价为null/缺省时，按既有总输入/输出与固定单价估算，basis仍为estimated。
3. 单列缓存价时，必须具有同一物理尝试的总输入、缓存命中、缓存未命中和输出用量，均为非负安全整数，且命中+未命中=总输入。金额为固定费＋未命中×输入价＋命中×缓存价＋输出×输出价，用既有BigInt定点算法，最后总额向上取整到微元，basis仍为estimated。
4. 缓存分解缺失、数量不守恒、无调用前依据或价格身份不匹配时，费用保持unknown/null并记录具体原因，不记0、不用当前报价补旧账、不自称精确；不因费用缺项把已收到的有效内容标成模型结果未知或重新付费。

预留是最坏费用估计，不是结算：不知道未来命中比例时，输入上界采用输入价与明确缓存价中的较大者，再加输出上界、协议/图片上界与固定费。没有证明缓存总更便宜，不加“缓存价必须更低”的无根据限制；`max_request_micros`保持已有最坏费用依据用途。

旧quote没有新快照字段，保持当时基础价格计算语义；不能根据后来新增窗口或缓存价回算“本来应收”。若旧quote意外已有新价格字段却缺调用前采用时段证据，按unknown处理，单列数据问题，不借历史时刻推算新快照。

## 3 必须一起接入的消费者

| 消费者 | 最小改动 | 完成判据 |
|---|---|---|
| `providers/usage-pricing.ts` | 报价匹配具体时段；保存时刻/段副本；预留取较大输入费率；结算严格缓存守恒；保留旧quote路径 | 边界仅命中一段，跨时段完成仍用调用前快照，价格换版不改旧attempt |
| `providers/usage-protection.ts`与回执写入 | 预留/提交/结算都持久保存同一快照；补记不得查新价覆盖历史；unknown费用与unknown模型结果分开 | 失败、重试、免费复用不重记；坏用量保留unknown和原因；旧费用/人工决定不变 |
| 后台`UsageProtection.tsx`及管理员价格保存 | 读取、显示、明确编辑/删除缓存价与时段；保存旧配置时保留不修改的新字段；保留expected_version和负责人确认 | 改说明/有效期后时段不被无声删除；缩短日期不裁剪时段而明确报错；非法顺序可修正 |
| 月账/费用详情 | 沿现有actual/estimated/unknown口径，显示采用的价格版本、时段、用量缺项原因；不把estimated改名actual | 汇总按物理attempt去重；未知不为零；账单对照能定位费率和用量来源 |

字段只添加到现有私有价格接口，公开HTTP、暂停、评分、模型路由与请求次数阈值均不改。原始供应商usage字段由既有provider读取层规范化；不以可选别名拼出来自不同响应的命中/未命中数量。如费用详情需新增HTTP字段，仍先提相应契约卡，不把私有quote整份任意暴露。

## 4 验收与发布边界

本契约片：旧输入深相等、空/缺新增字段、显式零/小数、相邻边界、逆序/重叠、越过北京时间有效日期、无效日历日期、时区/小数秒拒绝、缺段内费率、129段拒绝；OpenAPI受管生成物一致。自定义跨字段条件由Zod运行校验，OpenAPI形状说明不代替这些条件。

消费者片必须补：无命中/全命中/混合；命中价高于基础价的预留；缓存数缺失/负数/小数/超安全整数/不守恒；输出为0；仅固定费；价格过期；相邻边界前后；请求提交前跨边界等待；请求提交后跨边界完成；期间价格换版；进程重启；重试/免费复用；当前报价不能填历史缺账；后台读改存不丢字段、并发编辑冲突。实际CNY账单优先及缺用量不等于传输未知也须回归。

契约PR先供复核，不合并直到集成人确认设计；即使合并，也不得独立部署后在生产写含新字段的价格。因为旧后端可能接受并忽略新价、旧前端会丢失其不认识字段，必须完成消费者和表单后统一发布。回滚前不把已写新报价交给不支持它的程序；保留原价格版本与账本，不通过删字段改历史费用。
