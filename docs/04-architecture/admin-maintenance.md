# 后台维护

正文展示更新、日期校正和反馈处理都是受保护的后台操作，复用现有会话、能力与CSRF。契约在contracts/http/admin-maintenance；本准备片未安装运行处理器。

正文只刷新图片、链接和排版时，先读取原来源并预览数量变化，再按当前版本确认。正文文字必须相同；已有模型译文复用已有结果，人工译文保留，不能借预览调用新模型或付费读取器。新正文内容应另走正常抽取与评估。重跑各步骤的稳定请求编号须持久去重，不能仅靠队列短期单例键；已有操作原因要留下。

日期由操作者核对原文证据后校正或撤回；日期精度、真正时刻和未知分别保存。前后状态及是否退出自动事件/热度要先展示，提交时再次核验版本和人工控制。原稿链接、既有评分与人工归属不因元数据修正被覆盖。

反馈限流按同一来源共享一小时窗口：最多3份不同内容、20次尝试，持续超限暂停一小时。重复点击与丢失响应复用原反馈编号；改变内容、联系方式、页面或图片属于不同反馈。手动解除也清理旧限流窗口。邮箱封禁只由后台针对已保存反馈明确操作，48小时到期；自动限流不把未验证邮箱当作身份。原有人工长期封禁继续有效。

自动限流数据与后台人工控制须保持最小数据库权限，公开反馈写入端不能因此获得解除人工封禁、读审计详情或运营者凭据的权限。运行与迁移在统一分支接入后验证。

展示确认返回既有jobId结果，在content.extract-body可选presentation变体中由worker执行；该变体不进入常规评分流程，仍在写入前复核预览哈希与当前权限。
