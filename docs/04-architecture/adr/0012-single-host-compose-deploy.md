# ADR-0012：单机 Docker Compose 部署；按 digest 部署签名制品、自动回滚且回滚也要验收、发布成功后登记产品更新

- 状态：【设计】工程基线提案。部署区域“中国大陆”为【Owner 决定】（08-owner-voice DEC-02，2026-07-22；与 ICP 备案一致）；主机规格【Owner 决定】2026-10-01（DEC-18）：先做容量基准，达标沿用已购 4C4G，切换演练临时租按量机器；Owner 强调这是全新重写的项目。原第 2 条“镜像构建执行器”由 ADR-0017 取代。
- 修订：2026-10-01 按 Owner 答复修订——规格由“待容量基准、需 Owner”改为已定（容量基准仍须先做）；第 5 条同机切换窗口按 Owner 已定的全面切换与“不迁移旧数据”表述（Q-24、Q-25）。2026-10-03 按 Owner 更正修订第 5 条：旧站只读不保留，同机切换的磁盘例外改为“切换后到旧栈按退役清单回收之前”（08-owner-voice DEC-26，TASK-0016）。

## 决定

1. 首期部署在中国大陆的单台主机。默认先做容量基准：达标即用已购腾讯云轻量服务器（上海，Ubuntu 24.04，4C4G）；切换演练临时租用按量机器（DEC-18，Owner 2026-10-01 已定）。Docker Compose 运行 `caddy`、`web`、`public-api`、`private-api`、`worker`、`fetcher`、`postgres`，迁移与备份为一次性任务容器；没有运营台容器（`admin-web` 已取消，ADR-0008、ADR-0018）。容器内存初值与网络分段见 `07-deployment-and-ops.md` 2.2、2.3。
2. 【已由 ADR-0017 取代】镜像在独立构建执行器上按确切提交构建（默认不用 GitHub Actions，不在生产主机构建），生产主机只按 digest 拉取经受信公钥签名的制品。
3. 发布顺序：预检（可用内存 ≥1GiB、可用磁盘 ≥4GiB）→ 只增不破的迁移 → 替换服务 → 健康检查 → 公开读取冒烟 → worker 跑通一轮 → 外部读回发布标识头 → 成功后登记本版本的产品更新。任一步失败自动回滚到上一版本镜像。**回滚也要验收**：回滚后对上一版本重跑同一套检查，失败则非零退出、进入维护态（公开入口只读静态页或关闭）、告警、不登记产品更新；发布状态机持久化阶段，进程被杀后下次启动对账未完成的激活或回滚。始终保留当前与上一版本。验收：T-149、AC-OPS-06。
4. 新闻与法规的采集、加工、发布在服务器上持续运行，不依赖开发会话、构建执行器或 CI；它们不可用只影响软件发布。
5. 磁盘口径：系统盘已用 < 20,000,000,000 字节（Owner 对该服务器的要求；若换规格，按新盘容量的同一比例另定并由 Owner 确认，Q-24；同机切换后到旧栈按退役清单回收之前允许暂时超过，Owner 知情，Q-25；Owner 2026-10-01 已定：全部功能完成后一次性全面切换；2026-10-03 更正：旧站只读不保留，新站上线当天旧站停止服务）。回收对象只限已停止且身份匹配的受管旧容器、无引用的旧镜像标签、已验证的旧发布目录、泄漏的 Compose 网络；禁止全局 prune、强制删镜像、删卷、为达标删除业务数据或证据；回收失败只告警，不回滚已成功的发布；容器日志设大小上限。
6. 数据库不开放公网端口；私有页面与 `private-api` 只在 `PRIVATE_HOST` 的私有路径上可达（生产即主域名的 `/admin`，ADR-0026）。
7. 各服务按角色分别挂载只读密钥文件，不使用共享 `env_file`（`01-target-architecture.md` 第 9.1 节）；所有基础镜像写“补丁版本 + sha256 摘要”（ADR-0015）。
8. 备份与恢复：每日 custom dump 经 age 客户端加密后写入私有、版本化的对象存储桶（与原件分桶、分权限），默认保留 7 日 + 4 周（可选月备份）；默认 RPO ≤24 小时、RTO ≤2 小时（需 Owner，Q-59）；公网发布前与切换前各做一次隔离恢复演练，此后每月一次，结果只经告警推送（`07-deployment-and-ops.md` 第 5 节；验收 T-084）。对象存储桶是否已创建由 Owner 确认，默认按“没有”处理（Q-60）。

## 后果

运维简单、成本低；单机是单点，靠每日备份到对象存储与恢复演练兜底；扩容路径见目标架构第 12 节，默认触发线沿用旧ADR-0010（CPU>70%、内存>75%、数据库>12GB、搜索 p95>300ms、文档>10 万）。

## 推翻条件

容量基准显示 4C4G 无法同时满足公开读取目标与两条业务线处理吞吐时，按基准结果选规格或把 worker/fetcher 拆到第二台机器（须 Owner 批准费用）。
