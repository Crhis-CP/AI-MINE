# ADR-0030：退役新程序的API运行分流

- 状态：已接受；依据Owner 2026-10-25的固定AIHOT通用架构迁移决定（DEC-77），实施与上线分别验收
- 类别：Owner决定 + 工程落地
- 日期：2026-10-26
- 决策者：Chris确认架构目标，Codex落实已有统一API的运行契约退役
- 关联规格：TASK-0490、F-IAM-01、F-PUB-03、ADR-0028

## 背景

默认Compose已经运行api/worker/web，但新API仍可按API_ROLE启动public-api/private-api，web还可按PRIVATE_API_BASE_URL分流。这些是可执行的旧运行选择，不是保留矿业功能所必需。旧进程名同时出现在数据库权限工装和历史发布恢复代码中，不能按名字批量删除。

## 决定

1. buildApp不再接受运行角色参数，统一注册公开与受保护后台路由；startApi只启动统一API。API_ROLE省略或为api均可，旧分流及其他值在加载后台配置、建立数据库连接前拒绝，错误不回显值。
2. 移除npm私有API启动脚本。web生产代理、开发代理、SSR加载器及后台客户端统一使用API_BASE_URL；PRIVATE_API_BASE_URL不再选择目标，也不进入web允许的运行环境。
3. 保留后台Host校验、登录、会话、CSRF、模块后台授权、读者请求Cookie隔离和web无数据库/模型秘密。公开路径不套后台Host门。
4. 数据库真实角色与旧profile权限工装保留；它们不再能选择新API运行模式。现有heartbeat.private-api键保留供运行观察消费者连续读取。历史发布、备份和回退拓扑识别不改。

## 后果

内部buildApp及API地址帮助函数的源码调用契约改变，所有实际调用者与测试同批更新；对外HTTP路径、请求/响应、评分与来源规则保持。携带旧API_ROLE的新程序启动失败，需要按明确错误改为统一入口，不能静默运行另一套服务。旧制品仍按原发布恢复方案运行，不用新程序的运行选择替代恢复。

旧的“公共API不注册后台路由”测试改为同一入口下的Host/登录/CSRF/权限验证；真实public_read等数据库权限验证继续保留，不靠删断言过检查。

## 推翻条件

若Owner重新决定拆分服务，需要另立架构决定和发布范围；不通过恢复过时环境变量隐式启用。
