## 背景

“网站可以公开访问”不等于“可以保存全文、送第三方模型或在站内转载”。旧项目为此设计了技术获取、内部处理、持久化、公开展示四层权限，并逐源审定许可范围（例如 Geoscience Australia 的 CC BY 4.0、RSS 只有摘要等）。旧分支按“原文公开 / 译文公开”分开记录。AIHOT 用 `site_fulltext`、`syndicate_fulltext` 两个开关控制全文展示。A 包八项把全文与译文合并、没有到期时间；B 包七项没有“自写导读”、不分元数据与全文留存。

2026-10-01 Owner 声明全部信源都已获得许可：本包不再把“未知按禁止”作为建档默认，也不再要求逐源取证后才开放；矩阵的价值转为两件事——**逐源收紧**（来源方异议、Owner 指示或法律要求时即时关闭）与处理时的硬门（`ProcessingPermit`）。

## 决定

每个信源（来源契约，ENT-03）维护以下**九项**能力的权限（DEC-58，取两包与旧分支的并集），取值 `允许 / 禁止 / 未知`（Owner 声明许可的信源九项一律建档为 `允许`；`未知` 只作技术缺省，不再是建档默认）：

| 能力 | 含义 |
|---|---|
| `fetch` | 服务器抓取页面/接口 |
| `store_metadata` | 保存标题、时间、链接、署名等元数据 |
| `process_locally` | 在本机做清洗、判重、规则分类等处理 |
| `store_fulltext` | 保存正文全文与原件（决定是否写对象存储，ADR-0005） |
| `external_model` | 把内容（含标题、摘要）送第三方模型处理 |
| `public_excerpt` | 公开展示原文短摘录 |
| `public_summary` | 公开展示项目自写摘要/导读 |
| `public_original_fulltext` | 站内展示原文全文 |
| `public_translation` | 站内展示全文中文译文（改编） |

另有**预留的第十项** `syndicate_fulltext`（站外再分发全文：公开 API 正文、全文 RSS、公开 MCP 正文），默认关闭（按禁止处理；不在 2026-10-01 许可声明范围内，Owner 另行决定，Q-47），见第 2 条。

**每个权限版本**包含：各项取值；证据数组（链接、证据类型 `kind`、`checked_at`、`valid_until`、中文依据、所支持的用途、适用的主机与路径前缀；Owner 声明许可的证据类型为 `owner_declared`，证据文本“Owner 2026-10-01 书面答复”）；审定人（负责人，加入信源时一次确认）与时间；`expires_at`（`owner_declared` 为空，不自动到期）；条件码（`attribution_required`、`third_party_excluded`、`no_official_endorsement`、`licence_at_access_applies`，及文类范围与排除项）；`attachments_in_scope`（PDF、XLS、图像等附件是否在范围内，是**单独的布尔字段**，不是第十项能力）；给读者看的中文许可说明。

1. 取值为 `禁止`，或没有任何权限记录（技术缺省的 `未知`）时按禁止处理（失败关闭），只关闭这一层，不阻塞该信源在允许范围内的其他处理；“未知按禁止”不再是建档默认（Owner 2026-10-01 许可声明，DEC-33）。权限变化形成新版本，历史处理可追溯当时使用的版本；权限变化**不产生新的材料修订**（BR-SRC-14）。
2. 站外全文再分发（全文 RSS、公开 API 正文、公开 MCP 正文）与“站内展示全文”是两回事：只对 `syndicate_fulltext = 允许` 的来源返回正文。该项**默认关闭**（按禁止处理，不在 2026-10-01 许可声明范围内），启用与否由 Owner 另行决定（Q-47）；在此之前这些出口一律只给导读 + 原文链接（失败关闭）。本站页面按 `public_original_fulltext` / `public_translation` 判断。
3. **审定机制：加入信源时一次确认**（BR-SRC-36；取代已废弃的 BR-SRC-31 所定的“保守档自动生效、扩展档三类自动规则、负责人批量确认”，Owner 2026-10-01 已定）：负责人加入信源时一次确认并记录时间，九项用途一律建档为 `允许`，证据类型 `owner_declared`，证据文本为“Owner 2026-10-01 书面答复”，确认人为负责人；不再有待审定清单、三类自动规则、第四类自动规则与批量确认。没有证据的“允许”仍无法保存——`owner_declared` 即为该证据。中国行政文书的“逐篇核验链”保留身份与完整性核验的作用（确认是机关正式文书、署名与文号齐全），不再作为许可依据。礼貌抓取（限速、并发、robots）仍是工程默认：robots 明确禁止的路径默认不抓，负责人可凭许可逐源覆盖并留审计（ADR-0019）。
4. **证据时效**：每条证据必填 `checked_at`。`owner_declared` 不设自动到期（`valid_until`、`expires_at` 为空）：法规线“许可证据到期自动下线”的规则不再适用于它（Owner 2026-10-01 已定）；**质量资格**（完整解读按“法域 × 文书类型”抽检通过后开放等）的到期与续期规则保留。其他类型的证据（将来如出现带期限的单项许可）仍可带 `valid_until` / `expires_at`：到期前 7 天（可配置）推送到期清单告警；到期后相应用途立即不可执行（视为未知），依赖它的公开内容在读取层同步隐藏，不等下一轮任务（BR-SRC-32；验收 T-148）。
5. **逐源收紧，即时生效，分线处理**：来源方提出异议、Owner 指示或法律要求时，负责人逐源逐项关闭相应用途（收紧依据分别记为 `source_objection`、`owner_instruction`、`legal_requirement`），即时生效，已公开的全文或译文随之撤回，与下架联动（经抑制层，ADR-0004）。资讯线——停止受影响的处理，公开全文退为仅导读 + 原文链接，删除不再允许保存的正文；放宽只对之后的处理生效、存量有界补做（BR-SRC-14）；法规线——公开用途（原文、译文）关闭时，整篇正文与解读从所有公开入口移除，**不退为摘要**；保存或内部处理用途关闭时停止处理，已存原件与回执按 `store_fulltext` 单独裁定（BR-POL-17，R18-policy-docs-002）。
6. 处理许可（`ProcessingPermit`）由 sources 按当前权限版本、按 lane 签发，携带权限版本、用途与 `expires_at`；ai-gateway 与 content 执行前校验签名与版本，不 import sources（ADR-0006）；在途任务的结果写回再次核对权限版本（ADR-0005 第 7 条）。
7. **外文稿公开条件不变**（中文标题 + 导读 + 完整中文正文，DEC-35）：“仅导读”只剩两种情况——技术原因（取不到正文或正文不完整）与逐源收紧。
8. **许可依据由 Owner 保留**（建议，不阻塞）：Owner 保留许可依据（合同、邮件、条款截图）备查；“请书面列出已取得许可的来源与范围”不再是必须提供的输入。

## 后果

合规边界清晰且可审计；不需要运营台——加入信源时的一次确认与逐源收紧开关在最小私有页面完成（ADR-0018）；翻译与全文展示按源默认开放、可逐源关闭。
