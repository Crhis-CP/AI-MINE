# ADR-0019：独立抓取进程 fetcher——网络与解析隔离、无主库与模型凭据【新增】

## 背景

信源失败、恶意页面、慢浏览器与大 PDF 不应拖垮 API 与模型处理；抓取代码也不该拿到数据库口令与模型密钥。A 包把抓取放在 worker 内；B 包要求独立 fetcher、无主库权限、经内部有界调用返回对象存储引用。首轮 D12-architecture-007 担心独立服务偏重（内部协议、对象暂存与回收、两端超时语义、额外内存）；裁决 DEC-30 定为独立 fetcher。本文按“最轻的独立进程”落地。

## 决定

1. `apps/fetcher` 是独立进程（与其他应用同一镜像、不同启动命令），单独的内存与 CPU 限额。
2. **凭据最小**：持有有时限的任务描述、出站策略、只能写对象存储暂存前缀的凭据；**不持有**主业务数据库凭据、发布/审核写权限、模型密钥、告警渠道凭据。
3. **调用方式**：由 worker 中的 acquisition 经一个内部有界 HTTP 接口（单一端点，只在内部网络监听）同步调用；fetcher 自己不持队列、不持业务状态、不重试。任务状态、租约、检查点、重试与业务提交全部在 worker 侧 acquisition 完成；fetcher 只返回结果元数据与对象存储暂存引用（ADR-0005 的暂存 → 引用 → 回收）。
4. **执行内容**：RSS/API/HTML 抓取与列表分页、HTML 正文抽取（沿用 AIHOT 的纯 DOM 抽取组件）、PDF 文字层与表格解析、OCR；浏览器渲染默认关闭、按源开启，在受限子进程执行；不常驻 Chromium。
5. **安全规则全部保留在 acquisition 的 fetch 运行时入口**：SSRF 与私网阻断、连接时地址校验、DNS 重绑定防护、重定向与跨主机校验、大小/超时/单主机并发硬上限、robots 与权限矩阵门（`fetch` 能力；礼貌抓取——限速、并发、robots——仍是工程默认，robots 明确禁止的路径默认不抓，负责人可凭许可逐源覆盖并留审计）、不登录、不带 Cookie、不过验证码或 WAF 验证页、不伪装 UA；默认只接受 https，负责人可为单源开 http 例外并留审计（DEC-56）；原始内容一律视为不可信文本。
6. **合规网络**：采集只从部署所在的合规网络发起；官方 API/RSS 优先；源站从大陆不可达时，信源健康标“不可达（网络）”并如实显示，**不用代理、境外节点或第三方抓取绕过，不伪造新鲜度**；生产配置出现出网代理设置（如 AIHOT 的 `EGRESS_PROXY_URL`）即拒绝启动。需要境外采集节点时另立 ADR，写明法律与安全评估和凭据隔离（Owner 决定项，默认不设）。
7. **付费抓取服务**（AIHOT 的 jina 阅读器、公众号、社交数据等）默认关闭；若 Owner 批准启用，预留与结算由 worker 侧经 ai-gateway 完成，fetcher 只执行调用。
8. 以后若改为拉取型协议，也必须保持同样的权限边界，不能为方便把数据库口令注入抓取进程。

## 后果

- 抓取与解析的资源峰值、崩溃、恶意输入被关在 fetcher 内；公开 API 与模型处理不受影响；
- 代价是一个内部接口与一套暂存对象回收；由于 fetcher 无状态、无队列，协议只有“请求 → 结果/暂存引用 → 超时”三种结局，两端语义简单；
- 集成测试断言：fetcher 容器内读不到任何数据库或模型密钥文件；出网代理配置在生产被拒绝。

## 推翻条件与演进

浏览器/OCR 池成为测得的容量瓶颈或发生过隔离事故时，水平扩展 fetcher 或把它迁到第二台机器（接口不变）。若测量证明独立进程的内存成本在 4C4G 上不可承受，可暂时以 worker 的受限子进程运行同一代码，但第 2 条凭据约束不变，并另立 ADR 记录。
