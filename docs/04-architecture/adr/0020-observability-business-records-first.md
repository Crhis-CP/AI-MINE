# ADR-0020：观测以业务运行记录与告警推送为主，按 lane 计算指标；trace 后端按需引入【新增】

- 状态：【设计】工程基线提案
- 修订：2026-10-01 按 Owner 答复修订——指标与只读 MCP 的“预算”改“用量与熔断”，应用内告警补用量提示与异常熔断触发（DEC-08）；到期预警补新闻许可证有效期（DEC-40）。2026-10-01 追加——应用内告警补用量预警（熔断指标达阈值的 70%，先于异常熔断）。
- 类别：工程基线
- 关联：`01-target-architecture.md` 第 10 节、`07-deployment-and-ops.md`、PIT-006、ADR-0018（告警取代运营台状态页）；对应 B：`B:architecture/03-stack-decisions.md` ADR-N10、`B:architecture/05-workflows-and-state-machines.md` §8

## 背景

旧站曾停更 5 天无人察觉（`docs/reviews/product-production-audit-20260920.md:16-20@main`）；阶段饿死靠“最久未推进时长”这类业务指标才发现，而不是通用 trace。B 包要求 OTel trace/metrics 全链路与每 lane/stage 指标，但全链路需要常驻 collector 与存储后端，在 4GB 主机上每加一个观测后端都占内存；A 包的做法轻，但指标里没有 lane 维度。不设运营台后，状态必须靠告警推送到人。

## 决定

1. 首期唯一必需的观测通道：**业务运行记录入库 + 结构化 JSON 日志**。每次采集尝试、模型调用、发布、报告生成都有记录；明细保留 30–90 天后汇总为日聚合。
2. **指标全部带 lane 维度**，由 `platform/ops` 定时计算写表：每个 lane×stage 的队列最老积压年龄与可用并发、重试/死信/结果未知数量、来源成功检查/新内容/正文完整率/中文完成率（分开统计）、发现到公开延迟、发布新鲜度、模型费用（按业务线、能力、信源；含每千项费用）与缓存命中率、重复率与误合并率、数据库增长率与对象回收率、磁盘与备份状态、出口带宽与月流量用量（默认 70%/90% 告警）。
3. **超阈值即推送告警**（ADR-0018 第 3 条），告警含责任模块、lane、失败类别、最近成功时间与恢复建议，不含密钥与正文。低频官方源按“计划检查成功 + 真实无更新”评估，不因没有新法规就判宕机。页面正常、容器健康、worker 心跳都不能单独证明内容持续更新。告警分三层：应用内业务告警（本条；含用量提示、用量预警〔熔断指标达阈值的 70%〕与异常熔断触发）、**独立于应用的外部检查**（云监控 + 不在同一主机上的外部拨测，应用整体停摆时内部告警也会停）、日程型到期预警（服务器、域名、证书、COS 容量、模型余额、新闻许可证有效期），后两层不依赖应用自身，阈值与渠道见 `07-deployment-and-ops.md` 6.3–6.5（验收 T-146、AC-OPS-07）。
4. 代码层用 OpenTelemetry API 打点并在任务载荷中传递 trace 上下文，**默认不导出**；每个实例有自己的心跳键。
5. 只读 MCP（面向开发 Agent，经服务身份）提供脱敏后的运行状态、队列、用量与熔断状态、发布版本与错误样本查询。

## 后果

不新增常驻观测组件；Owner 通过告警知道异常，开发 Agent 通过只读 MCP 诊断；指标口径两条线一致、可比较。

## 推翻条件（引入 trace 后端）

跨进程排障连续两次依赖手工拼接日志，或 fetcher/worker 拆到第二台机器后，再引入 trace 后端（优先托管服务或轻量单机方案，内存预算单列）。
