# ADR-0007：AI 能力单元化，改动以评测结果为准

- 状态：【设计】工程基线提案（M0 结束前由架构 Agent 定稿）；“质量结论只来自真实样本、合成测试不冒充质量验收”承接【Owner 决定】旧ADR-0037:49-52@policy（2026-09-26）
- 修订：2026-10-01 按 Owner 答复修订——第 1 条“预算类别”改“记账类别”；第 4 条评估人已定为 Owner 本人（DEC-15）并补精选校准样本由 Owner 标注（ADR-0021）；新增第 6 条（评测用最小必要样本、不设金额上限）。2026-10-01 追加——第 4 条补矿业版评分标准草案须先经 Owner 审阅确认才生效（ADR-0021）。
- 类别：工程基线
- 关联：`02-rules/03-ai-capabilities.md`、`05-quality/05-evaluation-sets.md`；对应 B：`B:architecture/03-stack-decisions.md` ADR-N07、ADR-N12

## 决定

1. 每个 AI 能力由“提示词文件 + 输入/输出 schema + 模型路由 + 黄金集 + 评测脚本 + 记账类别 + 所属 lane”组成，提示词放在 `industry/prompts/<capability>/`，版本即内容哈希。
2. 修改提示词、门槛或模型路由的 PR 必须附开发集评测对比；发布前用留出集复核。
3. 误合并（把不同事件并成一个）视为高风险错误，单独报告，设置上限门槛。
4. 合成测试证明行为正确，不证明真实新闻或法规质量；质量结论只来自真实样本评测与业务验收。法规“完整解读”的质量资格评判由 Owner 本人按“法域 × 文书类型”一次性抽检（Owner 2026-10-01 已定，DEC-15）；精选评分的校准样本（100–200 条矿业样本）同样由 Owner 标注，矿业版评分标准草案生效前须先经 Owner 审阅确认（ADR-0021）；不设日常审核。
5. 法规线的正文理解、完整中文、解读与全篇核验是程序编排的固定工作图，不是 Agent 循环（DEC-16）。
6. 评测与研究用最小必要样本，不设月度金额上限（原“研究与评测每月 ≤15 元”Q-54 作废，DEC-08）；`make verify` 只用假模型与已缓存回执，真实模型评测另行发起，同一输入加同一提示词版本不重复付费（回执与缓存复用）。

## 后果

多个 Agent 可以并行改进不同能力；换更强模型时有客观依据；需要持续建设和维护黄金集（质量泳道负责）。

## 推翻条件

无。评测驱动是长期原则；具体指标与门槛在 `05-quality/05-evaluation-sets.md` 调整。
