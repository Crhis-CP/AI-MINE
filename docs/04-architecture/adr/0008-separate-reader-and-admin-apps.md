# ADR-0008：读者站与运营台分为两个应用、两个域名【已废弃】

- 状态：【已废弃】（v2.0 合并时作废）→ 由 **ADR-0018 最小私有页面取代运营台** 替代
- 作废依据：【Owner 决定】旧ADR-0037:21-22,37-38@policy（2026-09-26）“不设运营台，不以其他名称恢复逐条选稿、审稿、翻译、重试或发布的产品工作流”；裁决 DEC-04、DEC-30；2026-10-01 按 Owner 答复修订：Q-04 已答复选 A（最小私有页面，不设日常运营台），DEC-04 定稿
- 关联：`01-target-architecture.md` 第 3、8 节；`03-module-map.md` 第 6–7 节

## 原决定（A 包原文，已作废，仅供追溯；其中的 admin-web、运营子域、运营端口均已取消）

1. `apps/reader-web` 服务公开域名、匿名只读；`apps/admin-web` 服务独立运营子域、全部页面需登录。
2. 两个应用共享 `packages/ui`，运营台沿用读者站视觉风格。
3. `api` 进程开公开、运营两个监听端口；反向代理只把运营域名的 `/api/admin/*` 转发到运营端口。

## 为什么作废

- 独立运营台应用（A 包规划 13 个功能区、M1 17 页）与 Owner 2026-09-26 批准的“不设运营台”直接冲突；
- 同一 api 进程开两个端口时，公开端口一旦被攻破，同进程里就有运营写角色的数据库连接与会话密钥，“数据库登录分开”名存实亡（D15-secops-019）。

## 替代做法（摘要，以 ADR-0018 为准）

> 2026-10-06 附注：下文“独立的私有主机名”一句已由 ADR-0026 取代；后台在主域名的 `/admin`，以下原文保留。

- **不另起应用、不设独立 admin-web 与运营子域**：必要私有操作以“最小私有页面”承载，随 reader-web（`apps/web`）与 api 在私有主机名 `PRIVATE_HOST` 下提供；`apps/web` 内的私有页面是需登录的**独立路由组**，只在私有主机名响应；公开主机名访问私有路径返回 404 且不带 `Set-Cookie`；私有路由代码按路由拆包，**公开构建的产物与公开 HTML 不含私有路由清单与私有客户端**（边界脚本检查）。
- **私有接口**由 `apps/api` 同一镜像的 `private-api` 实例提供，前缀 `/api/admin/*`（`03-data/contracts/interface-behavior.md` §2.1），只接受私有主机名；`public-api` 实例只注册公开路由。两个实例各自只持有本角色的数据库登录与密钥文件，不再有“一个进程开两个端口”。
- **保留原决定中仍然成立的约束**：独立的私有主机名、独立的路由组、公开构建不含后台路由；私有页面沿用读者站的视觉风格与 `packages/ui` 设计系统。
- 私有路由归各模块的 `privateRoutes`（`platform/identity`、`sources`、`editorial`、`ai-gateway`、`feedback`、`publication`、`platform/ops`），不存在一个“后台模块”；归属表见 `03-module-map.md` 第 6 节。
