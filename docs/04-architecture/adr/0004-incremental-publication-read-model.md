# ADR-0004：公开读取采用逐条增量投影读模型，下架先行且失败关闭，禁止整站快照与发布代次

- 状态：【设计】工程基线提案（M0 结束前由架构 Agent 按基准定稿）；“下架跨升级持续有效、恢复须显式操作”为【Owner 决定】（旧ADR-0031，见 ADR-0011）
- 类别：工程基线
- 关联：`01-target-architecture.md` 第 5 节、`03-data/contracts/interface-behavior.md` §1.3–§1.4、PIT-037、PIT-057、裁决 DEC-47、DEC-48；对应 B：`B:architecture/04-data-model.md` Publication/PublicItemProjection 与 `B:architecture/05-workflows-and-state-machines.md` §6（发布代次方案不采用，其安全语义已移植）、B:ADR-N06（缓存可重建，已并入）

## 背景

旧项目把整个公开站点序列化为单个 JSON 快照并在读取时完整校验（旧ADR-0017 起点）。旧ADR-0035 实测：595 篇材料 + 290 份报告修订的同一公开版本，快照约 7.7MB，隔离冷读 0.5 核 12.0 秒、1 核 6.4 秒，而 Web 超时 10 秒；只能把发布上限从 8MiB 提到 12MiB，该 ADR 自认“不是存储架构整改”（`docs/architecture/decisions/0035-measured-reader-capacity.md:10-26@main`）。注意 8→12MiB 是上限，不是实测大小。

B 包的“发布代次”（building→validated→active、manifest、CAS 切换 current 指针、按 publication_id 存投影）本质是整版本快照的变体：要么每代复制全部公开投影，要么实现结构共享与引用计数；自动流水线每几分钟产生新内容，代次会非常频繁。AIHOT 使用“一个公开读取层 + 按条目一行的投影表 + 发布账本单调序号”，线上页面中位数约 10ms。

## 决定

1. `publication` 模块维护关系型投影表（资讯条目、事件/发展线、法规文书版本、主题、报告刊期、分面、搜索），由领域事件**逐条增量**更新；单条投影更新在一个事务内完成。不设全站代次、manifest 与 current 指针。
2. `content_version` 是不透明字符串（实现为发布账本的单调水位；`suppression_epoch` 只在内部使用、不对外暴露，公开响应不含 `policy_epoch`），任何投影变更与下架都使其变化；只用于 ETag 与前端版本检查。公开契约**不提供**按版本钉住读取（B 各 GET 的 `content_version` 查询参数删除，详情一律读当前）；单次请求在一个只读事务内自洽（DEC-47）。游标有两种，都不绑定全站版本：
   - **列表游标**绑定归一化后的筛选与排序条件（签名游标 = 筛选哈希 + 末条排序键）：被篡改或与当前筛选不符返回 400 `invalid_cursor`，不因内容版本变化失效，改变筛选即从首屏重新开始；
   - **阅读游标**（长文分块）绑定材料修订 `document_revision_id` 与语言表达 `expression_id`：材料修订、语言表达或公开资格变化时，每次续读都重新校验，换版返回 409 `revision_changed`、撤回返回 404/410，客户端整篇重读（`03-data/contracts/interface-behavior.md` §1.3）。
   B 的“游标绑定水位或 `policy_epoch`、过期或被回收版本返回 410/409”**不采用**：它要求服务端同时保留多个可读历史版本，与逐条增量投影不能并存，也会让外部 Agent 翻页时频繁失败。
3. 法规文书的公开投影以“文书版本”为单位：每个合格版本一行不可变公开记录 + 语言头 + 资格视图；新版本追加，不改旧版本；正文分页游标绑定该文书版本。
4. **下架先行、失败关闭**：抑制层（下架/撤回集合，带版本）在每次公开查询时优先叠加；无法确认当前抑制状态时停止返回可能被撤回的内容（返回 503 或占位），不回退到旧数据。撤回即时移除；公开响应不设长缓存，**不使用 `stale-while-revalidate`/`stale-if-error` 等“过期仍可用”的缓存**（JSON 与 RSS 为 `max-age=0, must-revalidate` + `ETag`，返回 304 前必须确认最新抑制状态；HTML 缓存 ≤60 秒）；下架提交后 60 秒内全部出口不可见（DEC-48）。投影重建是异步的，但正确性不依赖它。
5. 所有公开出口（页面、搜索、收藏解析、RSS、公开 API、公开 MCP、站点地图、分享图、报告）只读 `publication`，并适用同一抑制规则；缓存键含 `content_version`，不得依赖 TTL 自然过期实现紧急下架；清空缓存不丢任何事实或账单。
6. 合法空站（尚无任何公开内容：集合为空、详情 404、页面诚实空态）与损坏态（投影或抑制状态读取失败：错误态）严格区分，不得用示例内容填充。
7. 某条投影构建失败时保留该条的上一份合法投影（按条目实现，而不是整站回退）。
8. 报告刊期按“刊期 + 成员 + 修订”存储，引用固定修订，不复制正文；撤下的成员在任何刊期输出中消隐并显示“该条已撤回”；历史刊期只因更正或下架产生修订。
9. 提供全量重建命令与定期对账任务（投影 vs 事实、抑制集合 vs 投影）。
10. 容量硬约束：单次公开请求读取的行数与字节有上限，与库内总量无关；数据量扩大 10 倍时常用公开接口 p95 不劣化；预热后 p95 ≤ 300ms。

## 后果

- 读取性能与数据量解耦；下架对所有出口一致且即时；
- 需要保证投影与事实的最终一致：重建命令、对账任务与“抑制读取失败即关闭”的测试是本 ADR 的一部分；
- 放弃“跨页全站同一版本”的强一致；跨页出现新条目属正常（游标绑定筛选，不重复不遗漏已见条目的稳定排序由排序键保证）。

## 推翻条件

真实负载基准证明逐条投影无法满足一致性需求（例如报告与列表同屏矛盾被读者反馈确认），且代次方案在 10 倍数据下的存储与冷读指标经测量可接受时，另立 ADR。
