# ADR-0023：未知费用确认必须携带客户端已观察版本

- 状态：已接受（工程决定；TASK-0005精确路径计划已合入，接口与调用方按本ADR后续原子接线）。
- 类别：工程基线；落实已批准的未知结果不得盲目重发与人工核对规则。
- 日期：2026-10-04
- 决策者：架构集成人；关联 BR-COST-04、BR-COST-16、ADR-0002、ADR-0013、TASK-0005、TASK-0006。
- 编号：ADR-0022已为独立九类契约草案预留，本片使用未占用的0023，不修改九类决定。

## 背景

真实私有GET/POST与假供应商复现：操作者B看过attempt1但尚未提交，A确认未计费后worker的attempt2又unknown；B后来发送旧的 `{billed,note}` 表单，服务器只能读取attempt2的当前版本，仍会放行。Task6 v2的内部CAS能阻止服务器初读后的状态竞争，但不能代表客户端此前核对的版本。已有明细的JSON日期只到毫秒，也不能用于微秒版本比较。

## 决定

1. 复用既有 `GET /api/admin/runs`：每个receipt issue新增必填字符串 `version`；`POST /api/admin/receipts/:id/release` 必须在既有billed/note旁原样回传该字段。强制新前提是breaking私有请求契约；仅私有OpenAPI预发布版本从0.1.0升到0.2.0，public生成物不变，九类public版本另片交付。
2. version严格为 `rv1:` 后接64个小写十六进制字符；后半段是UTF-8 `stableJson(["receipt-observation-v1", id规范十进制字符串, attempts整数, updated_at的UTC六位微秒文本])` 的SHA256。复用现有sha256/stableJson，不引入密钥、盐、依赖、数据库列或token存储。它是并发前提，不是认证凭据。
3. GET与POST均从数据库精确值生成同一指纹；时间在SQL中归一UTC并保留六位微秒，不能经JS Date或浮点epoch。原显示日期保持。version绑定ID/attempt/精确时间，不能用另一回执的version，也不能在POST缺失时现读一个替代值。
4. 保留Host、会话、权限和CSRF优先级，在guard内验证请求。缺失/格式错400，格式合法但版本已变或串用409；与当前指纹一致后，仍用Task6内部CAS匹配unknown/attempts/数据库精确更新时间。拒绝不得写回执、尝试、文章恢复、放行审计或队列，不得重发；已计费缺金额契约仍409。
5. 对话框持有打开时的version。列表刷新不替换它；409清除旧对话框和旧依据，重新读取并显示当前尝试，操作者重新核对后主动提交。不自动把旧note配新version重试；未取得合法version时不可放行。
6. schema、GET、POST、生成private客户端、B2a白名单投影/组件及仍存在的旧消费者同批接线。可先交未激活的schema/纯函数/向量准备；超过400有效行先拆这些独立准备，不能先启用无安全消费者的半套接口。不改变投递POST、供应商计费分类、金额仓储、模型或阈值。

## 后果与验证

- 旧客户端缺version将被拒绝，必须随新客户端原子交付；沿用现有URL/响应字段与错误媒体类型。具体路径由Task5计划固定，不扩大backend写权。
- 真实回归必须阻断“GET1旧表单→A放行→worker2unknown→B旧POST”：409、第二次保持unknown、无第二条审计/恢复/队列、供应商仍仅2次。重新读取并核对第二次后可正常放行；保留服务器内部ABA与1微秒回归。
- 同receipt时间+1微秒、不同receipt、不同attempt的指纹不同；同一时刻不同数据库时区表示归一后相同。检查缺失/非法/旧/串用版本、auth/CSRF次序与UI409清依据，真实模型0。
- 本ADR不表示完整金额核销或费用仓储已完成；运营者仍须提供真实未计费依据，指纹不核验供应商账单的真实性。

## 推翻条件

若新的私有契约引入独立不可复用attempt身份或统一行修订号，可另立ADR替换指纹表示，仍须保留客户端已观察前提与数据库精确CAS。不得以后台刷新或自动重试取消人工重新核对。

## 备选方案

| 方案 | 未采用原因 |
|---|---|
| POST到达后只使用服务器现读版本 | 无法识别尚未发送的旧表单；已被真实路由探针证伪 |
| 回传JSON毫秒updated_at或只回传attempt数 | 前者丢微秒，后者不能识别同attempt中的精确版本变化，也不完整绑定receipt ID |
| 把version当认证token或加HMAC秘密 | 认证由既有Host/会话/权限/CSRF承担，本次只需并发前提 |
