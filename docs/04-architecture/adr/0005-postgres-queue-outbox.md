# ADR-0005：PostgreSQL 是唯一的结构化事实库；原件进对象存储；pg-boss 队列 + outbox/inbox

- 状态：【设计】工程基线提案（M0 结束前由架构 Agent 按基准定稿）
- 修订：2026-10-01 按 Owner 答复修订——第 5 条任务声明字段“预算类别”改“记账类别”（不设月度金额上限，DEC-08）；其余不变。
- 类别：工程基线
- 关联：`01-target-architecture.md` 第 6 节、`03-data/03-internal-contracts.md`、ADR-0016（lane×stage 调度）；对应 B：`B:architecture/03-stack-decisions.md` ADR-N05、ADR-N06（对象存储部分）与 `B:architecture/04-data-model.md` §5 第 2 条（事务顺序，已移植）

## 背景

A 包原标题“PostgreSQL 是唯一持久化”与部署文档“大对象直接存 COS”互相矛盾，模块表中也没有对象存储归属。法规线要按修订保存官方原件与附件（多为 PDF）；若存进数据库，数据库、备份和恢复演练会随之膨胀，重复旧项目的磁盘问题；AIHOT 只用本地数据卷，没有备份与多进程访问设计。旧批准任务书已要求“COS 保存获准 HTML、PDF、snapshot、大模型产物与备份，数据库保存 object key”（`docs/architecture/vnext/approved-target-brief.md:1768-1800@main`）。

队列方面，A 只写了“幂等键 + outbox + 死信”，没写阶段成功标记存在哪里、重复事件如何去重、长任务租约被抢回后旧结果如何作废；AIHOT 靠 `localConcurrency: 1` 保证归组串行（`packages/backend/src/jobs/events.ts:12`），多 worker 时不成立。

## 决定

1. **结构化事实**：PostgreSQL 18 保存业务事实、修订关系、审计、费用账本、队列（pg-boss）与检索索引；pgvector 扩展随镜像安装，但在聚簇基准证明必要前不建向量索引（ADR-0015）。首期不引入 Redis、Kafka、独立搜索或独立工作流引擎。
2. **原件与大对象**：获准保存的原始网页、PDF、附件、截图与报告产物存对象存储——生产用 S3 兼容接口，首选腾讯云 COS（旧仓库没有桶已创建与恢复演练的证据，按“未就绪”处理，是否已有桶由 Owner 确认，默认按“没有”、M0 前置批准创建，Q-60）；开发与测试用本地目录实现同一端口（`platform/storage`）。数据库只存对象键、sha256、大小、媒体类型、权限版本与到期时间，不存临时签名 URL。
3. **对象生命周期**由 `content` 模块负责：暂存 → 数据库引用 → 按来源权限到期删除 → 回收未引用对象。事务顺序：先写对象到暂存区，再在一个数据库事务内提交新修订、解析结果、阶段成功标记与对象引用；回收器清理超过期限仍未被引用的暂存对象。**对象上传成功不等于业务提交成功**。保存与否由权限矩阵的 `store_fulltext` 等能力决定（ADR-0009），未获准的只存元数据与链接。备份与原件分桶、分权限。
4. **outbox/inbox**：模块写入自身事实时，在同一事务内写入领域事件（outbox，信封必带 `lane`）；分发器把事件转为订阅方任务；消费方用 inbox 表 `unique(consumer, event_id)` 去重。
5. **任务声明**：每类任务声明名称、载荷 schema、所属 lane 与 stage（投入的队列 `<lane>.<stage>`）、幂等键、并发上限、重试次数与退避、超时、是否可能产生费用、记账类别、单次输入长度上限。队列按 lane×stage 分开，各有并发上限与保留份额（ADR-0016）。
6. **阶段成功**以各模块结果表上的唯一键 `(subject_revision, stage, recipe_version)` 为准（recipe 含解析/规则/提示词/输出 schema 版本，不含运行时间）；同键只有一个成功结果；pg-boss 归档或删除任务不影响该标记。短任务不另建通用执行账本。
7. **长任务租约**（全文翻译、法规全文处理与解读等）使用业务侧执行记录（任务 ID、租约令牌、尝试次数、检查点、来源权限版本、lane 控制修订）。结果写回是对 `(task_id, lease_token, attempt, 来源权限版本, lane 控制修订)` 的比较交换：任一项失配（租约被抢回、来源权限收窄、该 lane 已暂停）则只结算费用、留档，不晋升结果。pg-boss 只作投递器。
8. **全局串行**（如同一事件的归组合并）用数据库锁或唯一约束保证，不依赖某进程的 `localConcurrency: 1`；唯一冲突在确定性提交阶段重试，不重买模型结果。
9. **事件载荷**只含 ID、版本与 lane；订阅方处理时读取最新状态并判断是否仍需处理（例如材料已被下架则跳过）。
10. **失败与死信**：按“重试、退避与租约参数表”（`02-rules`，默认调度节拍 300 秒、任务最多 3 次尝试）自动重试；超过上限进入死信并推送告警（对象、失败类别、最近成功时间、恢复建议）。**不设人工逐条重试页面**（旧ADR-0037:21）；缺陷修复随代码发布后，由受控服务身份按批重放死信并写审计。

## 后果

单一关系型依赖、易本地复现；原件与数据库分开备份，数据库体积可控；需要维护对象回收器与“对象引用对账”任务。队列吞吐受数据库限制，首期规模足够；需要时可把 worker 拆到第二台机器，数据库不变。

## 推翻条件

观测证明 PostgreSQL 争用损害公开读取目标，或工作流语义（长程补偿、跨系统等待）无法用任务 + 业务记录表达时，再评估专用队列或工作流引擎（B:ADR-N05）。
