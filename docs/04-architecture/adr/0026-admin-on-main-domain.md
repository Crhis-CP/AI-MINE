# ADR-0026：后台回到主域名的 /admin，旧 admin 子域永久跳转

- 状态：【Owner 决定】已接受（Owner，2026-10-06，项目对话的决定卡 12:11:35Z 选「照 AIHOT」；原话见 `../../01-product/08-owner-voice.md` DEC-34）；上线以 TASK-0080 部署后的读回为准
- 类别：Owner 决定 + 工程落地
- 日期：2026-10-06
- 决策者：Owner
- 关联规格：F-ADM-07、INV-25、AC-SEC-01、裁决表 DEC-30
- 取代：ADR-0018 第 4 条中“只在私有主机名上响应”的主机部分；ADR-0008 的替代做法同步引用本决定

## 背景

新站后台原在 `admin.aiminingpolicy.com/admin`，主域名的 `/admin` 返回 404。上游 AIHOT 的入口只有一个站点（`deploy/Caddyfile:3-6@f4392e1`），部署说明写“后台在 `/admin`”（`docs/deploy.md:16@f4392e1`）。Owner 先询问 AIHOT 是否有这种后台子域，随后选「照 AIHOT」，选项写明「后台改回 aiminingpolicy.com/admin，重写线程改代码，部署前再问你」。本决定只改变地址与相应入口约束；部署前线上仍是旧子域，文档接受不代表搬迁完成。

## 决定

1. 后台页面在主域名的 `/admin` 下；私有接口 `/api/admin/*` 与登录接口 `/api/auth/*` 也在主域名下。
2. 保留配置项 `PRIVATE_HOST`，含义为“可以访问私有路径的主机名”，生产填主域名。其他主机名（服务器地址、内部主机名）访问私有路径一律 404 且不带 `Set-Cookie`；拒绝名单中 `/ops`、`/login`、`/activate`、`/internal`、`/api/private`、`/mcp-ops` 在公开 Web 入口的任何主机名上都为 404。
3. 私有路由组仍是 `apps/web` 内单独的一次构建；读者站构建不含私有路由与代码。`public-api` 与 `private-api` 仍是同一镜像的两个角色，各自只持本角色的数据库登录与密钥；`private-api` 只接受 `PRIVATE_HOST` 转来的请求。公开侧服务不持有管理凭据：同源后浏览器会把后台 Cookie 带到主域名请求上，网站转给公开接口时去掉 `Cookie` 头（TASK-0080）。登录、会话、防伪令牌与审计不变。
4. 私有构建的静态文件在 `/admin/assets/`，与读者站 `/assets/` 分开。
5. 私有路径（`/admin*`、`/api/admin/*`、`/api/auth/*`）响应一律 `Cache-Control: private, no-store`；后台页面带 `X-Robots-Tag: noindex`，任何缓存层（含 CDN）都不缓存私有路径。
6. 旧地址 `admin.aiminingpolicy.com` 保留解析与证书，入口层永久跳转（301）到主域名的同一路径与查询，做法同 www（TASK-0037）。这两个别名在入口层先跳转，不向应用开放私有路由。
7. 代码与入口配置由 TASK-0080 改；上线是生产部署，Owner 当时同意后执行。本 ADR 合并不等于上线。

## 后果

- 地址与 AIHOT 一致，少一个承载后台的子域；飞书登录回调本来就是 `SITE_URL/api/auth/callback`（`packages/backend/src/admin/auth.ts:15@1cf34cc`），搬迁后可落到登录接口，启用飞书时不用再改地址。
- 登录 Cookie（`amp_admin`，`Path=/`）会随读者页面与接口请求发出；读者页面不读取，网站转给公开接口时去掉，公开接口仍收不到管理凭据（决定第 3 条）。管理员需要在新地址重新登录一次。
- 同源后，读者页面一旦出现能执行的注入脚本，就能以已登录管理员身份读取防伪令牌并调用私有接口。此前子域隔离阻断这条路径；搬迁后依靠已有的入库正文净化和 TASK-0084 的 CSP（页面只运行带本次请求随机值的脚本，后台禁止被其他网站嵌入框架）。TASK-0084 应在 TASK-0080 部署前合并并同次上线；若 Owner 当时明确同意先搬、随后补防护，则补齐前只有正文净化这道防护。
- F-ADM-07、INV-25、AC-SEC-01、T-057、T-060 与架构、产品、部署文档同步；不改契约。地址与防护的实际状态仍须部署后从主机之外读回。
