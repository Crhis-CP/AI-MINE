# ADR-0006：统一模型网关：回执、用量账本、缓存、处理许可与异常熔断

- 状态：【设计】工程基线提案。其中先预留最坏成本、结果未知不自动重发为【Owner 决定】（旧ADR-0031）；默认供应商 DeepSeek 为【Owner 决定】（08-owner-voice DEC-10，2026-09-05；DEC-29）。**预算口径【Owner 决定】2026-10-01**：Owner 答复“预算无上限，但是不要浪费”（DEC-08），不设月度金额上限；原“月度 100 元硬限、80 元提醒、两线保底 40/40/20、预算不足只排队”全部作废；旧ADR-0031 与旧ADR-0037:44@policy 中“不扩大月度 100 元硬限、80 元提醒”的条款被该答复取代（旧站在切换前仍按其自身上限运行，与新项目无关）。异常熔断的三个阈值为【设计】默认值，放在受控配置里，负责人可调；熔断前先有 70% 预警（Owner 2026-10-01 确认“防烧钱熔断”并要求有预警）。

## 背景

旧项目先后出现 model_gateway、live_pipeline 内的模型调用、Hermes 容器、离线规则包等多套路径；曾出现付费结果丢失需要“恢复已付费草稿”、结果未知时重复付费的风险。AIHOT 的回执 + 调用次数熔断（每服务分钟/小时/日上限）机制已在线上验证；新项目沿用回执与结果未知处理，把“预算”改为用量账本与异常熔断（2026-10-01）。

## 决定

1. 所有模型与付费外部服务调用只经 `ai-gateway`；业务代码不出现提供商名称与 SDK。
2. 调用顺序固定：检查处理许可 → 查缓存 → 熔断检查（相关能力与来源未被异常熔断暂停，见第 10 条；任一指标达到其熔断阈值的 70% 时先推送预警、不暂停；不存在月度额度检查）→ 写回执并预留最坏费用 → 调用 → 先持久化完整响应与用量再使用 → 校验响应模型证据与输出 schema。缓存键 = 能力 ID + 环节 + 输入哈希 + 提示词版本 + **路由修订**（逻辑模型名、响应模型版本证据与参数集）+ 输出 schema 版本 + 词表与目标语言版本；用途与业务线不进键（同一输入、提示词、路由，评测与生产、资讯线与法规线共用一份结果），回执与账本仍按用途和 lane 分别统计（`02-rules/03-ai-capabilities.md` §1.3）。响应的实际模型名不在路由的响应模型白名单内即拒收，该路由退回评测，已确认用量仍记账。
3. 结果未知的调用被隔离，不盲目重发；预留费用在对账确认前不释放，不按等候时长自动转失败。
4. **不设月度金额上限，但不浪费**【Owner 决定】2026-10-01（取代原“月度 100 元硬限、80 元提醒；两线保底 40/40/20；预算不足只排队”）：付费调用不因累计金额而停止、排队或降级，“预算不足”不再是任何内容不处理、延后或降级的理由；外文稿完整中文、法规全文理解都按规格做，不降低公开标准、不把外文新稿降为摘要（DEC-09）。不设保底额与调剂额；因并发或供应商速率限制出现积压时，处理顺序仍是“法规 > 官方一手 > 其他”（DEC-08）。信源研究与评测同样不设额度，用最小必要样本。不浪费的纪律全部保留并由网关强制：能用程序、规则、缓存、数据库解决的不调模型（Tier 0 优先）；同一输入加同一提示词版本不重复付费（回执与缓存复用，缓存键见第 2 条）；先登记回执再调用；结果未知不盲目重发，逐笔核对（第 3 条）；每个能力有单次输入长度上限与重试次数上限，登记在能力注册表；便宜模型优先，贵模型只用于确需的环节。账本不变：预留、结算、未知三类分列，价格表有效期，金额精度（BR-COST-17 等，见 `02-rules/05-cost-and-budget.md`）。
5. 处理许可（`ProcessingPermit`）的类型定义在 `packages/contracts`，只能由 sources 模块签发，携带权限版本与签名；ai-gateway 只校验签名与版本，不 import sources；无有效许可的调用被拒绝。
6. **按环节配置路由**：每个环节（stage）绑定一条路由修订（RouteRevision：候选顺序、每候选最坏预留、允许用途、重试/熔断策略、缓存键版本、来源允许名单；换供应商或模型只产生新修订，不改变环节职责）。路由变更 = **发布一条新的 RouteRevision 并走准入状态机** `eval → shadow → canary → promoted`（另有 `rolled_back`；评测 → 影子 → 小流量 → 启用，见 `02-rules/03-ai-capabilities.md` §1.9）后才生效。模型接入与密钥录入在私有页面“用量与模型密钥”（OP-12/13）完成（ADR-0018）；页面上的环节指派提交的是新的路由修订，不能绕过准入。**不再有“运营台随手切换”，也不因单次失败自动重试到另一家提供商**：备用路由必须是已准入的另一路由，且相关来源在其允许名单内，否则只排队并告警。
7. 默认供应商为 Owner 已开通的 DeepSeek；任何新供应商（含 embedding）按新付费订阅处理，须基准证明必要并经 Owner 同意（DEC-29）。
8. `ai-gateway` 可以提供“有界工具循环执行器”（步数、请求数、token、时长与单次任务费用上限，每步走同一回执与熔断检查），但**不自带任何工具**：工具由调用方模块注入，抓取类工具必须经 acquisition 的受控抓取端口（由 fetcher 执行，遵守 robots、权限矩阵与 SSRF 守卫）。生产主链路不使用循环；循环只用于离线信源研究，启用前须经 Owner 批准（DEC-16）。
9. 读者请求永远不调用模型。
10. **异常熔断（防故障烧钱，不是预算上限），预警先于熔断**【Owner 决定】2026-10-01，阈值为【设计】默认值：以下任一触发，即暂停相关能力或来源的付费调用并告警，负责人在私有页面“用量与熔断”一键恢复——① 同一输入 1 小时内重复付费调用 ≥3 次；② 单篇资讯材料累计费用超过 5 元，或单份法规文书累计超过 100 元；③ 单日总费用超过过去 7 日日均的 3 倍且超过 50 元（没有历史数据时以单日 200 元为界）。**预警先于熔断**：任一指标达到其熔断阈值的 70% 时先推送预警（只提醒，不暂停任何处理），达到阈值才熔断；预警与熔断都走告警渠道（飞书群机器人为主、邮件为备），写明是哪一项指标、当前数值与阈值、涉及的能力或来源；预警记录在私有页面可查。阈值与预警比例（默认 70%）放在受控配置里（ENT-83 用量与熔断配置，只有负责人可改，写审计与版本）；熔断只停付费调用，不影响已公开内容、原生中文直出和不需付费的环节；熔断状态、触发原因与恢复记录经私有页面与只读 MCP 可查（规则见 `02-rules/05-cost-and-budget.md` BR-COST-20；熔断状态是 `03-data/01-domain-model.md` ENT-82，独立于人工暂停与部署暂停，恢复熔断不解除人工暂停）。
11. **用量透明**【Owner 决定】2026-10-01：账本按业务线、能力、信源分别记账；每月 1 日推送上月用量报告（费用、调用数、缓存命中率、单篇成本、最贵的 10 个任务）；月内累计每增加 100 元推送一次用量提示（只提示，不暂停任何处理；BR-COST-18、BR-COST-19）。新付费供应商仍须 Owner 开通账号并录入密钥（DEC-29），但不再以预算为由拒绝。

## 后果

- 成本可控、可审计、可复用；换模型是经准入的配置修订；
- 网关成为关键路径，必须有完善测试与假模型服务；
- 两条业务线的费用分线记账、可观测；没有金额上限，也就没有“额度耗尽而停摆”；熔断只停触发它的能力或来源，不拖停另一条线；
- 防故障烧钱靠异常熔断与每个能力的单次上限，不靠月度总额；阈值设得过紧的代价是误停（负责人一键恢复），过松的代价是漏停（用量提示与月报仍可见），阈值可调；70% 预警让负责人在熔断之前就能看到异常、提前介入。

## 推翻条件

供应商提供可证明的幂等请求与对账接口后，可简化“结果未知”处理；其余条款不因模型更强而放松。熔断阈值是可调默认值，按真实用量调整，不改变“只停付费、不停公开”的原则；Owner 如日后决定设月度金额上限，应新增 ADR，而不是改第 4 条。
