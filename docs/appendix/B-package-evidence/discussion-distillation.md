# 讨论蒸馏、证据强度与冲突消解

本文件记录本次真正取得的讨论及历史材料，不把助手方案、代码默认值或旧验收通过混写为用户已经定稿的产品要求。整理日：2026-09-29。产品、契约和架构文件是新团队的工作入口；本文件供查证，旧实现不是新工程蓝图。

## 1. 证据分级和适用次序

| 标记 | 含义 | 能证明什么 |
|---|---|---|
| U | 本轮或历史聊天中的用户直接表达 | 产品意图、明确取舍和授权范围；较新明确表达覆盖冲突旧表达 |
| A | 助手归纳、设计提议、实现报告 | 可供评估的方案或历史报告，不能自动成为用户决定或当前运行事实 |
| R | 本轮读取的仓库文档、配置、测试源码 | 对应版本表达过什么、有哪些可蒸馏的行为和反例；没有在本轮运行旧项目测试 |
| H | 历史运行/原件核对回执 | 对应时间的证据，不代替新系统实测，也不证明此刻生产状态 |
| N | 本交接包的新建议 | 可直接用于开发准备；明确标出的产品/费用待决项不能被代码默认值偷偷定稿 |

适用顺序：本轮明确目标 → 较新明确用户决定 → 无冲突历史业务行为 → 新的建议方案。助手曾建议“不要全部重写”，不约束本轮已经明确的以 AIHOT 源码起步重建；旧方案强调“只借鉴交互”，也被本轮源码基建要求覆盖。

## 5. 能继承的业务资产与不能伪称存在的资产

可继承：新闻/事件/法规分立的领域概念；实体别名与项目归属；完整中文和来源主张分层；正式文书版本、图件、脚注、例外与条款定位；宽准入与精选分开；去重/聚簇/实质进展区分；日期精度；多渠道下架一致；人工修订保护；持久任务、缓存、费用预留与未知结果隔离；持续信源测量；用户视角更新日志。

不能伪称存在：正式专有评分定稿、足量真实人工金标、已证明的跨语言聚簇质量、全部目标国家持续供给、所有必要附件完整处理、反馈自动改进已经有效、新版已部署、新架构已被真实负载验证。交接包为这些提供实现与验收标准，不制造通过结论。

H01 已登记 16 份模板：政策法规动态 9 份、主要条款解读 7 份。F17《法规政策动态信息报送要求.docx》仍标 `not_provided`。历史模板可提炼写作结构、条款与场景映射、语气及证据组织，不能当法律真值金标；本包没有嵌入私有原件。

## 6. 交给后续团队的使用方式

1. 先读产品定义、页面行为、数据与接口、模块说明、验收矩阵；任务只引用稳定 F/T 编号。
2. 遇到真实歧义，先查本表的 U/A/R/H/N 标记，再由产品负责人作单一决策；不要让不同 Agent 各自从旧代码推导规则。
3. 未取到的原件只影响必须依赖其精确内容的校准；不阻塞已清楚的功能、接口、权限和测试设计。
4. 将新确认的产品决定写回同一需求及决策登记，不能只留聊天结论或 Agent 私人记忆。
