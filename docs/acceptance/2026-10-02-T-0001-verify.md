实际的格式化提交 `5118b5d` 为 264 个文件、+16,910 / −3,194（一个测试文件需要格式化两遍才稳定，差 2 行）。

- **`css.parser.tailwindDirectives`**：设为 `false` 时 `apps/web/app/app.css` 出现 5 个解析错误，格式化中止；`true` 时正常。
- **`noRestrictedImports` 的 glob**：Biome 2.5.15 支持。实测在 `apps/web` 下导入 `@aihot/backend/src/db.ts`（命中 `@aihot/backend/**`）与 `postgres` 都报错，`zod` 不报；同样的代码放在 `apps/api` 下不报。真正的门禁仍是 boundaries 阶段（它还查动态 import 与 `package.json` 依赖）。
- **TS 7 兼容**：TypeScript 7.0.2 下 `react-router typegen && tsc` 通过；Vite 8.3.1 生产构建通过；Biome 处理全部 `.ts`、`.tsx`、`.css`。
- **栈兼容基准（7.3）**：干净环境按锁文件安装、类型检查、迁移、AIHOT 原测试全部通过（组合见本记录开头）。“生成客户端并与已提交版本逐字节一致”要等契约中心（TASK-0005）；PostgreSQL 18.6 的组合随 TASK-0006（T-0005）重跑；Node 26 非阻塞矩阵在 TASK-0012。发布配置里没有 `latest`：Dockerfile 与 compose 的每个镜像都写到补丁版本加 sha256，toolchain 阶段强制。
- **pnpm 12 的回退条件（ADR-0015）**：“与类型剥离冲突”这一半已排除：工作区包经符号链接解析，全部测试与构建后的站点都在 Node 类型剥离下运行。“镜像里装依赖”这一半**还没验证**：镜像构建在本容器跑不起来（第五节），要靠网络正常的执行器上的 compose-smoke 补上。
- **依赖审计**：`pnpm audit` 在本执行器网络上可达，结果 0。
- **密钥扫描工具**：选 trufflehog 3.97.9（交接包首选，旧仓库也用它），版本与四个平台的 sha256 写在 `scripts/verify/tools.json`。与交接包写法的一处差异：交接包写“官方已验证模式”，这里用 `--no-verification`，**所有候选都算命中**。原因：验证模式要把疑似密钥发给各家服务商去试，需要执行器访问外网，也违背“verify 不访问外网”（`AGENTS.md` 铁律 13）；不验证更严，误报用行内 `trufflehog:ignore` 加理由处理（3.97.9 实测有效），审查时逐条看。

## 五、未通过项与原因

| 检查项 | 现象 | 原因 | 处置 |
|---|---|---|---|
| compose-smoke | 没跑（回执里记为跳过） | 本容器的网络策略拒绝 `deb.debian.org`（镜像构建第一步 `apt-get` 装 `postgresql-client` 时 403）；构建容器里访问 npm 源也过不了本机的 TLS 代理。Docker Hub 拉镜像正常，所以 compose 文件与镜像固定本身没问题 | 在网络正常的独立执行器上跑（最迟随 TASK-0009 的本地预发）；这一步同时补上 pnpm 12 在镜像里装依赖的验证 |
| path-guard | 跳过 | 首个 PR 的基线提交没有 `lanes.yaml` 与任务卡，没有可比对的规则 | PR #1 合并后，之后每个 PR 都按 main 上的规则检查；首个拿到 `scope: full` 回执的 PR 记入 M0 退出检查表 ② |
| Actions 停用读回 | 未做 | 需要仓库设置权限，且属 Owner 授权事项 | 由 Owner 在仓库设置里停用后读回；在此之前，仓库里没有工作流文件，不会触发运行 |
| 契约漂移的违规用例 | 未做 | 契约中心还不存在 | TASK-0005 |

**真实拦截一次**：在干净检出上第一次完整运行时，secrets 阶段拦下了验证入口自己的一个测试文件——测试里写死了一个带口令的数据库地址（假口令）。trufflehog 与本项目规则都命中。改为运行时拼出地址；这些提交当时还没推送，已在本机重做，远端历史里从未出现。
