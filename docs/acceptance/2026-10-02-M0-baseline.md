## 一、怎么跑的

命令取自上游 `.github/workflows/check.yml` 的 `check` 作业，在干净检出上执行：

```bash
npm ci --no-audit --no-fund
npm run typecheck
npm run build -w @aihot/web
node --test apps/web/tests/*.test.ts
node scripts/migrate.ts && node scripts/seed.ts --topics-only
# 起 api 与 web（COLLECT_ENABLED=false、MODEL_CALLS_ENABLED=false）后：
node scripts/smoke.ts --base http://127.0.0.1:3000
node scripts/mcp-check.ts http://127.0.0.1:3000/api/mcp
npm test
```

行为基线（`04-aihot-adoption.md` 7.3）由新增的 `scripts/baseline/run.sh <输出目录>` 一次生成，结果在同名目录 [`2026-10-02-M0-baseline/`](2026-10-02-M0-baseline/)。同一提交连续跑两次，两份输出逐字节一致，所以之后的结构改动可以直接 `diff -r` 比对。

## 五、给 Owner 的汇报

1. **做了什么**：把 AIHOT 原样放进仓库后，先用它自己的检查把“现在是什么样”完整记了一份底，作为之后每一步改造的对照。
2. **证据**：前端 16 项、后端 161 项测试全部通过，构建后的网站冒烟检查通过。
3. **没做什么**：容器方式的整站启动检查没跑（这台机器拉不到容器镜像）；条目接口的响应快照要等测试工具（假模型服务）做好再补。
4. **风险**：本机数据库是 16 版，交接包目标是 18 版，升级后要重跑一次。
5. **下一步**：建统一验证入口（不用 GitHub Actions），然后去品牌、删除模型榜和 Codex 监控。
