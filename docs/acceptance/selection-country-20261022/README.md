旧24组候选只来自已公开、正文成功材料，并在采样时主动排除AR及若干监管关键词。它们可补普通内容保真检查，不能单独证明B的监管收益或AR精选效果；另发现Apollo两条不同阶段需要按项目家族复核归组。

仍缺：两份独立标签和家族裁决、完整原文及当前外部模型处理许可、若干监管阶段/例行许可对照和媒体层。15组只支持探索性结果，不满足既有100—200条正式校准要求。不得绕过现有确认门槛。

## Agent复现与继续执行

1. 使用独立数据库，不复制生产秘密。工具拒绝production环境、非`*_eval`/`*_test`/`*_ci`库名和所有分角色`DATABASE_URL_*`覆盖。必要配置通过现有安全机制注入。
2. 可用`node scripts/selection-experiment.ts --export-country <数据集名> --output <受限路径>`导出当前AR候选；导出无标签，family/occurrence以unreviewed标记，不可直接运行。来源许可不足会停止导出，不补造allow。
3. 独立人员核对家族与同次事实，分别填整体/AR价值和理由。不得把全局selected当作人工答案；空标签、同一人两标签、重复材料、跨split家族、输入/模型/提示词变动均会阻止运行。新原站样本先经现有来源/材料许可流程进入隔离库，再保存完整analysisInput、inputFingerprint和模型/提示词bindings。
4. 默认检查：`node scripts/selection-experiment.ts --manifest <冻结清单> --output <计划结果>`，零项目模型调用。受控运行：`node scripts/selection-experiment.ts --manifest <冻结清单> --output <结果> --run --task TASK-0401 --max-calls 105`。本卡最多15个材料，每个共享预筛一次及A/B/AR共六次评分；缓存减少实际新增调用，不增加金额上限。
5. 首轮每个逻辑请求最多一次物理尝试，失败不自动购买替代答案，保留人工核对。报告保留版本、回执与全部attempt，区分实际/估算/未知、币种、原费用与本次新增尝试，给出p50/p95。中间检查点可恢复，重新执行复用已取得结果。
6. 变更提示词/材料/模型后不得把旧窗口当作同一试验，也不得用同一任务额度不断重开试验。正式确认仍走既有SelectBench证据与Owner生效流程；本工具不生成确认记录。

工程验证使用`npm test -- tests/selection-experiment.test.ts`；只用本地假模型和合成来源许可，实际结果记录在本地受限日志。真实模型调用本次为0，人工盲标尚待完成。
