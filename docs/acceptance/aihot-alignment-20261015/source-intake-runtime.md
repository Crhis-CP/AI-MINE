# 来源增量接入命令的运行角色修复

生产验收发现，接入命令以迁移进程身份初始化数据库，而来源发布机构变更会在同一事务写入公开内容重建任务。迁移进程不允许访问任务队列，因此机构归一被阻止。修复只改变该CLI的运行身份与关闭顺序，不调整来源、许可、预览、模型或队列的业务规则。

- CLI使用worker进程身份，具备既有来源更新、审计和任务入队能力；不注册任何消费处理器。
- 只读计划仍不修改来源、不启动队列。执行模式沿用同一后台更新函数与事务，保留人工暂停。
- 退出时先停止队列连接和定时器，再关闭数据库；队列停止失败时仍关闭数据库。

最小回归直接启动`scripts/source-intake.ts`子进程，依次执行只读计划、两个来源的身份调整和重复续接。断言实际来源字段、两个持久化资讯线任务、原暂停状态与正常退出；没有用代码字符串匹配替代执行。隔离数据库及合成来源不访问真实网站或模型。

修复前`.verify/source-intake-cli-before.log`复现两个`blocked_identity_review_admin`及退出码2；修复后`.verify/source-intake-cli-after.log`证明主入口成功更新、任务入库、重复运行不再新增任务，原有增量接入及预览测试同样通过。完整发布与线上效果由集成人另行记录，本修复工作没有改变生产。

提交前快速检查的工具链、格式、类型、契约、边界、名称、数据归属与角色配置均通过。复用工作树残留旧网页构建导致的界面检查失败，使用当前源码重新构建后只补跑该阶段并通过；没有修改网页源码或放宽断言。此修复只涉及运维CLI，保留已经发布的重大版本日志，不新增读者更新片段。
