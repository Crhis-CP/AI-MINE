# 资讯来源增量启用清单

当前清单包含202个独立新增候选，均有真实原生列表预览证据。另有5份既有/同机构入口只用于身份归一，不计新增；紫金旧中文入口单独更新机构身份。**这些数字不是生产新增成功数，也不是已经自然采集验收的数量。** 最终只计启用读回、当前配置预览合格、自然任务取得有效条目的独立发布主体。

本批以前的270份运行来源、原规划目标和表外补充来源作为去重基线。按实际发布主体归并同站入口、同一机构中英文域名与出版集团品牌；不能仅凭名称相似或共同股东猜测是同一个发布方。The Australian Mining Review的出版方与Australian Mining不同，已据出版方页面核对。紫金中英文入口、Northern Miner集团与Prime Creative集团的具体依据在source-intake.json的alias_evidence中。机构归一同时用于热点参与方计算。

真实预览依据：existing-batch-preview.json、candidate-source-ready.json、additional-source-ready.json及tudor-source-ready.json。无法读取、robots拒绝或验证拦截仍在原阻塞记录中，不绕过，不用未通过条目凑数。日期未知保留未知，不用发现时间冒充；缺乏当前供稿的来源在生产自然采集验收时仍不能只凭一次历史列表预览通过。

## 执行

在最终已验证版本与生产数据库连接环境内，先运行只读计划：

```sh
node scripts/source-intake.ts docs/acceptance/aihot-alignment-20261015/source-intake.json
```

统一部署后，沿用同一清单执行：

```sh
node scripts/source-intake.ts docs/acceptance/aihot-alignment-20261015/source-intake.json --apply
```

执行复用现有后台接口函数、配置草稿、当前许可、预览绑定和版本检查，不重复seed覆盖运行库。不自动开通全文展示；新来源仅按本轮资讯采集授权建立许可，来源明示限制与人工收紧继续生效。每条只输出ID、状态和预览编号，错误细节留在私有后台。退出码2表示仍有阻塞，需要按记录处理，不能据退出结束宣称目标达成。

- 原有来源只在配置哈希与机构身份符合计划时调整；人工暂停、归档、已改配置不覆盖。
- 新来源先保存为停用，经当前配置与许可预览通过才启用。崩溃后可继续同一批次；遇到不是本批创建的同ID记录时停止该条，不冒充本批成果。
- 原有文章、来源ID、人工修订和权限不清理；配置信息变化采用草稿预览激活，并保留原审计。
- 预览遵守主机节奏、robots和访问拒绝；短暂等待在原有90秒截止内恢复，不绕过节流。超时或拒绝保持未启用，其他独立来源继续。
- 只将新的合格配置交给现有服务器日程。不会通过人工调用评分来制造“自然采集”证据；最终从运行记录与有效条目逐项验收。

运行库中已有148个启用入口、目录中的配置总数、202个独立候选、最终真正新增验收数是不同口径。当前未执行生产启用；202候选留有少量余量，但若自然运行失败导致不足200，仍须修复或补充，不能降低目标。
