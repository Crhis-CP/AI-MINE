## 执行

以下保留接入及必要续接的CLI用法；已经通过生产验收的来源无需为核验重复启用或预览。在最终已验证版本与生产数据库连接环境内，先运行只读计划：

```sh
node scripts/source-intake.ts docs/acceptance/aihot-alignment-20261015/source-intake.json
```

确有尚待接入项时，使用经核对的同一清单执行：

```sh
node scripts/source-intake.ts docs/acceptance/aihot-alignment-20261015/source-intake.json --apply
```

生产容器不包含docs目录；执行时从部署目录将经核对的清单只读挂载到容器，并传入实际挂载路径。执行复用现有后台接口函数、配置草稿、当前许可、预览绑定和版本检查，不重复seed覆盖运行库。不自动开通全文展示；新来源仅按本轮资讯采集授权建立许可，来源明示限制与人工收紧继续生效。每条只输出ID、状态和预览编号，错误细节留在私有后台。退出码2表示仍有阻塞，需要按记录处理，不能据退出结束宣称目标达成。

- 原有来源只在配置哈希与机构身份符合计划时调整；人工暂停、归档、已改配置不覆盖。
- 新来源先保存为停用，经当前配置与许可预览通过才启用。崩溃后可继续同一批次；遇到不是本批创建的同ID记录时停止该条，不冒充本批成果。
- 原有文章、来源ID、人工修订和权限不清理；配置信息变化采用草稿预览激活，并保留原审计。
- 预览遵守主机节奏、robots和访问拒绝；短暂等待在原有90秒截止内恢复，不绕过节流。超时或拒绝保持未启用，其他独立来源继续。
- 只将新的合格配置交给现有服务器日程。不会通过人工调用评分来制造“自然采集”证据；最终从运行记录与有效条目逐项验收。
