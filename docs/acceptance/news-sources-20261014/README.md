## 怎么核验的

- **入口**：每站找真实 RSS、列表页或 JSON 接口，写成仓库原生配置。没写选择器、靠默认抓取的不算通过；不编造选择器或订阅地址。
- **校验与预览**：配置先过仓库自己的配置校验（`assertSupportedConfig`）。然后用仓库的采集函数（RSS、列表页、JSON 列表）经仓库的礼貌抓取逻辑做真实预览：遵守 robots，同一主机两次请求间隔至少 5 秒，跳到别的主机即判失败，遇人机验证或 403 即判失败。前 3 篇文章页再单独抓一次，核对发布日期。
- **门槛**：
  - 有条目，且有条目选择器。
  - 文章链接唯一，都在允许的网址范围内。
  - 前 3 条都有可信的发布日期，没有未来日期；只有日期的不补时分。
  - 没有导航或菜单噪声。
  - 主题归属正确。
- **需要人工看的情况**：文章页抓取报错、列表日期与文章页日期差 3 天以上、最新一条超过一年、标题过短、条目少于 3 条却没有低频理由。这些逐条人工裁决，裁决理由写进逐源摘要。
- **复核人**：AI 开发 Agent。机器门槛加抽样人工核对，不是人工金标。
- **配置哈希**：每源的 `config_sha256` 绑定 `industry/sources.json` 里该源的完整条目，改任何一个字段都要重新预览。
- **网络口径**：预览在开发机网络下进行。正式站服务器在国内，部分境外站的结果可能不同，上线前须在正式站再预览一次（Q-69）。
- **排重口径**：只与仓库比对，标为 `repository_only_runtime_not_read`：没有读正式站数据库，不能说已与生产库全面排重。

## 裁决（证据能裁决的，不回抛）

- **紫金、Codelco 不计入新增**：两站在 `docs/data/source-targets-320.json` 已有规划条目；任务包计数规则写“原目标中的明确重复项不计”，包内预检也判为已规划目标。包的 `coverage/companies.json` 却把两家标为计入，导致包原版导出脚本必然失败。按计数规则不计入，照常配置验收；另做一份改版导出脚本单独列出已规划目标。International Mining、African Mining Market 同理。
- **艾芬豪不改仓库旧条目**：种子导入对已存在的来源一律跳过，改 `industry/sources.json` 既不生效又违反“不改旧源”；正式站补挂主题写进 Q-69。
- **文章页取不到的外文源判未通过**：外文新稿公开须有完整中文正文。文章页被 403、人机验证或 robots 挡住的源（如 African Mining Online、Boliden、SSR Mining、Alcoa），在正式站拿不到正文，不入库。
- **停更源不入库**：最新一条超过一年的判为不活跃（Boart Longyear、Master Drilling、CAMIMEX 等）。
- **改名重验**：替补源 Dyno Nobel 的名称草稿误写了另一家公司，改名后按新配置重新预览了一次。

## 仓库采集代码里发现的问题（另开卡，本批不改代码）

1. 文章页 head 与 JSON-LD 给出**同一个**日期时，日期解析把它当成“有冲突的备选”而丢弃（影响 Valterra、Mining Digital、Brasil Mineral）。
2. 两位数年份 `DD.MM.YY` 不在支持的日期格式内（影响 Antofagasta）。
3. 列表靠表单提交翻页时，只能取到首屏（影响艾芬豪完整列表）。
4. 列表数据只在 HTML 属性里的脚本对象数组中时读不到（影响嘉能可）。
5. `htmlJsonPath` 不能取根层字符串（影响中矿资源）。
6. RSS 里指向站外视频的条目是否按允许网址范围丢弃，待确认（影响 Sandfire）。
