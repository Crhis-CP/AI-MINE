# 数据库绑定生命周期修复

独立复核发现两类问题：file/reserve/cursor 返回的能力可在注销后继续执行；公开查询复用的 SQL 常量在首次根上被固定，closeDb 后重新初始化会报绑定已变。当前业务未使用前三种派生能力，不将此描述为已发生的公网越权。

修复将纯插值片段的重建与待执行查询的生命周期分开。普通查询和已访问查询方法的对象保持原注册，file、保留连接、游标及保存方法同样受约束；release/return/cancel 保留必要清理，异步 reserve 在注销后才取得连接会先释放再拒绝。

回归覆盖实际 v1Items 连续两代查询、嵌套标识符/JSON/unsafe 片段、旧待执行查询、file 工厂、已释放连接、迟到 reserve、未启动/在途游标和池连接回收。保存的工厂现在在调用时即可拒绝过期绑定，原测试继续断言同样的拒绝原因并同时接受同步/异步拒绝。原事务、savepoint、批量与回滚测试保持。

本修复的隔离 PostgreSQL16.14 行为基线、最终提交完整回执、独立复核和合并后 main 结果在对应 PR 留证。它不替代尚未完成的队列、真实数据库权限或线上验收。
