## 仍未解决的19项缺口

比较编号带模块前缀，避免与原审计编号混淆。P1为应优先处理的功能风险；新规格缺项和未合并参考实现遗漏的来由，详见三份逐项报告。

| 比较编号 | 优先级 | 功能缺口 | 用户影响 |
|---|---|---|---|
| pipeline/PIPE-23 | P1 | 事件/发展线/报告独立下架与恢复 | 运营者无法一次撤下存在问题的整组并保证后续重组不复活；也无法独立撤回一份仍含公开文章的报告。 |
| pipeline/PIPE-25 | P1 | 新闻报告跟随人工更正并形成修订 | 已更正文章的新事实不会自动修正已刊日报/周月报，报告继续展示旧数字或旧表述；撤回时只隐藏失效内容也未形成所要求的新修订记录。 |
| policy/POL-19 | P1 | 停跑跨刊期后遗漏的法规报告不能自动补出 | worker停跑或公开暂停跨过多周/月后，读者报告归档中会永久留缺期，即使本站当时已有材料；需要人工指定周期才能修复。 |
| reader/R34 | P1 | 日报RSS撤回后的旧导语残留 | 已撤回报道的概括仍可能经日报RSS继续传播；网页/机器报告已清除导语而RSS不一致。 |
| reader/R35 | P1 | RSS撤回后缓存及时失效 | 遵守响应头的阅读器或中间缓存可在撤回后继续直接复用旧RSS五分钟，不能保证60秒撤回；ETag不能迫使仍新鲜的缓存重新请求。 |
| pipeline/PIPE-04 | P2 | 不改变入口/分页时的检查点保留 | 仅调整初始回填上限等非分页配置也会重新进入 firstImport 分支，重新限缩候选和标记回填，影响采集连续性。 |
| pipeline/PIPE-05 | P2 | 信源归档与归档后的不可误恢复 | 弃用或错误来源只能长期混在暂停来源中；无法保留“已归档”语义及防误恢复约束。 |
| pipeline/PIPE-30 | P2 | 反馈结果未知后的同一提交去重 | 数据库已收件但客户端响应丢失时，用户重交会新增重复反馈并再次占用处理工作。 |
| policy/POL-14 | P2 | 列表默认语言仍跟随最后完成语言 | 文号/原名/日期等卡片信息会随后台处理完成顺序改变，并可能与点击后默认详情不一致。 |
| policy/POL-15 | P2 | 法规检索没有覆盖完整中文正文 | 读者按正文中的义务、条件或专业词搜索，会漏掉已有合格完整中文的法规。 |
| policy/POL-18 | P2 | 确认的正式公布日被报告标成日期未知 | 本已确认的刊宪/正式公布日显示成“日期待确认”，影响报告分区和按实际变化归期。 |
| policy/POL-21 | P2 | 严格解码缺少BOM与页面声明识别链 | 有效但非UTF-8的官方法规可能长期停在取得失败或不完整，缺少完整中文供稿；当前拒绝是保守失败，不是乱码被错误公开。 |
| reader/R10 | P2 | 其他来源展开面板的完整事件入口 | 只展开其他来源的读者无法从该面板进入完整事件；这是新规格功能缺项，不计为旧页面回归。 |
| reader/R13 | P2 | 无正文/补齐中状态及原文替代入口 | 读者无法区分正文在整理、没有取得、许可受限或页面漏载。 |
| reader/R14 | P2 | 来源时间与本站公开时间分列 | 读者无法分辨旧来源报道何时首次由本站公开，尤其补录内容容易混淆。 |
| reader/R16 | P2 | 代表稿与最新进展分别标识 | 阅读历史报道时无法直接识别官方代表材料及最新进展，核验和追踪成本增加。 |
| reader/R17 | P2 | 事件后续空态、失败态与摘要 | 读者无法区分确无后续、接口失败与尚未加载，并失去原有一句摘要。 |
| reader/R29 | P2 | 从当前页面进入反馈自动携带来源 | 从搜索/文章等SPA页面进入反馈会丢失或误报关联页，后台难定位故障和更正对象。 |
| reader/R33 | P2 | RSS摘要段首发布方署名及AI标识 | 只显示description的订阅器失去原有前置发布方署名；AI辅助生成内容也缺强制标识。 |

其中，法规全文检索和稳定默认语言在旧未合并分支已有参考实现；停跑补刊与编码识别在旧法规分支也存在局限，不能写成“旧站全部支持、新站丢失”。资讯报告的更正传播、组级撤回，以及日报 RSS 撤回残留均应在后续修复中联合验证。

这19项已核对证据并明确保留为未解决项。本轮没有在独立报告生成后静默修改审查基线，也不以反复追加审查追求“零意见”。
