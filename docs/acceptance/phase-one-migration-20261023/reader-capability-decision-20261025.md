## 调用量与费用怎么算

对这308个会话，先按当前材料版本、来源许可、人工状态和URL去重，得到真正需要读取的`N`。若首轮每个合格会话只尝试一个URL，则`N ≤ 308`；不是批准308次付费。建议先执行其中5个技术取材样本（覆盖HTML/PDF），它们不替换31篇固定模型评测样本。缓存/回执复用可减少新外呼；重试、跨日读取会增加实际调用，单独记账，不能把逻辑任务数当供应商收费次数。[本站回执身份](../../../packages/backend/src/providers/receipts.ts)、[本站Jina回执复用](../../../packages/backend/src/providers/jina.ts)

设实际收费token总量为`T`、每百万token价格为`p`，读取估算为`T ÷ 1,000,000 × p`。仅用公开索引的标准包折算价`p=$0.05`作**USD场景示例**，假设每次返回10,000 token且没有新增付费重试：5次约$0.0025，308次约$0.154。若每次20,000 token，308次约$0.308。这不是实测、账单、充值金额或预算上限；结算币种、税费和账户订单待核实。长期费用应使用恢复后的每日实际外呼和token观测，不能用337条历史积压除以9天充当稳定日流量。

读取费用**不含后续模型分析、归组和写作**。原抽取worker成功后会接续分析，故恢复执行卡必须同时列出所用模型、预计经过的步骤/调用数和用途；不能仅按Reader金额估算整条处理费用。取正文成功也不等于入选。[原任务衔接](../../../packages/backend/src/jobs/content.ts)

本站Jina适配器目前把用量头按约人民币0.36元/百万token记为`estimated`。它是代码中的历史估算，不能当作今日官方人民币报价或供应商实际收费；启用前应确定当前价格/币种依据如何记录，缺依据保持未知，不能改写历史或把估算标成actual。[现有估算实现](../../../packages/backend/src/providers/jina.ts)

## 恢复308个会话的执行边界

1. 重新生成候选清单，记录当前ID/修订、来源、URL、等待原因及旧会话；排除已恢复、来源停用/归档、许可不足、法规线和人工暂停/撤回/修订冲突，记录每个排除原因。不以旧数量直接重排。
2. 配置获准后，先核对依赖存在性和当前服务次数控制，再对确定的少量ID走原`content.rerun(..., "extract", requestId, actor, ...)`入口，使用稳定命令ID和审计理由；抽取过程再核许可、来源节奏与当前修订。不要直接改SQL状态或删除抓取请求来“解锁”。既有“重试失败稿”只选择`processing_state='failed'`，不能据它已运行就声称这些`analyzed/unknown`记录已恢复。[重处理入口](../../../packages/backend/src/admin/content.ts)、[失败稿范围](../../../packages/backend/src/jobs/content.ts)
3. 每批核对正文可用性、版本变化、后续模型结果、付费回执和新的等待/失败，按现有次数控制继续合格项。未知付费不盲重试；人工记录、旧文章ID/链接、事实关系和来源许可保持。308是诊断集合，不是删除名单。
4. 回退先阻止该恢复批次继续产生外呼，再恢复受限配置/程序；不撤销Chris原有暂停，不人为删除已取得正文或账目。临时抓取请求/缓存会按原流程在会话结束时清理，执行前保留必要审计摘要，不能把临时缓存当作唯一历史证据。服务恢复与“积压消化完成”分别验收。

需要Chris选择的是A/B/C（D仅在明确希望采用时进一步评估），以及由此涉及的外部服务/生产配置范围。未选择前，只继续仓库内巡检修复、材料准备和其他迁移，不执行采购、密钥读取或批量重处理。
