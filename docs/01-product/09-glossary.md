`传闻未证实` · `宣布` · `提案` · `征求意见` · `草案` · `立法程序中` · `已通过` · `已公布` · `已生效` · `执行中` · `司法裁决` · `已中止` · `已废止`

## 6. 事件成员关系

| 中文 | 代码名 | 计入独立证据 |
|---|---|---|
| 原始发布 | `original` | 是 |
| 独立确认 | `independent_confirmation` | 是 |
| 转载同稿 | `reprint` | 否（只增加转载计数） |
| 实质更新 | `substantive_update` | 否 |
| 正式更正 | `correction` | 否 |
| 跨语言分发 | `cross_language` | 否 |
| 评论解释 | `commentary` | 否 |
| 相互冲突 | `conflicting` | 是 |

代码名与 `03-data/01-domain-model.md` ENT-17、AI-08 和公开契约 §3.5 一致；`original` 由代表稿与来源一手性规则指定，不是模型输出。“关系未明”不再是成员角色：模型拿不准时按 `separate` 保持分立（DEC：拿不准就分开）。

成对关系判断的结论为三值：`same_event`（同一事件）、`progress`（同一发展线的后续）、`separate`（分开，带原因码 `unrelated` 无关、`roundup` 汇总稿、`insufficient_evidence`、`low_confidence`、`check_failed`）；AIHOT 的 SAME_OCCURRENCE / SAME_STORY / UNRELATED / ROUNDUP 由适配层映射（ENT-19）。事件之间的类型化关系 `updates` / `corrects` / `repeals` / `implements` / `related` 只由原文明示生成，`related` 不得显示为“后续进展”（ENT-68）。

## 13. 编号体系与外来编号前缀

完整规范见 `README.md`“编号规范”；本节只收术语层面的要点与易混组。

1. **主编号沿用 A 的分域编号**，新增条目在 A 的序列后顺延，**不复用、不重排**；作废的标【已废弃】并指向替代条目。
2. **B 的流水号是“规格卡 / 验收编号”**，原号不改写；与主编号的对应只在 `05-quality/07-traceability.json` 维护一处（`.md` 为同内容可读版，不一致以 `.json` 为准）。
3. **外来编号一律加前缀**（见 13.3），同一个“T24”“R03”“D05”“ADR 0012”不再有两三种含义。
4. 合并裁决用 `DEC-nn`；问题用一个 `Q-nn` 序列（A 的 Q-01～Q-22 原号保留，各专题的 OPQ、DQ、AIQ、EVQ 与 B 的 O-nn 并入同一序列、原号作别名，新增顺延）。
5. 包内不再使用 B 的证据代号（L01～L26、R01～R04、D01～D07），一律写“路径:行号@提交”或 `B:文件`；仓库内证据写 `路径:行号@main` 或 `@policy`，两包原件写 `A:文件`、`B:文件`。

## 14. 用语统一与禁用词

| 不要这样写 | 统一写成 | 说明 |
|---|---|---|
| 文章、文稿、稿件（作对象名） | 材料（内部）/ 条目（读者端与公开接口） | “新稿”“外文稿”只在已固定的读者文案与规则里保留，新写文档不再扩散 |
| 新闻线 | 资讯线 | 业务线只有资讯线与法规线 |
