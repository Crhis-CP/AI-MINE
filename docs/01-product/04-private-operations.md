## 1. 私有操作原则（所有页面的上位约束）

**P-1｜运营即数据，能力即代码。** 账号、信源的增改停启、模型接入与指派、用量与熔断（恢复熔断、调阈值、暂停）、下架与纠错、反馈处理、网站资料——在私有页面完成，不改 JSON、不改代码、不重新部署、不找开发 Agent。只有新增系统原本没有的能力（新分析阶段、新型信源等）才写代码。【设计输入】任务书 §2.1；Owner 2026-08-27「一方面是维护信源，一方面是切换模型」

**P-2｜人工是异常式，不是流程式。** 正常内容自动公开，发布不需要人逐条批准。人只在三种情况介入：主动发现问题要纠错或下架（OP-09）；机器无法解决、必须人决定的少数事项（来源方提出异议时逐源收紧权限 OP-04、异常熔断后的恢复与结果未确认的费用 OP-13）；建设期主动抽样标注（OP-11，默认关闭）。不以任何名称恢复逐条选稿或“待核查”堆积挡住公开。【Owner 决定 2026-09-26｜旧ADR-0037:21-22@policy】；Owner 2026-09-08

**P-3｜【已废弃】**“运营台首页是信源与自动运行总览”。已由 P-11 替代：私有入口页（OP-00-C）只是入口，不显示运行指标。

**P-4｜失败与人工审核分开。**“处理失败”是自动处理出错（系统自动重试，或需要安全重试、先核对原因），不是在等人；“人工审核”只指人主动保存但尚未发布的修订、或人主动暂放的稿件。“待核查”一词已废止，任何页面不得出现。【已验证】旧 PR #157

**P-5｜三条线互相隔离。** 采集线、模型线、业务线（资讯/法规）分开：异常熔断、费用结果未知、手动暂停模型处理只停付费模型工作（范围内新的付费调用），采集、正文清洗、规则判断和公开继续；暂停资讯线不影响法规线（反之亦然）。【已验证】旧 OP-04/OP-10（只停付费、不停公开）；【Owner 决定 2026-10-01】（异常熔断同样只停付费，DEC-08）；【Owner 决定 2026-09-26｜旧ADR-0037:23@policy】（业务线）；DEC-34

**P-6｜私有页面不在线，系统照常运转。** 页面关闭、出错或升级都不影响采集、整理和公开；页面上的写操作只写数据库或排队，联网和耗时工作交给后台程序。告警推送不依赖任何页面。【Owner 要求】Owner 2026-09-13

**P-7｜只说业务语言。** 页面不出现 adapter、hash、queue lease、embedding、schema version、Docker、SQL 等词；技术字段收在默认折叠的“高级诊断”。【设计输入】任务书 §3.1、§42

**P-8｜只说真话。** 0 与“暂时无法核对”分开显示；没有记录写“尚未记录”。“尝试采集、成功取得、新发现、中文完成、已公开”是五个分开的事实；保存了网址、有配置、抓到过样例都不等于“已接通”。【已验证】旧 OP-04 计数口径；Owner 2026-09-09

**P-9｜人工决定优先。** 人工下架、人工修订、人工暂停永远优先于自动结果；重采集、回填、重处理、软件升级都不能覆盖或复活。【已验证】旧 OP-06；ADR-0011

**P-10｜不要求人手写中文。** 中文标题、导读、译文由模型自动完成；内容还没有中文时显示真实原因（排队中、失败、熔断暂停等待恢复），不要求运营者先填；人工修订是可选的次级操作。【Owner 要求】Owner 2026-09-07

**P-11｜告警先于页面（新增）。** 运行出问题由系统主动推送，不要求任何人每天登录查看；页面只保留“必须由人做决定或操作”的动作。【设计】（由 Owner 已批准的“不设运营台”推出，旧ADR-0037:21@policy）；DEC-06

**P-12｜载体只有两种合法形式（新增）。** ①最小私有网页（给 Owner 与管理员）；②受控服务身份工具（给只读运维接口与部署流程）。**“命令行/命令”不是人类载体**：Owner 不使用终端，密钥一律经页面上的安全输入框录入。【设计】；Owner 2026-09-03、A:08-owner-voice OWN-15

## 4. 页面规格

### OP-00 全局规则

**层级**：切换前完成（M1：壳、入口页、隔离、确认分级与审计写入；T-0701）。

**目的**：规定所有私有页面共用的入口、导航、权限、语言、时间、写操作、确认、审计和错误处理规则。各页只写自己的差异。

#### OP-00-A 入口与隔离
- 私有页面与私有接口只在**最小私有页面的私有主机名**下提供（配置项 `PRIVATE_HOST`：与公开域名不同的子域，只承载最小私有页面、私有接口与只读运维 MCP，不是独立的运营台应用或运营子站，ADR-0018；默认取值与证书见 `04-architecture/07-deployment-and-ops.md` 第 1 节）；读者主机名访问 `/login`、`/api/admin/*` 等私有路径一律返回 404，且响应不带 `Set-Cookie`。【已验证】
- 私有主机名下除登录页外，全部页面与接口都要求登录；会话失效回登录页，登录后回到原页面（只允许私有路径）。【已验证】（回登录页）【设计】（回原页面）

**目的**：查看并维护单个信源——它是谁、按哪个配置版本在采、被允许做什么（权限与证据）、最近采得怎么样；启用前或改动后先试抓，看真实样例。

**角色与权限**：负责人。放宽权限、归档、开启 http 例外或 robots 例外为高风险；收紧权限为普通确认（OP-00-H）。

**输入（区块与字段）**
1. **头部**：名称；发布方（中文名 + 原文名，身份已核验/未核验/冲突，附依据链接）；法域与省州；机构类型；管理态；健康态；分级；参与方式；是否一手；入口网址（只有 https 且不含账号密码的地址可点击；启用了 http 例外的标“仅 http（例外）”且不可点击）；对应的原始信源表条目（点进 OP-07）。发布方身份为“未核验/冲突”时提供“确认为官方 / 按非官方来源处理 / 放弃该信源”三个动作（普通确认，记审计）。【已实现未验证】（只有安全地址可点击）【新增】（身份动作取代 A 的“官方身份无法确定”待办）
2. **按业务线的采集配置**（三层：发布方 → 信源 → 按业务线的采集配置）：同一信源可同时有“资讯线”“法规线”两条配置，各自有管理态、配置版本、频率、最近成功、下次运行、近期新增、当前公开；启用、暂停、恢复都按线操作，暂停一条线不影响另一条线。这一层就是 **ENT-56 采集配置**；状态、预览、游标、配置版本都挂在它上面，不在信源身份（ENT-02）上。【设计】；DEC-34；旧 operations-exit.md:16,30-31@policy
3. **操作条**：试抓预览、启用（待预览时）、暂停/恢复、立即运行（M2）、编辑、归档。【已验证】（旧测试与预览、启停、归档）
   - **立即运行**（M2，F-SRC-04；A 独有功能，B 无对应）：只对已启用、未暂停、未归档的采集配置开放，普通确认；产生一条可审计的采集运行任务（运行记录的触发方式记“立即运行”，BR-ACQ-25），仍由采集程序经生产获取路径执行，遵守同一礼貌间隔、每轮时长预算、租约与获取限制；该配置已有在途运行时复用同一任务；5 分钟内出现对应运行记录并写审计。网页请求只排队，不联网。【设计】；`07-sources-and-coverage.md` 5.3
4. **试抓预览**
   - 点击后提示“已安排试抓，采集程序会在下一轮执行，结果会自动更新。”，页面每 15 秒刷新；网页请求只排队，由采集程序联网；同一配置版本同时只有一个在途试抓，1 分钟内重复点击复用同一任务。【已验证】
   - 预览必须走**生产同一获取路径**（同一采集器与限制）；浏览器能打开不能替代采集器成功；测试用的固定样本（fixture）永不计作真实预览；权限只来自加入时的许可确认与逐源收紧，成功的预览不改变任何权限。【新增】B:F-004
   - 结果：“试抓通过：取得 N 条 · 时间”或“未通过：中文原因 · 时间”；3–5 条样例，每条含标题（链接原文）、来源发布时间（只有日期就只显示日期）、正文可得性（全文/仅摘要/无正文）、是否判为旧文；零新稿可说明为“低频来源”，不等于解析失败。【已验证】（旧最多 3 条样例与日期显示）【新增】（正文可得性）
   - 试抓不启用信源、不推进采集位置、不产生付费模型调用；单次试抓有页数与时长上限。【已验证】
   - **只有两种情况使旧结果作废：当前配置版本改变（影响采集的编辑）、信源被归档。暂停不使预览失效。**任务中断显示“试抓任务中断，尚未取得新结果，请重新试抓。”；从未成功显示“尚未取得成功的实际条目预览。”【已验证】（旧 2026-09-21 修复“暂停后无法恢复”）；DEC-57
   - **启用门**：首次启用须有**当前配置版本 24 小时内**试抓通过且至少 1 条样例，且“服务器抓取”“保存标题、时间与链接”两项权限为“允许”，且入口为 https（或已开 http 例外）；否则“启用”不可用并提示“请先试抓当前配置并取得实际条目，再启用信源。”。曾启用过的信源恢复不适用此门。【已验证】（预览有效期与样例数：`db/migrations/0010_source_operations.up.sql:100-105@main`）【设计】（最低权限）
5. **配置版本与编辑**
   - 显示当前版本号、生效时间、变更说明、创建人；历史版本列表只读；**版本对比**候选（不排期）。每次采集运行都记录所用配置版本，历史可追溯。【设计输入】任务书 §5；ENT-04
   - 编辑分两类：①**不影响采集**的项（名称、说明、许可说明、分级、参与方式、是否一手）保存即生效，**不暂停、不清游标、不要求重新试抓**；②**影响采集**的项（入口网址、获取方式、栏目与分页规则、允许主机、单次条数上限、频率范围）保存为新配置版本，新版本试抓通过并由操作人确认切换前，**旧版本继续采集**，供稿不中断；入口与分页规则未变时保留检查点。【新增】BR-SRC-23（旧站“任何保存都会暂停信源并清空采集位置”是已知坑）；D04-admin-007
   - 保存时先列出将修改的项目再确认；不能上传或粘贴可执行的抓取程序；系统尚不支持的网页格式在试抓时说明，不会因为保存了网址就开始运行。【已验证】
6. **入口传输、http 例外与 robots 例外**
   - 原始网址原样保存（原表有 63 个目标的 original_url、79 个 normalized_url 为 http，见 `A:data/source-targets-320.csv`）；**采集入口默认必须 https**，系统先尝试同主机 https。旧站入口只接受 https（`services/live_pipeline/source_registry.py:106,127@main`）。【已验证】（https 默认）
   - 确认某站确实不提供 https 时，负责人可为**单个信源**开启“仅 http”例外：高风险确认，记录依据与审计；此类信源的内容**不得作为“官方原文”的唯一完整性依据**；契约的 `entrypoint` 放宽为 http/https 并增加 `insecure_transport_exception` 标记。接入完成后统计真实只有 http 的目标数量，再决定是否保留该例外。【新增】DEC-56；D04-admin-018
   - **robots 例外**：robots 明确禁止的路径默认不抓，预览、研究、生产三条路径一致，运行记录显示“来源拒绝自动访问”及被拒绝的路径；负责人可凭许可（Owner 2026-10-01 的许可声明、来源方书面授权，或明确允许自动访问的官方接口条款）为**单个信源**逐源覆盖：高风险确认，必须写依据与原因，登记为该信源权限版本的证据并写审计；只对该信源生效、可随时撤销；覆盖不改变 robots 的缓存与内容变化复核，也不关闭公网地址校验等网络安全边界（BR-ACQ-15、BR-ACQ-16；T-142）。【新增】；DEC-33
7. **使用范围与权限**（ADR-0009；Owner 2026-10-01 已定：全部信源按“Owner 声明许可”建档，Q-02 已答复，DEC-33）
   - **基线**：信源加入时由负责人一次确认（OP-05），系统生成权限版本 1：九项用途一律“允许”，证据类型 `owner_declared`（证据文本“Owner 2026-10-01 书面答复”，确认人为负责人，记录确认时间），**不设自动到期**；本页没有“待审定”状态、没有规则建议、没有批量确认。旧站“四档使用范围预设”（仅标题与链接｜发布方允许使用的摘要｜政府机构标题与摘要｜明确授权的文本，【已实现未验证】`apps/web/components/admin-live/operations.tsx:1515-1524@main`）是逐源审定时代的快捷填充，新基线下不再使用：一律从“全部允许”起，只做逐项收紧。
   - **九项权限**（取两包并集，DEC-58）：服务器抓取｜保存标题、时间与链接｜本机清洗与规则处理｜保存正文全文｜交给外部模型处理（中文整理与翻译）｜公开展示短摘录｜公开展示本站导读｜公开展示原文全文｜公开展示译文。每项一个开关（允许／已关闭），附依据与说明；每个权限版本带**确认人、确认时间、范围条件与署名义务、附件是否在范围内**，版本不可变；仅带明确期限的补充证据才有到期时间（BR-SRC-32），`owner_declared` 不设到期。对象是 **ENT-03 来源用途契约 SourceContract**（A 原“信源权限”）。另预留**第十项“站外再分发全文”**（`syndicate_fulltext`：全文 RSS、公开 API 正文、公开 MCP 正文）：默认关闭（失败关闭；不在 2026-10-01 的许可声明范围内），本页只读显示、不提供放宽入口，站外出口只给导读与原文链接（Q-47）。【新增】ADR-0009、ENT-03
   - **“已关闭”只关对应那一层**，不阻塞该信源在允许范围内的其他处理；每行用一句话说明后果，例如“交给外部模型处理：已关闭——这个信源的外文材料不会生成中文标题和导读，只展示原文标题与链接”。没有任何权限版本记录的信源（失败关闭）显示“缺权限记录”，不能启用，由负责人补做加入时的一次确认。站点自己的限制声明（robots 的 AI 限制、“禁止转载”、条款要求书面许可）只作**线索**显示在“站点声明”区，提示负责人，**不自动关闭任何用途**（BR-SRC-16）。【新增】B:F-010；DEC-33
   - **逐源收紧**（用途改为收紧：允许 → 已关闭）：来源方提出异议、Owner 指示或法律要求时，负责人逐源逐项关闭用途（可多项，也可整源关闭），必须选**原因**（来源方异议 `source_objection`｜Owner 指示 `owner_instruction`｜法律要求 `legal_requirement`）并写明依据（来函或指示的摘要与日期）；**普通确认、立即生效**，确认框先显示受影响的已公开内容数（例如“12 篇将改为只展示导读与原文链接”）；已公开的全文或译文随之撤回，与下架联动（60 秒内全部公开出口不可见，DEC-48）。**放宽**（已关闭 → 允许；异议撤回或指示解除后）为高风险，只限负责人，必须写原因，只对之后的处理生效、存量有界补做（BR-SRC-14）。每次修改产生新权限版本，历史处理记录保留当时版本。固定提示“网页可以打开，不等于允许交给外部模型处理或在站内转载全文；本站的许可来自 Owner 的声明与来源方的授权。”【新增】（收紧机制）【已验证】（提示语，旧站）
8. **运行记录**：最近 20 次采集（时间、触发方式：定时/立即运行/回填/试抓；结果：成功/部分成功/失败/跳过；发现、新增、更新条数；耗时；中文原因；配置版本号）；回填进度（最近 72 小时 → 7 天 → 30 天，回填内容按原日期归档、不进入“今天”）。失败原因一律中文，见下表。【新增】ENT-08；BR-TIME-06/07
9. **最近材料**：最近 20 条（中文标题或原标题、来源发布时间、状态：已公开/已过滤/处理中/处理失败/已下架），点进 OP-09。【设计】
10. **修改记录**：本信源的审计记录（动作、操作人、时间、原因、前后变化）。【设计】
11. **高级诊断**（折叠）：信源编号、配置参数原文、上次读到的位置、配置内容指纹、最近错误码、最近任务编号。【设计输入】任务书 §42

**采集失败原因（中文，原 OP-08 保留于此）**：域名无法解析｜来源拒绝自动访问，需要更换正式公开入口｜入口不存在｜访问频率受限｜来源暂时不可用｜响应超时，请缩小单次范围｜订阅内容格式不受支持｜已连接但没有找到带有效标题、链接和日期的记录｜文章身份与详情地址不一致｜网页格式尚未支持｜需要浏览器渲染但环境未安装｜跳转到其他网站或内部地址，已按安全规则拦截｜响应过大，已按上限停止。【已验证】（旧来源错误原因中文映射）【新增】（后两项，A:06-security-and-access §6）

**规则**：单个信源失败只影响它自己；失败不推进“上次读到的位置”，下次从同一处继续；连续失败达到阈值（默认连续 5 次或 24 小时）的采集配置健康态转为 degraded，即界面的“降级修复中”（降低检查频率并触发告警），恢复成功后自动回到“正常”。权限某一层已关闭（或缺权限记录）只阻断对应动作；原始记录不可改写。【新增】ENT-56、ENT-09

**失败态**：无运行记录“尚未运行过。启用后，采集程序会在下一轮检查。”；保存冲突“该信源已被他人更新，请刷新后重试。”；试抓失败用上表中文原因。【已验证】（冲突提示）【设计】

**审计**：保存配置（新旧版本差异）、试抓、启用、暂停/恢复、归档、权限收紧/放宽（每项前后值、原因与依据）、开启/关闭 http 例外与 robots 例外、确认身份。【已验证】（旧来源配置、预览、状态变化均写审计）【新增】（权限前后值）

**阶段**：M1 骨架 → M2（F-SRC-03 配置版本与试抓预览、F-SRC-04 启用/暂停/恢复/立即运行/归档；T-0702），切换前完成；版本对比候选（不排期）。

**验收要点**
1. 只改名称或许可说明：信源不暂停、不需要重新试抓、采集位置不变。
2. 改入口网址产生新配置版本；新版本试抓通过并确认前旧版本继续采集；任何一次采集运行都能查到当时的配置版本。
3. 试抓只排队、由采集程序执行；1 分钟内重复点击只产生一个任务；试抓不产生付费模型调用；fixture 结果不能用于启用。
4. 暂停信源后预览仍有效；曾启用过的信源恢复无需重新试抓；只有改配置版本或归档才使预览作废。
5. 没有 24 小时内通过的试抓时，首次“启用”不可用并写明原因。
6. 把“公开展示原文全文/译文”收紧（关闭）后，所有公开出口立即只展示导读与原文链接（已公开的全文或译文 60 秒内撤回）；放宽任一已关闭的用途都需要负责人和原因；缺权限记录的信源在处理中按禁止执行。
7. 不提供 https 的站点：默认不能启用；开启 http 例外须高风险确认并留审计，且该信源内容不作为官方原文的唯一完整性依据。
8. （M2）“立即运行”只对已启用、未暂停、未归档的配置可用；点击后 5 分钟内出现触发方式为“立即运行”的运行记录并写审计；已暂停的配置在后续节拍中没有新运行记录（BR-ACQ-25）。
9. robots 明确禁止的路径在没有例外时不被请求（预览、研究、生产三条路径）；负责人逐源覆盖须高风险确认、写依据与原因并留审计，只对该信源生效、可撤销（T-142）。
10. 新加入的信源建档后九项均为允许、证据 `owner_declared`；收紧一项后该用途在所有出口即时消失、其余用途不受影响，并生成新权限版本与审计；管理员看不到收紧与放宽入口（T-151）。

**依据与退出依赖**：任务书 §5、§42；旧 OP-04 测试与预览、编辑表单、启停规则（线上已验证）；ENT-02（信源身份）、ENT-03、ENT-04、ENT-05、ENT-56（采集配置：管理态 × 健康态、配置版本、预览、游标）、ENT-08、ENT-09；F-SRC-01～F-SRC-04；ADR-0009；旧 PR #178；BR-SRC-12、BR-SRC-36、BR-ACQ-15、BR-ACQ-16；DEC-33、DEC-34、DEC-56、DEC-57、DEC-58；旧 operations-exit.md:8@policy（经验参考）。

**实现基础**：可复用 AIHOT 信源详情（预览抓取、暂停/恢复需原因、保存时列出修改字段并要原因、采集记录、修改记录，`AIHOT:apps/web/app/routes/admin/source.tsx`）。需改：预览改为采集程序排队执行；配置改为不可变版本；用九项权限矩阵（逐项收紧开关）替代 AIHOT 的“站内可展示全文”“对外接口可带全文”两个开关；AIHOT 新建表单默认勾选前者、不勾后者，与本项目 v2.1 基线方向一致（站内用途建档为允许，第十项站外再分发默认关闭），区别是本项目由负责人在加入时一次确认并记录 `owner_declared`；配置原文移入高级诊断。

### OP-05 添加信源

**层级**：切换前完成（M1 骨架 → M2 页面齐全；AI 研究 M3；T-0702）。

**目的**：人工添加信源只填三项——法域、网站名称、网站地址；语言、时区、更新方式、栏目、检查频率、权限线索等由系统检测并维护。

**延后/不排期**：每日费用明细、错峰状态、调用频率上限的调整界面（候选，不排期；只读运维接口已能查询每日费用）。用途配额、两线保底额与调剂额**已取消**（DEC-08）；“费用最高的对象”已并入月度用量报告（最贵的 10 个任务，BR-COST-18）。【设计】；D19-decisions-004

**消息规则**（改造自 AIHOT `packages/backend/src/notify/feishu.ts`、`deliver.ts`）：只发业务语言（对象、对读者的影响、建议动作）；**不含密钥、正文、个人信息**；同一对象同一类型持续未恢复时只推一次，之后每 24 小时提醒一次；恢复时发“已恢复”通知。另有两类定期摘要：每日一条摘要（取代系统页：当日各线公开条数、最近公开时间、积压、本月用量与熔断状态、最近备份与演练、当前与上一版本，07 6.6）；每周一条反馈汇总摘要（OP-14，不含联系方式、截图与反馈正文）。【设计】；D19-decisions-008

**失败态**：“告警渠道未配置：系统出问题时不会通知你。”（入口页横幅）；测试失败的中文原因；读取失败“暂时无法读取，请稍后刷新。”【设计】

**审计**：配置/修改渠道（只记指纹）、发送测试消息。【新增】

**阶段**：M1 引擎与渠道页骨架（可向测试渠道发送；T-0192、T-0706）→ M2 随首次生产部署上线并演练（F-OPS-03，目标环境持续运行前必备）；全部在切换前完成。**首次生产部署的前置条件**：渠道已配置且测试通过、告警接收人在云监控控制台确认可用，才算上线检查项通过（`07-deployment-and-ops.md` 第 9 节第 5 项）；告警不依赖任何页面，页面不可用时照常推送。【设计】；DEC-06

**验收要点**
1. 停掉自动处理程序，一个检查周期（≤5 分钟）内推送到渠道，读者站不受影响。
2. 资讯线、法规线分别停更时，各自触发告警并指明业务线（资讯线最近一次公开 >12 小时；法规线最近一次计划检查成功 >24 小时；T-102）。
3. 推送失败不丢：下个周期重试并走第二渠道，本页“未送达”列表可见；恢复后列表清空（T-146）。
4. 消息里找不到密钥、正文、个人信息；同一告警不重复轰炸，恢复时收到“已恢复”。
5. 修改渠道需高风险确认并留审计，向旧渠道与新渠道各推一条通知；渠道地址在页面、接口与日志中都不回显（只显示指纹）；管理员打不开本页。
6. 未配置渠道时入口页显示横幅，上线检查表不通过。
7. 替换模型密钥、调整异常熔断阈值、创建或重置账号后，渠道收到相应推送。
8. 备份 >36 小时无成功、距上次成功演练 >35 天、系统盘已用 ≥18,000,000,000 字节，各自触发对应的预警或严重告警。
9. 月内累计用量每增加 100 元收到一次用量提示（只提示、不暂停）；熔断指标达到阈值的 70% 收到预警；触发熔断收到“异常熔断触发”（含范围与恢复入口），恢复后收到“已恢复”；各类各一次、不重复刷屏（T-099、T-146）。

**依据与退出依赖**：旧ADR-0037:21@policy；旧仓库 `docs/reviews/product-production-audit-20260920.md:16-20@main`（停更 5 天无人察觉）；`04-architecture/07-deployment-and-ops.md` 6.3–6.6；`04-architecture/06-security-and-access.md` 第 3 节；B:quality/01 §14（异常延迟有告警）；F-OPS-03（规格卡 F-057）；ENT-51、ENT-53；T-099、T-102、T-146；DEC-06、DEC-08；Q-22（已答复）。

## 7. 载体、私有接口与工作包

### 7.1 载体

- **最小私有页面**随 reader-web 与 api 在私有主机名下提供，**不另起 admin-web 应用**（DEC-30；ADR-0018 取代 A 的 ADR-0008【已废弃】）。只要满足下列约束，是否拆进程由 ADR 比较后定（同一代码库、私有路由仅在私有主机名暴露的独立构建，或独立容器；ADR-0018 第 8 条的触发条件：私有页面依赖无法与公开包隔离，或安全审计要求物理隔离）：独立主机名（读者主机名访问私有路径 404）；独立路由组；私有代码不进公开页面包；**读者站构建产物不含后台路由清单**（AIHOT 默认的路由发现会把整张路由清单随每个公开页下发，见 `AIHOT:apps/web/react-router.config.ts:7-9`，必须关闭或分构建）；边缘层可复用 AIHOT 的会话校验端点做 `auth_request`（`AIHOT:apps/api/src/routes/admin-auth.ts:122`）。【设计】
- **受控服务身份工具**：worker、只读运维接口（含只读 MCP）、部署流程用服务身份，不依赖浏览器会话；`observer` 是机器只读身份，不是人类角色；机器行为与人类行为使用不同 actor。只读运维接口不给生产任意 SQL 或 shell 能力，数据脱敏（无密钥、个人信息、第三方全文、提示词）。只读运维接口的最小版本（健康、队列、运行记录、账本、审计、来源覆盖导出）随 M1 提供（AC-M0-16、T-135），取代被废弃的状态页。【设计】；F-OPS-04 由 M2 提前
- **“命令”不是人类载体**（P-12）；首个负责人开通属于部署方的一次性动作，负责人忘记密码走云控制台触发的固定脚本（OP-01 第 4 条；`06-security-and-access.md` 3.1），两者的操作步骤都记录在应急手册（§8.1）。
