- **两档标注**（Owner 2026-10-01，DEC-19）：每个功能的“阶段”列只有两种取值——**切换前完成**（全部排期功能，并写明在哪个里程碑 M0–M4 做完）与**候选（不排期）**。原“★ 切换必备”与“切换后”不再区分先后：★ 与“切换后”已全部删去，原“切换后”的功能（如公开 MCP、llms.txt、周月 AI 综合、精选与热点、人工精选、主题页）已并入 M3。
- **切换前全部完成，一次性全面切换**：“全部排期功能”= 本表除“候选（不排期）”以外的全部功能——资讯线、法规线、事件、精选与热点、报告、主题、搜索、收藏、对外出口（API、RSS、MCP 等）、最小私有页面、告警；各自通过验收后才一次性全面切换，旧站在此之前照常服务；“与旧站读者能力对等即切换”作废。
- **切换门槛**：全部排期功能验收通过；影子运行通过；恢复演练一次；告警渠道就绪；Owner 在真实公网与手机上逐项看过；其中精选须有“矿业版评分标准已由 Owner 审阅确认”与“门槛已完成一次留出集检查并留记录”两份记录（BR-SEL-08、BR-SEL-09、ENT-84、T-158、T-160；清单与切换日检查见 T-159）。不迁移旧数据（F-MIG-01【已废弃】），所以没有“导入对账”一项。切换当天文章页的“相关报道”“事件进展”与日报、周报、月报必须已有（F-MIG-02）。
- **法规政策线**从 M1 起与资讯线并行、隔离建设，**页面与管线功能计入切换门槛**：功能完成并通过验收场景即可；覆盖度（36 个法域的研究、取得、中文、解读、持续运行）在台账里如实展示并持续推进，**不以 36 个法域全部供稿为切换门槛**；完整解读仍按“法域 × 文书类型”抽检通过后分组开放（DEC-15）。此前“法规栏目不作切换门槛”的说法作废；研究与处理不得因切换排期而推迟（旧ADR-0037，Owner 2026-09-26 批准）。
- “阶段”写成“M1→M2”这类“Mx→My”时，前者是首次可用（M1 为合成闭环），后者是真实来源或完整验收；写成“M3（……）”时，括号说明该里程碑内的范围。

## 标签

| 标签 | 用法 |
|---|---|
| 【已验证】 | 旧仓库有验收记录或线上回读证据的行为（“旧站现状”列给出处）。只说明该行为在旧站确实可用过，**不等于旧站整体验收通过**：旧站整体验收与 24 小时/7 天观察均未通过（README.md:15-17@main），新系统仍须逐项重新验收。 |
| 【已实现未验证】 | 旧仓库（main 或法规分支）有代码，但没有验收记录，或已知验收未通过 |
| 【Owner 决定】 | Owner 已批准的决定，附日期与依据 |
| 【设计】 | 本包提出的设计，旧站没有 |
| 【新增】 | 旧站没有、本包新增的功能（含可改造 AIHOT 现成实现的） |
| 【已废弃】 | 不再实施，指向替代条目 |

新系统的实现进度另用 02b“全局完成条件”的六级状态（specified → implemented → locally_verified → integrated → live_verified → quality_accepted）。交接时本表全部功能为 specified。
