## 1. 对谁提供什么

### 1.1 服务对象与口径 【Owner 决定】2026-09-26（POL-D01/D02）

面向公开行业服务，不引用内部项目、谈判、特定企业私有事实，不写“我公司应当”。帮助读者理解一项法律或政策变更在**哪些地区、对哪些法定主体及受影响主体、针对什么活动、什么条件与例外、何时、通过何种直接或间接路径**产生作用。只做公开通用的条件化影响，不输出数值影响分，不做特定企业定向结论（DEC-11）。

一份合格文书支持动态、重点条款解读、原文/完整中文及周/月汇总；不是几条互不关联的 AI 文章（POL-D06）。

### 1.2 入口与交叉呈现 【Owner 决定】2026-09-26（POL-D05；DEC-02、DEC-62）

| 项目 | 规定 |
|---|---|
| 栏目名 | 法规政策动态 |
| 入口 | 桌面侧栏独立入口，紧排“矿业日报”之下；矿业日报页顶部放显式入口；手机在“更多→内容”（DEC-02；旧分支实现为侧栏独立入口） |
| 路由 | `/policies`（列表）、`/policies/{id}`（文书）、`/policies/{id}/history`（本站版本记录，F-POL-10、规格卡 F-066）、`/policies/reports?kind=weekly` 与 `?kind=monthly`、`/policies/reports/{id}`（D03-reader-pages-002） |
| 与新闻的关系 | 法规文书只在本栏目列出，不计入“全部矿业动态”条数；全库搜索在新闻结果下方加“法规政策”分区；新闻详情的“相关法规文书”块链接到被报道的文书；官方公告类新闻仍是新闻（资讯线），不生成文书；旧站数据不迁移（DEC-20、DEC-62） |
| AI 标识 | 详情、报告、RSS、API 显式标“AI 辅助生成/翻译”并带机器可读标识；官方中文标“官方中文”，不标 AI（DEC-38） |

### 1.3 无运营台 【Owner 决定】2026-09-26（POL-D03；旧ADR-0037:21-22@policy；DEC-04、DEC-14）

正常流程不设运营台，不要求逐篇选稿、翻译、重试或发布操作，不以其他名称恢复逐条审稿。法规线需要的私有操作放进“最小私有页面”（DEC-04）：文书下架/恢复/修订、来源增停与预览（按业务线的采集配置，DEC-34）、用量与模型密钥、建设期抽检评审（DEC-15，不是日常关卡）。运行状态与质量资格到期提醒改为告警推送（DEC-06，F-POL-11）。质量资格安装、来源契约导入属于工程入口，不是日常运营操作（旧分支 `runtime-materials.md:75-81@policy`）。

### 1.4 两线共享与隔离 【Owner 决定】2026-09-26（POL-D07；主编号 F-POL-08，规格卡 F-046 见 §4）

法规业务和新闻业务共享可靠获取、存储、模型网关、费用账本、身份等能力，但须隔离准入政策、暂停状态、优先级、任务种类、用量记账与熔断和质量门槛（不设保底额，DEC-08）。暂停新闻、新闻低分或新闻队列积压不能停掉法规任务；法规不能因“不是热门新闻”被过滤；法规 lane 的材料不经过新闻预筛（AI-01），准入取决于来源职责与文书身份（D07-ai-004）。

## 5. 展示层必须说清的状态

任何失败、未达资格、到期或撤回，只能映射到下表某一状态；**禁止用新闻导读（AI-04）、摘要或“资讯”形态顶替法规分析**（D07-ai-003；旧ADR-0037:55@policy）。各状态的读者可见文案以 `06-content-standards.md` DR-82（阅读状态）与 DR-98（读者文案清单）为准，本表只定状态映射；决定性附件缺失、容量超限按 DR-38“法规线”处理（不使用资讯线的“仅导读例外”）。

| 状态 | 读者能看到 | 不得说成 |
|---|---|---|
| 仅基本事实合格 | 文书身份、官方链接、已核实公布/变化日、事实提示 | 完整政策解读 |
| 原文可读但中文未完成 | 原文入口/允许展示的原文、中文处理中 | 全文中文 |
| 原文/中文完整、语义未通过或资格未授予 | 允许的阅读材料及相应状态，完整解读暂不可用 | 已验证法律结论 |
| 完整解读合格 | 清晰区分原文、官方中文/AI 辅助译文、平台解读、证据与条件 | 官方背书、个别企业定向法律结论 |
| 决定性附件缺失 / 字符完整性未核验 / 容量超限 | 已核实基础事实、缺项和原始入口 | 依据全文得出的确定结论 |
| 相关性为 uncertain 【设计】 | 保持“仅基本事实”形态，不升为完整解读；进入质量评测样本，不进入人工待办 | 与矿业经营相关的确定判断 |
| 相关性为 excluded 【设计】 | 不在本栏目列出（私有保留，供覆盖统计） | “无新法规” |
| 已更正/撤回 | 当前可用版本或不可用状态 | 缓存中的旧确定结论 |
| 许可被逐源收紧或质量资格到期 | 从列表、详情、正文、搜索、收藏、报告同步移除，不降为摘要 | 旧版本仍有效 |

> 基本事实形态的公开以来源契约的“公开原文”用途和文书身份核验为前提；原文与中文并排阅读须同时具备“公开原文”“公开译文”两项许可，只有其一时（默认都允许，只有被逐源收紧才会出现）按上表降级（`publication-runtime.md:16@policy`）。

## 6. 需新架构保留的接口语义

- **实体链**（D10-data-002）：PolicyInstrument（身份 = 法域 + 发文机关 + 类型 + 文号；无文号时退化为来源身份 + 官方 URL；**不含标题**）→ PolicyVersion（法定版本/汇编版，带多维法律状态与 TimeAssertion 形式的各日期）→ PolicyExpression（版本 × 语言 × kind[original | official_translation | ai_translation]）→ DocumentRevision（站内取得修订：内容哈希、有序节点，节点带层级、父节点、跨版本稳定 ID 与结构化定位如 `art:12/para:3`）+ Attachment（必要性、权利、完整性、取得状态）。每个（文书，语言）一个“当前公开头”；本站版本历史与法定沿革分开。
- **Interpretation**：输入修订、规则/模型执行身份、全部块覆盖、相关性（私有）、main_points、impacts、legal_state、relationships、gaps，全部绑定证据。
- **PolicyImpact**（BR-POL-13）：`{id, theme(七主题键), region, legal_actor, affected_actor, activity, condition, effect_mode: direct|indirect, impact, deadline?, exceptions?, evidence_ids[]}`。
- **公开 DTO 增补**（D11-policy-005）：Policy 增加 `impacts[]`、`main_points[]`、`themes[]`（由 impacts 汇总）、`change_kind`（首次公布/实质修订/勘误/废止/施行/登记汇编/其他）、多维 `legal_state`（DEC-36）；PolicyCard 增加 `themes[]`、`change_kind`、`applicability_summary`；列表接口的 theme 参数改为七主题枚举，并补日期与文书性质参数。路径前缀与字段命名以 03-data/02-public-api-contract.md 为准（DEC-21、DEC-51）。
- **只在私有侧**（不进公开 DTO）：相关性判定、QualityRelease、SourceContract 与证据、FetchReceipt、CatalogueScan、CoverageCell、PolicyReportMember{section, available_by_cutoff}（D10-data-003）。
- **公开资格**是单一判定函数：当前原件指针 ∧ 契约与用途未过期 ∧ 解读核验通过 ∧ 分块哈希一致 ∧ 资格有效 ∧ 未撤回；失配即从所有出口消失（BR-POL-11）。
- **Suppression** 的对象类型扩展到 PolicyVersion / PolicyExpression / PolicyInterpretation；对不可变公开版本的撤回是永久的，已撤销的资格 ID 不得复活（`publication-runtime.md:19-21@policy`）。

新闻和法规的可重用服务通过契约协作，不复用隐藏全局暂停、新闻相关性阈值或新闻正文容量作为法规规则。超长文书容量按真实样本测定（F-047），成本不能让系统“只理解前几段”（不设月度金额上限，DEC-08）。
