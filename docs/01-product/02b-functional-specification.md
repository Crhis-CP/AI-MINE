## 适用于全部规格卡的约束

- **兼容与旧数据**：无需兼容旧表名、旧内部接口和旧后台导航，也不迁移旧站任何数据（Owner 2026-10-01：全重做，DEC-20）；**旧链接、旧 RSS、旧接口全部不要**（Owner 2026-10-01：“旧文章链接也全都不要，相当于从 0 开始做文章内容”，DEC-21）：新站不为旧站的任何地址做兼容、重定向或专门的说明页，没有旧链接对照表、没有 301 映射、没有“本站已全新改版”专页、没有旧接口适配期；新站只有自己的路由与接口，访问新站不存在的地址（包括旧站的文章、事件、报告链接、旧 RSS 与旧接口地址）一律走通用的“页面不存在”（404，带首页与搜索入口，PG-17）；新公开 API 使用 /api/v3 前缀，只为避免旧客户端打到同名路径拿到形状不同的响应，不承担任何兼容义务；公开 ID 不复用是新站自身的规则（F-055【已废弃】）。业务语义须保持。
- **主线**：全部动态、正文阅读、自动处理为资讯主线；法规政策线从第一个里程碑起与资讯线并行、隔离运行（旧ADR-0037，Owner 2026-09-26 批准，DEC-01）。
- **不设日常运营台**（Owner 2026-09-26 决定，旧ADR-0037:21@policy）：本文件 §D 的私有能力只以“最小私有页面”（F-063，载体已由 Owner 2026-10-01 确认，Q-04 已答复）承载——账号、信源增停与预览、下架/恢复/修订、用量与模型密钥、反馈、网站资料；运行状态改为告警推送（F-057）与只读运维 MCP（F-064）；不做总览、审稿关卡、审计页（DEC-04）。
- **角色**：人类角色只有负责人（唯一）与具名管理员；能力按下列分配：内容修订与下架、异常重试、反馈处理为管理员默认具备；信源配置、用量与熔断阈值、账号、网站资料、审计读取为负责人专属；模型配置负责人可按人授予。observer 只作机器只读身份（只读 MCP、健康读取），不作人类角色（DEC-32）。登录只用密码的具名账号，不排期第二因素（DEC-05）。
- **公共边界**：公共接口只能读公开投影，匿名反馈是独立受限写入口。
- **用量与熔断**：不设月度金额上限（Owner 2026-10-01：“预算无上限，但是不要浪费”）；“不降级”与“不浪费”纪律保留（确定性优先、回执与缓存复用、结果未知不盲目重发、每能力输入与重试上限、评测与研究用最小必要样本）；按业务线、能力、信源记账，每月 1 日推送上月用量报告，月内累计每增加 100 元推送一次用量提示（只提示）；异常熔断（防故障烧钱，不是预算上限）只停付费调用、不停公开，熔断前有预警（任一指标达到其阈值的 70% 先推送预警，只提醒、不暂停，预警与熔断都走告警渠道）；积压时处理顺序仍是“法规 > 官方一手 > 其他”（DEC-08、DEC-09；BR-COST-17～20）。
- **外文新稿公开条件**：中文标题 + 导读 + 可取得且获准的完整中文正文；摘要不计全文；不编造译名（DEC-35、DEC-37）。
- **精选/热点**：Owner 2026-10-01 已定沿用 AIHOT 的机制并矿业化（预筛、同一标准独立两次评分、按信源分级门槛 T1 60 / T1_5 65 / T2 76、显示平均分与推荐理由、按事件的 48 小时热点榜前 10），随全面切换上线；矿业版评分标准是草案，生效前必须先交 Owner 审阅确认（提交时并排给出 AIHOT 原规则与矿业版改动点），未经确认不得用于正式站的精选；显示按 AIHOT（有评分的条目显示“AI 评分 · NN”小标签，没有评分什么都不显示）；日报、周报、月报从精选候选取材（DEC-65）；旧 55/70/65/75 公式等自设参数作废（DEC-10）。

## A. 来源与获取

### F-001 原始来源资产与覆盖台账
- 主编号：F-SRC-01、F-SRC-06、F-OPS-01；所属模块：sources、platform/ops。
- 输入/输出：原始表记录、URL、国家、机构 → 不可改写的 observation、规范来源映射、当前处置及证据。
- 正常：以 `data/source-targets-320.json`（`records` 层 321 条原表记录 + `targets` 层 320 个归并目标；两个 CSV 是它的表格版）完整导入（不做部分导入；导入的是 Owner 的原始信源表，属需求输入，不是旧站数据，T-147）；保留320目标是历史去重结果，重新核实别名/迁移。法域字典一次建全36个对象（33国+欧盟/联合国/OECD），每个带 news_scope / policy_scope；资讯线以18国起步、按实测逐步扩，不随法规线自动扩到33国（英国、伊朗、瑞士、玻利维亚、马里标为背景层，不进必达分母、排在其余之后；Owner 2026-10-01 已定，Q-09 已答复，DEC-03），法规线33国+3组织（DEC-03）；中国14个省区作下级法域，“跨国/未限定”单列、不计入任何国家分子。
- 计数口径（DEC-59，一张表供对账与验收共用）：原始记录数（321）与目标数（320）→ 已研究候选 → 已配置（有关联信源）→ 独立发布方数 → 预览通过 → 已启用 → 成功采集（至少一次取得实际条目）→ 持续供稿（近7天、近30天分报）→ 已公开产出 → 中文完成（标题导读与全文分列）。按“发布方 → 信源 → 按业务线的采集配置”三层中写明的层计数（DEC-34）；互不推导；“已导入/已配置不等于已接通”。
- 空/失败：未核实记待核实；无效网址记录新入口或具体阻塞；无近期稿与网络失败分开。缺值不可算0或active。
- 权限：公开只见必要来源署名；完整台账私有，导入者不可覆盖历史原始字段。
- 验收 A-F001：重复导入不增重复任务；每条原始记录可追溯且计数守恒；上述各计数不混算，多个配置指向同一发布方不虚增独立发布方数。（T-147；B：L02/L03）

### F-002 极简来源提交与自动研究
- 主编号：F-SRC-05、F-SRC-08、F-AI-04、F-ACQ-05；所属模块：sources、acquisition、ai-gateway。
- 输入/输出：国家、网站名、URL → 候选研究结果、身份/入口/语言/时区/处理权限依据、推荐采集配置。
- 正常：分两段交付。首版（M2）为确定性探测：API/RSS/Atom/站点地图/列表、平台族识别（含中国政府网站通用适配 F-052）、重复关系和可行获取方式，生成配置草案并发起预览请求；探测不出时进入“高级设置”，由负责人或开发 Agent 补配置。随后（M3）对身份冲突、栏目不明、条款归纳用有界工具循环离线研究，产物只是待准入的候选配置，生产主链路不用 Agent 循环（DEC-16）。技术参数作为高级信息，不强迫用户填写。默认只接受 https，负责人可为单源开 http 例外并留审计（DEC-56）。
- 空/失败：未知时区保持空；身份/权限缺证不启用；研究部分完成保存进度和未决点，不要求重填。
- 权限：信源配置能力，默认负责人专属（DEC-32）；普通读者无入口。模型研究只能提出证据与建议，费用记入用量账本、受异常熔断保护，不设月度金额上限（DEC-08）。载体为最小私有页面“信源”组（F-063）。
- 验收 A-F002：仅三项必要输入可建立候选；相同机构多个URL能关联；恶意/内网URL在任何获取前拒绝；http 入口无例外审计时拒绝。（B：L04；C：L11）

### F-003 辅助扩源与覆盖缺口
- 主编号：F-SRC-09、F-AI-04；所属模块：sources、ai-gateway。
- 输入/输出：目标国家、机构类型、覆盖缺口 → 有证据候选列表及重复/价值解释。
- 正常：优先补已定国家主管机关、环境、安全、公报、税务、贸易等缺口，同时覆盖媒体和矿企；搜索结果需逐项核实。缺口用两张矩阵并存：资讯扩源按“法域 × 机构类别”，法规验收按“法域 × 七经营主题”（DEC-60）。
- 空/失败：无可信候选显示未找到；已知失效不假装接通；未知身份和第三方转载不得冒充官方。
- 权限：系统可发现研究；新来源由负责人确认后加入（加入时一次确认许可，按 owner_declared 建档，DEC-33），不允许模型无限自扩张。
- 验收 A-F003：候选只能进入待准入状态；发现次数和正式来源数独立；研究与评测费用同样记入用量账本、受异常熔断保护，不设月度金额上限，研究与评测用最小必要样本（DEC-08）。（B：L04）

### F-004 来源预览与准入
- 主编号：F-SRC-03；所属模块：sources、acquisition。
- 输入/输出：精确配置版本、处理范围 → 同一生产获取路径的预览证据、结构化样本计数、时间/权利/身份结论。
- 正常：核对正式URL、解析质量、近期供给及AI处理资格；保存配置指纹和检验时间；预览绑定配置版本、权限版本与入口版本，三者任一变化即作废。**首次启用**须同时满足：预览针对当前配置版本、在24小时内完成、由worker经生产采集路径执行、状态通过且样例≥1（DEC-57；旧规则 db/migrations/0010_source_operations.up.sql:100-105@main）。预览不启用来源、不推进生产游标、不产生付费模型调用；每个配置版本只保留一个在途预览，重复提交复用。
- 扫描预算：声明为“先取后筛”的来源（如澳大利亚立法库先取分类结果再按矿业名称筛）显式配置原始候选条数、页数、外层时限与站点间隔（旧值 20 条/6 页/90 秒/10 秒间隔可作起点，展示不超过 3 条）；结果区分 `scan_incomplete`（到达扫描预算仍未覆盖完）与 `no_valid_record`（扫描完成且无合格记录）。
- 空/失败：零新稿可说明低频，不等于解析失败；TLS、身份、权限、解析、日期分别失败。浏览器能访问不替代实际采集器成功。
- 权限：信源配置能力（负责人专属）；对**尚未启用过**的来源，编辑采集身份字段会使旧预览不能用于首次启用。曾启用来源的恢复规则见 F-005。
- 验收 A-F004：并发编辑后旧预览失效；超过24小时的预览不能用于首次启用；fixture永不计作真实预览；预览不改变权限矩阵（权限由加入信源时负责人的一次确认与 owner_declared 建档决定，DEC-33）；前3条原始结果不含矿业词而后续有合格记录时不判“无合格记录”。（B：L02/L03；C：L11）

### F-005 来源暂停、恢复、立即运行与归档
- 主编号：F-SRC-04；所属模块：sources。
- 输入/输出：source、期望版本、动作（暂停/恢复/立即运行/归档）与原因 → 新来源状态、审计、调度生效状态。
- 正常：暂停后不派新任务；运行中任务在提交前重验状态。每条暂停必须记录范围（单来源/资讯线/法规线/付费模型）、原因、操作人、开始与到期时间，到期未恢复经 F-057 告警；熔断触发的自动暂停与人工暂停分开记录。**曾成功启用过的来源**暂停后可直接恢复，只重验发布方身份与权限未漂移、未归档、采集身份字段未改动，**不要求重新预览成功**（旧站 2026-09-21 修复“暂停后无法恢复”，docs/reviews/admin-click-verification-20260921.md:9@main；DEC-57）；从未启用的来源仍按 F-004 首次启用。立即运行只提前本来源下一轮检查，走同一用量账本与熔断检查、租约与获取限制。归档（A 包称“退役”）为终态，保留历史引用。
- 编辑：名称、说明、许可说明等不影响采集的字段保存即生效，不暂停、不清游标、不要求重新预览；入口、获取方式、分页规则等生成新配置版本，新版本预览通过并确认切换前，旧版本继续采集。
- 空/失败：已暂停操作幂等；配置冲突提示刷新；未知写回执先读回，不盲目重复。
- 权限：信源配置能力（负责人专属）；暂停不等于删除内容，也不能清账单/抑制记录。
- 验收 A-F005：暂停与取回并发不得写入过期结果；升级/初始化/部署保护流程不能覆盖或遗留人为暂停；最近一次预览失败的已启用来源仍可恢复；暂停到期未恢复产生告警。（B：L02；C：L11/L13）

### F-006 增量采集、调度与断点
- 主编号：F-ACQ-01、F-ACQ-03、F-ACQ-04、F-ACQ-06；所属模块：acquisition。
- 输入/输出：已启用来源、检查频率、时间窗口、checkpoint → 新材料与可续接进度。
- 正常：每5分钟检查到期来源，按各源频率抓取（“每5分钟检查”不等于每5分钟有新稿）；资讯与法规分别调度、互不饿死。最新材料优先；API/RSS优先于HTML/允许的浏览器；源间公平分配；保存页内尾部后再推进页码。
- 回填（取 A:02-rules/01-business-rules.md BR-TIME-07）：新来源热窗口72小时，每轮先看列表头部，按“条目ID + 修订”指纹判新；冷回填7天 → 30天，有界、低优先、与新稿共用同一用量账本与熔断保护、非高峰加工；30天后每24小时复扫；加工优先级按文章年龄；回填保留原日期且标旧文：来源日期不在今天的不进“今天”，没有来源日期的按发现时间进当天（目前的限制，BR-TIME-06 第 2 点）。法规线不受30天上限约束，另设窗口。
- 空/失败：没新稿成功结束；一条坏兄弟记录可隔离但记录覆盖缺口；整页不可判定不得推进“完成”；退避不拖垮其他源。
- 权限：后台服务；立即运行等工具触发仍用同一用量账本与熔断检查、租约和获取限制。
- 验收 A-F006：旧置顶不遮挡近期稿；中断重启不漏页/重复收费；单源限流不阻断网站；新来源回填不把30天前旧文当今日新稿；资讯全部暂停时法规调度照常。（B：L02/L07；C：L11）

### F-007 多格式读取与文章识别

### F-036 用量账本、复用、异常熔断与未知结果对账

## 全局完成条件

每个功能标记为 `specified / implemented / locally_verified / integrated / live_verified / quality_accepted` 之一并附对应证据；不能以代码存在或按钮可见越级。与 A 包原五态的对应：规划中 = specified，开发中 = implemented，已合并 = integrated，已上线 = live_verified，已验收 = quality_accepted（locally_verified 为本地验证通过，A 包无对应）。这是新系统的实现进度，与功能全集里描述旧站现状的【已验证】【已实现未验证】等标签是两条互相独立的轴；各完成状态分开签收、互不替代（BR-OPS-06）。没有实测数据的质量、性能、持续供给与成本结论保持待验收。

新增API/模型/任务必须能追溯到主编号与规格卡（F-<域>-nn / F-0nn）及业务规则，完成后更新契约和验收映射，而不是通过改旧代码反推需求。追踪以 `05-quality/07-traceability.json` 为规范源：每个主编号至少对应一个模块、一个页面或接口（用户可见时）、一条验收（AC 或 T，允许暂标“待补用例”）；每张规格卡的 A-Fxxx 验收语句至少挂一个 T 场景或标明待补；校验器对 F、AC、BR、INV 的双向孤儿报错。候选（F-EXT、F-ACQ-07、F-RPT-05）与已废弃条目（F-POL-06、F-ADM-01、F-ADM-05、F-IAM-02、F-MIG-01、F-PUB-06）豁免；暂无专用用例、暂挂现有 T 的只有 F-053、F-065（标“待补专用用例”）。
