# 时间语义

> 矿业政策情报跨越几十个法域、几十种网站格式。时间处理错误会直接造成“旧闻变新闻”“草案当生效”“编造发布时刻”等严重问题。本文是所有模块处理时间的唯一依据（ADR-0010）。
>
> **结论（v2.0，其中⑤已按 v2.1 改）**：①两条线的日期证据都带**精度与依据**；资讯线的发布时间照 AIHOT：网页列表和详情页只写日期的，取来源时区当天零点（中文信源为北京零点），网页只显示日期，不显示“00:00”（2026-10-05 改，BR-TIME-01）；法规线只有日期的在任何出口都只给日期，不补时分；②“今天”与日期分组按**北京时间自然日**，资讯线照 AIHOT 以时间线为准（BR-TIME-08）；③法律日期按**法域当地日历日**比较，不按日期自动推进“已生效”；④资讯线旧文照 AIHOT 判定：新信源首次导入的、标记为回填的、发现时已晚于来源时间 48 小时以上的为旧文，有来源时间的按来源时间进时间线（2026-10-05 改，BR-TIME-06）；⑤资讯线报告的出刊时间与时间窗沿用 AIHOT（北京时间，DEC-65）：日报每天 08:00 出刊并覆盖前一日 08:00 至当日 08:00，周报每周一 10:00 出上一个 ISO 周，月报每月 1 日 10:30 出上一个自然月；只在精选候选里取材（BR-RPT-02），资料进入站点后跨过刊期边界才确定精选公开时间的归入下一期候选池、不设“补录”小节，历史期只因更正与下架修订（BR-TIME-09）；⑥没有可靠来源日期的新闻材料照 AIHOT 公开，按发现时间进时间线（2026-10-05 改；法规文书：日期未知如实标待核实，BR-TIME-15 第 5 点）；⑦时间字段形状采用 B 的 TimeAssertion，并加中文标签与北京日期。
> 依据：裁决表 DEC-22（现仅保留“历史期不被改写”，归期与时间窗已被 DEC-65 取代）、DEC-24、DEC-36、DEC-49、DEC-50、DEC-65；旧ADR-0011:13-21@main（Accepted 2026-07-26）；旧ADR-0033:16,25-26@main；旧 requirements.md:38-40@policy；旧 `period-reports.md:9-15@policy`。A 包原稿（v1.0）的 BR-TIME-06“48 小时旧文”、BR-TIME-09 原挂在 Q-19 下、BR-TIME-12“日期待核实可公开”已按上述改写。
> **2026-10-05 改照 AIHOT**（Owner 2026-10-05 22:56:40Z：交接包的做法与 AIHOT 冲突时以 AIHOT 为准；【Owner 决定】2026-10-05 23:16:49Z：只写日期的稿子只显示日期；TASK-0040、TASK-0043）：资讯线的发布时间读法、网页显示、旧文、“今天”、排序、没有日期与未来时间的处理改照 AIHOT（BR-TIME-01、02、03、06、08、14、15，INV-06、INV-07）；网页只显示日期是 Owner 另选的显示规则。法规线的时间规则不变。
> **v2.1 说明**（Owner 2026-10-01 答复）：时间语义（精度、“今天”、日期筛选、法域日期等）本身不变；只随答复改了五处——许可/资格到期口径（`owner_declared` 不设自动到期，DEC-33）、模型用量月份（不设月度金额上限，BR-TIME-10）、回填与存量的用量口径（BR-TIME-07）、首次公开时间依据不再有“旧站迁移”取值（旧数据一概不导入，DEC-20，BR-TIME-11）、**资讯线报告的选材与出刊时间都沿用 AIHOT**（DEC-65，Owner：“时间也学 AIHOT”）：只在精选候选里取材，日报 08:00、周报周一 10:00、月报 1 日 10:30 出刊并按 AIHOT 的时间窗取材，不设“补录”小节（BR-TIME-09、BR-RPT-02）；法规线周月汇总不变（北京时间自然周、自然月，BR-POL-14）。

## 1. 时间字段

### 1.1 字段表

“TimeAssertion.meaning”列是该字段在统一数据形状（§1.2）中的取值；B 的 `meaning` 枚举为 published / updated / signed / registered / effective / event / discovered / uploaded / applicable / deadline / compiled / expires；v2.0 公开契约（`03-data/02-public-api-contract.md` §2）在此基础上新增 `public_inspection`（公开阅览）、`formally_published`（正式刊发）、`repealed`（废止）与 `site_public`（本站首次公开），不再借 uploaded / published 加 basis 文字区分；展示标签字段名为 `label`（另有 `meaning_label`、`beijing_date`）。

| 字段 | 含义 | 来源 | 精度 | 展示 | TimeAssertion.meaning |
|---|---|---|---|---|---|
| 来源发布时间 `source_published_at` | 来源标注的发布（或登记）时刻 | 列表页、详情页、接口、RSS | `date` 或 `minute` | 列表与详情的主时间 | published |
| 时间依据 `timestamp_basis` | 上一字段取自哪里（发布日期、登记时间、公报刊期等） | 采集适配器 | — | 不展示，用于审计 | basis |
| 来源更新时间 `source_updated_at` | 来源标注的更新时刻 | 同上 | 同上 | 详情页“来源更新于”；列表不显示（原“列表可带徽标显示”作废，2026-10-05，TASK-0043） | updated |
| 正式刊发 / 公布日期 `formal_published_date` | 公报/法规库的正式刊发、公布或刊宪日期 | 法规类来源 | `date` | 政策文书详情 | formally_published |
| 登记时间 `registered_at` | 法规登记时刻（例如澳大利亚立法库按 registerId 的登记） | 法规库 | 按来源 | 政策文书详情 | registered |
| 公开阅览时间 `public_inspection_at` | 例如美国联邦公报的公开阅览（上传）时间 | 法规类来源 | `minute` | 与生效日期分开标注 | public_inspection |
| 法律生效日期 `legal_effective_date` | 法律效力开始的日期（整体或分项） | 文书正文或来源字段 | `date` | 与公布日期分开标注 | effective |
| 适用日期 `applicable_from` 【新增】 | 规则开始适用的日期（可晚于生效，可追溯） | 文书正文 | `date` | 政策文书详情 | applicable |
| 征求意见截止 / 其他截止 `deadline` | 公开征求意见、过渡期、申报等截止日期 | 文书正文 | `date` | 政策文书详情 | deadline |
| 废止日期 `repealed_on` 【新增】 | 文书全部或部分废止的日期 | 文书正文或官方通知 | `date` | 政策文书详情 | 需契约增补 `repealed`（见变更请求）；增补前用 event，basis 写明“废止” |
| 条件日期 【新增】 | 带条件的生效或适用（“另行公告之日起”“达到某条件后”） | 文书正文 | 原文 | 原文照录 | effective / applicable，带 `condition_text`，**不转换成某个时刻** |
| 汇编 / 修订日期 `compiled_on` | 汇编版、更新文本的汇编日期 | 法规库 | `date` | 版本信息 | compiled |
| 成文/签署日期 `signed_date` | 文件落款日期 | 正文落款 | `date` | 不与网页发布时间混用 | signed |
| 发现时间 `discovered_at` | 本站首次抓到的时刻 | 系统 | 秒 | 私有页面与只读运维接口 | discovered |
| 许可/资格到期 `expires_at` | 质量资格的有效期，以及非 `owner_declared` 类许可证据的有效期（**`owner_declared` 不设自动到期**，Owner 2026-10-01，DEC-33） | 系统 | 日期或秒 | 私有页面；到期前告警 | expires |
| **首次公开时间 `first_public_at`** | 本站首次公开的时刻 | 系统 | 秒 | 详情页“本站公开”；不作排序与 RSS 时间依据：资讯线列表按时间线排序（BR-TIME-14），RSS 的时间照 AIHOT 用发布时间、没有时用发现时间（2026-10-05 改，TASK-0043） | **不属于 TimeAssertion**（系统事实，见 BR-TIME-11） |
| **精选公开时刻 `visible_after`** 【v2.1 新增】 | 条目作为精选对读者可见的时刻：自动入选为等事件归组完成后的放行时刻（最多 3 分钟，BR-SEL-02 第 6 点），负责人手动加入为加入时刻 | 系统 | 秒 | 不展示；**报告归期依据**（BR-TIME-09） | 系统字段（ENT-26） |
| 整理时间 `processed_at` | 本站生成中文整理的时刻 | 系统 | 秒 | 可在详情页标注“本站整理于” | 系统字段 |

### 1.2 统一数据形状：TimeAssertion 【设计】（DEC-50）

以 B 的 TimeAssertion（B:architecture/04-data-model.md §4、B:contracts/openapi.json 的 `TimeAssertion`）为底，加中文标签与北京日期；A 原稿的扁平字段 `published_at / time_precision / time_label` 是它的**展示投影**，不再是存储形状。

```json
{
  "meaning": "published",
  "raw": "2026年9月8日",
  "local_date": "2026-09-08",
  "local_time": null,
  "timezone": null,
  "utc": null,
  "precision": "date",
  "basis": "列表页“发布日期”字段",
  "condition_text": null,
  "label": "来源发布于 2026-09-08",
  "beijing_date": "2026-09-08"
}
```

| 字段 | 规定 |
|---|---|
| `meaning` | 见 §1.1；来源更新、抓取时刻、翻译时刻、本站入库时刻**不得**冒充 published |
| `raw` | 来源原始字符串（≤300 字符），保留不改写 |
| `local_date` / `local_time` | 来源当地的日历日与时分；`precision=date` 时 `local_time` 必须为空 |
| `timezone` | IANA 时区（如 `America/Santiago`）；**只在可验证时填写**，不得按国家、域名或服务器位置推断；未知为空 |
| `utc` | UTC 时刻；`precision=date` 时必须为 `null`（不得把日期存成“当日 00:00 UTC”）；分钟/秒精度才填，且要求 `timezone` 已知 |
| `precision` | `unknown / date / minute / second`；缺失时一律按 `date`，不得默认 `minute` |
| `basis` | 时间取自哪里（≤500 字符），用于审计与 `label` 生成 |
| `condition_text` | 条件日期的原文（≤2000 字符）与证据定位；不硬转成不存在的 instant |
| `label` 【新增】 | 中文展示标签，由后端按规则生成（例如“来源发布于 2026-09-08”“来源更新 09-08 14:20”“本站公开”），读者页不自行拼接 |
| `beijing_date` 【新增】 | 北京日期：分钟/秒精度 = `utc` 换算到 Asia/Shanghai 的日期；**仅日期精度 = `local_date` 字面值，不做时区平移**（DEC-49） |

- 旧仓库把仅日期存成当日 00:00 UTC（`services/live_pipeline/source_ingestion.py:121-122@main`，精度记 `date`），A、B 都**不沿用**；旧站实际回读 2026-09-15：493 条中仅日期精度 331 条（旧 README.md:25@main），即约三分之二的条目只有日期。
- 资讯线列表照 AIHOT 按时间线排序（BR-TIME-14），不另设排序键（原“只知日期时用单独的稳定排序键”作废，2026-10-05，TASK-0043）。
- 日期必须知道格式与语言才能解析（BR-TIME-12）。

## 2. 规则

每条规则后的“对应 B 规则 / 典型反例 / 验收”为统一字段（D20-integrity-002）；B 规则指 B:product/04-business-rules.md 的 BR-nn，验收引用 B 的 T-nnn 与 A 的 INV-nn。阶段按 M0–M5（DEC-44）。

**BR-TIME-01｜只写日期的来源：发布时间取当天零点，网页只显示日期** 【Owner 决定】2026-10-05（Owner 2026-10-05 22:56:40Z，DEC-66：交接包的做法与 AIHOT 冲突时以 AIHOT 为准；【Owner 决定】2026-10-05 23:16:49Z：只写日期的稿子只显示日期；TASK-0040、TASK-0043）｜M1
资讯线网页列表和详情页里只写日期的来源（如“2026-09-08”；“2026/09/08”“2026年9月8日”要信源声明格式，见下方“目前的限制”），发布时间取来源时区当天零点：时区用信源配置的 `publishedAtUtcOffset`，默认 +08:00，中文信源是北京零点；ISO 写法也一样（AIHOT 把单独的 ISO 日期读成 UTC 零点，即北京 08:00；本站为了网页认得出“只有日期”，改读来源时区零点）。网页上，时刻正好是北京 00:00:00 的只显示日期，不算“几天前”：列表时间栏显示时间线时刻，正好北京零点的（只写日期的旧文）显示“—”，只写日期的新稿显示本站收到的时间；文章页“发布时间”看发布时间，只写日期的只写日期。不设回退徽标（原 DEC-24、DR-71 的“来源更新 → 本站公开”回退作废）。资讯线的 RSS、API、MCP 照 AIHOT 输出存着的时刻。
- 法规线不在本条：只写日期的在任何出口都只给日期，不补时分（BR-TIME-04、BR-TIME-13）。
- **目前的限制**（2026-10-06，与 TASK-0040“没做”第①、③条一致）：①这个读法只在网页列表和详情页（`sources/web-list.ts`、`sources/collect.ts`）；RSS、Atom、JSON 列表只写日期的，发布时间仍为空，接入这类信源前改成同一读法（集成人开后续卡）。②斜杠、点号、年月日写法要信源声明日期格式才读得出；不补零的写法（如“2026/9/8”）声明了也读不出；读不出的没有发布时间（BR-TIME-15）。③非 +08:00 的信源，只写日期的零点不是北京零点，网页认不出“只有日期”，会显示成“13:00”“08:00”等。另外，未来时间的判定除了 AIHOT 的 1 小时，还有日期证据的 5 分钟（BR-TIME-15 第 1 点），也和 AIHOT 不同。
- **对应 B 规则**：BR-14（精度诚实：网页不显示虚构的时刻）
- **典型反例**：网页把只写日期的稿子显示成“00:00”或“08:00”；把“更新于 14:20”当来源发布时间
- **验收**：T-007、T-016；INV-06

**BR-TIME-02｜存储统一 UTC，保留来源时区；时间用 TimeAssertion 表达** 【设计】（TimeAssertion 形状）｜【Owner 决定】2026-10-05（发布时间的读法照 AIHOT，见下）｜M1

- **对应 B 规则**：BR-14；B:architecture/04-data-model.md TimeAssertion
- **典型反例**：未知时区按国家猜；把抓取时刻、翻译时刻当发布时间
- **验收**：T-007；INV-06

**BR-TIME-03｜展示：北京时间为基准，来源当地时间有意义时括注** 【Owner 决定】（旧ADR-0011:21@main，Accepted 2026-07-26：以北京时间为基准，同时展示来源当地时间）｜【已实现未验证】（北京时间展示：现役读者层只用 Asia/Shanghai，`apps/web/lib/reader/preferences.ts:82@main`，只有代码、无验收记录）｜【设计】（当地时间括注：**旧站读者页未实现**——现役读者层与 `services/live_pipeline/reader.py@main` 均不返回来源当地时间，只有早期证据列表组件 `apps/web/components/evidence-list.tsx@main` 显示原始当地时间；括注规则为本包新设计）｜M1

## 3. 验收要点

1. 资讯线：只写日期的来源，文章页只写日期；列表时间栏按时间线显示，正好北京零点的显示“—”，只写日期的新稿显示本站收到的时间；网页上不出现“00:00”；RSS、API 输出存着的时刻；不设徽标。法规线：只写日期的在列表、详情、RSS、API 中都不出现时分（T-007，INV-06）。
2. 旧文判据照 AIHOT：新信源首次导入的、标记回填的、发现时晚于来源时间 48 小时以上的是旧文，48 小时以内与以上各有样例（如昨天与三天前的稿），只写日期的按那天零点算；来源日期不在今天的旧文不出现在“今天”，旧文都不进当期报告正文；没有来源时间的旧文按发现时间出现在当天（目前的限制）（T-145、T-016，INV-07）。
3. 公布日期与生效日期不同的法规，详情页两者分别显示；生效日已到但有分项施行、过渡期、中止证据的文书不派生“生效日已到”；智利 10 月 1 日生效的规则在北京时间 10 月 1 日零点不显示已到（T-026）。
4. 跨时区材料的北京时间与来源当地时间换算正确（含夏令时切换）；时区未知的带时分时间降为日期精度（T-007）。
5. 报告的出刊时间与去向表逐行有用例：日报 08:00 出刊、窗口 [前一日 08:00, 当日 08:00)（07:59 与 08:00 的边界、跨午夜、跨月末）；周报周一 10:00 出上一个 ISO 周、月报 1 日 10:30 出上一个自然月；精选公开时刻跨过刊期边界的归入下一期（不设补录）；取稿等待仍在提交的发布事务；缺刊期每小时补出；仅日期的来源不影响归期；旧文不入报；更正/下架才产生新修订；同刊期重跑幂等（T-043、T-044，INV-21）。
6. 列表按时间线排序稳定，翻页不重不漏（T-042、T-045）。
7. 没有可靠来源日期的新闻材料照 AIHOT 公开、按发现时间排（BR-TIME-15，2026-10-05 改）；法规文书的未知日期显示“待核实”而不顶替（BR-TIME-15 第 5 点）。
8. 首次公开时间在重处理、修订、翻译、下架恢复后不变（INV-08）。
