## 1. 复盘：为什么停下来

- **依据**：DEC-71、`changes/TASK-0367-policy-pause.md`、`modules/policy/README.md`、`modules/policy/backend/`。
- **公开说法**：因成本和技术问题暂停。
- **代码层面的原因**：以下四点从代码结构推断。重启前要按第 6 节第 0 步，从费用记录里核实。

| 推断的原因 | 代码里的依据 | 本设计的应对 |
|---|---|---|
| **整篇交给模型**：全文翻译（`policy_fulltext`）、扫描件识别（`policy_vision`）、解读（`policy_interpret`）、复核（`policy_verify`）、归组（`policy_group`），一份文书要调用好几次 | `provider.ts` 的 Purpose 枚举；`domain/` 下的 fulltext/vision/interpretation 三套运行时 | 先做不调用模型的部分；模型只解读**变化的条款**，不翻译全文 |
| **范围太宽**：约 50 个法域（33 国、14 个中国省区、3 个组织）一起扩建，每个来源的格式都不一样 | `industry/jurisdictions/data.json` | 试点只做中国国家层面和矿业主管部门，阿根廷国家公报加两省，再加两组行业规范 |
| **单位不对**：以“资料”和“页面”为单位处理，版本和条款关系要靠模型重建 | `interpretation-*`、`processing-plan.ts` | 以**文书（work）—语言版本（expression）—修订（version）—条款（provision）**为基本单位，生命周期事件单独记录 |
| **流程长、状态多**：采集、全文、视觉、解读、复核各有队列和回执，失败面大 | `jobs.ts`、`receipt-recovery.ts`、`processing-notice.ts` | 先合并成三段：存档、结构化、解读；前两段是确定性的，可以重跑 |

## 2. 原则

1. **窄而深**：法域少、来源少，每个来源做到条款级、版本级。
2. **先确定性，后模型**：元数据、原文存档、条款切分、逐条对照、关键日期全部由程序完成，有固定样本测试；模型只做“这次改了什么、影响谁”。
3. **引文由程序核对**：解读里每一处引用，都要在对应版本的条款原文中逐字找到，找不到就不发布。
4. **只采集许可允许的来源**：遵守 robots、许可和频率限制，不绕过登录和验证码。
5. **预算写死**：每份文书、每天都有模型调用上限，超出就排队，不扩写。

## 3. 数据模型（沿用现有契约，补生命周期）

现有公开契约已经有 `versions`、`expressions`、`legal_state`、`dates`（`packages/contracts/src/http/policy.ts`）。重启时沿用这些，只补两样：

- **`provision`（条款）**：文书某个修订下的一条，带稳定编号（第 X 条、Artículo X）、原文、所在章节、上一修订中对应的条款（没有则为空）、变化类型（新增、修改、删除、未变）。
- **`lifecycle_event`（生命周期事件）**：包括拟议、征求意见开始与截止、通过、公布、施行、修订、废止。每个事件带日期、精度、来源证据（文书或公报的具体位置），以及“原文确认”还是“计划”。

读者端的生命周期只显示原文确认的当前阶段（TASK-0519 已经按这个口径实现）。

## 4. 流水线（三段）

| 段 | 做什么 | 是否调用模型 | 可否重跑 |
|---|---|---|---|
| **存档** | 按来源适配器发现新文书或新修订；保存原文的 HTML、PDF 字节和哈希，以及获取时间和许可依据 | 否 | 是，按哈希去重 |
| **结构化** | 抽取元数据（文号、机关、性质）；按来源规则切分条款；与上一修订逐条对照；用规则抽取关键日期；推进生命周期状态机 | 否；扫描件先标为“需人工”，不调用 vision | 是 |
| **解读** | 只针对变化的条款：说明改了什么、影响谁、何时生效；输出结构化 JSON，引文由程序逐字核对 | 是，每份文书 1 次，变化条款超过 N 条就分批 | 结果按“修订 + 条款集合”的哈希缓存 |

现有 `domain/` 里的 originals、extraction、xml-structure、references、metadata 可以复用到存档和结构化两段。fulltext、vision、interpretation 三套运行时只留接口，重启首期不启用。

## 5. 试点范围（任务书 v2）

- **中国**：国家层面（全国人大、国务院）和矿业主管部门（自然资源部、应急管理部、生态环境部）的法律、行政法规和部门规章。
- **阿根廷**：国家公报 Boletín Oficial，Salta 和 Catamarca 做完整底本，Jujuy 作对照。
- **行业规范**：矿山安全和生态相关的国家标准；国际上做 GISTM（全球尾矿管理标准）和 ICMM 的绩效期望。欧盟可选，不进首期。

每个来源先确认许可：可采集、可存档、可展示全文还是只能摘录。确认记录写入 `industry/policy-sources.ts`。
