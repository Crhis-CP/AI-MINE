# 验证与兼容性说明

## 基线与实测

读取了 [AI-MINE 的 AGENTS.md](https://github.com/Crhis-CP/AI-MINE/blob/e75f033d0e1b626c9af3fe274464171d4d6f6806/AGENTS.md)、[新闻目录](https://github.com/Crhis-CP/AI-MINE/blob/e75f033d0e1b626c9af3fe274464171d4d6f6806/industry/sources.json)、[法规目录](https://github.com/Crhis-CP/AI-MINE/blob/e75f033d0e1b626c9af3fe274464171d4d6f6806/industry/policy-sources.json)、[来源创建校验器](https://github.com/Crhis-CP/AI-MINE/blob/e75f033d0e1b626c9af3fe274464171d4d6f6806/packages/backend/src/admin/sources.ts) 和 [原生 config 键集合](https://github.com/Crhis-CP/AI-MINE/blob/e75f033d0e1b626c9af3fe274464171d4d6f6806/packages/backend/src/sources/config-keys.ts)。基线 `main@e75f033d0e1b626c9af3fe274464171d4d6f6806` 含 412 条新闻配置、156 条法规目录。它们是仓库目录数，不能替代实时运行来源数。

本包使用 Node 24.19.0 和该 checkout 安装的依赖执行原生字段校验与离线重放。字段校验回执见 `evidence/native-schema-validation.json`；原生重放见 `evidence/native-replay.json`。重放直接调用当前 `fetchRss`、`fromHtml`、`jsonListDocument`、`fetchDetail` 和 `previewSourceDate`，仅将传输替换为本次实际取得的公开响应，未改采集函数。

原生配置 76 份；可抽取条目的配置 72 份；新闻现场预览候选 58 份。访问受阻、候选配置、日期缺口和政策日期语义均保留，没有将 `verified_config` 这个研究字段当作生产启用依据。公报、法规、历史目录可能提取到链接而不符合新闻发布时间门槛，具体看每条 raw date 数量和 meaning。

## 验证到了什么

- 原附件 83 条均有映射；101 个登记项均有完整官网及监测入口。
- 原生配置使用现仓库支持的字段；ID、lane、停用默认值及日期时区证据单独检查。
- 采集列表、RSS 或 JSON 使用实际响应重放，记录条目数、非空标题与链接数、原始日期字段数和新闻日期解析数。
- 有详情样本的入口执行实际详情解析；这是抽样，不是所有新闻详情的全面验收。
- 重复处理脚本接受原仓库目录和严格全量运行快照，只生成提议文件；对应聚焦测试在 `evidence/prepare-sources-tests.txt`。

未运行生产预览、生产数据库修改、定时采集、模型处理或群推送。没有从网页重新分发整篇新闻、整份 RSS 内容或站点原始 HTML；回执保留必要 URL、日期、数量与正文哈希。

## 在目标机器复核

先把包解压到独立目录。下面使用的三个变量是任务路径，不替换任何系统环境变量。示例路径须由现场 AI 换成实际绝对路径：

```bash
AIMINE_REPO=/absolute/path/to/AI-MINE
SA5_PACKAGE=/absolute/path/to/20261019_南美五国矿业信息源_AIMINE接入包_V1
SA5_REVIEW=/absolute/path/to/source-review
mkdir -p "$SA5_REVIEW"
node "$SA5_PACKAGE/tools/validate_native.mjs" --repo "$AIMINE_REPO" --package "$SA5_PACKAGE" --out "$SA5_REVIEW/native-schema-validation.json"
python3 "$SA5_PACKAGE/tools/prepare_sources.py" --repo "$AIMINE_REPO" --package "$SA5_PACKAGE" --out "$SA5_REVIEW"
python3 "$SA5_PACKAGE/tools/test_prepare_sources.py" --repo "$AIMINE_REPO"
```

`prepare_sources.py` 的输出目录必须在仓库以外。它不会调用 API、连接数据库、更新源、启用源或改原目录；`news.catalogue.proposed.json` 是供审阅的完整提议，不是要求直接覆盖原文件。包内附带的 `plans/reconciliation.json` 仅为本次目录级建议。

运行快照必须由目标环境导出、去掉凭证。`schema_version` 为 `aimine.runtime-sources.v1`，结构模板见 `templates/runtime-inventory.template.json`。模板默认故意不完整，会被脚本拒绝；它不是实际运行快照，也不证明目标库为空。请填入真实 `snapshot_at`、`environment`、`complete`、`coverage`、`pagination` 和 `sources`，完整性断言必须来自实际导出。

`coverage` 需要 news/policy 两线、归档与未归档覆盖，`total_rows`、`by_lane`、`by_archive_state` 的数量必须与全部行一致。`pagination` 需要全部页完成、预期页数等于实取页数、next_cursor 为空。每条至少有 id、kind、lane、完整 config、enabled、显式 owner_entity_id、显式 archived_at。具体检查以 `tools/prepare_sources.py` 的 `runtime_rows` 为准。不要把缺少归档状态或漏分页的响应贴上“完整”标签。

```bash
python3 "$SA5_PACKAGE/tools/prepare_sources.py" --repo "$AIMINE_REPO" --package "$SA5_PACKAGE" --runtime-json /absolute/path/to/complete-runtime-sources.json --out "$SA5_REVIEW"
```

没有完整快照时仅做目录层面比较；提供不完整快照会被拒绝，不会生成“真正新增”的保证。数据结构变化时应读最新 API/表结构导出完整状态，不能通过虚构 completeness 标志绕过检查。

## 重复判断的边界

重复识别分为相同 ID、原生身份、语义上相同入口、已知原目录映射、同机构不同栏目。原生身份计算使用目标仓库的纯 URL 规范化与 `sourceIdentity` 实现，以匹配正式创建端的约束；语义比较保留关键查询参数，辅助发现 RSS／HTML／语言版本关系。共享政府门户按机关进一步区分。

目录匹配和运行库匹配分别报告。一个源写入目录并不证明已经建入运行库；同机构一个栏目暂停也不证明其他栏目暂停。同 kind 相同原生入口跨 lane 会被正式创建端判重，应显式复核。实际启用、归档或来源缺失只能由完整运行记录证实。

## 当前格式注意点

| 项目 | 本包的处理 |
| --- | --- |
| `sourceDate` | 只用现行格式、pattern、语言和真实语义；无来源时区证据则不写 timezone |
| `publishedAtSelector` | 列表与详情的读取规则不同；meta 内容日期使用详情配置或已验证正则 |
| `json_list` | BCRA 的 form-urlencoded 不能冒充 bodyJson；API 未观察到则不捏造 |
| `owner_entity_id` | 草稿留 null，`proposed_owner_key` 供现场映射，保持现行 owner |
| `tags` | 草稿不将媒体所在国或五国范围硬贴给所有文章 |
| `enabled` | 全部 false；运行状态不因草稿默认值而覆盖 |
| `policyProfile` | 已有官方公报 profile 随配置保留，仍需按最新政策流程处理 |
| `_amp.initialBackfillLimit` | 属于当前仓库已支持键，不能据一次上限内结果宣称未来全量覆盖 |
| 外部说明字段 | 在 registry/profile 旁表，不塞入原生 config |

原生字段通过只表明当前结构受支持；真正接入应继续按 [source-intake.ts](https://github.com/Crhis-CP/AI-MINE/blob/e75f033d0e1b626c9af3fe274464171d4d6f6806/scripts/source-intake.ts) 和仓库审计流程验证现场行为。
