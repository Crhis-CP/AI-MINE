# 给接入 AI 的任务

## 目标和输入

请将本包用于完善 **Crhis-CP/AI-MINE** 的“南美五国矿业法规与新闻动态”来源，覆盖秘鲁、哥伦比亚、阿根廷、圭亚那、苏里南，以及原表指定的全球／中国媒体、宏观和国际组织。来源已按附件逐项映射，用户允许重复来源不再接入，或在有实测依据时优化现有来源。

本包基线：`e75f033d0e1b626c9af3fe274464171d4d6f6806`。共有 101 个入口、76 份原生配置草稿。先读最新 `AGENTS.md`、当前任务与 Owner 决定；如果目标分支与此基线不同，以最新实际代码重新校验。包内所有 `sa5-*` 都是提议 ID，不能据此判断来源是新增。

## 1. 先核对身份和当前状态

读取 `config/registry.json`、`industry/sources.json`、`industry/policy-sources.json` 及完整的运行来源记录。运行盘点必须包含两个 lane、全部分页、启用／暂停／归档源以及完整 config 和 owner 信息；不要把后台第一页、仅启用列表或统计汇总当成完整盘点。

使用 `tools/prepare_sources.py` 只读生成建议。没有完整运行盘点时，它只给目录层面结果；可以准备代码草稿，但不能声称已完成生产去重。严格快照格式和命令见 `04_验证与兼容性说明.md` 以及脚本 `--help`。

逐项处理：

1. **同一原 ID 或同一采集身份**：读取现行配置和状态，复用已有 ID。有正常替代记录时优先核对该记录，保留旧记录的暂停／归档状态。
2. **同一发布者、不同栏目／语言／RSS**：比较覆盖面、更新速度、日期质量和内容重叠，再决定优化、保留补充栏目或跳过。不要只凭同域名删除新栏目。
3. **目录中有记录、完整运行盘点确认缺失**：按现有目录 ID 完成建源流程，不另造一个相同站点的新 ID，也不能称为“已接入”。
4. **`collect: null` 的政策目录**：完善原目录记录，如 PE-002、CO-002；不能因无采集配置而重新创建同一目录主体。
5. **真正新增且样本具备预览条件**：以停用草稿进入既有接入流程，完成实际预览后按届时的接入指令推进。
6. **受阻、缺日期、停更或需要适配**：保留总登记和具体问题，不改成任意 RSS，不用抓取时间替代发布日期。

现有记录的人工暂停、归档、全文权限和 owner 不应被默认值覆盖。暂停是具体 source/lane 的状态，不能扩散成同一发布者所有栏目都暂停。实际创建接口还会检查跨 lane 的同 kind 同入口，遇到冲突应明确复核，不能自行切换业务线。

## 2. 按仓库现有格式接入

`native.sources.json` 中每行是来源种子对象，字段为 `id/name/kind/lane/config/tier/first_party/owner_entity_id/participation_mode/interval_minutes/tags/site_fulltext/syndicate_fulltext/enabled`。`kind` 只使用现仓库支持的 `rss`、`web_list`、`json_list`。选择器、日期规则和 API 映射均放在支持的 `config` 键内。

`registry.json`、`monitoring_profile.json`、状态、国家别名、证据和 adapter recipe 都是给 AI 的旁表，不是引擎会自动加载的字段。不要把它们塞进原生 `config`。

资讯草稿对应 `industry/sources.json`，应在工作分支中增量合并。`policy.sources.json` 是带 `lane: policy` 的原生来源草稿，**不是** `industry/policy-sources.json` 的法规目录结构；后者还含 jurisdiction、authority、type、role、collect、状态和来源登记信息。需要更新目录时，逐条映射到已有政策 ID，保持其真实登记状态。

不要把整份 `native.sources.json` 交给 `scripts/seed.ts`。该脚本的新闻种子路径不按本包 lane 分流，且只按 ID 忽略冲突。对新闻新增源，先把提议配置增量写入目录，再由已有 `source-intake.ts` 创建和预览；不要先向运行库跑 seed 再伪称是同一 intake 批次创建的记录。

HTTP `SourceCreateRequest` 与种子对象也不同：它需要 `permission_scope`、`attachments_in_scope`，不直接接受 seed 的 lane/owner/enabled 字段；业务线由服务层上下文传入。按当前后端代码做显式映射，不能把整行 seed 原样 POST。校验工具做了这种字段映射，但不会创建来源或授予权限。

## 3. 使用实际校验器和现行接入流程

在目标 checkout 依项目规定安装依赖后，运行：

```bash
node "$SA5_PACKAGE/tools/validate_native.mjs" --repo "$AIMINE_REPO" --package "$SA5_PACKAGE" --out "$SA5_REVIEW/native-schema-validation.json"
python3 "$SA5_PACKAGE/tools/prepare_sources.py" --repo "$AIMINE_REPO" --package "$SA5_PACKAGE" --out "$SA5_REVIEW"
```

路径变量示例和运行快照说明见 `04_验证与兼容性说明.md`。这些命令只校验或写审阅目录，不连接生产数据库。

需要使用已有 intake 时，由现场 AI 根据**最新目标配置和真实运行记录**生成 manifest：`batch` 使用 `source-intake-YYYYMMDD`；每项含 `id`、`target_config_hash`、`expected_config_hash`、`expected_owner_entity_id`、`owner_entity_id`、`expected_existing`。哈希算法是仓库 `stableJson([kind, config])` 的 SHA-256。不得把目录 hash 冒充当前运行 hash，也不要在未知 owner 时填写随机 ID。

```bash
node --env-file-if-exists=.env scripts/source-intake.ts /absolute/path/to/manifest.json
```

该命令属于目标仓库正式流程，虽然默认只读评估，也会初始化该环境的数据库访问。`--apply` 会创建／更新并在条件通过时启用新闻来源；本包没有运行它，也没有生成可以盲目执行的生产 manifest。接入 AI 按用户届时授权和仓库规定执行。

`news.preview-ready.sources.json` 只是减少初筛工作，不代表里面全部是新增来源，更不代表已启用。当前法规安排以 `AGENTS.md`/DEC-71 为准：本包提供法规配置和适配改进，不自行恢复法规后台采集或接法规模型。

## 4. 日期和实际采集验收

先核对实际响应不是登录页、挑战页、跳转落地页或空壳，再验证标题、规范链接、逐条日期、详情访问以及列表覆盖。RSS 返回 XML、HTTP 200 或 CSS 匹配数量都不足以单独验收。

日期只有“日”就保留日精度；页面无时区就保留源站本地表示。`reference_timezone_only` 仅用于人工理解，绝不注入 `sourceDate.timezone`。不得从 URL 日期、数据库 created 字段、固定 00:00、抓取时间或网站上传时间推断法律公布／生效时间。

本仓库 `previewSourceDate` 只接纳 `published/source_published`，所以法律正式公布、网站公开、议案事件日期可能有真实字段但不能通过新闻预览门槛。阿根廷公报、圭亚那电子公报、CNV 规范、众议院议案都保留真实语义，需由政策流程区分处理，不为“通过”改成普通新闻日期。

涉及 `detail.maxFetches` 的来源，本轮通常只核验一篇详情，不能外推成所有列表项日期都合格；Mysteel 置顶项和 Panorama 首屏大图也需按实际详情验证。列表上限和高频更新另看 `03`：当日预览得到 60 条不等于已覆盖全部。

通过预览后还要观察自然定时采集、入库、去重、日期保留以及详情可读性。原生 intake 的 `natural_collection_accepted: false` 不能被解释为已经完成自然运行验收。

## 5. 五国群范围和来源关系

按 `monitoring_profile.json` 把五国范围映射到现有群选择／展示环节，继续复用统一采集、预筛、评分、聚簇和审计链路。普通、具体的矿业行业信息也可以入库；精选、热点是否展示按现有规则判断，不在本包加分数阈值。

国家归属以文章事件／法律适用关系为准。Infobae 矿业标签、全球矿业媒体、中国媒体均可能覆盖多个国家；不能给每篇统一补上五国标签。AUC、ODIHR、Coal Age 和 WHO 按与五国矿业经营的实际关系进入群内，保留其原始来源价值。

owner 采用运行库已有实体；同一机构多个入口关联同一发布者。同集团媒体关系已有公开证据的包括 Aspermont 四个品牌、The Northern Miner Group 三个品牌，建议复核现行 owner 映射，避免重复计算独立来源。`proposed_owner_key` 是映射建议，不是已经创建的数据库实体。
