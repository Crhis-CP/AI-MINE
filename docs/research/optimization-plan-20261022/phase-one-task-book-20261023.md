AI-MINE第一阶段优化任务书
一、任务目标与执行依据
我希望在已经完成的工作基础上，将 AIHOT 的完整架构和通用运行机制迁移到 AI-MINE，统一替换现有对应部分，并在这一基础上保留和完善我的矿业产品功能。

迁移后，网站应形成一套协调运行的产品：资讯能够稳定获取、按既定矿业标准筛选、按国家和业务查阅与分发，事件前后关系清楚，日报、周报和月报正常生成，金属价格及运行提醒准确，前后台方便使用。

项目仓库：
- AI-MINE
- AIHOT
1. 本任务书作为本轮统一依据
本任务书替代此前关于第一阶段优化的任务书，作为本轮工作范围、迁移方向、优先顺序和完成标准的统一依据。

此前任务书不再作为并行执行清单，其中未纳入本任务书的新增建议和后续阶段安排，不自动追加到本轮。

旧资料继续用于核对我已经确认的业务规则、原有功能、历史决定和完成情况。已经明确的人工控制、数据保留要求及操作权限继续有效。
2. 接续已完成成果，针对差距调整
此前已经实施了一部分计划，应先核对哪些已经完成、哪些只完成了一部分、哪些虽然存在但实际效果仍不符合要求。
- 已经符合本任务书要求、能够融入 AIHOT 统一体系的成果，直接接续使用。
- 部分完成的事项，补齐剩余功能和使用效果。
- 与本轮迁移方向冲突、相互重复或运行不稳定的部分，针对性调整。
- 对已经正常使用的功能，迁移后应继续保持可用。
保留成果以产品功能、业务要求和实际效果为标准。现有实现可以根据迁移需要复用或重新实现。
3. 本轮仅推进第一阶段
本轮集中完成现有资讯产品的迁移、适配和优化。

法规解读试点、法规专用识别翻译、订阅收费及新增昂贵行情服务，留待后续规划。已有法规内容、入口及人工暂停状态予以保留，本轮不因迁移自动启动第二阶段工作。

资讯中涉及矿业监管、政策及法律变化的内容，继续按现有资讯范围处理。现有金属价格功能及其告警修复，属于本轮工作。
二、整体迁移与保留要求
1. 以 AIHOT 为统一基础
本轮整体迁移 AIHOT 的架构及通用运行机制，接管 AI-MINE 对应部分，完成网站前台、后台和日常自动运行之间的统一配合。

对于两者共有的功能，按照 AIHOT 的整体体系实现，再接入 AI-MINE 的矿业内容、配置和业务要求。迁移完成后，同一项工作应由明确、统一的流程负责，避免新旧流程同时运行，造成重复处理、结果冲突或反复提醒。

本轮的整体迁移方向已经确定。实施重点是完成适配、接续已有成果并解决实际问题。
2. 明确保留什么
对象	本轮处理要求
AIHOT的完整架构及通用机制	作为迁移后的统一基础，整体接入并承担对应工作。
两者共有的产品功能	按AIHOT的整体体系统一，适配AI-MINE的内容和业务要求。
AI-MINE已有、AIHOT没有的功能	保留功能及使用效果，并融入迁移后的产品；不要求沿用原有实现方式。
AI-MINE全部信源	保留来源清单、有效配置、启用或停用状态及相关历史；对获取问题针对性修复。
矿业选材、评分和分类规则	沿用我已经确认的业务标准，不随架构迁移被替换为AIHOT的行业规则。
历史内容及使用记录	保留已有资讯、报告、事件关系、来源链接及有效人工处理记录，维持阅读和追溯的连续性。
已完成的优化成果	核对符合本任务书后直接接续，部分完成的只补齐差距。


迁移前应对现有产品功能逐项核对，明确哪些由 AIHOT 承接、哪些需要作为 AI-MINE 的独有功能继续适配。核对范围以现有产品及已确认功能为准，不能只保留本任务书中举出的几个例子。
3. 保留矿业业务判断
AIHOT 提供统一的产品基础，AI-MINE 继续使用自己的矿业信源、关注范围、分类、评分标准和品牌表达。

迁移过程中，不能自动导入上游的行业示范内容，覆盖我的来源和矿业配置；也不能把上游默认设置直接视为我已经确认的业务规则。

我已经认可的人工修订、撤回、暂停和归属调整，在迁移后继续有效。
三、评分规则与模型安排
1. 先核对实际生效的规则
将我已经确认的选材范围、评分标准、分类规则，与当前网站实际采用的安排逐项对照。

现行标准、已认可但尚待验证的调整、候选评测稿，应明确区分。核对其确认范围和生效安排，避免把实验方案直接变成网站正式规则。

评分保护不仅包括权重和门槛，还应覆盖预筛条件、排除范围、降分条件、国别判断、去重及最终入选条件。

架构迁移、模型调整和页面优化，都不得夹带未经确认的评分变化。
2. 修复执行问题，审慎调整业务标准
发现问题后，分清两种情况：
- **执行偏差：**原文不完整、内容识别错误、规则未正确采用、处理卡住、去重或发布错误等，直接定位并修复。
- **业务标准需要调整：**列出原有要求、拟调整内容、具体理由和真实案例，按我已经明确确认的范围执行；新增调整需由我确认后生效。
已经明确确认的内容不重复询问。需要新决定的，应给出具体差异和效果，不能只提出笼统的“优化评分”。

即使评分文字没有变化，更换模型或改变材料处理方式后，也要检查实际选材结果，防止网站的判断在迁移中发生偏移。
3. 模型按第一阶段实际需要配置
完整迁移 AIHOT 的基础能力后，实际启用哪些模型、是否需要多个模型，结合现有成果、内容质量、稳定性和成本决定。

先核对当前实际启用的模型及其职责。现有安排满足要求的继续使用；存在明确问题的，再比较版本升级、处理方式调整或多个模型分工。

比较应使用相同材料和评价标准，重点看：
- 重要资讯是否能够正确识别和筛选；
- 中文标题、摘要和事件理解是否准确；
- 是否经常失败、等待过久或重复处理；
- 相同工作量下的实际总费用。
优先复用已有有效结果，减少无效调用、重复计算和失败重试。多模态能力仅在第一阶段确有图片或附件处理需求时评估，不为第二阶段提前扩大配置。
四、优先修复的问题
1. 金属价格、低频信源和重复提醒
针对目前金属价格及部分信源频繁提醒的问题，先核对实际收到的提醒、对应来源、触发时间和当时的数据状态，再修正判断方式。

逐个区分以下四件事：
1. 来源本身多久发布一次。
2. 本站计划多久检查一次。
3. 最近一次检查是否成功。
4. 当前数据属于哪一天或哪一期。
日更、周更、旬更、半月更、月更等，按实际来源分别处理，并考虑正常发布延迟及适用的节假日。

迁移和修复后应达到以下效果：
实际情况	网站与提醒应有的表现
尚未到来源更新期，或处于正常休市、发布间隔	保留当前有效数据和真实所属期，不作为故障反复提醒。
已成功检查，确认来源没有新数据	记录检查成功，保持正常等待状态。
原站已有新内容，本站未按计划取得	查明原因，按实际影响提示并恢复获取。
抓取失败、解析错误或数据确有异常	说明具体问题、影响范围及系统处理状态。
同一问题持续存在但没有变化	合并记录和提醒，避免每次检查都重复通知。
问题已经恢复	关闭对应异常，按需要提供一次恢复信息。


提醒应让人直接看懂：哪个来源出了什么问题、是否影响阅读、系统能否自行恢复、是否需要人工处理。

同时核对价格页面的数值、单位、币种、所属期及最近检查时间。数据日期保持真实，来源没有更新时，不改变日期制造已经更新的印象。

本项以现有价格服务准确、稳定、少误报为目标。发现实际的数据处理或展示错误，一并修复。
2. 月报自动生成与补刊
本项处理网站的矿业资讯月报，并检查它与日报、周报之间的配合。

先根据已确认的出刊时间、时区、上线范围和资料情况，明确哪些刊期已经应当生成、哪些尚未到时间，再逐期查明缺失原因。

完整核对以下过程：
到达出刊时间 → 取得当期内容 → 汇编生成 → 网站展示 → 失败后恢复与补刊。

重点解决：
- 到时间没有开始生成。
- 当期日报或资讯存在缺口，后续没有补齐。
- 生成过程中失败，之后没有自动恢复。
- 空记录或异常记录被误认为已经完成。
- 月报已经生成，但读者页面没有正常显示。
- 停机、升级或其他中断后，错过的刊期没有补刊。
修复自动流程后，补齐已经到期、具备相应资料且应当生成的历史刊期。继续使用已确认的选材和编排规则，不能为了出刊而放宽评分、混入其他月份内容或编造材料。

验证到期出刊、错过时间后补刊、失败恢复和重复执行。手动生成可用于排查，完成验收还应证明正常自动流程能够运行。
3. 功能配合与持续自动运行
在 AIHOT 统一体系下，检查采集、筛选、归组、发布、推送、报告和后台操作是否协调，解决相互冲突、重复执行及状态不一致的问题。

迁移后应做到：
- 日常工作按既定安排自动完成。
- 个别来源或任务失败时，其他正常工作能够继续。
- 服务恢复后，未完成工作可以接续。
- 积压能够被发现并逐步消化。
- 重复执行不会造成重复内容、重复推送或重复付费。
- 人工修订、撤回和暂停不会被自动任务覆盖。
- 用户打开网站时，能够看到准确的当前状态和已有内容。
网站应能在没有开发工具持续介入修复的情况下完成日常运行。 对需要人工判断的事项，清楚提示原因，不把正常等待不断转化为人工处理任务。
五、资讯产品完善
1. 国别分发与分类
保留一个不按国家拆分的总推送渠道，并完善阿根廷专门精选渠道，逐步形成对应飞书群的分发能力。

先把阿根廷的信源、选材和分发做好，再按同样方法推进秘鲁等国家。优先完善阿根廷，不缩减现有其他国家的信源和有效功能。

国家归属应根据内容实际涉及的事项判断，区分来源网站所在国、企业注册地、项目所在地和实际影响范围。跨国事项应能正确关联多个国家。

国家、业务主题、公司和项目应配合使用。围绕以下实际需要确定并落实页面入口：
- 查找某国近期矿业及经营变化。
- 查找监管、劳动、环境、投资并购等业务动态。
- 持续跟踪某个公司、矿山或项目。
读者主要通过国家和业务找到内容；来源分级继续服务于来源管理和既有质量规则。

网站和群推送使用一致的选材结果，并处理重复发送、失败重试和后续更正。国别精选如涉及新的评价视角，按已有确认及评分管理要求执行。
2. 精选漏选与内容准确性
继续处理矿业主管部门、行业监管等有价值动态未进入精选的问题。

从真实文章追踪原始发布、发现、获取、内容理解、评分、事件归属和最终展示，查清它具体在哪一步没有得到正确处理。
- 材料没有完整取得的，修复获取。
- 内容或事件阶段理解错误的，修复理解和表达。
- 评分正确但后续卡住的，修复后续流程。
- 确实涉及评分标准的问题，提出具体调整并按确认范围实施。
验证样本同时包含应选内容、普通内容和容易混淆的情况，包括监管实质变化、官方例行活动、许可进展、宣传稿及重复报道。

中文标题和摘要应准确保留主体、动作、阶段、数字、条件和新增事实。申请、批准、安排开展、实际启动及已经完成等状态，应清楚区分。

优化后同时检查重要内容漏选和普通内容误入，避免只修好几个已知案例。
3. 信源保留、获取与融合
完整承接 AI-MINE 现有信源及其有效配置，核对哪些已经稳定使用、哪些获取不完整、哪些存在失效或重复入口。

对现有来源的获取问题逐项修复，并围绕既定矿业关注范围补齐必要缺口。来源能够取得内容后，还应核对正文、日期、附件和后续更新是否可靠。

根据不同网站采用适合的获取方式，必要时利用其他成熟开源项目补足能力，使信源能够持续进入统一的资讯处理流程。

信源是否完成接入，以实际取得有效内容和持续更新为准。迁移不能造成已有来源、历史文章或有效来源关系丢失。
4. 热点榜与事件故事线
在 AIHOT 的事件组织与展示基础上，保留并适配矿业事件特点，继续完善热点榜和故事线。

精选与普通资讯都参与关联。未进入精选的内容，后续出现有关报道时，也应能够作为有效历史背景。

清楚区分：
- 同一事实的不同报道；
- 同一事项的后续进展；
- 同一企业或项目中的不同事项；
- 涉及多个事件的综合报道。
重点检查跨语言、企业及矿山别名、同一企业多个项目，以及跨月、跨年的后续进展。

用户进入事件或项目页面后，应能看清事情从何时开始、经历哪些关键变化、目前进展如何，并可返回各条报道核对。原文没有提供的日期和因果关系不补造，人工纠正的归属继续保留。
六、前后台与使用体验
1. 前台阅读与交互
以 AIHOT 的整体页面组织和交互方式为基础，完成 AI-MINE 的矿业内容适配，并衔接原有独有功能。

围绕查找、阅读和追踪资讯，完善筛选、返回、阅读位置、加载反馈、错误提示及手机操作。

页面反馈与实际状态一致，区分正在加载、暂无内容、正常等待更新和处理失败。主要功能之间能够顺畅切换，原有内容和链接保持可访问。
2. 轻量后台
后台适合多人和非专业人员开展日常管理，保留必要的来源管理、内容查看与纠正、运行状态和异常处理入口。

复杂处理主要由系统承担。后台用清楚的业务语言说明发生了什么、系统正在如何处理、管理者需要做什么。

多人协同应有必要的操作权限和记录，人工修改可以追溯，避免互相覆盖。迁移后不增加日常管理负担。
3. 访问速度
分别检查国内外代表性网络下的电脑和手机访问，定位影响打开页面、切换栏目和阅读内容的主要原因，再完成针对性改善。

代理、节点调整或服务器配置变化，应结合实际效果、持续费用和维护负担决定，避免单凭感觉扩容。

前后比较使用相同页面和尽量一致的访问条件，重点看用户实际完成关键操作是否更顺畅。
4. 品牌与域名
保留品牌名称调整及提前安排域名的工作。结合产品定位提出少量候选，核对名称使用情况、域名可用性及现有链接衔接。

产品继续使用 AI-MINE 自己的品牌体系。新名称由我确定，域名注册、购买和正式切换按明确授权执行。
七、实施与验收
1. 围绕统一迁移推进
先核对现有功能、已确认规则、信源和已完成成果，确定哪些已经符合目标、哪些仍需接续和调整。

整体迁移与现存问题修复结合推进，优先解决价格及信源误报、月报未自动生成，以及影响日常运行的故障。国别分发、信源获取、精选处理、事件关联、页面和后台工作按实际依赖衔接。

迁移切换前后，应核对主要功能、历史内容、来源链接和人工状态，确保新产品承接完整。
2. 按实际结果验收
验收项目	完成标准
整体迁移	网站以AIHOT的完整架构和通用运行机制统一运作，相应旧流程得到替换，各功能协调运行。
独有功能	AI-MINE原有且AIHOT没有的产品功能完整承接，使用效果保持或改善。
信源与历史内容	现有信源、有效配置、历史内容、来源链接和人工记录得到保留。
矿业规则	已确认标准与实际生效行为一致，候选方案和正式规则清楚分开。
金属价格与告警	正常更新间隔被正确识别，真实异常能够发现，同一未变化问题不反复刷屏。
