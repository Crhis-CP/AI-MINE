5. **由外部来证明结果正确。** 官方公报目录、官方多语种文本、历史监管事件、持证律师、主管部门登记系统，都比你我的判断更可信。

## 一、顶尖专家会做、原题目没要求的事

### 1. 开工前先建合规义务登记表

每一条义务都写清楚：依据条文（附原文链接和条号）、对本站是否适用、现状证据、不满足的后果、负责人、复核日期。至少覆盖以下几类。

**在中国大陆运营**

- 《互联网新闻信息服务管理规定》（2017）：第 2 条定义“新闻信息”，包括经济等社会公共事务的报道和评论；第 5、6 条规定许可制度和申请条件。
- 《互联网信息服务算法推荐管理规定》（2022）第 24 条：具有舆论属性或社会动员能力的算法推荐服务须备案。精选、热点排序是否属于这一类，需律师判断。
- 《互联网信息服务深度合成管理规定》（2023），以及《生成式人工智能服务管理暂行办法》（2023）。
- 《人工智能生成合成内容标识办法》和 GB 45438-2025，2025-09-01 起施行。项目已实现显式和隐式标识，需要复核。
- 修改后的《网络安全法》，2026-01-01 起施行，新增了人工智能条款。
- 《个人信息保护法》和《网络数据安全管理条例》（2025-01-01 起施行）。反馈表单、访问日志都涉及个人信息。

**内容使用**

- 《著作权法》第 5 条：法律、法规、国家机关具有立法、行政、司法性质的文件及其官方正式译文，以及单纯事实消息，不受著作权法保护。这对法规线有利，但官方网站的使用条款、robots 规则和反爬措施仍要遵守。
- 外国官方文本逐个法域核对。例如：美国联邦政府作品不受版权保护（17 U.S.C. §105）；英国立法使用 OGL v3.0；欧盟委员会文件按 2011/833/EU 决定再利用；澳大利亚联邦立法登记使用 CC BY 4.0；加拿大适用 Reproduction of Federal Law Order。
- 新闻媒体稿件：欧盟 DSM 指令（2019/790）第 15 条规定新闻出版者权，第 4 条规定文本与数据挖掘可以用机器可读方式保留。法国、西班牙等成员国已转化为国内法。

**面向海外读者**

- 欧盟《人工智能法》第 50 条透明度义务自 2026-08-02 起适用。其中第 50(4) 条要求：为公共利益事项告知公众的 AI 生成文本须披露，经过人工审核并由人承担编辑责任的除外。本站是否在适用范围内，需律师判断。四语 README 会把海外读者引到网站，所以这一条也要进登记表。

**法律信息服务的边界**

- 只提供公开、通用的条件化说明，不对特定主体给法律意见。每页注明“以官方原文为准，不构成法律意见”。原规格已有这条原则（POL-D01），四种语言要保持一致。

具体做法：开发方起草登记表，持证律师出具书面意见，把结论写回登记表；之后随法规变化，每季度复核一次。

### 2. 重启之前，先复盘法规线为什么停

用暂停前的实际数据回答这几个问题：

- 每份文书有多少页，扫描件占多少，字符量多大；
- 处理失败在哪一步；
- 每份文书发了多少次模型请求、花了多少钱；
- 有多少来源因为使用条款或网络原因受阻。

“成本和技术问题”要拆到可以动手修的那一层，否则重启后会再失败一次。

### 3. 基本单位从“文章”换成“法律文书及其生命周期”

一部法律会经历：草案或征求意见、审议通过、公布、施行、出台配套细则、修订、废止，也可能被法院暂停后又恢复。读者最需要知道两件事：它现在处于哪个阶段；从哪天起，对谁生效。

两个现成的例子：

- 中国《矿产资源法》2024-11-08 修订通过，2025-07-01 施行。配套的《矿产资源法实施条例》以国务院令第 839 号公布，共 8 章 79 条，2026-06-15 施行。
- 阿根廷冰川法修改案 2026 年先后由参议院、众议院通过并公布，此后曾被法院以临时措施暂停，又被上级法院撤销暂停。具体日期须以官方公报和判决原文核对。

按“新闻”处理，最容易在这里出错：同一部法律被多次报道，会被误当成多次变化；被暂停的法律，会被误报为已经生效。业内通行的做法是 FRBR 分层（作品、版本、载体），再配上 Akoma Ntoso、ELI 这类标识规则。项目不必照搬标准格式，但内部数据模型要有这几层。

### 4. 先做不调用模型的条文对比，再用大模型解读

把新旧版本按条款对齐，生成逐条增删改对照（redline）。这一步不调用模型，成本接近零，任何人都能复核。

模型只给有变化的条款写中文说明。每一句都要标出条款号，再由程序检查引文能不能在官方原文里逐字找到。官方已有译本的，直接用官方译本。

这是对“成本和技术问题”最直接的回应。

### 5. 给读者一份日期日历，不只是一条消息

强监管行业的读者首先要知道：什么时间之前，要做什么。日历里列出征求意见截止日、公布日、施行日、过渡期截止日、配套细则的出台期限。

日期只取官方原文；原文没写的，显示“未知”。这与现行时间规则一致。

### 6. 把“行业规范”单列出来，并定义清楚

原题目提到了行业规范。专家会把它和法律分开，分成三类：

- **国家和行业标准**：中国的 GB、GB/T、DZ/T（地质矿产）、AQ（安全生产）等矿山相关标准，跟踪它们的发布、实施和废止公告。
- **国际自律与报告规范**：GISTM（全球尾矿管理行业标准，2020）、ICMM 采矿原则、IRMA 标准、EITI 标准（2023 版）、OECD 冲突与高风险地区矿产供应链尽职调查指南。
- **资源量与储量披露规则**：CRIRSCO 模板、JORC、NI 43-101、美国 S-K 1300。

这几类规范在发布方、版本节奏和版权条件上都和法律不同。许多标准的全文受版权保护，只能收录元数据和官方链接。

### 7. 精简先测量：删不用的，不重写正在用的

先盘点以下几项：

- 没有被引用的文件、导出和依赖；
- 循环依赖；
- 重复代码；
- 近半年改动最频繁、又最复杂的文件；
- 生产日志里一次都没被调用过的路由和任务。

删除时先下线观察，再真正删除。保留现有的模块化单体结构（web / api / worker，加上 backend 和 modules），不拆微服务，不换框架。

### 8. 规则和文档瘦身，只留一个现行入口

- `AGENTS.md` 只保留现行规则，被取代的决定移到决定记录。
- 新写一页“现行状态”，列出目标、边界、暂停事项和授权。新会话读完这一页就能开工。
- 452 张任务卡和 228 个片段不删除，按年份归档，保留索引。

### 9. 多语言 README 按专业方式做

- 中文是源语言。另外三种语言的文件顶部都写明“译自中文版某次提交”。
- CI 检查四份的章节结构、链接和图片是否一致；中文改了、译文没跟上时给出提示。
- 建一份中、英、西、法术语表，统一“精选”“热点”“日报”“法规政策动态”“AI 辅助生成”等词。
- 西班牙语和法语请母语者审校。
- 免责声明四种语言保持一致。
- 写明网站内容是中文。

### 10. 公开法规内容的更正和撤回

法律信息出错，代价比普通资讯高。每次更正都保留原版本、更正原因和时间，并在页面上显示出来。项目已有修订和撤回机制，需要在法规线上公开展示。

## 四、除了你我之外，什么能证明结果正确

这些证明来自官方材料和外部第三方，与 DEC-76“不以 Owner 盲标或人工金标为前置”一致：它们是外部参照，不是人工标注。

| 证明者 | 能证明什么 | 怎么记录 |
|---|---|---|
| 官方公报目录 | 有没有漏收（召回） | 存档每一期目录，与系统收录清单逐条对账 |
| 官方原文 | 日期、条款引用、引文是否逐字正确 | 程序比对，不一致就不公开 |
| 官方多语种文本 | AI 翻译的质量 | 同一部法律的官方译本与 AI 译文，算自动指标并列出差异样例 |

## 五、改写后的题目

> 以下用你的口吻写，确认或修改后即为本轮唯一任务书。

### AI矿策第二阶段任务书（深度版）

#### 一、目的

帮助全球关心矿业的人，在有限的时间里读到更可靠的矿业资讯，以及矿业相关法律法规和行业规范的变化：变了什么，影响谁，从哪天起生效，现在处于哪个阶段，原文在哪里。

这一轮往深做，不往大做：法域少而精，每一项都要有外部可以核对的证据。

#### 二、做什么，按什么顺序

**第 0 步：合规底线（先做；完成之前，法规线不公开新内容）**

1. 建立合规义务登记表。覆盖中国大陆运营的许可与备案、算法与 AI 生成内容标识、个人信息与数据、内容版权与来源条款、面向海外读者的规则，至少包含本文第一部分所列条目。每条写明依据原文、适用判断、现状证据、后果、负责人和复核日期。
2. 以主管部门的查询结果为准，核清新闻许可和公安联网备案的真实状态；请持证律师出具书面意见，说明现有资讯线和重启后的法规线各自可以公开到什么程度。律师结论与现行做法不一致时，由我决定整改方案。
3. 按律师意见更新关于页、条款与隐私、免责声明。条款的具体内容由我确认。

完成标准：登记表里没有“未判断”的条目；律师意见已归档；页面上的声明与登记表一致。

**第 1 步：重启法规和行业规范的变化追踪（窄而深）**

1. 先复盘暂停原因。用暂停前的回执、失败记录和原件统计，写清成本和技术问题分别出在哪一步。
2. 试点范围：
   - 中国：国家层面和矿业主管部门。
   - 阿根廷：国家公报加 Salta 省；Catamarca 建立矿业法规底本；Jujuy 作对照。
   - 行业规范：先做矿山安全和生态相关的国家和行业标准，以及 GISTM、ICMM 的版本变化。
   - 欧盟可以作为第三个试点（官方多语种文本对验证翻译很有用）。
   - 其他法域保留登记，本轮不接入。
3. 以“法律文书及其生命周期”为基本单位：草案或征求意见、通过、公布、施行、配套细则、修订、废止、司法暂停和恢复。每个阶段都要有官方原文依据。
4. 先做不调用模型的部分：官方元数据、原文链接和存档、条款切分、新旧版本逐条对照、关键日期。之后才让模型给有变化的条款写中文说明，每句标条款号，由程序核验引文；有官方译本的优先用官方译本。
5. 读者能看到：
   - 法规变化列表；
   - 文书页，包含当前阶段、时间线、逐条对照、中文说明和原文；
   - 日期日历，列出征求意见截止日、施行日和过渡期。

   资讯里与法规有关的报道，链接到对应的文书。
6. 只采集许可允许的来源，遵守 robots 和使用条款。受阻的来源留在登记里，写明原因，不绕过限制。

完成标准见第五部分。

**第 2 步：精简架构和规则（以测量结果为准）**

1. 出一份盘点：未使用的文件、导出和依赖，循环依赖，重复代码，改动热点，生产中从未被调用过的路由和任务。
2. 删除与合并都先下线观察，再真正删除。保持现有的模块化单体结构，不换框架，不拆服务。
3. `AGENTS.md` 只保留现行规则，并同步模板；新增一页“现行状态”；历史任务卡和片段归档，保留索引。
4. 把关键约束写成自动检查：模块边界、没有循环依赖、没有未使用的导出；全新克隆后，用假模型一条命令启动并通过冒烟检查。

完成标准：盘点出的未使用项清零，或逐项写明保留理由；`AGENTS.md` 加“现行状态”页合计不超过 150 行（建议值）；全新克隆冒烟检查纳入完整验证并通过；读者能看到的功能没有回退。

**第 3 步：四语 README（中文、英语、西班牙语、法语）**

1. 中文 `README.md` 作为源文，另建 `README.en.md`、`README.es.md`、`README.fr.md`。每份顶部放语言切换，并注明对应的中文版提交。
2. 内容包括：
   - 项目目的；
   - 网站能做什么；
   - 网站内容为中文，保留原文链接；
   - 法规线的当前状态，如实写暂停或恢复；
   - AI 生成标识，以及“不构成法律或投资建议”的声明；
   - 数据和版权说明；
   - 本地运行；
   - 贡献与许可。
3. 设计：统一的标题区，深色和浅色截图，简洁的表格和流程图；不堆徽章。
4. 建立术语表；西班牙语和法语请母语者审校；CI 检查四份的结构、链接和图片是否一致，中文更新而译文没跟上时给出提示。
5. 遵守仓库现有检查。例如根目录文件中不出现上游项目名，署名留在 `NOTICE` 和 `UPSTREAM.md`。

完成标准：四份 README 的结构检查和链接检查通过；有母语审校记录；在 GitHub 上用电脑和手机查看都显示正常，并截图存证。

**第 4 步：统一验收与发布**

沿用现有规则：对准确的最终提交做完整验证，生成正式受测制品，准备好备份和回退，按我的具体授权部署；上线后在公网和手机上核验。
