# 运维读取与固定采样

周月报告警复用编排器的日报周期证据：结束日早于首期日报的周期不要求出刊；自首期日报起已齐全、原刊没有主条目的安静周期可以不留周月刊。两种情况都不因下一轮补刊刚进入running或其它刊期失败而重新报警。没有日报、周期缺刊或原刊主条目现已失去公开资格时，即使通用补刊记录为ok且当前合格条目为0，也不能认定正常不出刊。已挂上的空刊或坏刊继续提醒；读取不改任务状态、不补造空期、不调用模型。

未知回执日报按 `receipts.attempts` 区分仅尝试一次与已尝试多次；尝试次数不证明自动重试，也不证明是否计费。日报提示未知结果可能阻塞对应的新内容处理，不再统一声称不影响读者或无需处理。人工放行仍要求供应商确认最新尝试未计费，未知费用继续保留；自动恢复规则见 DEC-70 / ADR-0028。

信源周报压缩错误文本使用 PostgreSQL 的 `[[:space:]]` 字符类，保留英文单词和错误原因；最多显示160字符。资讯健康按编辑来源和热度信号分开；连续失败、近7天至少5次且占比至少10%的反复失败/详情失败进入日报。7天无新内容只进入周报，以90天内至少4个产出日的间隔中位数作比较，超过4倍才列为超出节奏，历史不足明确未知。首次导入折为到达当天，转发现有稿件的发现渠道单独统计；月更等慢来源不会仅因7天静默被认作故障。正文展示失败保留，须同篇正文展示成功或语义正文新版才能消除，其他采集成功和媒体更新不替代修复。日期许可拒绝同时记录用途、判定原因和文书域名，方便区分资源范围不匹配与用途禁止，不输出查询参数。

TASK-0323的`scripts/source-health-repair.ts`仅用于已核实的三处官方文书域名，默认展示计划，显式`--apply`才通过来源模块的版本围栏与审计写入。新证据限定文书路径和fetch/store_metadata/process_locally，不改变既有deny/unknown、全文、外部模型和公开用途。旧权限版本永久保留；目标已登记或来源受限时停止，避免重复或覆盖人工变更。

`operations/reports`沿既有出口提供`refreshOperationalSnapshots`和`readOperationalSnapshot`。worker每两分钟顺序读取各模块自有的固定聚合端口，单查询2秒上限；数据经严格的`@amp/contracts/ops-mcp`结构验证后写入ops.operational_snapshots。原始错误不写入快照，采样失败保留最后成功时间并标明失败时间；超过5分钟的样本显示陈旧。

TASK0484仅准备processing运行结果的可选body_reader契约，以及bodyReaderConfiguration提供的disabled/missing/configured/unavailable和固定中文detail；配置齐全不是服务可用证据。该契约PR没有调用此getter或输出新字段，旧MCP payload不变；后续消费者由下述TASK0485接通，与material_wait并列。

private-api的`POST /mcp-ops`只接受当前具名Owner与既有CSRF，提供`read_operations`一个工具和固定13数据集，每次最多100行。服务最多2个并发读取，每位Owner每分钟30次；不接受订阅、任意查询、任务或命令。专用ops_read仅SELECT快照；缺专用地址不退回private_ops。身份与调用审计仍由auth承担，当前Owner能力锁持有到读取与审计完成；角色被撤销即拒绝后续读取。

数据集包括心跳/备份记录时刻、任务运行、来源、材料处理、采集、月内实际回执汇总、费用预警与熔断、发布投影、脱敏审计动作、账号汇总、反馈汇总、评测数量和队列汇总。返回均带采样时刻、覆盖与排除说明，不能把采样成功解释成服务健康、法规质量合格或全来源完整覆盖。原始正文、提示词、任务载荷、错误原文、密钥、个人信息和审计前后值均不进入投影。

Web入口在所有主机名上拒绝/mcp-ops，public-api不注册它；不会新增公网入口或日常运营总览页面。部署时仅为private-api配置独立只读地址，凭据不进入仓库或聊天；Owner通过私网与现有具名登录通道使用。本次开发未创建真实服务账号或生产连接。

## 读者反馈投递

`operations/feedback`的`submitFeedback`只收件并在同一事务写入pending标记；`forwardPendingFeedback`供worker每分钟调用。仅worker设置`FEISHU_FEEDBACK_ENABLED=true`及专用`FEISHU_INTERNAL_CHAT_ID`后发送，沿用消息应用凭据，不回落到告警群。历史反馈不补发；并发领取、截图上传结果和飞书消息编号均持久保存。明确失败五分钟后重试，发送结果未知或进程中断后保留unknown供核对，禁止盲目重发。后台截图与处理记录保留；删除与发送用行锁排序，删除后不再投递。本站180天留存不自动撤回飞书副本，隐私说明明确由负责人处理副本。

未确认送达的反馈向现有运行提醒群发一次数量提醒，不包含正文、联系方式、截图或相关页面；提醒成功后持久标记，重试期间不反复提醒。同一群同时被配置为反馈和告警目标时，不发此异常提醒。


定时生命周期：worker完成当前定时任务注册后，删除不在本版本列表中的cron.*队列，连同旧排程及等待作业一起退役；已被此前版本取消排程的残留队列也清理。普通工作队列、稿件、回执和费用不受此操作影响，job_runs独立审计保留。后台现状按queue只读端口返回的现存定时队列筛选，历史流水继续包含已退休任务；读取现状不会启动队列producer或handler。

API心跳看门狗串行检查故障与恢复，飞书发送成功后才写通知状态；失败或通道禁用保留原状态，下轮继续。它不修改worker任务、内容或费用，也没有新增自动Agent消息目的端。

反馈每个匿名来源使用数据库内的滚动小时窗口：最多3条不同反馈、20次尝试，重复提交也计尝试；超限后只暂停该来源1小时。相同正文、联系方式、页面和截图字节在窗口内复用原记录，原提交编号可长期安全重试。自动暂停不关联未验证邮箱；后台确认滥用后可单独暂停邮箱48小时。到期即恢复，人工恢复来源同时清空窗口。公开收件角色仅能写反馈自有窗口，不能写人工封禁或身份审计。

TASK0458：feedbackKeys可为当前IP提供模块自有匿名来源标识，与原source/email共同查询已有有效封禁；同一收件事务中在配额或记录写入前查询，永久/临时/到期语义保持。异常或非法数组明确失败，不绕过人工控制。模块只收到IP，不收到正文、邮箱、截图，不新增IP持久保存；本批无实际提供者、不新设封禁、阈值或消息投递。

## 第一阶段等待与费用口径

来源健康汇总区分真实失败、当前未恢复的异常等待与正常主机访问间隔；当前等待由采集模块活动会话与当前绑定的采集记录确认，后台详情仅展示历史采集记录及该次计划重试时间，不以旧记录冒充当前会话。原调度、许可及人工暂停保持。

用量周报不再查询当前价格补算历史缺账；只汇总发生时保存的实际/估算金额及币种，缺项保持未知而不补0。真实零金额与缺金额分别呈现。月报/后台说明现有估算未拆分缓存与峰谷，不代表账单或每条合格内容成本。没有周/月累计金额上限，报告数字变化不等于实际节约；服务滚动请求控制和未知回执恢复不变。

### 价格与来源提醒（TASK-0429）

报价所属期和检查成功时间分别判断：价格年龄达到原登记阈值，但近期实际检查成功且没有更新时，保留原报价，正常等待；抓取失败、缺项、坏数据仍分别说明。半小时调度与来源发布频率不同，不把读取页面时间写成价格更新时间。

价格及来源异常仅在首次出现、原因/影响变化或恢复时通知。既有alerts.state保存比较依据；日摘要与即时异常按独立字段合并，避免互相覆盖。来源等待时间、连续失败次数增长本身不产生新原因；采集关闭或人工暂停不作为恢复证明。其他服务的原有提醒频率未调整。

报告恢复只依据本轮确实检查过的刊种：worker启动等待、采集/模型禁用、人工暂停或尚未到检查时间时，保留旧报告异常，不发送恢复消息；同样保留因启动等待而跳过的内容处理、热点异常，内容处理禁用或暂停也不视为恢复。实际检查确认恢复后只关闭一次。原20分钟启动等待和报告出刊资格保持（TASK-0428）。

TASK0485已接PR324契约：原告警与processing巡检共用配置判断，运行结果并列body_reader与material_wait。关闭备用仍统计等待；配置不可读不阻断统计，统计失败不补0且保留配置状态。未调用外部服务，旧MCP payload不变。源码接通不等于生产已显示。
